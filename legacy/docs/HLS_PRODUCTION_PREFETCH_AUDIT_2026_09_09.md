# HLS 预取接入生产 relay（2026-09-09）

源码提交 `5688d18c6779326a984f57584b86b26ef7d51f4f`，起点 `8734fc95`，承接[原子准入审计](HLS_PREFETCH_PLAN_AUDIT_2026_09_09.md)。本批把调度器直接接到 `FFmpegHlsInputRelay → FFmpegService → FFmpegManager`，不再通过额外实验 HTTP 适配层取得主要原生证据。

## 接入范围

新增显式 `hlsPrefetch` / `enablePrefetch` 参数，默认 false，且仅录制 drainOnStop 模式可用。当前不改变所有用户默认行为；预取 HTTP 合同、来源代次、停止边界与真实平台验收完成后再推进默认启用。

根媒体清单作为单路选择；根 master 只在上一批的无歧义计划成立时获取全部初始 snapshot 并原子选中。任一路初始合同失败则整体保留旧 relay；既有多质量/字幕/未支持 LL-HLS 不被强行改成单路。预取准备由根请求处理器拥有，停止会取消准备 token，关闭等待处理器及实际网络所有者。

## 所有权和 HTTP

- 直接使用生产共享 `HlsUpstreamClient`，延续平台 TLS、代理、Cookie、敏感头、来源查询策略及读预算；没有增加第二个 HTTP 客户端或第二层媒体拷贝。
- 选定来源代次只有一个 32 条目 / 16 下载 / 128 MiB 池，每体内存阈值 512 KiB。生效后未选中/注释内资源 ID 不再进入旧媒体暂存路径，避免同时开出一套 legacy spool 预算；不支持的代次仍完全走原路径。
- 缓存本地 ID 按完整 cache key 区分，而非仅上游 URI；反向 key 表用于准确退休注册项。清单注册项继续保留当前/前代及活跃请求，并额外保护调度器仍需的缓存身份。
- 就绪缓存通过读取租约直接发送，重复读取和 HEAD 不重新下载；媒体长度和 Content-Type/Content-Range 取自已封口验证的元数据，不输出 Cookie 或来源令牌。
- 整对象缓存可忽略 Range 发送完整 200；这符合 [RFC 9110 §14.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)。它不是高效任意区间读取实现。绝对 BYTERANGE 当前只开放与所缓存切片精确匹配的 GET，保持 206 与原始 Content-Range，错误范围不返回错位字节；仍需补真实 BYTERANGE 原生兼容范围。
- 新增仅含 statusCode 的上游响应异常，缓存 403 等保留原 HTTP 状态，不统一吞成 503；元数据/长度合同错误仍独立处理。错误表有数量与身份退休约束，不存完整错误响应或秘密头。

## 停止和事件

finish 先冻结清单与准入，原有有限排空期限到达后取消未就绪体、停止传输；已就绪 MAP/KEY/媒体继续从缓存读取。close 先结束本地 writer、等处理器释放租约，再关闭池与连接所有者。

缓存覆盖缺口回调接入实际 FFmpegRecordSession：检查会话身份、录制状态和停止/续签标志，只在活动代次第一次变为缺口时发事件；终态仍使用同一持久化覆盖字段。不会伪造一条 FFmpeg 日志来触发现有正则。
