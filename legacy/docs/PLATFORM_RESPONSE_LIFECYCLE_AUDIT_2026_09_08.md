# 平台 API 响应收尾与总读取期限（2026-09-08）

## 基线与来源

基线 `044faa21c0dc33b4cd30dbbe4760c43c3b9ebb76`，版本仍为 3.1.8+4121。
沿[花椒 API 审计](HUAJIAO_API_AUDIT_2026_09_08.md)发现的 Dio 流收尾问题，
检查站点 API 中直接取消包装流订阅的调用，覆盖映客、克拉克拉、猫耳、TwitCasting，
花椒作为已修订的对照。没有远程源码同步、依赖升级、设备或账号操作。
修订提交 `a482e57683fb0c5380e098edcfbee98b3c744ebd`；源码/证据哈希记录在
`local-artifacts/platform-response-lifecycle-20260908/validation-source.json`。

冻结 Pure Live 上游 `c6c9bd70aedc503c003110dae10a83ad0bb891d8` 没有这四个新增适配器。
问题归类为 **fork-regression**：维护分支新增有限响应读取器时，错误地将取消 Dio
包装流等同于停止适配器响应源。不是证明用户当前手机出现卡顿、发热或连接故障。

当前实现来源：映客 f9791b7c、克拉克拉 8d5883f1、猫耳 7aaecb8e、TwitCasting 1a18f353。
核对本机锁定 Dio **5.11.1** 的 `lib/src/response/response_stream_handler.dart`：
`responseSink` 没有向源转发订阅取消；请求 CancelToken 的处理才会停止接收定时器、
调用响应关闭和源订阅取消。测试使用真实 Dio 分发/转换链及可观测适配器源，不只是直接测 StreamIterator。

## 复现与修订

| 场景 | 基线观察 | 修订 |
| --- | --- | --- |
| 四平台 HTTP 403 响应体持续开放 | API 已报 access，上游取消次数仍为 0 | 每请求独立取消作用域，返回错误前结束对应源 |
| 四平台收到大于 1 MiB 的块 | API 已报 schema，上游取消次数仍为 0 | 超限退出同时取消当前请求，不只取消包装订阅 |
| 每秒收到小块、持续超过 20 秒 | TwitCasting 在 24 秒测试外层截止时仍未完成 | 使用总读取预算与 StreamIterator，不让每块重新启动 20 秒预算 |
| 同一调用方令牌的两个并行请求，一项失败 | 另一项应继续到成功 | 只取消内部令牌，不取消调用方/共享 Dio，不关闭其他请求 |
| 请求结束后继续复用调用方令牌 | 后续调用仍应成功 | 每次创建独立令牌，finally 解除取消转发并结束本次工作 |

公共 `withRequestCancellation` 提取自已通过测试的花椒实现，五个平台复用；
保留各平台原有 URI、请求头、代理路由、重定向设置、响应格式和业务状态分类。
TwitCasting 额外补齐注入文本/JSON 的 UTF-8 **字节**上限，以及取消与类型化请求错误同时发生时的取消优先级。
各 API 仍在读取字节前后执行自己的长度/错误分类检查，没有增加重试或共享缓存。
