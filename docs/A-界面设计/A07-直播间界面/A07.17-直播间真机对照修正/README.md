## 3.x 的样子和问题

- 01 信息行：`AudienceStrip`（`apps/pure_live/lib/features/live_play/layout/room_info_bar.dart:193-240`）是 `Wrap`（间距 14），哔哩哔哩有三个数（在线 1.0万、热度 162万、看过 7.8万）加时长时，K90 上放不下，时长折到第二行，信息行变高，和右边的画质、线路按钮对不齐（截图 `shots/k-room.jpg`）。设计 A07.1 v4-room 是一行。
- 02 手机横屏：`roomPageLayout`（`apps/pure_live/lib/features/live_play/logic/room_layout.dart:66-70`）高度小于 480 且横着时用 `landscape` 分栏（A07.5 第 149 行：聊天栏 300，没有出过图、没在真机上看过）。K90 横着是 869×400：右栏里信息行折成三行，“去登录”提示条加本地弹幕输入框把弹幕列表压到只剩一行（截图 `shots/k-now.jpg`）。
- 03 竖屏流：画面按“高”的高度排，底下又有本地弹幕输入框（A08.2），弹幕列表只露两行；设计 A07.2 v4-stream-mid 同一位置能看到 5 行；画面上方还有约 35 px 黑边（画面没有贴到顶）（截图 `shots/vertical-vs-design.jpg`）。

## 设计（按 D-003 由维护者定，第一阶段出图后发评审页给用户看）

- c1 信息行：数字超过两个时按宽度挑：放不下时先去掉“看过”，再把时长换成短格式（“6:45”）；一行放不下就整体缩到 `bodySmall`，不折行。所有直播间信息行高度固定。
- c2 手机横屏：不用平板的分栏。建议 A：手机横着且不全屏时，画面占满高度、左边，右边 280 宽只放弹幕列表（不放信息行和本地输入框；信息行收进画面上栏的标题，点标题打开详情）；建议 B：手机横着时直接进横屏全屏（和多数视频应用一样）。选 A（保留 3.x“横着也能看聊天”的用法），出图后评审。
- c3 竖屏流：默认用“中”的高度（v4-stream-mid）；本地弹幕输入框在竖屏流里收成弹幕列表右下角的一个星形按钮（A08.2 c13 的窄宽度收起规则），点了再展开；查清画面上方黑边的原因（`LiveVideoView` 的对齐或安全区）。

## 实现和验证

- 未开始。第一阶段出 c2 的效果图（手机横屏 869×400）和评审页，c1、c3 按上面的规则直接做。
- 测试：`apps/pure_live/test/features/live_play/` 的布局测试加 393×852、869×400、竖屏流三种尺寸：信息行只有一行；横屏右栏能看到至少 5 行弹幕；竖屏流能看到至少 5 行弹幕。
- 真机：K90 哔哩哔哩热门房间（三个数）、手机横放、抖音竖屏直播，各截一张和设计对照。
