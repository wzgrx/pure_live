## 类型和生命周期

- `PlaybackSource` 区分真实远端 URL 与 `OwnedPlaybackSource`。后者保存公开身份和创建函数，没有可导出的媒体 URL；短期本地 URI 仅在原生打开回调中存在。
- `play(String, …)` 保留兼容入口，统一委托类型化 `playSource`；请求列表与头部在派发时复制。自有输入与远端 URL/头部/查询策略混用，在改变播放意图前报错。
- `_currentSource`、源分组与提交快照保存实际类型。相同公开名字的不同配方属于不同分组，避免错误复用旧画质；URL 类型继续按 URL 值识别。
- 重播、重试、软件解码恢复、引擎回退、EOF 和有界延迟重试重新调用配方；不复用旧 seat。引擎切换及 Windows 预热替换仍由原有提交/回滚事务持有资源。
- 新播放、重播、重试、暂停在派发时取消未提交输入。旧输入的迟到错误先检查意图，避免为新请求启动旧恢复。暂停在原生分配前也生效。
- “已选源”与“原生已打开”分别记录：被取消的首次创建在恢复时重新打开；已有源的预热候选被取消后，恢复只继续旧源，不多建会话。
- 恢复请求传递 `currentSource`，自有源的 `currentUrl` 为 null；恢复结果有独立 `.owned` 入口。远端按 URL 的线路策略不应用于自有源，也不传入其提交元数据。
- `RoomSessionSnapshot` 携带无活动资源的配方；提交合并、预备悬浮和管理器重入保留它。仅更新音频保留；替换 URL、房间或画质而未提供新配方时清除。

兼容快照的字符串 `currentUrl`/`dataSource` 对自有源为空，仅表示没有可导出媒体 URL；实际打开分支使用类型，不将空字符串或身份文字传成原生媒体地址。
