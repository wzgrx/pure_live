# 竖屏播放选择器布局与事务审计（2026-09-12）

- 范围：直播画面控制栏中的“房间画面方向”和“竖屏全屏显示模式”选择器、记住房间方向开关、取消/系统返回语义及窄屏大字号布局。

## 稳定问题与根因

1. 两个旧选择器都把全部选项放入仅限制宽度的不可滚动 `Column`。显示模式还为四个选项同时展示较长说明；在 320×480 / 3.0 倍文字下，后部选项和开关会超出单个可见区，弹窗没有内容滚动所有者。
2. “记住房间方向”在弹窗内直接写入持久设置，但方向选择只有在返回非空结果后才提交。因此先切换开关再按取消、系统返回或遮罩关闭，会留下没有配套方向选择的设置副作用。
3. 方向和显示模式各自维护一份密集 `ListTile` 弹窗，长译文的自然高度、整行点击、描述和固定取消动作缺少同一布局合同，后续容易继续漂移。

## 修订

- 新增独立的播放选择器组件；两个弹窗统一使用视口约束的滚动内容，取消动作留在滚动区外，选项整行可点。
- 房间方向弹窗把“是否记住”保存在路由本地草稿。选择方向时以 `PortraitOrientationPickerResult` 一次返回方向和记忆策略；取消、系统返回和遮罩关闭均返回空结果，不写持久设置或房间覆盖。
- 提交端仅处理完整结果，先更新记忆策略，再以同一值写入持久/会话房间方向并刷新呈现策略，避免读取弹窗外已变化状态。
- 方向选择补充记忆策略说明；竖屏全屏显示模式保留每项说明和当前选中标识，在大字号下通过滚动逐项可达。
- 控制栏图标与弹窗使用同一显示模式图标映射，减少两处视觉语义分叉。
