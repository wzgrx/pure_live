# M13.3 页面：直播间（主要流程）

- 日期：2026-10-01
- 目录：`apps/pure_live/lib/features/live_play/`（8 个文件，约 3000 行）
- v3 来源：标签 `v3.2.11` 的 `lib/modules/live_play/`（67 个文件，18475 行）。本次做主要流程：进房、播放、弹幕、关注、人数；其余功能见“留给后续”。
- 用到的包：`live_core`（房间、平台、人数口径 `audience.dart`）、`live_player`（`PlaybackSession`、`LiveVideoView`、`MpvEngineConfig`、`roomVolume`）、`live_media`（`PlaybackPlan`）、`live_danmaku`（连接、过滤、通知节流）、`live_store`（设置、关注、历史、屏蔽）、`live_ui`（主题、状态页、头像、设置积木）。

## 做法

- **页面怎么取服务**（M12 的约定）：`sitesProvider.maybeOf(platform)` 取平台，`danmakuProvider.connectionFor/supports` 取弹幕，`playbackSessionFactoryProvider(config:)` 建一个播放会话（页面持有，离开时 `dispose`），`storeProvider` 取设置和数据。播放设置（硬解、自定义输出、兼容模式、RTX 超分）组成 `MpvEngineConfig` 传给会话（M12 留给 M13 的一项）。
- **逻辑和界面分开**：`room_controller.dart` 的 `LiveRoomController`（`ChangeNotifier`）对应 v3 的 `LivePlayController` + `PlayerController` + `DanmakuController`，所有依赖从构造参数传入，测试直接用假平台、假弹幕、假引擎驱动。界面只读它的状态。
- **一个阶段代替四个标志**：`RoomStage`（`loading`、`failed`、`offline`、`unplayable`、`playing`），播放中的细分（打开、缓冲、出错、暂停、回放播完）直接看会话的 `PlaybackState`。每次加载有序号，晚到的回答丢弃（v3 的 `_roomLoadEpoch`）。
- **进房**：取详情 → `withAudienceFallbackFrom` + `fillFromDetail`（保留卡片上的人数、名字、头像、分区）→ 关注里有这个房间就更新它的快照 → 能播（直播或回放）就发现画质（`LiveQualityDiscoveryScope`，离开时取消）→ 按偏好选默认画质（v3 规则：同名优先，否则按五档名字的相对位置）→ `resolvePlayUrls` → `PlaybackPlan.of(preferH264:, onDemand: 回放)` → `session.open`（带刷新回调 `resolvePlayUrlsForRecovery`、房间音量）。打开成功后记观看历史（`store.history.record`，历史页 M13.6 依赖）、连弹幕、拉醒目留言。
- **画质和线路**：画质切换期间旧流继续播；平台实际给的画质和请求的不同时，选中实际那档并提示（`resolveAppliedPlayQuality`）；未确认的画质名后加“?”。线路由会话管理（`selectLine`，失败自动换线由会话做）。
- **出错和重试**：详情失败保留卡片信息、状态待定（`pendingAfterError`），按错误类型显示原因（要登录、地区、不存在、网络、平台拒绝、接口变化、没有流），重试重新进房；播放失败先 `session.retry()`，平台说不能播（终态）时重新进房。
- **定时刷新（B-24）**：页面打开期间每 60 秒取一次详情（平台有轻量的 `getRoomDetailForRefresh` 就用它）：未开播的房间开播后自动开始播放；播放出错且平台说已下播时显示未开播；弹幕连接已结束（下播后平台断开）而主播仍在播时重连。标题、人数随之更新（Steam 等需要定时刷新人数的平台也由它覆盖）。
- **弹幕**：连接事件逐条处理：`DanmakuReady`/`DanmakuReconnecting`/`DanmakuClosed` 变成聊天列表里的状态行（原因文字照 M5.0 的表）；聊天经 `DanmakuMessageFilter`（去重闸门、屏蔽词和用户、合并重复、相似过滤，设置和屏蔽表改动立即生效）后进列表和飞行层；人数更新按类型写进在线/热度/累计；醒目留言进醒目留言页并在列表里加一行；撤回（`LiveRetraction`）从列表和飞行层同时撤下；通知（订阅、突袭、公告）用单独样式的行，同一文字 3 秒内只显示一次；礼物先不显示（B-21）。首次连接的超时从 v3 的 20 秒改为 30 秒（见问题 6）。
- **飞行弹幕**：`danmaku_overlay.dart` 自己画（`Ticker` + `TextPainter`，描边、透明度、字号、粗细、速度、区域照设置）。v3 用的 flame_barrage 是游戏引擎加本地补丁，为一个飞行层引入整个 flame 不值得，也避免改应用的依赖。没有空闲轨道时丢掉这条，不叠在一起。
- **布局**：宽度 ≤ 680（v3 的分界）上下排：16:9 画面、信息条、四个标签页；更宽时聊天在右侧（宽度 34%，300～400）。网络电视不显示聊天（v3 同）。全屏时只有画面和控制条；手机上进入沉浸模式并转横屏（竖屏流保持竖屏），返回键先退出全屏。桌面：双击画面切换全屏，Esc 退出、F 切换、空格暂停。设置“默认全屏”打开时，开始播放后自动全屏（v3 同）。

## 界面改进

- **人数**：信息条同时显示“在线 N”“热度 N”“累计 N”（有哪个显示哪个），平台支持在线但还没收到时显示“在线 待刷新”；未开播不显示人数（19-4、26-8）。
- **开播时间**：信息条显示“已开播 1 小时 20 分”，房间信息里显示具体时间（10-3、25-12、33-7 等）。
- **受限房间**：标题前加受限标记（付费、私密、需登录、仅限 App……），拿不到流时画面区说明原因（统一原则“播放时说明原因”）。回放房间标“录播”，播完显示“回放已播完 / 从头播放”。
- **房间信息**：点标题或菜单打开“直播间信息”：标题、状态、开播时间、受限说明、公告、简介、房间号和链接（可复制）。公告取本次详情（不沿用存下的旧公告，FC2 那条注意事项）。
- **状态显示在画面区**：进房中、未开播（封面暗底 + 头像 + 原因 + 刷新，并说明“开播后会自动开始播放”）、失败原因 + 重试，代替 v3 的 Toast。
- **控制条**：画面上一排按钮（暂停、刷新、弹幕开关、全屏），4 秒无操作自动隐藏，点画面切换，鼠标移动显示；全屏时顶部有返回和标题，底部带画质、线路。
- **聊天列表**：通知、醒目留言、状态行各有样式；粉丝牌显示在名字前；长按（桌面右键）可复制或屏蔽发送者，屏蔽后该用户已有的消息立即消失；醒目留言标签页标题带数量。
- **关注**：已关注用浅色按钮，关注成功有提示；窄屏用心形图标。
- **飞行弹幕**：自绘，不叠字；撤回的消息同时从画面撤下。
