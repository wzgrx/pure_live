# DLNA 发现、投屏事务与对话框布局审计（2026-09-12）

## 范围与基线

- 基线：`947d8a15dea227153ba690e52523405a9a1e001a`。
- 范围：播放器和工具箱选定直播地址后共用的 `LiveDlnaPage`，包括媒体地址入口、SSDP 发现、手动刷新、设备快照、切换接收器、`SetAVTransportURI → Play` 时序、退出清理及对话框状态布局。
- 本批仅使用受控发现/接收器替身和 Widget 环境；没有连接手机、发送真实 SSDP 组播、控制局域网电视或投送真实媒体。

## 源码复查发现

1. 搜索停止计时器只在页面初始化时创建一次；20 秒后手动刷新不再拥有新的停止边界，界面可长期停在搜索态。
2. 连续点击刷新会重入 `DLNAManager.start()`，新旧 socket、设备流和订阅没有代次归属；迟到的旧发现结果可覆盖当前界面。
3. 设备快照只向 Map 追加，搜索结果已删除的接收器仍保留在列表；空名称和发现异常也没有稳定可见状态。
4. 选择设备时分别发起 `pause`、`setUrl` 和 `play`，三个 Future 都未等待；`play` 可早于媒体地址设置完成，连续点击会发送重复命令，异常从点击回调逸出。
5. 页面退出只停止搜索，已在途中的设置地址仍可在退出后继续发送 `play`；开始发现的异常也没有页面内重试入口。
6. 内容固定为 200×200，只有标题刷新图标，没有关闭动作、当前投屏状态、进行中门禁和错误恢复；窄屏大字号下状态和设备行可达性缺少约束。

## 修订

- 仅接受无内嵌凭据的 HTTP(S) 媒体地址；非法输入直接进入可关闭终态，不启动发现。
- 将组件与具体 DLNA 包之间抽象为发现会话和接收器端口；每次搜索独立拥有订阅、计时器和代次，刷新先启动旧资源释放，迟到快照被隔离。
- 快照按设备 ID 整体提交，移除消失设备；空名称使用双语回落，搜索中断保留已发现设备并显示说明。
- 投屏改为单一活动事务，严格串行“暂停旧接收器 → 设置新地址 → 开始播放”；旧接收器失联不阻断新设备，关闭或设备移除后不再续发 `play`。
- 起始、搜索、空、失败、投屏中、投屏成功和投屏失败都有可见状态；列表显示当前接收器，失败可在原位重试。
- 对话框改为窄边距、有界滚动内容、可换行标题和固定关闭动作；320×480 / 3.0 倍英文下空态重试、长设备名称/标识和关闭操作保持可达。
