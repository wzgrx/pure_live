# 微博分享文本预处理修订（2026-09-11）

## 来源与复现

基线 `608c1d5d084498dca061eba9a2401763d90dfa9f`。本批只处理共享 URL 提取器与已有微博链接解析器的组合，平台仍未注册到应用列表。

`WeiboLink.parse` 已检查原始路径并拒绝末尾 `/.`、`/..`，但 `LiveUrlTool.sharedHttpUrls` 的通用尾部标点清理会先删掉句点，将两种错误路径变成可接受的尾斜杠路径。另一条输入在 URL 后紧接 `。打开应用观看`，没有空白分隔，通用清理又会保留整段正文。

最小复现中的场次 ID 为测试值 `1022:2321325000000000000000`：

1. 官方观看 URL 后加 `/.`，提取后比原文少一个句点。
2. 同一 URL 后加 `/..`，提取后比原文少两个句点。
3. 同一 URL 后加中文句号与分享正文，正文仍被当作 URL 的一部分。

三条基线测试实际均失败：`local-artifacts/build-records/20260910T171022054Z-quality-focused.json`，0 PASS / 3 FAIL。记录保留，不将预期的红基线标为成功。该轮格式检查及仓库静态检查通过；并未运行分析或设备测试。收尾活跃重型进程计数为 2，后续守卫对其他 Java 工作排队，未停止其他任务。

分类为 `fork-regression`（维护分支共享提取器与新适配器的组合契约缺口）：特殊中文边界及点路径保留逻辑在 `127c5781782535976af187d05648cf7cbd9ceedc` 仅对小红书主机生效，微博走通用分支。没有本轮上游最新版比较证据，不将其归因为上游缺陷，也没有合并上游。

## 修订

- 将 `weibo.com` 与 `www.weibo.com` 纳入现有严格分享文本处理分支；不改其他平台的主机规则。
- 区分中文正文标点、普通句末标点与结构性点路径；交给微博解析器继续拒绝歧义路径。
- 保留场次 ID 的 ASCII 冒号、允许的编码冒号，以及查询参数原始百分号编码大小写；不经 URI 重序列化改写链接。
- 新增 19 项确定性测试，包含原三条复现、两种主机、中文/ASCII 标点、两类场次 ID、移动观看路径、大小写及显式默认端口、查询/片段和编码点路径。

没有修改播放/录制实现、设置迁移、平台注册、依赖、用户数据或版本号。回滚只涉及共享提取器此次主机扩展及相应测试/文档。
