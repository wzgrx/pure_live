## 目标

1. 屏蔽的用户、屏蔽词对礼物也生效；断线重连补发的礼物不重复。
2. 同一个人连击同一个礼物，聊天列表只有一行，数量往上涨（“×10”变“×20”），不再一下一行。
3. 忙的直播间礼物不把聊天挤出列表：每秒最多加 10 条礼物行，500 行里礼物最多 150 行；免费礼物超了直接丢（只计数）。
4. 每秒 200 条的基准里加礼物，界面线程不变慢。

## 方案

- c1 过滤：`DanmakuMessageFilter.accepts` 对 `gift`（和 `superChat`？**选 A：只加礼物**；醒目留言是付费内容、3.x 也不过滤，维持现状）走去重闸门（`message_gate.dart`）和屏蔽表（`block_list.dart`，屏蔽用户看 `userName`，屏蔽词看礼物名和 `message`）；合并重复、相似度不用于礼物（礼物本来就重复）。控制器的礼物分支调 `_filter.accepts`。打码昵称照 D-013 不能屏蔽。
- c2 合并（在控制器、`ChatFeed` 之前，V03.5 第 6.4 节）：键 = `comboKey`，没有时 = 送礼人 + 礼物编号；同一个键在 **5 秒**内又来，并且那一行还在列表最后 **20 行**里，就不加新行，改那一行的 `count`（平台给了 `comboTotal` 用它，否则累加）；跟随时这一行移到最下面，用户往上翻（定住）时不移动只改数字。`ChatFeed` 加一个“替换某一行”的方法（D04 的文件，只加不改原有行为），仍然每帧最多通知一次。数字跳动的动画是 A08.11 的事，这里只给“这一行更新了”的信号（例如行的 `revision`）。
- c3 限速（V03.5 第 6.8 节）：每秒最多加 **10 条**新礼物行，超出的同类礼物只累计到已有的行，免费礼物直接丢；`ChatFeed` 里礼物行最多 **150 行**，超出时先丢最老的礼物行，不丢聊天。数字写成控制器里的常量，测试覆盖。
- c4 基准：`chat_benchmark_test.dart` 加“每秒 200 条聊天 + 50 条礼物（同一礼物连击、不同礼物各一半）”，和改之前对比（调试模式只能前后比，D04 的规则）；目标界面线程 ≤3 毫秒/帧（UI.md 第 9.4 节），真机 profile 数字在 verify.md 里记。
- c5 “在聊天列表显示礼物”关着时：礼物仍不进列表，合并和限速不运行（不白算）。
- 需要选的（D-003，维护者定）：c1 醒目留言过不过滤 → A 不过；合并窗口 → 5 秒（照 V03.5）；“最后 20 行”的范围 → 照 V03.5。
- 不做：飞行弹幕里的礼物和它的每秒 3 条（A08.12）；平台连击号的解析（E05.5、D07.4、D07.6）。
