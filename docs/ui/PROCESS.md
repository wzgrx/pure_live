# 界面重构：每个任务的做法

照 U.2a 竖屏直播间和 U.2f 直播间弹窗走过的流程整理。每个任务（[TASKS.md](TASKS.md) 里的一行）都按这 10 步做，做完一步在任务文件夹的 README 里更新状态。

| 步 | 做什么 | 产出 | 谁 |
|---|---|---|---|
| 1 | 读代码 | 清单一节 | 我 |
| 2 | 还原 v3 | v3 图 | 我 |
| 3 | 设计新方案 | 新设计图 | 我 |
| 4 | 对比页 | claude.ai 页面 | 我 |
| 5 | 确认 | 确认结果 | 用户 |
| 6 | 导出和上传 | `compare/<编号>/` | 我 |
| 7 | 开发任务书 | 任务书 | 我 |
| 8 | 开发和测试 | 代码、测试、记录 | 开发代理 |
| 9 | 合并 | 门禁、推送 | 我 |
| 10 | 下一个 | | |

## 1. 读代码

- 从 [TASK_FILES.md](TASK_FILES.md) 找到这个任务对应的 v3 文件（手机、平板、电脑看 `v3:`，电视看 `tv:`），全部读完；再读 v4 现在的实现和参考项目里对应的部分。
- 在 [V3_UI_INVENTORY.md](V3_UI_INVENTORY.md) 加一节，写四件事：
  - **v3 的样子**：结构、控件顺序、图标原名、文字（取自 `assets/translations/zh.json`）、尺寸、颜色角色、手势和快捷键；它会弹出的每个对话框、面板、菜单；代码里按宽度分支的地方。
  - **v3 的问题**：编号、问题、根因、文件:行。
  - **v4 现在的偏差**。
  - **v3 文件 → v4 文件**。
- 功能有多种状态的（例如录制任务有 9 种），先把全部状态和数据从代码里列出来，再设计。

## 2. 还原 v3

- 不截图，按代码画：HTML 加 v3 的字体和图标（Remix、CustomIcons、Material Icons、v3 的弹幕 SVG），无界面浏览器渲染成图（`chrome-headless-shell --force-device-scale-factor=3`），ffmpeg 转 JPEG。颜色用 `ColorScheme.fromSeed(Colors.blue)` 的实际值。画面和头像用示意图片并标“示意图片”。
- 每个文字、选项、分组、数值都从代码取，不凭印象；长的面板画完整内容（长图）。
- 形态按 [TASKS.md](TASKS.md) 第 2 节，出齐 v3 里有的：竖屏 393×852、横屏 852×393、宽屏 1280×800、电脑 1920×1080、电视 1920×1080。
- 每种状态一张（例如没任务、已监控、录制中）。

## 3. 设计新方案

按计划书第 4 节的原则，尤其是：

- **v3 为准**：位置、顺序、图标、弹法照 v3；每处改动都对应一个 v3 问题编号或用户的要求。
- **各客户端一致**：同一个功能在各形态是同一个组件、同样的样子和操作，屏幕大小只决定放在哪。
- **不先定统一规则再套**：逐个看 v3 好不好用。
- **功能一项不少**：v3 的每个动作、设置都要在新设计里找得到；改了位置的列对照表。
- **状态齐全**：加载、空、出错、受限、进行中、完成等。
- **性能**：计划书第 7.4 节的约束（不用模糊、分层重绘、列表懒加载等）。

## 4. 对比页

一个任务（或一批相关任务）一个 claude.ai 页面，章节固定：

1. 说明：这一屏是什么；改版时写清“这一版改了什么、上一版为什么不行”。
2. 对比：左 v3、右新设计，各形态、各状态。
3. v3 的问题：编号、问题、位置（文件:行）。
4. 改了什么：保留、修改、增强，每条对应问题编号。
5. 每个按钮是干什么的、怎么用：按钮名和用法，一个不漏。
6. 需要你选的：每处给建议和另一种。
7. 性能要点。
8. 参考（如有）：被否决的旧版、v4 现在的样子。

页面的 HTML 存在仓库外 `~/ref/design/compare/<编号>.html`。

## 5. 确认

- 用户逐条看，可以只确认一部分；没确认的改了再发新版（同一个页面地址，标“第 N 版”）。
- 用户否决的，在 README 里写清原因和教训（例如 U.2f 第一版、第三版）。
- “需要你选的”没有单独回答时按建议做，并在 README 里注明。

## 6. 导出和上传

- `python3 tools/ui/export_compare.py <页面.html> docs/ui/compare/<编号>/page` 按章节导出图片。
- 主要的单张图放进 `docs/ui/compare/<编号>/`，文件名 `v3-<内容>.jpg`、`v4-<内容>.jpg`。
- 写 `README.md`：状态、确认日期、各版经过、对比页章节链接、单张图表、确认的改动清单、按钮用法、待选和决定。
- 更新 [TASKS.md](TASKS.md) 的状态和 `docs/PLAN.md` 的 U.x 行；`tools/gate/gate.sh --all` 通过后推送。

## 7. 开发任务书

写给开发代理的任务书，内容：

- 范围：这个任务的 README、对比页导出图、清单一节；v3 和 v4 的文件。
- 逐条的改动清单（照 README），每条要做到什么样。
- 不能动的：别的任务的界面、原生部分、版本号、用户的 3.x 安装。
- 代码放哪：`features/<模块>`（按 `logic/`、`layout/`、`player/` 等子目录）和 `packages/live_ui`；颜色和图标走 `live_ui`，不新增直接写的颜色和图标，不新增跨功能引用（门禁“ui structure”）。
- 测试要求（第 8 步）；提交和记录要求。

## 8. 开发和测试

- 先还原 v3 布局，再加确认过的改动。
- widget 测试固定控件的顺序、图标和位置；各形态（竖屏、横屏、宽屏）至少一个布局测试；逻辑测试照旧。
- 和原有测试冲突的，按设计改，原因写进记录。
- `docs/ui/records/<编号>.md` 写实现记录：逐条对照表（做了没有、偏差和原因）、新设置项、`ui_baseline.json` 的变化、测试数量。
- 涉及列表、弹幕、动画的，profile 模式看帧时间。

## 9. 合并

- 合并开发分支，`tools/gate/gate.sh --all` 通过后推送。
- 门禁基线（`tools/gate/ui_baseline.json`）只减不增。
- 更新 TASKS.md、计划书第 11 节、`docs/PLAN.md` 的 U.x 行。

## 10. 下一个

一批确认后，开发和下一批对比图并行；每批 2～4 个界面。
