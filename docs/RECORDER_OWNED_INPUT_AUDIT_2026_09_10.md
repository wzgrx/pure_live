## 消费者与所有权

- `ResolvedRecordStream.owned` 保存公开 LiveInputRecipe、实际画质确认和请求游标；自有输入是一条逻辑线路，轮换越过该线路后进入下一画质，单档最后回绕。Cursor 适配器即使对越界线路返回同一配方也不会伪造第二条线路。空 URL 仅是无导出地址的兼容视图，不进入原生参数。
- 录制绑定与播放独立：每次尝试重新读取 watch 元数据，传明确分辨率/码率、`recording:true` 与既有应用/录制代理策略；不复用播放 seat 或旧本地 URI。
- `OwnedRecordInput` 提供私有地址、关闭、排空预算、覆盖缺口和尾部舍弃信息。NiconicoHlsInput 转发 relay 事件，并在 seat/relay 关闭后保留无凭据的终止计数；清除监听者。
- 实际 RecorderController 使用 `startOwned`，按取得的真实私有 URI 延迟生成完整 FFmpeg 参数；输出设置在分配前冻结。无占位媒体 URL、无额外套一层 relay、不向本地输入转发站点凭据。任务的 currentUrl 为 null，配方/seat/本地 URI 不写入任务持久化；画质与线路文字照常保留。
- FFmpegService 在初始化/分配之前预占同一 taskId。停止创建中的任务立即通知取消，等待迟到的输入关闭；重复开始遭到明确错误。普通 URL 和自有输入共用该生命周期，Manager 不再在预占边界之外等待初始化。
- 原生打开、参数构建、创建失败和执行异常进入资源清理。手动停止先完成输入排空，超出输入自己的预算再调用原生取消；FFmpeg 原生退出与输入清理分别等待，清理期间仍占用任务。自然 EOF 仍是可重试输入结束，不伪报直播下播。
- 终止事件保留排空、强制取消、活动覆盖缺口和尾部舍弃，不把“已排空”升级成完整解码证明。普通直链的 HLS/FLV 行为与元数据入口保留。
