## v3 的样子

文件：`lib/recorder/pages/recorder/recorder_page.dart`（下面只写行号）、`lib/recorder/widgets/recorder_bounded_scroll.dart`。

**入口**：手机（宽度 ≤680）是首页底部导航的第四个标签“录制中心”（`Remix.download_2_line` / `download_2_fill`，`modules/home/mobile_view.dart:56-63`），默认就有；宽度 >680 时这个标签从导航栏去掉，改为导航栏上方的图标按钮（`Remix.download_2_line`，提示“录制中心”，`tablet_view.dart:138-146`），点开是一个新页面。直播间录制对话框的“进入录制中心”也打开这个页面（`live_play_controller.dart:1059`）。

**顶栏**（`:35-53`）：标题“录制中心”居中（20 号半粗，主题 `centerTitle: true`）；左边：能返回时是返回，不能返回且 `Get.width <= 680` 时是菜单按钮 `Icons.menu_rounded`（设置、关于、历史记录、备份与恢复，Windows 多“在新窗口打开”，`common/widgets/menu_button.dart`）；右边：`Remix.folder_video_line` 22（提示“打开文件夹”，打开录制根目录）、`Remix.settings_5_line` 22（提示“设置”，打开录制设置），再留 8。

**状态筛选**（`recorder_bounded_scroll.dart:10-91`）：九个等宽按钮“全部、录制中、等待开播、排队中、重连中、处理中、已完成、失败、已停止”（`:15-25`）；宽度 <600 每行 3 个，600–899 每行 5 个，≥900 一行 9 个；每个高 48、圆角 11、间距 3、外边距 10 / 6；选中是主色容器底、加粗 700，未选中是最高表面容器 46% 底、500；字 12（`labelMedium`）。下面一条分隔线。列表不能左右滑（`NeverScrollableScrollPhysics`）。没有“准备中”的筛选；没有数量。

**排序**（`recorder_task_ordering.dart`、`record_status.dart:17-38`）：“全部”先按状态：录制中、重连中、处理中、准备中、排队中、等待开播、失败、已完成、已停止，同状态新的在前；其他筛选只按时间。

**卡片**（`:448-711`）：表面色底（和页面同色）、圆角 18、8% 轮廓描边、淡阴影，内边距 14，卡间 14；点卡片进直播间（`:491-506`）。

- 封面 150×90、圆角 14；左上角状态标签：状态色 82% 底、白字 12 粗（`:253-301`）。卡片内宽 <480（随字体放大）时封面单独一行在上，否则封面在左（`:560-576`）。
- 标题 15 粗 700、最多两行；头像 24 + 主播名 14 半粗次要色；一行标签：平台（`Remix.plant_fill` + 大写平台 id，如“BILIBILI”，平台色 10% 底）、清晰度（`high_quality_rounded` + “原画”，没有时“自动”）、线路（`alt_route_rounded` + “线路1”，有时才显示）、人数（按口径：热度 `whatshot` / 在线 / 累计观看 / 粉丝 / 观看）（`:517-558`）。
- 统计框（录制中、重连中、处理中、准备中，或录过东西时）：主色 5% 底、圆角 14；四项：时长 `timer_outlined`“00:12:34”、大小 `storage_rounded`“356.21 MB”、速度 `speed_rounded`“1.0x”、码率 `graphic_eq_rounded`“3.2 Mbps”；下面一条 4 高的主色细条，始终满格（`:579-611`）。
- 重连中、准备中：状态色 8% 底的条，`sync_rounded` + 状态名（`:612-635`）。
- 录像有缺失：三级容器色条，`warning_amber_rounded` +“录制中已跳过缺失或过期的直播片段……”“停止时部分输入未完整接收……”（`:636-665`）。
- 有失败信息且不在录制：错误容器 52% 底，`error_outline_rounded` +“最近失败（{阶段}）：{原因}”，最多 3 行（`:666-691`）。
- 底行：左边 `schedule_rounded` + 开始时间“10-01 21:18”，右边按钮（`:692-705`、`:341-446`）：

| 状态 | 状态色 | 按钮（从左到右） |
|---|---|---|
| 录制中、重连中、准备中 | 绿、橙、琥珀 | 删除、停止（红色实心） |
| 排队中 | 深紫 | 删除、启动（主色实心）、取消（描边） |
| 等待开播 | 浅橙 | 删除、立即检测 |
| 失败 | 红 | 删除、重试 |
| 已完成 | 蓝 | 删除、重新录制 |
| 处理中 | 青 | 删除、启动 |
| 已停止 | 灰 | 删除、启动 |

  “删除”是红字文字按钮（15 号）；其余按钮高 48、圆角 12、字 12 粗。“启动 / 立即检测 / 重试 / 重新录制”都调用 `forceStartTask`。

**删除**（`:743-809`）：对话框标题“取消监控”，正文“确定停止监控“{标题}”？已经保存的录制文件会保留。”，按钮“取消”“确认”（红色实心）；确认后先停止（有分段就合并），再从列表删掉（`recorder_controller.dart:1435-1448`）。

**空**（`:811-841`）：92 的主色 8% 圆底 + `video_collection_outlined` 42，“暂无录制任务”16 粗，“添加直播间后将在这里显示”13 次要色；九个筛选为空都是这一个。

**宽屏**：没有最大宽度，卡片拉满整个窗口；封面在左（`:96-101`）。

## 拿不准的地方

1. 录制中点“删除”：v3 先停止再合并，合并慢时卡片要等合并完才消失；新设计这段时间显示“正在整理文件”。
2. Android 上“打开文件夹”打开某个子目录，各机型的系统文件管理器是否都支持（v4 现在只对公共目录有效），要在 K90 上看。
3. “播放”只能放最近一次合成的文件（v4 的 `lastOutputPath`），同一房间更早的录像从文件夹找。
4. v3 人数一行在录制任务里是轮询时更新的（`live_record_task.dart:212-228`），开播检测关着时可能是很久以前的数字；新设计照 v3 显示。
