# 录制目录、存储耗尽与自动恢复权限审计

## 范围与根因

本轮以 `5b3a3e15` 为审查基线，主修订落在 `723b4452`，缓存额度增量落在 `f07d1861`，设置即时应用增量落在 `afdcff04`。范围限录制目录选择、目录可写性探测、自动恢复权限语义、FFmpeg 存储耗尽分类、兼容续接策略和安全回收额度，没有构建 APK、操作手机或执行 Windows GUI；Computer Use 与 Astra Light 使用均为 **0 次**。

源码审查确认九个可重复或可由确定性夹具证明的缺口：

1. 设置页在验证候选目录前就写入 Hive；选中文件、只读目录或失效路径时会先覆盖最后一个可用目录。
2. 并发可写性检查共用固定 `.pure_live_write_probe_$pid`，不同录制任务可能相互删除探针并产生假阴性。
3. 启动期默认目录初始化与稍后完成的用户目录选择存在竞态，旧初始化结果可能覆盖新选择。
4. 连续点击目录行可以打开多个选择事务，界面也没有忙碌状态。
5. 开机自动恢复录制在控制器初始化阶段调用交互式权限请求，可能在没有用户动作时弹出系统权限界面。
6. `RecorderContinuationPolicy` 的旧事件兼容路径未识别存储耗尽与输出写入错误；缺少显式 `retryable` 字段时可能继续重连。
7. FFmpeg 将本地空间耗尽归入通用输出路径错误，用户看不到独立、可定位的存储诊断。
8. 缓存额度回收只统计可删除的旧文件，没有把受保护的活动输出计入总量；当活动录制加旧文件超过上限、旧文件自身却低于上限时，旧文件不会被回收，空间压力会持续增加。
9. 设置页开启缓存限制或调低上限时只持久化配置，实际回收要等录制控制器下一次最长一分钟的定时检查；用户已确认的新约束没有立即生效。

## 修订

- `CacheService.prepareRecordDir` 先解析候选目录，再在真实目标目录内用 `Directory.createTemp` 创建原子唯一子目录，完成写入、`flush` 和仅限自有探针的递归清理；`canWriteRecordDir` 成为设置页与录制启动共用的单一判定入口。
- 目录选择收敛为“选择 → 等待启动初始化 → 实际写入检查 → 持久化 → 发布 UI/缓存大小”。失败候选不改现有配置；`selectingRecordDirectory` 合并重复点击并驱动具名进度指示器。
- 用户在启动初始化期间完成的选择拥有最终写入权，不再被默认目录初始化回写覆盖。
- 权限检查增加 `requestIfMissing` 语义：用户显式开始录制仍走交互请求，自动恢复只做静默探测。
- FFmpeg 新增非重试型 `storageFull`，识别 `no space left on device`、`disk quota exceeded` 和 Windows 磁盘空间不足标记，并映射到双语 `recorder_storage_full`。
- 兼容续接策略补齐存储耗尽、只读文件系统、输出打开失败、分片打开失败、trailer/交错帧写入失败等本地终止标记。
- `f07d1861` 的缓存额度快照统计全部受管文件，但删除候选仍严格排除活动目录；活动输出单独低于上限、与旧文件合计超过上限时，会先回收最旧的已完成文件而不触碰正在写入的分片。
- `afdcff04` 将缓存限制开关接入控制器事务；开启限制或在已开启时调低额度会立即执行回收并刷新页面大小。修订号循环会合并执行中的连续修改，同时保证最新额度再应用一次；关闭状态下调整数值不触发文件扫描。

本轮没有 schema 迁移。回滚 `723b4452` 会重新引入上述目录事务、并发探针、权限弹窗和误续接缺口；回滚 `f07d1861` 会恢复活动输出不计入额度的错误回收语义；回滚 `afdcff04` 会让设置页的新缓存约束再次延迟到定时检查。
