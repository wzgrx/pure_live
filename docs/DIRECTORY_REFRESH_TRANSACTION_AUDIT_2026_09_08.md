# 目录刷新快照一致性审计（2026-09-08）

起点 `c0cdf52f`（应用源码 `58546f51`），版本 `3.1.8+4121`。承接 [目录恢复审计](DIRECTORY_RECOVERY_AUDIT_2026_09_08.md)，按当前任务继续优先源码和确定性测试；本轮没有手机操作、上游合并或版本发布。

## 根因与复现合同

`LiveDirectoryController.refreshData` 在新请求完成前清空原生目录缓存、身份集合和游标，并把 `currentPage / _visiblePage` 设为 1，但仍保留旧卡片。旧目录第三页刷新时，首先出现“第一页页码 + 第三页卡片”；请求失败后缓存和总数也与卡片脱离。后续跳页或改条数会用旧目录的用户操作去索引新目录，不只是页码文字错误。

此路径原样存在于维护分支首次引入可选原生目录合同的 `52f3f0bcb83f48f4a88bf4a384a37dcc4ad2c230`，分类 `fork-regression`。上一轮恢复按钮/预检代次修订 `58546f51` 没有处理该刷新事务边界；没有依据把此新控制器的问题归给上游。此次不修改无原生目录合同的平台分页器，不同步上游。

确定性复现：原生第一页提供 60 个房间且明确结束，UI 每页 20 条，移动端连续加载至第三页或桌面跳第三页；再让刷新第一页挂起并失败。期望旧卡片、第三页、总数 60、原来的下一页状态一致保留；错误提示提供恢复动作。新目录成功（包括合法空目录）才替换页码和卡片。

## 修订设计

已把每个原生目录的房间、身份集合、下一页、终止/容量标志归为独立 buffer：

- 已提交目录仍服务现有卡片；刷新在另一个 buffer 中从第一页构建。
- 新目录产生可展示卡片或合法终止空页后，提交它的页码和卡片，再更新其总数/加载状态。
- 新目录失败而尚无可展示结果时，旧快照及其分页元数据保持；重试继续新目录原生游标，空页预算也不倒退。
- 显式桌面翻页或改条数选择仍在显示的旧目录，并放弃未提交刷新；不混用两个目录的页码、身份集合或原生游标。
- 持续刷新、改条数和关闭保留已有取消/代次归属。每个 buffer 仍受 `maxBufferedItems` 上限约束，最多保留两个，而非每次刷新复制全量旧列表或累积历史快照。
- 新目录已有部分卡片但后续页失败时，仍遵循现有部分成功合同：显示新目录的部分结果，重试仅补该目录失败游标。
