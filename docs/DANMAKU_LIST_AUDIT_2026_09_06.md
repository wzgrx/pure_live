# 弹幕列表累计数审计（2026-09-06）

## 已复现与修复

对应用户操作矩阵 A4-02。列表暂停追尾后显示新消息累计数；生产控制器每批合并消息并把历史限制为 500 条。原列表用长度增长或尾部变化估算新增数量，因此：

- 满 500 条后新到 3 条，长度不变，只计为 1 条。
- 屏蔽最后一条或清空历史时，尾部变化也被计为新消息。

将原算法无语义变化地抽到生产使用的 `DanmakuArrivalCounter` 后，两条确定性测试分别得到期望 3/实际 1、期望 0/实际 1。红测记录 `local-artifacts/build-records/20260906T051510374Z-quality-focused.json`。

修复按对象身份比较前后快照，只保留当前受控历史的身份集合，不建立无限增长的会话去重集合。不按文本去重，因此内容相同的独立弹幕仍分别计数。新增满容量批次、删除/清空、重排/重复快照、整批替换覆盖。

修复后计数器、滚动策略及控制器生命周期三个测试文件和一次 analyze 通过，记录 `local-artifacts/build-records/20260906T051848635Z-quality-focused.json`。本轮尚未构建、安装新候选，未把计数器单测标成完整列表交互验收。

## 下一处定向检查

暂停列表保留 `_visibleMessages`，`_onMessagesChanged` 在暂停时只累计数量并返回；屏蔽操作调用 `removeDanmakuWhere` 更新控制器，而列表行本身没有订阅屏蔽设置。需补真实 Widget 验证：屏蔽已冻结、甚至已从控制器历史淘汰的行，是否立即从用户当前列表移除，同时仍保持暂停、不自动跳到底部。当前为源码发现的可疑路径，未冒称已有行为复现。

累计数修复不替代长按屏蔽、回到底部、滚动手势及 120 Hz 呈现矩阵。其余通过证据继续复用，后续构建与设备验证与同批列表修复合并。
