## 复现与根因

加入不改变既有行为的文档加载接缝后，有效红测为 **0/8 PASS**：

1. 云端 `config` 为 Map 时，页面模型虽会解析，原始预览和收藏/历史计数却只读取字符串 JSON，结果显示为空或为 0。
2. 邮箱、版本、更新时间、备份版本或配置分区类型异常时，直接类型转换会让整个用户详情加载失败；无效 JSON 也会丢失仍然有效的账号元数据。
3. 缺少注册时间时模型会用当前时间代替；邮箱注册写入旧字段 `createdAt`，读取只认 `created_at`。
4. 每次上传配置都重写 `created_at`，把注册时间错误地变成最近同步时间。
5. 页面没有文档替换和请求代次边界，旧请求可覆盖新账号；空白文档 ID 仍会进入后端读取。
6. 后端错误原样显示且没有重试动作；固定 `Column`、单行元数据和并排计数在 320×480 / 3.0 倍英文下产生横向与底部溢出。

## 修订

- 云端模型统一接收字符串 JSON 或 Map；外层对象、各配置分区、标量字段和备份版本分别归一化，畸形分区只回落自身，不再阻断其余资料。
- 注册时间同时读取规范 `created_at` 与旧 `createdAt`，缺失时显示“时间未知”，不再伪造当前时间；邮箱注册改写规范字段。
- 配置上传改为 Firestore 事务：已有规范注册时间保持原值，旧字段首次迁移到规范字段，新文档才写服务器时间戳；并发更新由事务重试维持同一不变量。
- 详情页使用请求代次和挂载状态隔离文档切换、迟到完成及退出；空白身份在本地直接进入未找到状态。
- 加载失败改为双语通用提示并提供重试，诊断只进入调试日志；无效配置仍保留账号元数据并显示空预览。
- 页面统一为可滚动长页，元数据按宽度和字号纵向/双列响应，原始 JSON 使用有界高度与横向滚动；加载、错误和空状态也保持大字号可达。
