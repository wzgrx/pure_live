# 电视二维码设置同步生命周期与输入审计（2026-09-12）

## 范围与基线

- 基线：`bdb0b5bf0f4b5a2c727c6f24810766eceb5003a8`。
- 范围：备份设置中的电视二维码同步页，覆盖扫码输入合同、重复帧事务、相机控制器所有权、异步退出、相机错误和窄屏大字号结果页。
- 本轮只做源码、确定性 Widget/输入回归、静态分析与仓库审计；未连接手机、访问真实电视服务、构建安装包或发布版本。

## 复现与根因

为旧页面先加入不改变行为的扫码器、控制器与同步服务测试接缝，修改前 7 项行为回归为 **0/7 PASS**，稳定复现前六类缺陷；代码审查同时确认第七项布局问题：

1. 空条码或 `rawValue == null` 时直接对首条结果做空值断言，扫码流抛出类型异常；合法地址位于同一帧后续条码时也不会被读取。
2. 旧地址判定只搜索文本中的 URL 片段，带说明文字、用户信息、路径、查询参数的二维码都会被当作电视服务器地址提交。
3. 相机连续帧可在第一次同步完成前重复进入处理器，对同一地址并发发送多次完整配置。
4. 同步回调异常会逃逸；页面退出后迟到结果仍执行提示和 `setState`，稳定触发已释放 State 更新异常。
5. 初次打开页面默认点亮手电筒；自动闪光状态又在顶栏按钮内部嵌套第二个按钮，同一视觉控件有两条点击路径。
6. 重试直接覆盖控制器且页面没有释放逻辑，旧控制器和最后一个控制器都遗留；快速重试也没有忙碌门禁。
7. 成功/失败页使用固定居中 `Column`；在 280×360、3.0 倍英文下，重试动作落到当前视口外且没有滚动路径。

根因是扫码回调缺少输入边界和事务状态机，相机控制器没有明确页面所有权，异步提交也没有页面生命周期代次；呈现层同时把相机默认状态和普通字号布局当作固定前提。

## 修订

- 新增严格的 HTTP(S) 服务器 origin 规范化：只接收带主机的完整 origin，统一协议/主机大小写并去掉唯一的根路径；用户信息、业务路径、查询、片段、控制字符及越界端口全部留在扫码态。
- 遍历一帧内全部条码，忽略空值和无关内容；首个有效 origin 在任何 `await` 前锁定事务，同一同步期间的重复帧共用一次提交。
- 同步异常统一收束到可重试失败状态；操作代次和 `mounted` 双栅栏隔离退出后的迟到结果，页面退出不再弹提示或更新旧 State。
- 页面明确拥有每个 `MobileScannerController`：重试和路由释放都执行一次释放，重复释放按控制器身份去重；重试释放期间按钮禁用，避免生成孤立控制器。
- 手电筒默认关闭；自动/开/关/不可用只保留一个带双语 Tooltip 的操作，前后摄像头切换也补齐可访问标签，控制异常保留诊断而不打断页面。
- 实际相机页增加双语扫码目标提示；相机错误提供页面内说明和重试。同步中、成功和失败状态统一进入安全区内的可滚动居中布局，并用清晰的成功/失败图标及“重试”动作表达当前状态。
