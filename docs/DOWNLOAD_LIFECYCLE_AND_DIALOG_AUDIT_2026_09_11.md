## 修改前问题

1. Android 下载完成后把 `file.parent.path` 交给系统，实际打开的是下载目录而不是 APK 文件，安装流程未从目标文件启动。
2. Windows/Linux 在 `OpenFilex.open` 后先解除窗口关闭保护并直接 `exit(0)`，随后才检查打开结果；打开结果检查因此失去执行机会。便携 ZIP 或历史版本附件也会触发同一进程退出。
3. `fileName` 直接进入 `path.join`，URL 末段还通过字符串拆分取得；路径分隔符、上级目录片段、查询参数、Windows 保留名和控制字符均未归一化。
4. 每次下载前遍历并删除目录内全部 `.apk`，随后直接写最终文件。并行任务、取消、超时或进程退出可能留下被误认作完整包的文件，也会提前移除其他已下载 APK。
5. Android 对 ZIP 等普通附件同样请求“安装未知应用”权限；普通文件下载提示仍固定写作 APK 下载/安装。
6. 下载标题、状态、进度和取消按钮使用固定横排；状态只显示一行。窄屏大字号下长文件名、错误详情和后续动作缺少完整滚动面。
7. 文件打开失败时弹窗已经关闭；用户只得到短暂提示，没有保留文件的明确状态和再次打开动作。

## 修订

- 下载文件名统一从建议名或 URL 路径解析，剥离目录片段、查询影响、控制/双向文本字符和 Windows 非法/保留名称，并限制长度；最终路径始终落在应用下载目录。
- 下载先写入 `.part`；完成后通过 `.previous` 备份事务替换目标。中断恢复会还原旧文件或清理已提交备份，取消及传输异常会删除暂存文件。
- Android、桌面和其他平台共享“打开已完成文件”流程；Android 传入真实文件路径。桌面启动文件后保持应用进程，由系统安装器按自身关闭协议处理；ZIP/普通附件不再退出应用。
- 打开失败会保留完整文件和弹窗，展示完整错误详情，并提供“重新打开”和“关闭”；再次打开直接复用现有文件。
- 更新入口先验证绝对 HTTP(S) 地址并归一化文件名；Android 仅对 `.apk` 请求安装权限，普通 ZIP/附件直接进入下载流程。
- 弹窗改为最大宽度约束的整体滚动布局；窄屏或大字号下图标/标题、进度/百分比和错误动作纵向排列，状态详情不截成单行。
- 传输、下载目录、系统打开、运行平台和完成延迟均可注入，生产默认仍使用 Dio、应用下载目录、Android 文件打开器和 `OpenFilex`。
