# IPTV 返回直播事务与布局审计（2026-09-12）

## 范围与基线

- 本批基线：`b21c77a9af933f60462c4c57b5075ca7d3a5d51c`。
- 对照的本地冻结上游对象：`c6c9bd70aedc503c003110dae10a83ad0bb891d8`。
- 归因：`upstream-existing`。冻结对象中的直播节目分支同样只关闭节目单，没有恢复原始直播源；回看区间字段也缺少显式清除路径。
- 本批只修订用户仓库，未执行 fetch、merge 或上游同步。

## 首个无效状态

1. 正在播放回看时点击当前直播节目，旧逻辑只关闭节目单，播放器继续停留在回看源。
2. 节目单没有明确的“返回直播”动作；单靠节目行上的直播标签无法表达当前正在回看及其切换状态。
3. `LiveRoom.copyWith(null)` 会保留旧值，无法一次清除 `catchUpUrl`、`catchUpStart` 和 `catchUpEnd`，旧区间可能继续污染节目高亮。
4. 旧布尔结果混合“当前启动失败”和“旧请求被取代”；前者可被误判为 `superseded`，从而吞掉失败反馈。
5. 返回直播与在途回看之间缺少 latest-wins 结果合同；空原始地址、重复动作及迟到结果的路由和提示语义不完整。
6. 返回动作必须在 EPG 加载、错误或空列表时仍可达，并在 320×480、3.0 倍文字下保持自然高度和可点击性。

## 修订

- `LiveRoom` 增加统一的活动回看判定，并以 `withoutCatchUp()` 生成新快照，显式清除完整回看区间且不修改旧对象。
- IPTV 播放切换结果改为 `started / superseded / failed` 三态；当前失败发布失败状态，被取代任务静默结束，不再混淆两者。
- `LivePlayController.returnToLive()` 复用同一播放代次和直连播放器启动路径，以原始 `link` 打开直播，并在切换前提交已清理的房间快照。
- 点击当前直播节目与明确的“返回直播”按钮共用 `VideoController.returnToLive()`：重复操作合并，旧播放器只关闭一次，成功后才提示；迟到任务不发布旧提示。
- 原始直播地址为空时保留节目单和当前播放器，不创建新的播放器事务，并给出地址错误反馈。
- 节目单顶部增加全宽返回直播动作。它独立于 EPG 正文状态，因此加载、错误和空列表都可见；进行中禁用并显示进度，`Wrap` 与自然高度覆盖窄屏大字号。
- 中英文补齐“返回直播”和完成提示。
