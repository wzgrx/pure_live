# 虎牙与共享播放器：已派发延迟重试所有权

## 修改前的源码发现

本地冻结 `9f9ce5c5`；只读上游 master 为 `c6c9bd70aedc503c003110dae10a83ad0bb891d8`，
本轮没有合并。`PlayerManager` 的延迟重试和帧恢复取消逻辑来自本分支 `db7d0df33`，
当前上游没有此延迟重试函数；分类 `fork-regression`，不是把服务器或 WUP 修复当作本地缺陷来源。

前一批撤销的是看门狗/恢复事务和网络预取占用原生队列，本次追踪到更后的独立阶段：

1. 即时线路/内核恢复耗尽，进入有限退避。
2. Timer 到点，先把 `_transientLiveRetryTimer` 清空，然后排队并等待取流请求。
3. 此时旧原生连接恢复出帧；`_notePresentedFrameProgress` 只检查 Timer 非空，误以为没有重试。
4. 迟到的取流成功、空列表或异常继续触发换源/重新打开，反而打断已恢复的画面。

错误不在计时秒数，而在把 Timer 的存活等同于整个异步重试事务的存活。源码疑点先由生产
PlayerManager 的可控解析器测试验证；复现与最终测试记录在下节补充。

## 定向方案与边界

- 对退避、排队、等待解析、准备候选一直保留显式重试所有权，而非只持有 Timer。
- 复用既有 session / intent / retry revision；每个异步边界及最终回退重开前重新验证。
- 原有“退避期真实帧恢复后撤销”的规则覆盖到已派发阶段；不把 `playing=true` 或一条普通日志
  当作媒体恢复，不修改真实 EOF 的即时恢复分类。
- 不新增轮询、播放器、缓冲、重试次数或延迟；持续故障仍保留有限退避恢复。
- 普通/横屏/小窗共用该管理器；不调整比例识别、弹幕/UI、签名、Android生命周期或录制。

## 资料

- [Dart Timer.cancel](https://api.dart.dev/dart-async/Timer/cancel.html)：计时器取消针对尚未执行的回调，
  已派发回调中的异步工作需要独立的状态验证。
- [上游取流修复](https://github.com/liuchuancong/pure_live/commit/c5944dd5a529cd93eb29486500abd5d496618f80)

  是取流合同参考，不覆盖本分支独有的延迟重试所有权。
