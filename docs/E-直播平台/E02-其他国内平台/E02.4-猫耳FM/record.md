## 做法

- **接口和输出沿用 v3**：`LiveSite`、`LiveRoom` 等模型和 3.x 的 JSON 不变。v3 实现过的可选能力全部保留：刷新（`LiveSiteRoomRefresher`）、录制详情（`LiveSiteRecordRoomResolver`）、原生目录分页（`LiveSiteDirectoryPager`，推荐和分区都用）、可取消的搜索（`LiveCancellableSearch`）、按关键词决定是否翻页（`LiveSearchPaginationPolicy`）、恢复时重新取流（`LivePlayRecoveryResolver`）、签名地址的续期时间（`LivePlayLeaseMetadata`）。另加 `LivePlayUrlResolver`（线路带请求头和租期）和 `LiveSiteLinks`。
- **请求照 v3**：全部是 `fm.missevan.com/api/v2/` 的匿名 GET，一次调用一个请求。
  - 请求头是 v3 的 `playHeaders`：`Referer: https://fm.missevan.com/`、`Origin`、UA `Mozilla/5.0`；不跟随跳转。
  - 分类 `meta/data`；推荐和分区 `chatroom/open/list?p=`；搜索 `chatroom/search`；详情 `live/{id}`。
- **解析照 v3 的严格程度**：
  - 列表和搜索的页必须回显请求的页号和每页条数，`maxpage`、`count` 必须有；超出 `maxpage` 的页必须是空的。不符合就报 `ApiChanged`，不当成“短页”。
  - 一行的 `status.open` 只能是 0 或 1，`score` 不能为负，房间号和主播号必须是数字。有一行不对，整页报错。
  - 回答超过 1 MiB 也是 `ApiChanged`。
- **进房、刷新、录制是同一个请求**（v3 也是）：`live/{id}` 同时带着拉流地址，放进 `MissevanRoomData`（不存储）。播放直接用它，不再发请求；恢复时重新读详情，拿新签名的地址。
- **画质照 v3**：HLS、FLV 两个“画质”，HLS 在前（排序 2、1），名称就是 `HLS`、`FLV`。每个画质一条线路：
  - 地址升级为 https；
  - 带 v3 `PlaybackHeaderResolver` 里猫耳的请求头；
  - 租期取 `expires`，提前 1 分钟续期（v3 的 `getPlayUrlRefreshAt`）。
- **纯音频直播照 v3 处理**：流里是 AAC 加 16×16 的 H.264 占位画面，平台层不把房间标成纯音频，也不写编码，播放器按实际的轨道处理（v3 `missevan_api.dart:338-339` 的做法）。
- **分区有两个命名空间，现在是三个**：分类是 `meta/data` 的标签页，`areaType` 就是命名空间。
  - `catalog` 用 `catalog_id` 请求，`tag` 用 `tag_id`，站点后来加的 `list`（团播）用 `type`；
  - `LiveArea.identityKeyFor` 对猫耳把 `areaType` 算进身份，所以 `catalog:104` 和 `tag:104` 是两个关注分区；
  - v3 的分类仍是一个“猫耳 FM”组，标签页按站点的顺序排列。
- **房间号保持请求时的号码**：回答的房间号必须和请求的一样，不一样就报 `ApiChanged`。猫耳不需要别的编号；`userId` 仍是主播号（`creator_id`）。
- **没有 Cookie、登录和弹幕**：v3 的猫耳全部匿名，弹幕是 `EmptyDanmaku`，所以没有弹幕参数类，也不注入 `CookieVault`。

## 样本与 v3 的冻结输出

归档没有猫耳的 `expected.json`：归档的旧版对照工具只做了前五个平台，v3 应用现在也构建不了。本模块用 `fixtures/missevan/legacy_expected.dart` 生成：

## 保持 v3 行为、没有采用归档 v4 或上游做法的地方

- **画质仍是 HLS、FLV 两个**，HLS 在前。归档 v4 改成一个画质“原画”下两条线路、FLV 在前，画质菜单会变。
- **分类仍是一个“猫耳 FM”组**，标签页按站点顺序。归档 v4 分成“分区”“团播”“标签”三组。
- **续期提前 1 分钟**。归档 v4 是到期前 min(10 分钟, 寿命的 1/4)。
- **请求头照 v3**：UA 仍是 `Mozilla/5.0`。归档 v4 用完整的 Chrome UA，上游与 v3 相同。
- **详情仍填关注数**（`attention_count`）。归档 v4 漏了它（对照笔记 `sub_A.md`）。
- **标题不解 HTML 实体**，同 v3。归档 v4 会解，样本里没有实体。
- **搜索每页条数照调用方给的**（搜索页用 20），限制同 v3：1～100；超过 100 个字符或含控制字符的关键词拒绝，不截断。归档 v4 固定 20 条、截断到 100 个字符。
- **刷新也校验拉流地址**：刷新和进房是同一个请求、同一套解析，在播房间的地址不合规时刷新也报错，同 v3。
- **没有弹幕**。归档 v4 已经做了猫耳弹幕（规格 §7），v3 没有。
