# 工具箱剪贴板与页面入口审查（2026-09-07）

基线 `068ccd68`，对应 [辅助页面功能组](AUXILIARY_PAGES_AUDIT_2026_09_07.md) 的工具箱子项。测试在临时 Hive 与模拟系统剪贴板通道运行，没有读取电脑/手机真实剪贴板、请求直播平台或操作手机。

## 复现与来源

- 页面每次 build 都安排自动读取，既不合并重复请求，也不检查控件生命周期；读取返回后同时覆盖两个输入框。
- 真实页面用例复现新输入被覆盖、输入后主动清空又被回填、已有草稿被替换、页面重建产生第二次读取、关闭后使用已释放的 TextEditingController、剪贴板 PlatformException 外泄，以及普通平台关键词误填和 Twitch 链接漏识别。
- 冻结上游 `c6c9bd70aedc503c003110dae10a83ad0bb891d8` 的 controller/page 存在相同逻辑，归为 **upstream-existing**；未拉取或合并上游。
- 初轮 `20260906T225615566Z-quality-focused.json` 中离页夹具只卸载 Get 根，未保证控制器 onDelete，命中的是迟到 snackbar 的 GetRoot 异常；不把它当成释放异常证据。随后修正明确关闭控制器及清理条件，`20260906T225921406Z-quality-focused.json` 的 **8/8 红测分别失败**，包含确定的 disposed TextEditingController 异常，没有以夹具连带错误充数。

## 修改

- 自动读取从页面 build 移到控制器 onReady；一个控制器生命周期只尝试一次，重复调用和重建都不再次读。两个输入已有内容时直接保留，甚至不读剪贴板。
- 两个字段分别跟踪编辑代次；只填充读取开始时为空、期间从未编辑的字段。输入后再清空也是有效编辑，不使用“现在仍为空”误判用户意图。
- 控制器关闭后不写输入、不显示提示；关闭时移除监听并释放两个控制器。平台剪贴板不可用或未实现时结束自动读取，正常手动输入仍可继续。
- 自动识别只做本地 URI 主机判断，覆盖现有十个平台的主机及 b23/抖音分享入口，拒绝普通关键词、伪装后缀、userinfo 和无关链接。不自动解析短链或发起网络请求；保留原分享文本和原两项工具动作。
- 英文窄屏大字体下，“支持平台”标题与图标在无约束 Row 中溢出；标题使用 Expanded 后按可用宽度换行，保留字体大小和完整文字。两个清除图标增加现有翻译的 Tooltip，输入框仍分别清除，折叠不清除草稿。
