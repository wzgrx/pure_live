# 功能开发计划（Android）

- 版本：第 1 版（2026-10-02），待用户确认
- 配套：[INVENTORY.md](INVENTORY.md)（功能清点）、[TASKS.md](TASKS.md)（任务和真机验证清单）、[PROCESS.md](PROCESS.md)（每个任务的做法）、`templates/`
- 背景：用户 2026-10-01 决定先做完 Android 和 Windows 的界面，再按界面那套流程开发功能；2026-10-02 因额度紧张，功能阶段**只做 Android（手机、平板）**，Windows 也放到以后。

## 1 目标

v3 的每个功能在 Android 上都能正常使用，最后在 K90 上逐项验证通过。

## 2 范围

| 做 | 暂缓 |
|---|---|
| Android 手机和平板上 v3 的全部功能：清点里“部分 / 缺失 / 有问题”的补齐修好，“没验证”的在 K90 上验证 | Windows（清点第 13 节，14 项）、Linux（M12.6）、电视（M14.2～M14.5、U.15b～U.15i）、苹果平台 |
| 已暂停的半成品：M12.5（分支上有 4 个提交）接回；M13.17 的余项拆进各任务 | M13.19 截图目录（属于界面阶段的检查工具，分支没有提交） |
| 已批准升级（UPGRADES）里还没做的，放在最后一档（F.5a） | v3 没有的新功能（开播提醒、WebDAV 定时备份等），要做先问用户 |

## 3 原则（做决定时按这个顺序）

1. **v3 为基线，功能一个不少**：入口、操作、设置项都在；去掉的只有用户决定过的（Firebase 云账号、多播放内核）。
2. **先找根因**：每个问题写清根因（文件:行）再改；半成品先读懂再接，不重写一遍。
3. **3.x 数据照旧生效**：设置、关注、历史、Cookie、录制任务的键名和含义不变；3.x 的设置在 v4 里不生效的（清点第 15 节）算“有问题”。
4. **界面用已确认的设计**：有界面的功能照 `docs/ui/compare/<U.x>/` 已确认的设计做，不重新设计；确实要新界面的（例如权限说明）先看 U.14 有没有定。
5. **按使用频率排序**：看直播、关注和开播状态、弹幕、清晰度线路、录制、搜索、分区、备份恢复在前，冷门的在后；每个任务标“必须 / 应该 / 可以以后”，额度不够时先做完“必须”。
6. **性能和资源**：不增加常驻的定时器和后台任务；放在界面线程外的重活保持在外面；改动涉及播放或弹幕的，在 K90 上看帧时间和内存（UI_PLAN 第 9 节的指标）。
7. **加速规则照旧**（AGENTS.md）：测试只写主要路径；任务分支只跑相关测试，合并的人跑完整门禁；几个任务一起合并、一起推送、一起装机验证。

## 6 和界面任务的关系

功能阶段在 Android 界面做完之后开始（用户决定）。有界面的功能都用已确认的设计：

| 功能 | 界面任务（`docs/ui/compare/`） | 现状 |
|---|---|---|
| 直播间的播放、全屏、竖屏、弹窗、状态、小窗、本地互动 | U.2a～U.2g、U.2j、U.2k | 完成 |
| 飞行弹幕渲染（F.2a～F.2c 在它的基础上做） | U.2h | 未开始 |
| 刷新率和帧率匹配 | U.2i | 未开始 |
| 首页、浏览、卡片 | U.3、U.4 | 完成 |
| 搜索、历史 | U.5a～U.5c | 开发中 |
| 设置（播放、通用、数据）、录制设置 | U.6c～U.6e、U.7b | 设计已确认，待开发 |
| 多画面、网络电视、账号 | U.8、U.9、U.10 | 完成 |
| 备份、WebDAV、设备同步、工具箱、关于、标签、屏蔽 | U.11、U.12 | 设计已确认，待开发 |

规则：功能任务改到的文件如果有界面任务在开发，等那个界面任务合并后再开始；界面任务的记录里写了“留给功能”的，并进对应功能任务（TASKS 的“来源”一列）。

## 7 风险和需要用户定的

| 风险或待定 | 对策 / 建议 |
|---|---|
| **3.x 数据迁移没法在 K90 上验证**：测试包包名是 `.v4dev`，读不到 3.x（`com.mystyle.purelive`）的私有目录；规则又不许动 3.x | 待用户选（F.4a）：A（建议）用 3.x 导出的备份文件在测试包里恢复，验证备份格式；Hive 文件直读由单元测试覆盖，覆盖安装留到发布（M15）时在备用机上做。B 由用户自己用 adb 把 3.x 的 `app_settings.hive` 复制给测试包（要 root 或 `run-as` 不可用时没法做）。C 全部留到 M15 |
| “退出时销毁播放器”（`useHardStopOnExit`）v4 没有对应行为 | 待用户选（F.1d）：A（建议）保留开关，“关”时离开直播间把播放器留给下一个直播间（和应用内小窗共用 `RoomRuntime`）；B 去掉这个开关，设置页不再显示 |
| 弹幕相关的修复（F.2a～F.2c）和 U.2h 的弹幕渲染选型改同一个文件 | F.2 排在 U.2h 之后；U.2h 如果换掉弹幕层，F.2a 的帧率、字体、纯文字在新弹幕层里一起做 |
| M12.5 分支基于旧目录（`lib/pages/`），master 已搬到 `features/` | F.0a 按文件对照搬过去，不直接合并；分支的测试照搬 |
| HyperOS 可能划掉应用就杀进程，录制和后台播放挡不住 | F.9b 实测；挡不住时在录制设置里写明“需要在系统设置里允许自启动和后台运行” |
| 海外平台在国内要代理，K90 上验证要用户开代理 | F.9 只把海外平台列为“有条件时验证” |
| 额度不够 | 按 TASKS 的档位，先做完“必须”（3 个小、5 个中） |

## 8 验收标准

每个任务：

- [ ] 功能对比页（或小任务的改动清单）列出的每一条都做到，偏差写进记录；
- [ ] v3 的行为一项不少；3.x 的设置和数据照旧生效；
- [ ] 单元测试或组件测试覆盖主要路径（`flutter test`、相关包的 `dart test`）；改了原生部分的，`flutter build apk --debug` 通过；
- [ ] 门禁 `tools/gate/gate.sh --all` 通过（合并的人跑），已推送；
- [ ] K90 上按 TASKS 第 5 节对应条目验证，结果写回 TASKS（通过 / 有问题和现象）；
- [ ] 记录 `docs/features/records/<编号>.md` 写好：改了什么、根因、测试、真机结果、没做的和原因。

整个阶段：TASKS 里“必须”的任务全部完成；TASKS 第 5 节 K90 清单里 5.1～5.4（F.9a～F.9c）的条目全部通过（标了“F.x 之后”的随那个任务）。
