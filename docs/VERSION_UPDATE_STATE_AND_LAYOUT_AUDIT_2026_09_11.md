## 修改前问题

1. `VersionUtil.checkUpdate` 没有返回成功状态；请求为空或抛出异常时只写静态提示，缓存的版本、ABI 和下载信息仍可能残留。
2. `VersionController.checkNewVersion` 缺少完整 `try/finally` 事务。版本清单或包元数据异常会让加载态长期保留，页面没有独立失败态和重试动作。
3. 控制器通过 `VersionUtil` 内另一份静态 `PackageInfo` 判断新版本；直接进入更新页时，这份状态可能尚未初始化，与控制器实际读取的本机版本分裂。
4. 发布身份缺少版本或构建号时仍拼接资产地址；控制器还会猜测构建号，可能展示 Release 中不存在的文件。
5. 下载源按钮固定为两列和 38 像素高度，动作弹窗由紧凑 `ListTile` 承载长地址。窄屏大字号下按钮、弹窗动作和错误重试缺少连续可达布局。
6. 页面直接读取全局更新日志，控制器失败后可能继续显示上一轮内容；复制和下载动作也没有统一限制到绝对 HTTP(S) 地址。

## 修订

- `VersionUtil.checkUpdate` 返回明确成功状态；空响应、异常或坏缓存统一清理版本、构建号、日志、ABI、MSIX 和更新标志，外部数字字段接受整数或数字字符串。
- `VersionController` 以单次事务管理加载、错误和所有发布字段，异常路径始终结束加载并清空旧地址；重复检查由事务栅栏合并。
- 包元数据加载器与更新检查器可注入；新版本判断直接使用同一控制器读取的 `PackageInfo.version`，不再依赖另一份初始化时序。
- 资产生成要求 HTTPS 项目地址、非空规范版本和正构建号；`v`/`V` 前缀统一归一化，缺失构建号时直接进入可重试失败态，不再猜测文件名。
- 更新页增加独立失败说明和重试按钮；状态内容及普通内容均可滚动。顶栏高度、大字号下载源列数、按钮最小高度和文字行数按视口调整。
- 下载动作弹窗整体可滚动，完整地址可选择；下载、复制、取消均为稳定且可测试的全宽动作。页面过滤非 HTTP(S) 或相对地址，下载启动异常提供双语反馈。
- 页面只呈现控制器本次事务提交的更新日志和资产地址，失败检查不会泄漏上一轮静态内容。
