### 完整解码发现的缺口

随后串行用独立 FFmpeg、2 个解码线程、`-xerror` 对三个文件进行完整解码，记录
`recording-full-decode.json`（62.865 秒，结束活跃重型进程 0）：

- 第一份退出码 0，但 stderr 有 `error while decoding MB 90 52, bytestream -5`，
  **不计为无错误通过**，只看退出码会漏报。
- 第二份退出码 0、无错误日志。
- 第三份退出码 `-1094995529`，AAC `Input buffer exhausted before END element found`，
  整体校验失败。正常显示时长/大小和容器可读不代表码流完整。

当前已确认输出中有损坏编码包，尚未证明发生在直播输入、FFmpeg 停止/分段还是 TS→MP4 收尾。
三个原文件与哈希已保留，不覆盖或删除，不用转码/裁尾把损坏隐去。本批 keyboard 修复不涉及
录制，后续单独比对原始捕获、停止边界、最终包时间戳，并补充不影响实时观看负载的输出验收方案。
因此本轮录制标记为**界面/时长/大小通过，完整媒体校验失败**，正式交付门禁继续保留。

继续对照已确认一处策略不一致：播放器在原生 WUP FLV 的凭据刷新时间只预取下次地址，
不重开健康连接（`PlayerManager._scheduleProactiveSourceRefresh` 的原生凭据分支）；
`RecorderController._scheduleRecorderLeaseRefresh` 则仍把 `refreshAt` 无条件转换为
`ffmpeg.refreshLease`，最终调用 FFmpegKit.cancel。签名可新开截止时间并非既有连接寿命。
这与三个录制 attempt 约 270 秒的间隔相符；仅凭时间相符，尚不足以断言它产生了全部坏包。

后续独立修复批次：复用 `HuyaTransportPolicy.hasNativeFlvCredential`，原生健康 FLV 只预取凭据，
真实 EOF/网络故障再使用新凭据恢复；网页短租约/HLS 与其他平台策略分别保留。增加真实生产

然后捕获保留 TS 的录制与手动停止样本，核对每个坏包的位置及最终 MP4。该录制改动尚未实施，

## Esc 焦点边界修复

来源：全局键盘监听最早见 `133466e0`，本分支 `784770ac` 增加普通房间主动 pop；当前
上游 `c6c9bd70` 也含此实现与提交。此项不属于虎牙服务器问题，且合并当前上游不会消除它。

确定性红测 `20260905T102646121Z-quality-focused.json`：9 通过、1 失败。
全屏菜单第一次 Esc 本应只关菜单，实际同时调用了一次退出全屏。
普通 Material/Get 房间仅关闭菜单的用例在修改前已通过；**实机所见直接回主页的完整触发条件
尚未由简化夹具复现**，不把这个观察和全屏红测混为同一已证明的场景。

根因是 `HardwareKeyboard.addHandler` 的所有监听都会收到事件，返回 true 不阻止其他 Flutter
监听。菜单处理了 Esc，房间全局监听仍执行。采用 Flutter 的焦点分发，而非延时去重：

1. 移除全局硬件监听，使用现有 `CallbackShortcuts` 的 Esc 绑定。
2. 页面 `FocusScope` 提供无播放器/离线页的焦点退路，同时让内部输入、控件优先处理。
   初版普通 `Focus` 抢走了同时 autofocus 的子控件，新增测试后改为 Scope，保留失败记录。
3. 核对当前路由，只响应本页；关闭菜单后下一次独立 Esc 才退出呈现或房间。
4. Esc 不接收 repeat，避免长按一次从全屏一直退到主页；PiP、普通返回、宽屏合同保留。

最终 `20260905T103213286Z-quality-focused.json`：15/15，通过菜单、dialog、sheet、
Get 命名路由、子控件优先、重复键、离线页与系统返回相邻测试。之前的格式失败、平台 override
夹具清理失败、nullable 编译失败均留在本地日志，没有计入功能红测或成功结果。

资料：[HardwareKeyboard](https://api.flutter.dev/flutter/services/HardwareKeyboard/addHandler.html)、
[CallbackShortcuts](https://api.flutter.dev/flutter/widgets/CallbackShortcuts-class.html)。
只修改键盘 UI 作用域，没有变更传输/解码/画面比例、增加播放器或恢复循环。
此修复晚于上述 e89db809 Windows 候选构建，候选 GUI 结果不当作修复后的实机复验。
回滚可只还原 keyboard 源文件与对应测试；没有设置、数据库、ABI 或平台凭据迁移。
