说明 1：报告表里的距离是 iOS 减速公式的极限值 v ÷ ln(1/0.135)；Flutter 在速度低于 20/dpr dp/s（K90 是 3 倍，6.67 dp/s）时就停，所以屏幕上实际停在极限前 3.33 dp。500 dp/s 时屏幕上是 246.4 dp，比表里的 250 少 1.4%；加上这 3.33 dp 后和表差 0.06%。3000、6000 dp/s 直接比也只差 0.2%、0.1%。时长表里取到 0.1 秒，和公式本身的值比差 0.3%～0.5%（120 Hz 一帧的取整）。测试里两种比较都写了，也和 v3 实测值逐帧比较。

### 偏差和原因

1. **快滑到顶会停住，不回弹；手指往下拉才有橡皮筋和刷新头。** 这是 v3 的实际行为：easy_refresh 的头部默认 `hitOver: false`，快滑碰到顶部时直接停（不让惯性把刷新头带出来）。我在本机用 easy_refresh 3.5.1 量过：从 300 dp 以 3000 dp/s 往上滑，最低点 0.00。底部：没有更多数据时快滑会冲出去再弹回（v3 冲出 58 dp），还有更多时停在列表尾（v3 一样）。调研报告写的“两端回弹”指手指拉过头；如果想让快滑到顶也像 iOS 那样弹，需要维护者决定（见最后）。
2. **回弹弹簧比 v3 硬。** 任务单定了质量 1、刚度 500、阻尼比 1；v3 用的是 Flutter 默认的滚动弹簧（质量 0.5、刚度 100、阻尼比 1.1）。所以松手到开始刷新、完成后收回、拉一点松手弹回都从 v3 的约 650 ms 变成 342 ms，底部冲出也从 58 dp 变成 39 dp。滑行（减速）本身和 v3 完全一样。
3. **第二行写“上次刷新时间”。** U.1c 的图上是“上次加载时间”，任务单写“上次刷新时间”，按任务单。翻译键沿用 v3 的 `refresh_last_updated_at`，占位符从 `%T` 改成 `{time}`（v4 的 i18n 用具名参数）。
4. **松手后、到位前（v3 的 ready）显示“正在刷新...”和转圈**。v3 这时写“加载中...”。只差几百毫秒，统一成一句。
5. **上拉加载没有搬进组件。** 房间列表本来就有 U.4 确认过的列表尾（离底 600 dp 自动加载，比 v3 的 70 dp 早，滑得更顺），只加了 `stopAtEnd`：还有更多时快滑停在列表尾。关注、历史、分区、WebDAV、备份都是一次取全，没有加载更多。
6. **WebDAV 下拉时不再整页转圈。** 以前下拉一开始就把列表换成整页加载，刷新头根本看不到；现在下拉刷新时列表留着，头部显示进度，列完再换（`_load(keepRows: true)`）。失败照旧显示出错页。按钮“刷新”和进目录还是整页加载。
7. **改了 `features/areas/area_card.dart`。** 任务单没列，但 `AreaGrid` 自己写死了 physics，不加一个 `physics` 参数就没法用刷新组件的物理。和 `platform_areas_view.dart` 同目录，只加参数，默认值不变。
8. **不算安全区。** v3 的头部会把状态栏高度加进触发距离；这几处列表都在标题栏或标签栏下面，安全区本来是 0，就没做。
9. **v3 的 WebDAV、备份页没有下拉刷新**（4.0 加的 `RefreshIndicator`）；现在和其他列表一样。

## 根因

v3 的热门、分区房间、历史放在 `EasyRefresh(child:)` 里，列表自己没写 physics，于是用的是 `ERScrollBehavior` 给的 `_ERScrollPhysics`（继承 `BouncingScrollPhysics`）：iOS 式减速（摩擦 0.135）、拉过头越拉越沉、不画拉伸，加上经典头。v4 把这些列表换成了 `PureLiveScrollPhysics`（Android 上是 Clamping + Material 3 拉伸）和 Material `RefreshIndicator`：减速快得多（500 dp/s 只滑 58 dp）、列表在顶部不跟手、下拉的是一个圆圈。v3 的字还是反的（往下拉写“上拉刷新”，U.1c P19）。

## 前后对比（K90：400×869 dp、3 倍、120 Hz；widget 测试量的）

测量方法：在 widget 测试里放一个 200 行、每行 100 dp 的列表，跳到 8000 dp 处，按给定速度松手（`goBallistic`，和真手指 `fling` 量出来一样），每 8.33 ms 推一帧直到停。v3 一列是在本机临时工程里用 easy_refresh 3.5.1 按 v3 的配置（`ClassicHeader`、`ClassicFooter`）、同一个 Flutter 3.47.5 量的（临时工程不在仓库里）。

## 要在 K90 上看的（维护者做）

准备：装这次的 debug 包（开发者选项里“显示刷新率”可开可不开）。

1. **热门页快速上滑、到底、到顶**
   - 热门 → 任一平台。手指快速往上划几次：列表比以前滑得远、停得慢（拖尾长），连续快划会越来越快。
   - 一直划到底：还有更多房间时停在“加载中”的列表尾上，然后接着出现新房间；到了“没有更多数据了”时快划会冲出去一点再弹回。全程不出现拉伸变形。
   - 手指按住往上拉过底：越拉越沉，松手弹回。
   - 快速往下划回顶部：在顶上停住，不会自己冒出刷新头，也没有拉伸。
2. **下拉热门**
   - 在顶部手指往下拉：列表跟着手往下走（越拉越沉），露出的空白里是向下箭头 + “下拉刷新”，下面一行“上次刷新时间 H:mm”。

   - 刷新完：“刷新成功”和 ✓ 停 1 秒，然后收回（约 0.35 秒），“上次刷新时间”变成现在。
   - 拉得不够就松手：弹回，不刷新。
   - 断网后下拉：“刷新失败”加原因，页顶出错横幅也在，卡片留着。
3. **其他刷新列表手感一致**：分区里的房间、关注（各状态标签）、观看记录（标题栏刷新按钮会自己拉出刷新头）、分区列表、WebDAV（下拉时文件列表不消失）、备份与恢复，都和热门一样。
4. **设置页到头仍然是拉伸（不变）**：设置 → 任一页面，拉到顶和底都是 Android 的拉伸效果。
5. **搜索页的平台横条**：左右拉到头有拉伸（以前没有）。

## 需要维护者决定的

1. **快滑到顶要不要也弹一下？** 现在照 v3：快滑到顶直接停，只有手指拉才出橡皮筋和刷新头。如果想像 iOS 那样惯性冲到顶也弹，只要在 `refresh_view.dart` 去掉“快滑到顶停住”这一条，但刷新头会被惯性带出来一点（不会触发刷新）。
2. **弹簧要不要回到 v3 的软弹簧？** 现在按任务单用 1/500/1（约 0.35 秒停稳）；v3 是约 0.65 秒。如果真机上觉得“太利落”，改 `appRefreshSpring` 一处即可。
