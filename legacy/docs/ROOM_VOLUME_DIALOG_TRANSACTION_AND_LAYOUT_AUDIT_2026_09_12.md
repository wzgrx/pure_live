# 当前直播间音量事务、边界与布局审计（2026-09-12）

## 范围与基线

- 基线：`0bb6e96e84f77441a42a161dfb21541799f0e518`。
- 范围：播放器更多菜单中的“房间音量”弹窗、全局静音、手机/电脑默认音量、当前房间音量应用、持久化边界及窄屏大字号布局。
- 本批使用真实弹窗 Widget、真实音量设置控制器和受控播放器/系统音量替身；没有连接手机、操作真实声卡或启动直播。

## 稳定复现与根因

1. 默认音量先乘以 100 再调用 `toInt()`，持久化值为 `NaN` 或无穷时直接抛出异常；`Slider.clamp` 也不能把 `NaN` 变成有效值。
2. 标题、图标和百分比使用两个无弹性的嵌套 `Row`；旧 `AlertDialog` 在桌面路径还强制最小宽度 500。320×480 / 3.0 倍英文稳定产生两个标题行向右溢出 **818 / 903 像素**、对话框向底部溢出 **224 像素**，恢复默认与操作区不能连续到达。
3. 确认先写入三项设置，再以未等待的播放器调用应用音量并立即关闭；平台写入失败、连续点击和退出期间都没有明确事务所有者。
4. 三个临时 `Rx` 在静态 `show` 外层创建，生命周期不属于对话框 State；界面也没有解释“房间音量”同时修改两端全局默认值。
5. 备份导入与旧持久化只拒绝非有限值，没有把有限但越界的默认值和房间值归一化到 `0..1`，运行时写入也可再次保存非有限值。

## 修订

- 弹窗改为自有 State：静音和两端音量均为本地草稿，恢复默认仍可取消；取消不触碰持久化设置和当前播放器。
- 确认只启动一个异步提交：按 Android/iOS 或桌面选择本设备草稿值，静音统一应用 0；等待活动播放器写入成功后再提交三项设置并关闭。
- 提交期间禁用确认、取消、恢复、开关和滑杆，并由 `PopScope` 保持路由；异常时保留草稿和原设置，显示双语内联错误后允许重试。
- `VideoController.trySetVolume` 将活动房间归属、原生写入、超时及房间保存结果传回事务弹窗；普通音量控件继续复用原 `setVolume` 入口。
- 对话框改为最大宽度 520、最大高度随视口收敛的有界布局；主体弹性滚动、底部操作固定，标题使用 `Expanded` 换行并保留独立百分比。
- 新增双语范围说明，明确保存手机和电脑默认值，并把本设备值应用到当前房间。
- 音量设置控制器在启动时修复旧持久化值，备份导入和房间映射统一钳制到 `0..1`；非有限运行时写入保持最后有效状态。播放房间读取同样对非有限覆盖值安全回落。
