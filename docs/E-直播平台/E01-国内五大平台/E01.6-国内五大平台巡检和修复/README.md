## 目标

哔哩哔哩、斗鱼、虎牙、抖音、快手的推荐、分类、分区、搜索、进房、清晰度和线路、链接（和弹幕能不能连上）定期用真实接口跑一遍；平台改了接口或加了风控时，在用户发现之前修好。每一轮的产出：

- 一份当天的结果表（每个平台每项“正常 / 失败 / 没测到 / 不支持”，失败写原因）；
- 每个失效有根因（文件:行）、脱敏的新样本、改之前会失败的测试、修复提交，修复后重跑这一项。

这是持续任务：三个阶段做完算一轮，以后每两周（或用户反馈某平台打不开时）再做一轮，结果追加到 record.md。

## 方案

- c1 写巡检清单：在 E07.1 的 `CHECKS.md` 里把五大平台这五行写全（检查项 P1～P13 的对象：关键词、在播房间怎么挑、固定的未开播房间、不存在的房间号、平台特有的情况：哔哩哔哩短号 6 和轮播房间、斗鱼靓号 1 和别名 `lpl`/`LPL`、轮播 93976、虎牙别名 `lpl` 和回放房间、抖音 `web_rid` 和游戏直播间、快手大小写不同的 `kpl704668133`）。E07.1 还没写 `CHECKS.md` 时由本任务先建，格式照 E07.1 的任务书。
- c2 逐个平台跑一遍：`live_cli patrol bilibili douyu huya douyin kuaishou --danmaku 60 --out runs/<日期>.md`；工具还没有时照 2026-10-01 的做法写临时程序（不进仓库），检查项和判定同 `CHECKS.md`。匿名、只读、直连、不发言；媒体每条线路只读开头 64 KB；快手请求间隔 2.5 秒；遇到风控就停，换时间再跑。
- c3 修复失效的：每个失效先录样本（脱敏）、写改之前会失败的测试，再改 `packages/live_core/lib/src/sites/<平台>/`；弹幕协议的失效开到 D01 对应任务，连接凭据（哔哩哔哩 `getDanmuInfo`、抖音签名、快手 feed 参数）的问题可以在这里一起修。修完回到 c2 重跑这一项。

- 第 1 轮 2026-10-08 做完（[record.md](record.md)）：五个平台没有适配器失效；斗鱼一个“在播但断流”（`streamStatus: 0`）的房间线路 404，是平台状态，处理方式作为候选等维护者定。
