## 0 调研要点

## 1 设计原则

1. **画面第一。** 直播画面和“谁在播”是每个页面的主角，其它元素不用时就退场：控制层自动隐藏，弹幕一键开关，有剧场模式，直播间不显示导航。
   检验：紧凑竖屏下 16:9 画面占满宽度；展开及以上等级，画面宽度不小于窗口的 60%（聊天栏默认 360dp）。
2. **一眼看清谁在播。** 关注页首屏回答四件事：谁在播、播什么、多少人、哪个平台。状态用文字加形状表达，不只靠颜色；人数和时长用等宽数字，刷新时位置不跳。
   检验：393dp 宽的手机首屏至少显示 6 个开播直播间（紧凑密度至少 8 个）。
3. **不打断观看。** 换画质、换线路、换台、断流恢复都在画面里完成：停在最后一帧，显示细进度提示，不弹阻塞对话框，不跳页。出错时在原地说明原因并给出下一步（重试、换线路、查看平台状态）。调整弹幕样式时，改动实时作用在正在播放的画面上。
4. **每种输入都是一等公民。** 触屏、鼠标键盘、遥控器各有一条完整的操作路径。同一个操作在各设备上叫同一个名字、在相同的相对位置（PLAN 一致性规则）。TV 不是放大的手机界面，桌面也不是拉宽的手机界面。
5. **轻就是快。** 每个视觉决定先过性能预算：不用模糊和装饰性动画，封面按显示尺寸解码，看不见的画面暂停解码。旧版 Windows 首页空闲就占 481 MB，Android 直播间 PSS 462 MB（BASELINE），界面层不能再加重。
6. **尊重肌肉记忆。** 旧版操作默认保留；新手势要么不和旧手势冲突，要么默认关闭；改变之处第一次出现时提示一次，并写进更新说明。

放弃的备选原则：“推荐和发现优先”（这是聚合看播工具，用户已经知道要看谁）；“互动和社区优先”（不发弹幕、不送礼是 Simple Live 被认可的地方 [R3]）；“各平台原样还原”（五个平台的界面差异很大，照搬会让同一操作在不同平台位置不同）。

## 2 视觉方向

### 2.1 整体风格

**决定**：以 Material 3 为基础的“安静界面”：中性表面，少量品牌蓝做强调，用色调层级而不是阴影分层。组件跟随 M3 Expressive 的最新形态：灵活导航栏、收起和展开两态的导航轨、按钮组、M3 加载指示器 [R20–R22]。动效用 standard 方案，形状只用基础圆角。Windows 上有五处贴近 Fluent：弹层圆角 8、系统标题栏跟随深浅色、右键菜单、常显的细滚动条、悬停态 [R28][R29]。

**理由**：Flutter 原生支持 M3，组件和无障碍语义现成可用；Android 是主力平台。看直播时界面应该退到后面，Expressive 的回弹和形状变形会抢走对画面的注意力，还会多出重绘。

**放弃的备选**：
- 全面采用 M3 Expressive（回弹弹簧、形状变形、加粗强调字）：抢注意力，动画成本高。
- Windows 用 Fluent 组件库另做一套：两套组件，截图测试翻倍。
- Mica / 亚克力背景：需要透明窗口参与合成；省电模式和非活动窗口下本来就会退回纯色 [R30]，收益小。
- 模仿某个平台（如 B 站粉）：聚合应用不应偏向任何一家。

### 2.2 颜色

**品牌色**

| 名称 | 色值 | 用途 |
|---|---|---|
| 品牌蓝 | `#2E6FE0` | 配色种子、应用图标主色、主要按钮。白字对比 4.7:1 |
| 品牌青 | `#45D4EA` | 图标渐变的另一端、插画点缀；不用于文字 |
| 品牌夜蓝 | `#0B1B3F` | TV 横幅和预览版图标的底色。白字对比 16.9:1 |

**理由**：
- 延续现有图标的蓝青渐变（取样 `#3A70CF` → `#4FB8F9` → `#64DDED`）。覆盖安装后，老用户在桌面上还认得出。
- 冷色和五个主力平台的暖色品牌（B 站粉，斗鱼、虎牙、快手橙，抖音黑红）分得开，平台 logo 放进界面不打架。“直播中”用红色，品牌色若用红或橙会混淆。
- Fire TV 设计指南也建议电视上用偏冷、饱和度较低的颜色 [R18]。
- 旧版默认色 Material Blue `#2196F3` 配白字只有 3.1:1，不满足 AA；`#2E6FE0` 色相相近、明度更低，白字对比达到 4.7:1。

**放弃的备选**：保留 `#2196F3`（对比不足）；紫色（Twitch 紫，也接近 B 站粉）；红或橙（与“直播中”和平台色冲突）；绿（与“成功”语义冲突）。

**配色生成**：品牌主题用 `ColorScheme.fromSeed(seedColor: #2E6FE0, dynamicSchemeVariant: fidelity)`，主色贴近品牌蓝，中性色色度很低，封面颜色不会被表面染色。
- 理由：默认的 tonalSpot 会把主色压成灰蓝，品牌辨识度低；fidelity 保留种子色，同时由色调算法保证对比度。
- 放弃：tonalSpot（太灰）；vibrant（色相偏移，表面偏彩）；content（跟着封面变色，列表里不稳定）。
- **第三色改用品牌青**（设计系统阶段补充）：fidelity 的第三色是种子色的暖色补色（浅色 `#964200`，橙色），会和“直播中”及平台色混淆。改为用品牌青 `#45D4EA` 的色板生成第三色一组（浅色 tertiary `#006572`），实现上是 `fromSeed` 之后用 `copyWith` 替换 tertiary 四个角色。
- 生成结果和 157 组对比度检查见 [tokens.json](tokens.json)、[contrast-report.txt](contrast-report.txt)；设计系统页面：https://claude.ai/artifact/JA858yzW77FSJ9mMdNz7LK ；页面稿：https://claude.ai/artifact/PAavLD9hN6VdLFgNYXkEr4 。

**语义色**：固定值，不随主题色和动态取色变化。

| 角色 | 浅色 | 深色 / 纯黑 | 说明 |
|---|---|---|---|
| 直播中 | 底 `#D92D20`，白字（4.8:1） | 同左 | 徽标总是叠在封面上，两套主题同色；必须带“直播”二字，不只靠红点 |
| 录制中 | 同上红色 | 同左 | 用实心圆点图标加“录制”二字，和“直播”靠文字区分 |
| 成功 | `#1B7236`（白底 6.0:1，所有容器层 ≥4.6:1） | `#6FDD8B`（深底 11:1） | 设计系统阶段由 `#1E7F3C` 加深：原值在 `surface-container` 及以上只有 3.9–4.3:1 |
| 警告 | `#915600`（白底 5.9:1，所有容器层 ≥4.6:1） | `#FFB95C`（深底 10.9:1） | 平台异常横幅、弱网提示；由 `#9A5B00` 加深，原因同上 |
| 错误 | 配色方案自带的 error 角色 | 同左 | 取消旧版把深色 error 改成 `#FF6347` 的做法 |

- 开启动态取色时，成功和警告按 M3 的 harmonize 向主色轻微偏色；“直播中”红不偏，保持可认。
- 各平台的品牌色只出现在它们的 logo 里，界面本身不用。

**三套主题**

| 主题 | 定位 | 表面 |
|---|---|---|
| 浅色 | 白天浏览、搜索、设置 | 配色方案的浅色 surface |
| 深色 | 夜间使用 | 配色方案的深色 surface |
| 纯黑 | OLED 省电、暗室观看 | surface `#000000`，容器 `#0E0E10` / `#161618` / `#1E1E21`，正文 `#E6E6E8`（16.9:1，不用纯白以减少 OLED 上的光晕） |

- 默认“跟随系统”。纯黑是深色下的一个开关（“深色时使用纯黑背景”），跟随系统进入深色时同样生效。
- 播放器区域、全屏、剧场、多画面、画中画和小窗在所有主题下都是黑底白字。理由：视频周围是亮色时会放大黑边、暗环境刺眼；Twitch 电视版改版时也换成了深色界面 [R11]。
- TV 模式只提供深色和纯黑（§5.3）。
- 放弃：把纯黑做成和深色并列的第三种模式（用户分不清选哪个）；深色固定用 `#121212` 灰（和动态取色不协调）。

**动态取色**：Android 12 起可选“跟随壁纸取色”，Windows 可选“跟随系统强调色”，默认都关闭。开启后只替换主色、次色、第三色和中性色，语义色不变。
- 理由：旧版 `enableDynamicTheme` 默认就是关闭；新装用户应该先看到品牌色；壁纸取出的颜色可能和平台 logo、封面冲突。
- 放弃：默认开启（品牌色从新装用户眼前消失）；不支持（旧版已有，Android 12+ 用户习惯）。

**主题色**：保留“自选主题色”：品牌蓝（默认）+ 8 个预设 + 自定义色值。迁移规则：旧版 `themeColorSwitch` 是默认的 `#2196F3` 时改为品牌蓝，其它值原样作为种子色。任何种子色都经 `fromSeed` 生成符合对比度的色调，自定义不会破坏可读性。
- 放弃：只留品牌色（选过旧版 14 种颜色的用户会丢设置）。

**对比度规则** [R31][R32]
- 正文不低于 4.5:1。大字（24sp 常规或 19sp 粗体以上，即 WCAG 的 18pt / 14pt 粗体）、图标、输入框边框、焦点框不低于 3:1。
- 画面上的文字和图标下面垫黑色渐变遮罩，从透明到 60% 黑。在纯白画面上，55% 黑配白字是 4.7:1，取 60% 留余量；不用模糊。
- 系统要求高对比度时（Windows 高对比度、Android 14 的对比度滑块 [R23]），用 `fromSeed` 的 `contrastLevel` 生成高对比度方案。
- 设计系统阶段用脚本检查所有前景与背景的组合。

### 2.3 字体

| 平台 | 字体设置 | 理由 |
|---|---|---|
| Android | 不指定字体族，用系统默认（Roboto 或厂商字体，中文回退到 Noto Sans CJK、MiSans、HarmonyOS Sans 等）。按应用语言设置 locale（zh-Hans / zh-Hant），让回退选中正确的简繁字形 | 沿用旧版做法，尊重厂商字体；Flutter 有把中日韩字形渲染成简体变体的已知问题 [R35]，繁体界面要截图验证 |
| Windows | `Microsoft YaHei UI` → `Microsoft YaHei` → `Segoe UI Variable Text` → `Segoe UI` → `Segoe UI Emoji`。繁体时前两项换成 `Microsoft JhengHei UI` → `Microsoft JhengHei` | 微软推荐的简繁界面字体是带 UI 后缀的版本 [R29]；旧版显式指定雅黑，以避开 Flutter 在 Windows 上的中文渲染问题 [R36] |
| Linux | `Noto Sans CJK SC` → `Source Han Sans SC` → `WenQuanYi Micro Hei` | 只要求能编译运行 |
| macOS / iOS | 系统默认（苹方） | 同上 |

- **字重**：正文 400，标题和强调 600。不靠 500 区分层级：微软雅黑只有细、常规、粗三档，500 会落回常规，层级就没了。放弃：M3 默认的 500 标题字重。
- **字阶**：用 M3 字阶，改两处。最小字号 12sp（M3 的 labelSmall 11sp 改为 12sp；Windows 规定常规字重最小 12px [R29]）。中文行高不低于字号的 1.4 倍，向上取偶数（例如 bodySmall 12/16 改 12/18，titleLarge 22/28 改 22/32；原稿写的 22/30 只有 1.36 倍，设计系统阶段更正）。
- **数字**：人数、码率、时长、时钟、倒计时一律用 `FontFeature.tabularFigures()` [R37]。等宽只在同一个字体内生效，数字要落在拉丁字体上渲染。人数写成“1.2万”“3.4亿”（英文界面写“12K”）；不做数字滚动动画。
- **字号缩放**：跟随系统字体缩放（Android 14 起非线性缩放，最大 200%），再乘以应用内的“文字大小”（0.85–1.3），合计上限 2.0。画面上控制层的文字缩放上限 1.3，避免遮挡画面；弹幕字号单独设置。
  - 理由：旧版有 5 个分项字号（`fontSizeBodyLarge` 等）加一个缩放系数，组合太多，布局无法测试；统一成一个系数后可以用截图测试覆盖。迁移时由旧值换算出一个系数。
  - 放弃：保留分项字号。
- **可选字体**：保留“自定义字体”：可以导入本地字体文件；在线下载列表只收 SIL OFL 等与 AGPL 兼容的字体（如 Noto Sans SC、霞鹜文楷）。不做品牌专用字体。
  - 理由：中文字体 8–20 MB，不能打进安装包；品牌字体还要解决许可证。
  - 放弃：内置品牌字体。

### 2.4 圆角、间距、层级

**圆角**：4 级加全圆，是 M3 圆角刻度的子集 [R24]。

| 令牌 | 值（dp） | 用于 |
|---|---|---|
| r1 | 4 | 徽标（直播中、画质标签）、进度条、提示气泡 |
| r2 | 8 | 封面、输入框、菜单项；Windows 上的对话框和菜单 |
| r3 | 16 | 卡片容器、侧栏、Toast、Android 菜单 |
| r4 | 28 | Android 的底部弹层和对话框 |
| 全圆 | — | 按钮、筛选标签、头像、开关 |

- 不圆角：视频画面（任何模式）、多画面格子、贴边面板的贴边一侧、最大化的窗口 [R28]。
- 理由：Windows 11 的弹层用 8、控件用 4 [R28]，Windows 上弹层用 r2 更像系统。视频不圆角既是性能要求（不裁剪），也和系统播放器一致。
- 放弃：M3 Expressive 的 35 种形状和形状变形；Windows 单独一套圆角令牌。

**间距**：4 点网格 4 / 8 / 12 / 16 / 24 / 32 / 48（同 PLAN）。

| 等级 | 页边距 | 网格间隙 |
|---|---|---|
| 紧凑 | 16 | 8 |
| 中等、展开 | 24 | 12 |
| 大、超大 | 32 | 16 |
| TV | 左右 48、上下 28（规范为 5% 安全区，即 48 / 27，上下取不小于 27 的 4 的倍数）[R14] | 20（TV 网格规范值；是 4 的倍数，但不在上面的档位里，只在 TV 使用）[R14] |

**页头与内容共用页边距**（2026-09-28 设计复核补充，`live_ui` 的 `PageAppBar`、`PageTabBar`、`PageBody`）：标题从页边距开始；有返回按钮时按钮图形在页边距上，标题在它后面 32dp；最后一个操作按钮的图形结束在右页边距上；横向标签的第一个文字从页边距开始；列表行的内容也从页边距开始（不小于 Material 的 16 / 24）。内容居中限宽的页面（“我的”、设置分组、IPTV、录制中心、观看历史），标题与内容列的左缘对齐，返回按钮挂在它前面。TV 的页边距取卡片网格留给焦点放大的 8dp（导航轨和安全区已经留出其余部分），TV 的列表行保留 16dp 内边距，给焦点底色留空间。
- 理由：复核发现标题用 AppBar 默认的 16，内容用 24 或 32，中等宽度下差 8dp、大宽度差 16dp，TV 上标题反而比卡片靠里。
- 放弃：只改 AppBar 的 `titleSpacing`（标签栏、列表行和操作区仍然各用各的）。

**层级**：用色调层级（surface → surfaceContainerLow … Highest）区分层次，不用投影。只有浮在画面或内容之上的元素（菜单、对话框、小窗）用一级阴影。
- 理由：深色和纯黑下阴影几乎看不见；列表里每张卡片都画阴影会增加光栅化开销。
- 放弃：卡片投影。

**触控目标**：手机和 TV 最小 48dp [R33]；桌面指针设备用紧凑密度，但不小于 32dp（WCAG 2.2 下限是 24px [R34]）。

### 2.5 动效

**时长三档**（同 PLAN）

| 档位 | 时长 | 用于 | 缓动 |
|---|---|---|---|
| 快 | 100 ms | 按压、开关、焦点缩放、悬停 | standard |
| 中 | 200 ms | 控制层淡入淡出、菜单和弹层出现、标签切换 | 进入用 decelerate，退出用 accelerate |
| 慢 | 300 ms | 页面切换、面板展开收起、底部弹层 | emphasized |

- 退出比进入快一档（例如弹层进入 200、退出 100）。
- 跟手动画（拖动面板、下拉刷新、滑动换台）松手后用不回弹的弹簧（阻尼比 1），相当于 M3 的 standard 动效方案 [R21][R25]。
- 页面切换沿用旧版的 FadeForwards：本项目 issue #852 发现，Flutter 由手势驱动的共享元素转场在部分 ColorOS 上会卡住输入。支持预测性返回的预览。

**不做动画的场景**
- 视频本身：换画质、换线路、换台时不做交叉淡化，旧画面停在最后一帧，新画面就绪后直接切换。
- 画面尺寸变化（进出全屏、剧场、小窗）：动画只做合成层的位移和缩放，结束后才让内核按新尺寸渲染一次。
- 高频数字（人数、码率）：直接替换。
- 列表：卡片出现时不做逐个错峰的动画；骨架屏是静态的，没有扫光。
- 弹幕层本身在动，周围不再叠加装饰动画；不播放全屏礼物特效。
- 不做无限循环的装饰动画。加载指示器只在可见时运行，静止界面可以降到低刷新率。

**减少动态效果**
- 系统“移除动画”（Flutter 的 `disableAnimations`）：所有非必要动画时长为 0 [R38]。
- 系统“减少动态效果”（`reduceMotion` [R39]）或应用内开关：位移和缩放改为 100 ms 以内的淡入淡出；TV 焦点只变描边不缩放；上下滑换台不做滑动过渡。
- 应用内开关放在“外观”，默认“跟随系统”。理由：Windows 的系统设置不一定传得到 Flutter，需要应用内兜底；对应 WCAG 2.3.3 [R40]。
- 放弃：M3 Expressive 的 expressive 弹簧（有回弹，控制层过冲会多画几帧）；再加一档 500 ms（大面积动画在画面旁边分散注意力）。

### 2.6 图标

**决定**：全部使用 Material Symbols Rounded 可变字体（`material_symbols_icons`，Apache-2.0）[R26][R27]，去掉 Remix 图标和旧的 CustomIcons.ttf。

| 轴 | 规则 |
|---|---|
| 填充 FILL | 未选中 0，选中或开启 1（导航当前项、弹幕开、已关注、静音中） |
| 字重 wght | 400；画面上的控制层 500（复杂画面上更清楚） |
| 等级 GRAD | 浅色 0；深色和纯黑 -25（降低亮图标在暗底上的眩光 [R26]） |
| 光学尺寸 opsz | 等于显示尺寸：20 / 24 / 40 / 48 |

- 尺寸：列表和工具栏 24，密集信息 20，控制层 24（紧凑）或 32（展开以上和全屏），TV 32。
- Symbols 里没有的图标（弹幕开关等）按 Rounded 的 24dp 网格和 2dp 笔画自绘为矢量，放在 `live_ui`，开关两态都要有。
- 风险：Flutter 的图标裁剪曾导致可变图标的填充状态渲染错误（#183381，已由 PR #183857 修复）[R41]。第 3 阶段在 3.47.5 的 release 构建上用填充切换的截图测试验证；如果没修好，就对图标字体关闭裁剪，并记录包体变化。
- 理由：一套图标、一种笔画；开和关只改填充轴，不换图形；Rounded 和品牌图标的圆角几何一致。
- 放弃：Outlined（M3 默认，但和圆润的品牌图形不协调）；Sharp；Windows 上单独用 Segoe Fluent Icons（两套图标）；SVG 图标集（每个图标一个文件，不能用轴表达状态）。

## 3 品牌与美术

### 3.1 应用图标

**概念：演进，不重做。** 保留现有图标的两个识别点：带天线的电视外形，和中间的播放三角。重绘成更简洁的几何：
- 屏幕是 16:10 的圆角矩形；两根天线缩短、对称、圆头；播放三角用负空间挖出。
- 渐变从品牌青到品牌蓝，120°，左上浅、右下深（Windows 图标规范的默认角度和光源方向 [R42]）。
- 只用一个隐喻（电视 = 看直播），图标里不放文字 [R42]。

| 交付物 | 规格 |
|---|---|
| Android 自适应图标 | 108dp 画布，前景电视在 66dp 安全区内，白色背景 |
| 单色主题图标（Android 13+） | 电视剪影加镂空的播放三角 |
| Windows ICO | 16 / 20 / 24 / 32 / 40 / 48 / 64 / 256。16 和 20 去掉渐变和天线的圆头细节，只留屏幕和三角 |
| TV 横幅 | 320×180（xhdpi，另出 mdpi 到 xxxhdpi），夜蓝底 + 图标 + “纯粹直播”字标；中文、英文各一版（横幅必须带文字，每种语言一版）[R19] |
| TV 启动器图标 | 自适应图标；TV 不支持主题图标 [R19] |
| 预览版（`.next`） | 同一图形反色：夜蓝背景 + 白色电视，不加文字角标 |

- 放弃：全新图形（丢掉老用户的识别，覆盖安装后桌面图标突然变样）；把平台 logo 拼进图标（商标问题）；3D 或拟物（小尺寸发糊）。

### 3.2 品牌标识与启动页

- **字标**：“纯粹直播”和“Pure Live”，用系统字体粗体排好后转成矢量轮廓，不随包附带字体。只用在关于页、TV 横幅和安装程序上；应用内的普通页面不放 logo（内容优先）。
- **组合**：图标在左、字标在右，间距为图标高度的 1/4。
- **启动页**：Android 12 起用系统 SplashScreen API，图标用自适应图标的前景，背景跟随深浅色（浅色白，深色取深色 surface），首帧后立即退出，不做品牌动画；去掉旧版的 Flutter 启动页（`showSplashPage`）。Android 8–11 用同样的主题背景加居中图标。Windows 在首帧后才显示窗口（旧版已经如此）。
  - 理由：PLAN §10 的启动预算；旧版启动页让人多等一次。
  - 放弃：品牌动画启动页。

### 3.3 空状态与错误插画

**风格**：细线条加一块色面的双色矢量插画。线条用 onSurfaceVariant，色面用 primaryContainer。颜色取自主题令牌，所以浅色、深色、纯黑和动态取色下都自动协调。以品牌的电视形象为主角做变化，不画人物，不设吉祥物。尺寸不超过 160dp（TV 200dp），线宽和 Symbols 的笔画成比例。

| 场景 | 画面 | 文案与操作 |
|---|---|---|
| 关注为空 | 空屏幕加一个加号 | 一句说明 + [去发现] [粘贴链接] [导入旧数据或备份] |
| 无人开播 | 熄灭的屏幕加月亮 | “关注的主播都没开播” + [看全部关注] |
| 搜索无结果 | 屏幕里的放大镜 | 建议换关键词或平台 |
| 网络错误 | 天线断开 | 原因 + [重试]；离线时显示缓存内容 |
| 平台异常 | 屏幕加警示三角 | “斗鱼接口异常（来自每日巡检）” + [重试] [查看状态] |
| 播放失败 | 屏幕里断开的播放三角 | 按错误分类说明（链接过期、地区限制、需要登录）+ [重试] [换线路] |
| 无历史 / 无录制 | 空屏幕加时钟 / 录制圆点 | 一句说明 |

- 文案先说发生了什么，再给下一步，不写“出错了，请稍后再试”这类没有信息的话。
- 技术：SVG 在构建时编译为 vector_graphics 二进制（运行时不解析 XML）；每张不超过 4 KB；颜色在运行时按令牌替换。
- 放弃：3D 或位图插画（体积大，不跟随主题）；Lottie 动画（新依赖，持续占用 CPU）；吉祥物（美术成本高，风格难统一，容易像某个平台）。

### 3.4 平台 logo、封面和头像

- **平台 logo 原样使用**：用各平台的官方标识，不重绘、不改色、不做单色化、不随主题着色；在资源清单里记录来源和获取日期。
  - 小尺寸（16 / 20dp）放在中性底色的 r1 圆角方块上，保证浅色和深色下都清楚；最小 16dp，TV 24dp。
  - 官方有矢量就用 SVG（编译为 vector_graphics），否则用 WebP 两个尺寸。
  - logo 只用来标明来源，不当装饰或大号导航图标。
  - 关于页注明“各平台名称和标识归其所有者所有，仅用于标明内容来源”。
  - 放弃：统一风格的重绘 logo（有侵权风险，也更难认）。
- **封面**：加载中显示 surfaceContainerHighest 的静态色块，不转圈；加载失败或没有封面时，同样的色块中间放 24dp 的平台 logo。
- **头像**：加载失败时显示首字母圆形，底色由主播 ID 散列到 8 个中性色调之一。
- **表情**：WebP，按平台按需下载（PLAN §09），按显示尺寸（20–24dp）解码。

## 4 信息架构

### 4.1 一级入口

| 入口 | 内容 |
|---|---|
| **关注**（默认启动页） | 顶部筛选：开播 / 全部 / 分组；排序：开播时间、人数、平台、自定义；多选后可“加入多画面”“设置分组”“取消关注”；逐个设置开播提醒；平台异常时顶部显示横幅。开播的直播间用封面卡片，未开播的用紧凑行（头像、名字、上次开播时间），不加载封面 |
| **发现** | 平台切换（横向的 logo 标签，可以排序和隐藏）→ 每个平台下分“推荐”和“分区”；常用分区置顶；IPTV 作为一个“平台”出现在这里 |
| **搜索** | 一个输入框。识别到链接或分享口令时，顶部直接出现“打开直播间”；否则跨平台搜索主播和直播间，结果按平台分组，可筛选“只看开播”；有搜索历史 |
| **我的** | 观看历史、录制中心、多画面、平台账号、备份与同步、设置、关于与更新 |

- **启动页固定为“关注”**（TV 导航指南要求固定的起点 [R16]），可以在设置里改成“发现”。
- **直播间和多画面是全屏路由**，不显示导航栏或导航轨；从哪个入口进来，返回就回到哪里，并保留滚动位置。
- **多画面的入口**：关注页多选、直播间的快捷面板和 ⋮ 菜单（“加入多画面”）、“我的 → 多画面”（恢复上次的布局）。
- 理由：“热门”和“分区”合并，是因为两者都是“按平台浏览”；链接解析并入搜索，是因为用户粘贴链接和输入关键词在同一个地方。
- 放弃：
  - 跨平台混排的热门：各平台人数口径不同（真实人数、热度值），混排没有意义。
  - 旧版“一级菜单可排序和隐藏”（`savedMenuIds`）：只有 4 个入口且都必要，可排序会破坏“同一操作同一位置”。迁移时丢弃这个设置，在更新说明里写明。
  - “录制”作为一级入口（旧版宽度 ≤ 680 时显示）：录制管理是低频操作。
  - 搜索只放在顶栏、不做入口：TV 需要独立的搜索页，手机底栏入口也更好够。
  - 本地互动（虚拟金币）：信息架构里不给入口，与“纯粹”的定位不符；模块是否删除由对应规格和 ADR 决定。

### 4.2 直播间卡片的统一操作

关注、发现、搜索、历史里的卡片操作完全一致：
- **点击**：进入直播间。
- **长按（手机）/ 右键（桌面）/ 长按确认或菜单键（TV）**：操作菜单：关注或取消关注、设置分组、加入多画面、分享、复制链接、在新窗口打开（Windows）、打开原站。
- **桌面悬停**：显示完整标题；可选静音预览（见 §6.1）。
- **关注页的多选**（2026-09-28 实现，product F-FAV-09）：关注页的卡片菜单第一项是“多选”，从这里进入；长按本身仍是菜单，不直接进入多选，保持上面“完全一致”和 §6.4 第 14 条。桌面上 Ctrl / Shift 点选直接进入多选。多选时顶栏是“已选 N”，带全选、取消和三个操作（加入多画面、设置分组、取消关注）；返回键和 Esc 先退出多选。TV 不提供多选。
  - 放弃：长按直接进入多选（安卓文件、相册的习惯）：关注页的长按就和发现、搜索、历史不一样了，也改掉了旧版的“长按 = 菜单”。

### 4.3 列表信息密度

- 开播卡片：16:9 封面；封面左上是平台 logo（16dp），右下是人数（等宽数字），左下是“直播”徽标或开播时长；封面下方，“标准”密度为主播名一行加标题一行，“紧凑”密度为“主播名 · 标题”一行。
- 卡片不放主播头像：平台 logo 加名字已经够认，每张卡省一次图片解码。头像用在未开播的紧凑行和直播间顶栏。
- 默认密度：关注页“紧凑”（沿用旧版 `enableDenseFavorites` 默认开启），发现和搜索用“标准”。
- **行的宽度**（2026-09-28 设计复核补充）：未开播的紧凑行、录制任务、观看历史这类“行”，最宽为一个可读宽度（720dp 加两侧页边距），不随窗口铺满。和卡片网格同页时（关注、搜索），行从网格的左缘开始；整页都是行时（录制中心、观看历史），和“我的”、设置一样居中。
  - 理由：1920 宽的窗口里平台 logo 离名字隔着一整屏；录制任务行有操作按钮和两三行说明，做成和网格同列数的行卡（每张约 217dp）会挤不下，所以两处都用限宽。
  - 放弃：与网格同列数的行卡（录制行放不下，关注页的“状态未知”标签会把名字挤成省略号）。
- **搜索结果里的未开播房间**和关注页一样用紧凑行（头像、名字、标题、平台 logo），放在开播卡片后面的“未开播 N”下，不画空白封面卡。

### 4.4 设置分组

PLAN 的 6 组扩为 8 组加“关于”，另加设置搜索：

| 分组 | 内容 |
|---|---|
| 通用 | 语言、启动页、退出行为、开机自启（Windows，新装默认关闭）、屏幕常亮、刷新率、自动检查更新 |
| 外观 | 主题模式、纯黑背景、主题色与动态取色、文字大小、字体、卡片密度、减少动态效果 |
| 播放 | 默认画质（Wi-Fi 和移动网络分开）、解码方式、低延迟、默认全屏、全屏方向、竖屏直播适配、后台播放、画中画和小窗、返回键行为、定时关闭、手势开关（上下滑换直播间等） |
| 弹幕 | 显示、样式（字号、字重、描边、透明度、速度）、显示区域、密度上限、屏蔽词和屏蔽用户、合并重复、相似过滤、画中画弹幕 |
| 录制 | 保存位置、分段、格式、并发数、结束后转封装 |
| 平台与账号 | 平台的启用和排序、各平台登录（说明 Cookie 加密存储、默认不进备份） |
| 网络 | 代理（全局和按平台）、DoH、局域网权限说明 |
| 数据与同步 | 备份与恢复、WebDAV、局域网同步、历史记录上限、清理缓存、导出诊断包、崩溃上报（默认关） |
| 关于 | 版本与更新、平台状态、开源许可、商标声明 |

- 理由：约 230 个设置键（诊断 05 ⑤）。只分 6 组时，录制的 21 项要并进“播放”（本身 28 项），这一组会接近 50 项；Cookie 是敏感信息，单独成组才好说明加密和备份范围；录制有 21 项独立设置。设置搜索同时索引标题、说明和旧版名称，老用户按旧叫法也能搜到。
- 开机自启：旧版在 Windows 上首次启动就默认开启（诊断 05 标为待确认），v4 新装改为默认关闭，旧用户迁移时保留原值。理由：不经同意就开机自启，不符合“隐私默认安全”的精神。
- 录制中心页里放一个直达“设置 → 录制”的链接。
- 布局：紧凑和中等是分级页面；展开及以上是左侧分组、右侧内容（可读宽度不超过 720dp）；TV 为两栏。
- **设置搜索**（2026-09-28 实现）：搜索框在设置首页列表的最上方，两栏布局时在左栏顶部。索引每个设置项的标题、说明、所在小节和 3.x 的旧名称（取自 3.x 的中英文界面文字，繁体界面用繁体字写出；存在 `settings.search.legacy`）。标题命中排在前面，其次是旧名称（结果注明“3.x：旧名”），再次是说明和小节。点结果打开所在分组，滚动到那一项并高亮 2 秒。TV 不提供设置搜索：遥控器输入慢，而且搜索框会在进入列表时抢到第一个焦点并弹出键盘。
- 放弃：保持 6 组（每组太长）；录制设置只放在录制中心（用户会到设置里找）。

## 5 尺寸等级与 TV

### 5.1 判定规则

1. **TV 模式**：检测到电视（`UI_MODE_TYPE_TELEVISION` 或 leanback 特性）时自动进入，也可以在设置里手动开关（照顾投影仪和报错类型的盒子）。TV 模式下不再按宽度分级。
2. **宽度等级**：按窗口可用宽度分级，与 Android 窗口尺寸等级一致，包括 WindowManager 1.5 新增的“大”和“超大” [R43][R44]：紧凑 < 600、中等 600–839、展开 840–1199、大 1200–1599、超大 ≥ 1600。
3. **高度等级**：紧凑 < 480、中等 480–899、展开 ≥ 900。**高度紧凑优先**：手机横屏宽约 850–930dp，按宽度属于“展开”，但高度紧凑（99.78% 的横屏手机高度 < 480dp [R43]），必须按“横屏手机”布局，不能套用展开等级的分栏。
4. **折叠屏姿态**：半开的桌面姿态和书本姿态单独处理，控件和文字避开铰链 [R45]。
5. 页面只读父组件的约束（`LayoutBuilder`），不读整屏尺寸（诊断 03 ①.3 的问题）。窗口尺寸变化时切换布局，但保留滚动位置和播放状态，不重建播放器。

### 5.2 各页面布局

| 页面 | 紧凑 | 中等 | 展开 | 大 / 超大 |
|---|---|---|---|---|
| 导航 | 底部灵活导航栏（M3 Expressive，比旧版矮） | 收起的导航轨（96dp） | 收起的导航轨，可手动展开 | 展开的导航轨（240dp），可收起并记住状态（导航轨顶部的切换按钮；选择存在本机的应用偏好 `app.navRailExtended`，对展开及以上等级都生效） |
| 关注 / 发现网格 | 2–3 列（393dp 手机为 2 列） | 2–3 列 | 3–5 列 | 大 4–6 列，超大 6–8 列 |
| 直播间 | 画面满宽在上，下面是聊天列表；竖屏直播用三档面板 | 画面在上，聊天可折叠；桌面姿态时画面在上半屏，控制和聊天在下半屏 | 画面 + 右侧聊天栏 320dp | 画面 + 可拖宽的聊天栏（280–480dp，默认 360dp）；可切换剧场模式 |
| 多画面 | 1×2 竖排，最多 2×2 | 2×2 | 2×2 / 1+3 | 2×2 / 1+3 / 3×3，可以自由调整 |
| 搜索 | 顶部平台标签 + 卡片网格 | 同紧凑 | 左侧平台筛选栏（全部 / 各平台）+ 卡片网格 | 同展开 |
| 设置 | 分级页面 | 分级页面 | 左侧分类 + 右侧内容 | 同左，内容区不超过 720dp |

- **搜索布局**（2026-09-28 修订）：结果和关注、发现一样用卡片网格，列数按同一公式；展开及以上把平台标签换成左侧的筛选栏（约 200dp，列出“全部”和各平台，排序和“只看开播”放在网格上方）。设计复核补充：紧凑和中等的平台标签和发现页一样带 logo、占满一整行，排序和“只看开播”放在标签下面的第二行；筛选栏只列出“综合”和有结果（或搜索失败）的平台，其余收进“其它平台 N”，点开或选中其中一个时展开；平台名单行显示，过长用省略号。放弃“列表 + 详情”：§4.2 规定卡片点击就进直播间，详情窗格要求先点选再进房，和其它页面的卡片操作不一致；直播间本身就是详情。
- **网格列数** = clamp(⌊(内容区宽度 + 间隙) ÷ (最小卡宽 + 间隙)⌋, 2, 8)，内容区宽度 = 窗口宽度 − 导航 − 两侧页边距。最小卡宽：紧凑 160dp，中等和展开 180dp，大和超大 200dp（桌面看得远，卡片不宜过小；1920 宽的窗口约 7 列、每张约 217dp）。列数只由内容区宽度决定，不按等级查表；到“大”等级时导航轨展开、内容区变窄，列数可能少 1 列，这是预期行为。
- **高度紧凑（手机横屏）**：进入直播间直接全屏，聊天以浮层打开；其它页面用导航轨，顶栏随滚动收起。发现页（2026-09-28 设计复核）：去掉页面大标题，“推荐 / 分区”做成平台标签那一行末尾的分段按钮，这一行随内容向下滚动收起、向上滚动或回到顶部时出现（`ScrollAwayHeader`）。关注页：顶栏（标题、排序、一键多画面、刷新）同样随列表收起；多选时顶栏放着操作，固定显示（`ScrollAwayHeader.pinned`）。
- **直播间的展示状态**只有一个枚举（诊断 03 ⑥）：内嵌、剧场、全屏、竖屏全屏、画中画、小窗。视频表面只挂载一个，切换状态时移动它，不重建。
- **剧场模式**：隐藏信息栏，画面占满窗口高度，背景为深色。聊天栏另有独立开关（C 键或侧栏把手）。旧版的“宽屏”（隐藏右侧弹幕栏）对应新版的“收起聊天栏”。
- **全屏时的聊天栏**：展开及以上等级以侧栏形式挤压画面；手机横屏以右侧浮层显示（宽 40%，70% 黑的纯色底），可以关闭。聊天栏里是弹幕列表加置顶的醒目留言；礼物只显示为列表里的一行。
- **书本姿态**：画面在铰链一侧，聊天在另一侧。
- **大屏上的方向锁定**：面向 Android 17 的应用，在最短边 ≥ 600dp 的设备上方向锁定会被系统忽略，且不能退出 [R46]。平板和折叠屏上的“强制横屏全屏”“竖屏全屏”不能靠锁方向实现，只能按当前方向布局：竖屏直播在横屏平板上居中、两侧留黑；横屏直播在竖屏平板上满宽居中。锁方向只在手机上生效。

**直播间控制层**（参考 Simple Live 的布局 [R5]）
- 顶部：返回、主播名和标题、画中画、⋮ 菜单（打开原站、分享、复制直链、投屏、定时关闭、录制、加入多画面、在新窗口打开）。
- 底部：刷新、弹幕开关、弹幕设置、画质、线路、全屏；桌面另有音量滑块。
- 全屏时侧边有锁定按钮；锁定后隐藏控制条，禁用滑动和双击。

### 5.3 TV 模式

- **画布** 960×540dp；左右留 48dp、上下留 28dp 安全边距，背景和可滚动内容可以延伸到边缘 [R14]。
- **导航**：左侧收起的导航轨（只显示图标），获得焦点时展开显示文字；入口和手机相同。
- **网格**：4 列（每张约 183dp，间隙 20dp）；按行列记忆焦点，返回列表时焦点回到原来那张卡片。
- **焦点**：卡片放大 1.05 倍 + 3dp 描边（深色下用接近白色的 onSurface，焦点前后对比不低于 3:1 [R47]）+ 一级阴影；按钮用底色变化表示焦点。低端盒子的“性能优先”模式只描边不缩放 [R15]。
- **字号**：比手机大一级，正文不低于 14sp（1080p 下约 28px）[R17][R18]。
- **主题**：只有深色和纯黑。理由：客厅通常较暗，大面积白底刺眼。
- **直播间**始终全屏；多画面固定 2×2；设置为两栏。
- **搜索**：系统输入法加语音输入。
- **焦点预览**：可选，默认关闭。开启后焦点在卡片上停留 1 秒，就在卡片内播放静音、最低画质的预览（Twitch 电视版的做法 [R11]），同一时间只有一个。
- **实现细则**（2026-09-28，决定见 docs/adr/0026-tv-mode.md）：
  - 画布缩放系数 = min(宽 ÷ 960, 高 ÷ 540)，逻辑尺寸和设备像素比按它换算，封面仍按物理像素解码；相差 1% 以内不缩放（1080p、4K 电视在常见密度下本来就是 960×540）。
  - 安全边距作为系统安全区交给页面：顶栏、底部面板和列表自动避开，背景铺满到边缘。
  - 导航轨收起时 = 左边距 48 + 图标列 72，页面从 120dp 开始（4 列卡片约 179dp）；获得焦点时展开到 248dp，盖在页面上而不挤压，网格列数不变。启动时焦点在导航轨；从导航轨按右回到这个入口上次聚焦的控件；页面左边缘按左回到导航轨。
  - 按钮除了底色加深，再加 3dp 近白描边：有的按钮自带颜色，单靠底色在电视上看不出焦点。对话框和底部面板打开时焦点落在第一个控件上。
  - 设置在“通用 › 电视”：“电视模式”（自动 / 开启 / 关闭，默认自动，只在本机生效）和“电视焦点只描边”（即性能优先，默认关）。
  - 语音输入：搜索框在设备有语音识别时显示麦克风按钮，调用系统识别，不引入插件；输入法自带的麦克风同样可用。
  - 焦点预览尚未实现（需要单独的预览播放器），暂不提供设置项。
- 放弃：
  - 顶部标签导航：540dp 高的画布上纵向空间最紧；左侧轨道和手机、平板的入口顺序一致。
  - Leanback 式按行横向浏览：关注列表是一个整体，按平台分行会把它拆散；网格更直接。

### 5.4 桌面窗口

- 最小窗口 360×400（逻辑像素），能落到紧凑布局；记住窗口大小、位置和最大化状态；按显示器的缩放比例渲染。
- 使用系统标题栏，跟随深浅色；全屏时隐藏。放弃：自绘标题栏（会丢掉贴靠布局和系统无障碍支持，代码也更多）。
- 有悬停态、带快捷键的提示、右键菜单、常显的细滚动条；横向标签支持滚轮。
- 键盘焦点框只在使用键盘时显示，鼠标点击不显示。

### 5.5 与 PLAN 第 08 节的差异

1. PLAN 把手机横屏（约 860dp）写在“中等”一行；按宽度它其实属于“展开”。改由“高度紧凑优先”规则处理。
2. 导航：展开等级改用收起的导航轨（PLAN 写的是展开的导航轨），把宽度留给 4 列网格和直播间的聊天栏；大和超大的“固定侧边栏”用 M3 Expressive 的展开导航轨实现，因为导航抽屉已被弃用 [R22]。
3. 网格列数改为按最小卡宽计算，不再按等级写死（PLAN 为 2 / 3 / 4 / 5–7）：各等级的结果与 PLAN 相差不超过 1 列，而且任意窗口宽度都有合理结果，桌面上拖动窗口时不会出现过宽或过窄的卡片。
4. 新增：直播间不显示导航；TV 模式只有深色；Android 17 大屏忽略方向锁定时的布局。

### 6.4 必须保留的旧操作习惯

每一条在第 3 阶段都要变成回归测试（来源见诊断 03 ①.2 和 ⑤）：

1. 手机单击：可见且在播放 → 隐藏；暂停中 → 显示并继续播放。桌面单击只显示控制层。
2. 控制条范围内的点击不触发弹幕命中。
3. 双击：竖屏源进入竖屏全屏，其余进入全屏；在剧场或全屏中先退出。
4. 左侧上下滑调亮度、右侧调音量；锁定按钮锁住所有手势。
5. 竖屏直播间的三档面板；拖过最低档或点把手进入竖屏全屏；竖屏全屏时在底部上滑退出。
6. 点击或长按命中的弹幕，打开复制和屏蔽菜单（两个开关默认开）。
7. 返回键层级：弹层 → 全屏或剧场 → 普通 → 离开；Esc 走同一条链。
8. 应用内小窗：有弹层时隐藏；手机上第一次点击显示控件，再点回到直播间；只有在有画面且没有加载错误时才转为小窗。
9. 切换画质和线路不重建播放器，以最后一次选择为准。
10. 进入直播间不改设备音量（全局静音除外）。
11. 强制横屏全屏退出后恢复竖屏（手机）。
12. 可选的“默认全屏”：进入直播间后自动全屏。
13. 多画面：四宫格等布局中点格子切换声音焦点；一大多小中点小格晋升为大画面、点大格显示控制；长按或右键打开格子菜单；点空格选直播间。
14. 卡片长按或右键 = 操作菜单。
15. Windows：在新窗口打开直播间；小窗可选置顶。
16. 键盘：Space 和媒体键暂停，R 刷新，↑↓ 音量 ±5%，Esc 链。
17. 回到前台时识别剪贴板中的分享口令（兼容旧格式）。
18. 定时关闭。

## 7 性能约束对设计的影响

依据：BASELINE（Windows 首页空闲私有内存 481 MB，一个直播间 801 MB，3 格多画面 1054 MB；Android 直播间 PSS 462 MB，其中原生堆约 157 MB、图形约 145 MB）和 PLAN §10。

1. **视频上方不用模糊，也不常驻会开离屏层的效果**（BackdropFilter、Opacity、ShaderMask、ColorFilter）[R48]。PLAN 说的“避免半透明图层”指的是离屏层；直接画半透明颜色（渐变遮罩、纯色面板）可以用。落到设计上：控制层下面是黑色线性渐变；全屏聊天浮层是 70% 黑纯色；小窗和菜单不用毛玻璃。唯一的例外是控制层淡入淡出：只在 200 ms 的动画期间对控制层整体用一个透明度层，完全显示或完全隐藏时不带透明度层（隐藏时不绘制）。
2. **整个应用都不用模糊背景**，包括导航栏和顶栏：滚动时每一帧都要重算模糊。用不透明的表面色，滚动后换一档色调。
3. **视频、弹幕、控制层各自隔离重绘**（各自一个 RepaintBoundary）。控制层的淡入淡出和自动隐藏不能让视频层或弹幕层重绘；人数等高频字段单独订阅，不让整页重建（诊断 03 ③-4）。
4. **视频不圆角、不裁剪、不加边框阴影**。多画面格子之间用 2dp 黑色间隙；声音焦点用 2dp 描边加扬声器图标表示（不只靠颜色）。
5. **画面尺寸变化的动画只做合成层变换**，结束后再按新尺寸通知内核；看不见或被完全覆盖的画面暂停解码；多画面小格自动降画质，默认开启（旧版默认关闭）。
6. **列表**：卡片固定高度，但高度按当前文字缩放算出，不写死常数；封面按显示尺寸解码（`cacheWidth` = 显示宽度 × 像素比）[R49]；平台图片 CDN 支持尺寸参数的，请求接近显示尺寸的图（具体写在各平台的 `spec/sites/*.md`）；限制图片缓存的总大小。
7. **未开播的关注不加载封面**（改用头像行）：少解码、省内存，也不会显示过期的封面。
8. **骨架屏是静态的**，没有扫光；加载指示器只在可见时运行；没有常驻的循环动画，静止的界面可以降刷新率。
9. **不做全屏礼物特效，不做人数滚动动画**；表情按需下载，按 20–24dp 解码。全屏闪烁效果还可能违反 WCAG 2.3.1（每秒闪烁不超过 3 次）[R50]。
10. **弹幕样式只提供描边，不提供模糊阴影**；透明度用文字颜色的 alpha 直接绘制，不用 Opacity 包住弹幕层。
11. **圆角用装饰的 `borderRadius`，头像用图像填充的圆形装饰**，不用 ClipRRect 或 ClipOval 包住图片 [R48]。
12. **播放器只有一份**：小窗、画中画和直播间共用同一个播放器和同一个弹幕引擎（旧版每个直播间有两个弹幕引擎）；同一时间最多一个预览播放器。
13. **多画面的默认最大格数**按设备内存和硬件解码能力决定，超出时提示，而不是悄悄卡顿。
14. **阴影只用于浮层**，卡片用色调层级表示层次。
15. **Windows 不用 Mica 和亚克力**；Impeller 在 Windows 上有已知的性能问题（flutter#191353，见 PLAN §18），视觉效果越简单越稳。
