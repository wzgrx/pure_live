# E01.2 斗鱼

- 日期：2026-09-28
- 目标：`packages/live_core/lib/src/sites/douyu/`（`douyu_api.dart` 纯解析和签名，`douyu_site.dart` 请求编排）
- 样本：`fixtures/douyu`，29 个真实接口录制，另有签名向量（S07）和续期向量（S12）两组合成样本，来自归档。每个录制样本附有 v3 解析器的冻结输出 `expected.json`。弹幕样本 `danmaku/S13-live` 一并复制，留给 D01。
- 参考：
  - 归档 v4 的斗鱼适配器和规格（`spec/sites/douyu.md`，其中 27 条回归条目 REG-DOUYU-001～027）；
  - pure_live_TV `9fb40418`：续期提前量改为最多 90 秒、登录后可选“强制续期”，续期结果直接替换 Cookie，弹幕去掉了几处修复。只核对，没有采用，原因见下文；
  - 2026-09-28 的实机探针：靓号、别名、分享页的跳转，以及新适配器从分类到取流的完整链路。

按 E01.1 的做法：解析写成纯函数，请求编排单独一层，用样本对照 v3 的输出，差异逐条说明。

## 做法

- **接口和输出沿用 v3**：`LiveSite` 和 v3 实现过的全部可选能力（关注刷新、录制详情、画质确认、恢复取流、录制游标、续期时间），外加 `LiveSiteLinks`。3.x 的 JSON 不变。
- **签名、请求头和会话按 v3 的 `DouyuUtils` 重写**：
  - 一个请求链只用一个设备号（DID）：登录 Cookie 里有 `dy_did` 就用它，否则每个适配器随机生成一个。描述符请求、签名表单和 Cookie 三处一致；
  - 描述符按秒比较有效期，提前 30 秒作废，最多复用 5 分钟，换了 DID 立即作废，并发请求只取一次；
  - 取流请求最多两次：第一次失败后续期登录（能续的话），第二次强制换新描述符；
  - 登录 Cookie 由构造参数注入的 `CookieVault` 提供；续期需要的 LTP0、单独保存的 `dy_did` 和保存时间由注入的 `DouyuLoginStore` 提供，续期后写回。适配器不读全局设置。
- **v3 的“列表和搜索走 v4 桥接”**：v3 最后的代码里，斗鱼的分类、分区、推荐、搜索和别名链接都经由桥接走归档 v4 的适配器（ADR 0012，3.3.x 取消发布）。这里统一重写，桥接修过的问题（标题实体、轮播状态、别名解析、按服务端信号判断末页）保留，桥接为了适配 v4 模型做的改动（热度转成数字）不保留。
- **取流结果由线路组成**：每条线路带地址、FLV 格式、CDN 码、v3 播放层的斗鱼请求头（Origin、房间 Referer、UA、DID Cookie），以及 `PlayLease`：
  - 地址里 `expire` 大于 0 才有租期，从发起请求前的本地时间算起；
  - 提前 `min(45 秒, 租期的四分之一)` 续期，300 秒的租期在第 255 秒续；
  - `cutsConnection: true`：到期时 CDN 会断开已建立的连接，续期拿到的新流要按关键帧拼接进来（G）。
  
  `LivePlayLeaseMetadata` 仍然实现，按地址查到同一份租期。

## 与 v3 的有意差异

| # | 差异 | 原因 |
|---|---|---|
| 1 | 房间号保持请求时的地址，真实房间号放进 `DouyuRoomData`，签名、取流、Referer、弹幕都用真实房间号 | v3 详情返回 `room.room_id`。用靓号或别名打开的房间，刷新时身份会变，关注合并失败 |
| 2 | 靓号和别名都能打开（问题 1）：数字先请求 `betard`，不认识再读房间页；非数字先读房间页的 302 | v3 的靓号链接必然失败；别名在 v3 只有链接工具经桥接能解析，详情不行 |
| 3 | 识别分享页 `www.douyu.com/room/share/<号>` | `betard` 自己返回的 `room_url` 就是这种地址，301 到 `/<号>`（2026-09-28 探针）。v3 把 `room` 当成别名去请求 |
| 4 | 标题、简介、名字解码 HTML 实体 | 问题 5 |
| 5 | 搜索里的轮播房间是回放 | 问题 6。沿用已有的“回放”状态，界面不变 |
| 6 | 出错抛类型化错误，不返回出错快照 | 问题 2、3、9 |
| 7 | H5 接口 `error != 0` 不重试 | 问题 4 |
| 8 | 空关键词不发请求，直接返回空列表 | v3 发出去，平台回“kw不能为空”，界面报错 |
| 9 | 线路自带请求头和租期 | 见“做法”。v3 的请求头在播放层，租期要另外查询 |
| 10 | 缺失的图标、头像、简介为空 | 问题 7 |
| 11 | 分区和推荐请求带 API 请求头和 DID Cookie | 与 v3 的桥接一致；v3 旧代码只发 `Dart/…` 的 UA |
| 12 | 空令牌不算登录 | 问题 10 |
| 13 | 取流失败后只在第一次失败后强制续期；签发时间取发出成功那次请求的时刻 | v3 每次失败都续期一次（失败两次就续两次）；签发时间取在续期、换描述符之前，最多早了几秒，租期因此提前到期。新取法仍早于服务端签发，不会晚 |

保持 v3 行为、没有采用归档 v4 或上游做法的地方：

- **房间号不换成规范房间号**。归档规格要求“收藏键、Referer、弹幕全部使用规范 rid”，但那样用靓号关注的房间身份会变，理由同 E01.1 的短号。
- **续期提前量 45 秒**。上游改成最多 90 秒（300 秒的租期提前 75 秒），理由是给“取新地址、连接、读到关键帧”留余量；没有实测数据说明 45 秒不够，先按 v3，等 G 的拼接实测后再定。
- **不采用上游的“登录后强制续期”**：登录后的地址是 `expire=0`，上游在 Cookie 页加了开关，打开后按 5 分钟续期。这是新的界面选项，列为后续候选。
- **自动续期仍在适配器里**：取流前登录不到一天就续，取流失败后强制续一次，和 v3 一样。归档 v4 改为应用启动时和每 6 小时检查一次，失败后不再补续，没有采用。上游把续期结果直接替换整个 Cookie（LTP0 丢失，下次再也续不上，REG-DOUYU-023），不采用。
- **`【回放】` 开头的标题仍算未开播**（只有 `videoLoop == 1` 算回放）。规格要求算回放，但没有样本，v3 的测试也固定了现在的行为。
- **搜索热度保留平台文字**（`353.9万`）。桥接转成了数字；界面按数字和文字显示的结果相同，排序也都能解析。
- **UA 沿用 v3**：API 和媒体用 Chrome/128，`betard` 用 Edge/114。归档 v4 统一换成 Chrome/140。
- **签名的设备号只看 Cookie 里的 `dy_did`**，单独保存的 DID 只用于续期（规格待确认第 16 条）。
- **多个线路按顺序逐个签名**，不并发；线路身份是请求的 CDN 码，不改成响应的 `rtmp_cdn`（规格待确认第 6 条）。
- **保留 `searchAnchors`**。规格说它没有调用方，但 v3 有，搜索页以后可能用到。
- **进房前的历史醒目留言仍为空**（`getSuperChatMessage` 用基类的默认实现），和 v3 一样；醒目留言只从弹幕来（D01）。

## 回归条目的覆盖

REG-DOUYU-001、003～016、022～027 都有测试或实现直接覆盖：

- 001 租期（`expire=300` 提前 45 秒、`cutsConnection`）；
- 003、004 DID 一致、账号的 `dy_did` 优先、LTP0 不发给取流接口、403 的类型；
- 005～011 画质顺序、按确认档位分组、未确认档位、CDN 基址、绝对地址、实体、恢复时重新签名；
- 012、013 详情失败抛出、录制只签当前线路；
- 014 播放和录制共用线路上的请求头；
- 015、016 描述符按秒计时和合并请求、纯 Dart 签名；
- 022～025 令牌类型和保存时间、合并保留 LTP0、没有 Set-Cookie 不算续期、识别 passport Cookie；
- 026、027 热度口径、显示服务端确认的档位。

不在本模块：

- 002（多画面的恢复次数）在 G。014 里“CDN 返回 4xx 时重新取流”由播放和录制处理（G、H01.1）。
- 017～021 属于弹幕协议，在 D01。
- 025 的“粘贴 passport Cookie 不覆盖登录”是账号页的保存逻辑（M13），本模块提供 `DouyuApi.isPassportCookie`。

## 测试

89 个用例，`live_core` 共 265 个，连续跑 3 次全部通过：

- `douyu_api_test.dart`（56 个）：逐个样本对照 v3 的输出，有意的差异逐条断言；签名向量、续期向量；无样本的规则（移植 v3 的 `douyu_playback_parser_test`、`douyu_quality_ack_test`、`platform_signing_utils_test`、`douyu_cookie_session_test` 中固定行为的部分）；错误类型。
- `douyu_site_test.dart`（33 个），用样本回放加少量合成响应：
  - 分类、分区、推荐、搜索的请求和请求头，搜索每页条数，空关键词；
  - 详情：房间号保持、靓号经房间页换成真实房间号并记住、别名先读房间页、不存在、错误映射；
