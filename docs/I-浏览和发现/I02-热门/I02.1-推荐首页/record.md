# I02.1 推荐首页（热门）

- 日期：2026-10-01
- 目录：`apps/pure_live/lib/features/popular/`（`popular_page.dart` 页面和平台标签、`popular_grid.dart` 单个平台的列表、`popular_feed.dart` 取数和翻页、`popular_rooms.dart` 卡片数据和过滤、`pagination_bar.dart` 桌面页码栏、`room_menu.dart` 卡片菜单、`share_command.dart` 分享口令）
- v3 来源：标签 `v3.2.11` 的 `lib/modules/popular/`（4 个文件 541 行），以及它用到的 `common/base/`（`BasePageView`、5 种翻页控制器、桌面页码栏，约 2150 行）、`common/widgets/room_card.dart` 的菜单和关注按钮、`common/utils/share_command_handler.dart`、`plugins/share_command_handler.dart`（分享口令）

## 做法

- **服务**：照 I01.1 的“页面怎么取服务”。平台 `sitesProvider`，设置 `watchSetting`/`storeProvider`，跳转和提示 `AppNavigator`，后台回来的信号 `HomeSignals.resumedAfterBackground`。
- **数据放在 provider 里**：`popularCatalogProvider` 为每个平台保存一个 `PopularFeed`（取到的房间、是否还有、请求状态、桌面当前页），整个应用期间保留。首页外壳切换菜单时页面会销毁重建，数据不丢，也不重新请求（v3 用 GetX 控制器常驻做到这一点）。
- **取数（`RoomSource`）照 v3 按平台选择**：
  - 有原生目录的平台（`LiveSiteDirectoryPager`，游标平台用 `LiveSiteCursorDirectoryPager`）：按平台的页码或游标取，是否还有看平台的回答；
  - 固定窗口（v3 调好的大小）：斗鱼 40、虎牙 120、SOOP 60、TwitCasting 60、Twitch 100、网易 CC 100、抖音 20，回答不足一个窗口就是最后一页；
  - 一次取完：快手、网络电视（IPTV 保持播放列表原顺序，不排序）；
  - 其他平台：每次 30 个的固定页，空页结束。
- **一份目录，两种翻页**：取到的房间去重（按房间身份）后存成一份列表，每块按人数排序（v3 `rankPopularRoomsByAudience`，`LiveRoom.compareAudienceRanking`）。手机在列表末尾继续取；桌面的第 n 页就是这份列表的第 n 段，不够时再取。连续两块没有新房间、或一次加载超过 20 个请求就停（v3）。
- **刷新**先在旁边建新列表，成功后再替换；失败时旧列表留在屏幕上（v3 目录控制器的做法，推广到所有平台）。
- **隐藏不能播放的直播**（UPGRADES 统一原则）：设置 `showUnplayableInDiscover` 关时，隐藏轮播和受限房间（付费、订阅、私密、仅限 App、地区、加锁、不可播放；需登录和年龄限制只在该平台没有 Cookie 时隐藏）。隐藏的房间不计入每页数量。改设置立即生效，不重新请求。
- **卡片**：`LiveRoom` → `RoomCardData`（`AudiencePolicy.cardOf`）：人数按 `audience.dart`（`audienceValue`/`audienceType`，实时在线设置和平台列表），数字照 v3 `readableCount` 显示为“1.2万”/“1.2K”；只有直播中显示人数；受限类型和轮播写在 `restrictionLabel`；图片地址用 live_core 的 `normalizeImageUrl`；外观按设备取手机或桌面的卡片设置（预设或自定义），网格 2～5 列（v3 的宽度分界）、间距读设置。
- **页码设置**：每页条数 `page_default_size`（0 时按宽度 20/12，同 v3）、可选项 `page_size_options_raw`（JSON 或逗号分隔都认）、每页选择器和跳转输入框按设置显示。

| v3 | v4 |

| 手机：下拉刷新、上拉加载 | 有（上拉改为滚近底部自动加载，见界面改进） |
| 桌面：页码栏（刷新、上一页、页码、下一页、每页条数、跳转）、左右方向键翻页 | 有 |

| 空、出错、需要登录三种状态；有内容时顶部细进度条 | 有，出错文字改（问题 3） |

| 卡片点击进直播间；长按、右键打开菜单 | 有 |

| 标签：未关注时先提示并询问关注；选择标签、新建标签 | 有；新建只填名字，编辑、删除、描述在标签管理页 |

| 卡片外观、间距设置 | 有 |

## 界面改进

| 改了什么 | 为什么 |
|---|---|
| 平台标签从标题位置移到标题栏下方，占满宽度；标题栏显示“热门” | v3 手机上标签夹在菜单和右侧按钮之间，一次只看得到 3 个左右平台 |
| 标签栏末尾加“全部平台”按钮：底部弹出所有平台（带图标），一点直达，旁边是“平台显示”入口 | 最多 34 个平台，横向滑动找平台很慢 |
| 首次加载显示静态骨架卡片（不是整页转圈） | 看得出版式，切换平台不闪；不做每卡动画（v3 发现很耗电） |
| 刷新失败保留列表，顶部横幅写明原因，可重试或关闭；加载更多失败在列表底部重试 | 见问题 4 |
| 出错原因按种类说人话（网络、频繁、风控、Cookie 过期、地区、接口变化） | 见问题 3 |
| 卡片标出受限类型（付费、加锁、仅限 App、地区受限、需登录、订阅专属、私密、年龄限制、不可播放）和轮播 | UPGRADES 统一原则“卡片标出受限类型”、1-1 |
| 不能播放的直播默认隐藏，列表底部（或空状态）提示“已隐藏 N 个……”并有“显示”按钮（打开设置项） | 统一原则；隐藏要让用户知道并能一步改回 |
| 目录说明默认一行，点按展开 | 说明是次要信息，不挤占列表 |
| 列表不满一屏自动加载；底部显示“加载更多”或“没有更多数据了” | 见问题 5 |
| 没有平台时的空状态和入口 | 见问题 7 |
| 关注、取消关注后提示“已关注 xx”；菜单里显示分区和受限类型，房间号可选中复制 | 成功反馈；信息更全 |
| 跳转输入框按设置显示 | 见问题 2 |
| 改“优先实时在线”后，其他平台下次打开时自动刷新 | v3 只刷新当前平台，其他平台的顺序是旧设置排的 |

## 留给后续

| 内容 | 原因 / 去向 |
|---|---|
| 手机分享用系统分享面板 | 应用没有 `share_plus`，需要协调者加依赖；现在所有平台都复制口令 |
| 移动网络提示条、请求前的断网检查 | 应用没有 `connectivity_plus` |
| 列表显示开播时间（UPGRADES 7-9、10-3、25-12、33-7） | `live_ui` 的 `RoomCardData` 没有开播时间字段，要先在 live_ui 加 |
| 卡片映射、受限规则、卡片菜单、分享口令、取数和翻页的类（`AudiencePolicy`、`cannotPlayHere`、`showRoomMenu`、`encodeRoomShareCode`、`PopularFeed`/`RoomSource`）分区房间、关注、搜索、历史页也要用 | 现在放在本页目录；建议协调者移到共享位置（例如 `lib/common/`），`popular_restriction_*` 等键随之改成通用前缀 |
| 分区页共用的 `*_directory_scope` 原文改写 | 共享键，留给分区页 |
| 标签的编辑、删除和描述 | 标签管理页 |

另：`live_ui` 的 `PureLiveScrollPhysics` 放在别的物理效果里当 `parent` 时没有边界（可以无限滚出内容），要放在最外层，例如 `PureLiveScrollPhysics(parent: AlwaysScrollableScrollPhysics())`。
