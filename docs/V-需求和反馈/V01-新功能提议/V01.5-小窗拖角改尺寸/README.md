## 目标

应用内小窗（离开直播间时在首页角落继续播的那个）现在大小固定：手机上宽 220（屏幕短边 × 0.56，限制 220～360），不能改；看的时候想大一点只能回直播间。系统画中画在 Android 上可以用两指拉大，但拉大后飞的弹幕不跟着变大（缩放上限 1.0），显得很小。提议：

1. 应用内小窗右下角拖动改大小，记住上次的大小（c1、c2）；
2. 设置里加“小窗大小”（c3）；
3. 小窗和画中画放大时弹幕跟着按比例变大（c4，其实是现有行为的修正，可以先单独做）。

## 评估结论和设计（定稿，2026-10-09）

做不做已由 D-036 定了（同意做，第三档；新设置默认让老用户感觉不到变化）。下面是补完的评估和维护者按 D-003 选的方案（用户随时可以推翻）；实现任务是 [A07.22](../../../A-界面设计/A07-直播间界面/A07.22-小窗改大小和尺寸设置/README.md)（c1～c3），c4 已由 [D03.3](../../../D-弹幕/D03-飞行弹幕引擎/D03.3-小窗和画中画的弹幕/README.md) 做完（待真机）。

### 上游怎么做的（读过的提交）

- pure_live `f9e03f446`：应用内悬浮窗交给 media_core 的 `FloatingWindowOverlay`，打开 `resizableByDrag`：右下角一个 30×30 的把手（半透明黑底、`⌟`），拖它改大小、拖画面移动；按钮改成触屏点一下出 3 秒、鼠标悬停出（4.x 的 A07.8 c2 已经是这样）。把手的写法有个毛病：`resizeTo` 用的是“开始时的大小 + 这一帧的位移”，不是累计位移，所以拖一路只长最后一帧那几个像素（media_core `~/ref/media_core/packages/media_core_floating/lib/src/floating_window_overlay.dart:278-296`）。
- media_core `7319d2d`、`c073f52`：四条边、四个角都能拖（`FloatingResizeHandle`，默认仍只有右下角），改大小时对边不动、保持画面比例；随后把把手改成看不见的触控区。上边的触控区让开右上角的按钮。
- pure_live `e437b5bd8`、`dc7298500`、`a25facd94`：记住位置和大小，按直播流的方向（横屏流、竖屏流）各记一套，存成一个 JSON 设置 `floatWindowGeometry`（应用表面里的像素坐标）。
- pure_live `582e355f7`：Windows 画中画的“基准尺寸、最小宽、最小高”三个滑条（Windows 画中画驱动的，和应用内小窗无关）。
- pure_live `b2cca41c7`：小窗弹幕缩放上限 1.0 → 2.0；`2ee3ee8fd` 又把小窗弹幕的倍率钳回 0.4～1.0（“小窗比房间画面小，弹幕不该更大”），同时修了它自己设置页写错对象、改了不生效的问题。

### 4.x 现在（改之前）

- 应用内小窗：`apps/pure_live/lib/features/live_play/mini/floating_window.dart`，大小 `features/live_play/logic/mini_window.dart` 的 `inAppMiniSize`（A07.8 c6：短边 × 0.56，220～360；竖屏画面高 1.2 倍、宽至少 120），位置 `inAppMiniOffset`（默认右下角，离边 16，手机首页在底部导航栏上面 16）。拖动只改位置（`MiniPlayerSurface` 的 `onPan*`），不能改大小，没有大小设置。
- 小窗弹幕按窗口宽度缩放（`CompactDanmakuMetrics`，D03.3 以后上限 2 倍），所以小窗变大以后弹幕自然跟着变大，不用另做。
- 系统画中画的大小由系统定（两指拉大是系统的），桌面小窗已经能拉边改大小（A07.8 c1）：都不在这次范围。
