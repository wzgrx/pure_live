# W 上游借鉴

跟踪 3.x 作者 liuchuancong 的五个上游仓库的更新，逐条对照 4.x：上游修好的、4.x 也有的问题开成任务修掉，可借鉴的新功能进 V01 提议，不适用的写清原因。这一组自己不写代码，只出对照记录和任务。排在 V 需求和反馈之后：它和 V 一样是“新工作的来源”，但来自上游而不是用户。

## 范围

- 管什么：
  - **定期对照**（W01）：每周一次（D-027），拉取五个上游、从上次看到的提交接着看、逐条判断四类（4.x 也有的问题、可以借鉴、已经有、不适用）、写对照记录（每次一个 W01.n）、登记任务。
  - **参考仓库**（W02）：五个上游和 v4 存档、3.x 只读副本的清单、本机位置、许可证、怎么更新；主仓库的远程 `upstream`。
- 不管什么（归哪里）：
  - 对照出的修复 → 目标组（例如 H01.5 录制、E05.3 平台模型、A07.15 直播间手势、G02.2 播放、O06.1 返回手势）。
  - 可借鉴的新功能 → [V01 新功能提议](../V-需求和反馈/V01-新功能提议/README.md)（D-026、D-027），用户确认后才做。
  - 不适用、决定不做的 → [V04](../V-需求和反馈/V04-不做的/README.md)（例如 Anime4K）。
  - 照搬上游的新架构（上游把播放换成 media_core、用 GetX 路由）：不做，只借鉴修复的思路和行为（PROCESS 第 9 节第 5 条）。

## 风险和注意

- **只读上游**：不往上游推送（`upstream` 现在的推送地址也是上游仓库，建议关掉）；`~/ref/` 的副本只拉取不改。
- **不拉标签**：`git fetch --no-tags upstream master`，上游的 `v3.x` 标签可能和本仓库的同名标签指向不同提交。
- **许可证**（PROCESS 第 9 节第 5 条）：借鉴 AGPL-3.0 的代码，提交里注明来源仓库和提交；MIT 的保留版权声明。对照记录只写思路和位置，不贴大段代码。
- **不照搬架构**：上游 2026-10 前后把播放全部换成 media_core，随后修的一串“进直播间黑屏、切清晰度卡住、小窗回直播间崩溃”是它新架构的问题，4.x 不适用（W01.1）。判断“4.x 也有”时一定要在 4.x 代码里找到对应位置。
- 新功能不直接做：进 V01，用户确认后在目标组开任务（D-026）。
