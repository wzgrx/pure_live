# Firebase 认证控制器与会话同步审计（2026-09-12）

## 范围与基线

- 基线：`da8452a9a7c81914ea7105cb52afc9c6be8e6543`。
- 范围：Firebase SDK 初始化、认证状态监听、登录完成接线、权限/角色读取、自动配置恢复、上传/下载身份边界及备份页状态文案。
- 本轮只做源码、确定性单元/Widget 回归、静态分析与仓库审计；未连接手机、访问真实 Firebase、修改账号数据、构建安装包或发布版本。

## 复现与根因

加入不改变既有结果的认证后端接缝后，有效红测为 **0/6 PASS**：

1. SDK 初始化被 `firebase.google.com` 营销网站探测阻断；该网站超时并不能证明 Auth/Firestore 服务不可用，反而会让有效配置停在初始化失败页。
2. 已登录用户在初始快照同步完成后仍依赖认证流再次回放才进入 ready，流回放缺失或延迟时页面会长期保持未就绪。
3. 初始用户与认证流的同一用户事件分别下载权限和配置，登录页又手动重复相同流程，一次登录可产生多轮同步与提示。
4. 初始化重试直接覆盖订阅句柄，旧监听仍然活动；后续每个认证事件会被重复处理。
5. 空 UID 用户事件被直接忽略，旧登录身份、角色与上传权限继续留在界面状态中。
6. 控制器在初始化等待期间退出后，迟到任务仍会初始化 SDK、建立监听并更新已关闭控制器。

代码复查还确认：`FirebaseManager.getInstance()` 每次都会创建新对象；权限/角色集合在请求完成前就清空，旧账号迟到结果可覆盖新会话；自动恢复遇到已有用户文档但没有 `config` 时会把空配置当异常；登录日志包含邮箱和 UID。

## 修订

- 初始化直接以 Firebase SDK 结果为准，营销网站探测只保留为显式诊断入口；连接和失败文案同步改为真实的“初始化”语义。
- 控制器增加生命周期代次、身份代次和唯一认证订阅；重试先等待旧订阅取消，退出立即使初始化、流事件和同步收尾失效。
- 初始快照、认证流回放与登录页完成回调共用同一用户事务；同身份在途同步合并，成功身份不重复同步，失败的可选同步保留后续重试机会。
- 空用户和空 UID 统一按退出处理，清理当前用户、角色和上传权限；初始已登录用户无需等待流回放即可进入 ready。
- 登录页只把认证用户交给控制器并等待同一同步任务，不再自行重复读取权限/下载配置；诊断日志移除邮箱和 UID。
- `FirebaseManager` 改为进程级稳定单例，并合并 SDK 初始化任务；权限、角色和可见性先构建本地快照，仅在请求用户仍为当前身份时一次提交。
- 自动配置恢复按预期用户校验身份，自动路径静默处理“没有云端配置”；JSON 字符串与 Map 共用严格解析，标量/列表保持损坏数据错误。上传事务及下载恢复在关键异步边界重新核对身份。
