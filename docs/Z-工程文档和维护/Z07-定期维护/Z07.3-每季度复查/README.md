## 方案

- c1 检查清单（写进本 README，每季度照做）：
  1. DECISIONS：每条读“依据”，看现在还成立吗；不成立的加新条“取代 D-xxx”，旧条状态改“被取代”（PROCESS 第 13 节，维护者改）。
  2. 规则：PROCESS、ENGINEERING、UI、AGENTS.md、`docs/README.md` 里写的路径、命令、包名、版本、节号是否和仓库一致（可以先跑 `python3 tools/docs/docs.py --check`，再人工看它查不到的：章节号、命令、包名）。
  3. 任务：`docs/tasks.toml` 里没完成的，按档位找出超过期限没动的（`git log -1 --format=%ad -- <任务文件夹>` 看最后一次改动），每个写建议：留、降档、拆小、不做（不做的移到 V04 并写 DECISIONS）。
  4. 子分类：没有任务的、长期没动的，确认范围说明还对。
  5. 文档版本：这一季度有没有结构变化，CHANGELOG 和标签是否补上（D-028）。
- c2 第一次做（2026-12 底）：按清单走一遍，结果写进 `record.md`；把上表“已知的”不一致逐条处理（改不了的开任务）。
