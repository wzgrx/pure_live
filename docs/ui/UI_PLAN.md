# 界面与布局重构计划书

- 日期：2026-10-01
- 状态：已确认（2026-10-01）。逐个界面的设计以 `docs/ui/compare/<编号>/README.md` 为准；第一个确认的是 [U.2a 竖屏直播间](compare/U.2a/README.md)
- 范围：手机、平板、Windows、Linux 的全部界面；电视模式（M14）作为单独一组
- 配套文档：`docs/ui/V3_UI_INVENTORY.md`（v3 界面清单与审查，逐步补全）、`docs/PLAN.md`（总计划和模块流程）

---

## 1. 背景

### 1.1 现状

M13 的 18 个页面任务按“界面可以自行设计改进”的授权写成，并行开发，没有逐个控件对照 v3，也没有对比图审核环节。结果：

- **直播间偏差最大**（对照见清单第 5 节）：
  - 竖屏时画面上栏不显示，纯音频、投屏、小窗被挪到下栏；
  - 下栏没有关注胶囊、弹幕设置、方向、画面比例，弹幕开关换成了字幕图标；
  - 信息行从 v3 的一行变成两行，挤在一起；
  - 顶栏菜单图标、录制按钮和 v3 不同；
  - 弹幕列表的样式也改了。
- **图标普遍不一致**：v3 每个位置用的图标是固定的（193 种 Remix、182 种 Material、几个自带的 CustomIcons），v4 大多换成了别的 Material 图标。
- **布局细节各页各写**：同类元素（顶栏按钮、空状态、标签栏）在不同页面长得不一样。

### 1.2 根因

1. 任务说明允许重新设计，但没有要求“先还原 v3，再列出改动请用户确认”。
2. 没有统一的图标入口和组件约束，每个页面自己挑图标、自己写状态页。
3. 没有界面级的测试固定控件的顺序、图标和位置，偏差没有被发现。
4. 用户看到成品时已经写完，返工成本高。

### 1.3 v3 自身的问题（审查要修的，详见清单）

- 结构：整页 `Obx` 重建、`Get.width` 判断布局（窗口缩放时不跟随）、`AppTextStyles` 和主题字号两套并存、颜色硬编码白和 `grey[900]`。
- 界面：直播间下栏在手机上放不下靠横向滚动、关注入口在同屏重复两处、主播名和平台分区字号相同没有主次、弹幕列表每条一张带边框的卡片导致密度低、平台标显示平台 id 大写、常用的“历史记录”藏在菜单里、同一个图标在不同位置表示不同含义。

## 2. 目标

1. **以 v3 为基线**：界面、布局、操作逻辑、功能以 v3 为起点（`docs/PLAN.md` 第 1 节）。
2. **修掉 v3 的问题**：每个问题写清根因和位置，在重构里修。
3. **优化、完善、增强**：每一项都在对比图里列出，经用户确认后才做。
4. **流畅**：K90 上 120 赫兹时 99% 的帧在 8.3 毫秒内；Windows 144 赫兹同样；没有连续掉帧。
5. **多平台、多形态**：手机、折叠屏、平板、Windows、Linux 的任意窗口尺寸，触摸、鼠标、键盘都好用；电视用遥控器能完成全部操作。
6. **好维护**：外观集中一处，页面按功能分目录、和 v3 一一对应，界面测试固定关键布局。

## 3. 调研结论

### 3.1 Flutter 官方指南

- **架构**：界面层分“视图”和“视图模型”（逻辑放在视图模型，视图只负责显示）；中大型应用推荐按功能组织目录（feature-first）。
  - 来源：[Guide to app architecture](https://docs.flutter.dev/app-architecture/guide)、[Architecture case study](https://docs.flutter.dev/app-architecture/case-study)。
- **自适应布局**：
  - 按可用宽度决定布局（`MediaQuery.sizeOf`、`LayoutBuilder`），不要用设备方向切换布局；
  - 分档：紧凑 <600、中等 600–840、宽 ≥840；
  - 要支持鼠标、触控板、键盘快捷键，触控目标够大，键盘能导航。
  - 来源：[Adaptive and responsive design](https://docs.flutter.dev/ui/adaptive-responsive)。
- **性能**：
  - Impeller 自 3.27 起是默认渲染器，着色器提前编译，基本消除首次卡顿；
  - 掉帧主要来自绘制阶段：复杂自绘、过多半透明合成、不必要的 `saveLayer`；
  - 基本功：`const`、懒加载列表、`RepaintBoundary` 隔离独立更新的区域、图片按显示尺寸解码（`cacheWidth`/`cacheHeight`）、重活不在界面线程、靠 profile 测量而不是猜。
  - 来源：[Why Flutter apps drop frames](https://www.appsonair.com/blogs/why-flutter-apps-drop-frames-and-how-to-fix-it)、[How to optimise your Flutter app (2026)](https://foresightmobile.com/blog/how-to-optimise-your-flutter-app)。

### 3.2 Material 3 窗口尺寸分档

- 宽度分五档：紧凑 <600（几乎所有竖屏手机）、中等 600–840（竖屏平板、展开的折叠屏）、宽 840–1200（横屏平板）、大 1200–1600、特大 ≥1600（桌面）。
- 高度分三档：紧凑 <480（横屏手机）、中等 480–900、宽 ≥900。
- 宽度比高度更重要（内容多是竖向滚动）。
- 来源：[Window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/window-size-classes)。

### 3.3 Android 刷新率和视频帧率

- **帧率 API**：Android 11 起，应用可以告诉系统想要的帧率（`Surface.setFrameRate()` 等）。
  - 视频播放时传准确帧率（29.97 不要四舍五入成 30），兼容性标记用 `FRAME_RATE_COMPATIBILITY_FIXED_SOURCE`；
  - 有的设备切换刷新率无缝，有的会黑屏约一秒，可以要求“只在无缝时切换”；长时间的视频可以接受不无缝的切换；
  - 暂停或播完时传 0 清除。
  - 来源：[Frame rate](https://developer.android.com/media/optimize/performance/frame-rate)、[Match content frame rate（电视）](https://developer.android.com/training/tv/playback/framerate)。
- **高刷**：Flutter 应用默认不会主动请求屏幕的最高刷新率，系统会给较低的档位；需要应用自己请求（v3 和 v4 已在 `MainActivity` 里做）。
  - PiliPlus、Kazumi 用 `flutter_displaymode` 让用户在设置里选一个固定的显示模式；
  - v3 的“均衡”策略（交互时高刷、停下回落）比它们更细，保留并增强。
  - 来源：[flutter_displaymode](https://pub.dev/packages/flutter_displaymode)、[Flutter 120Hz 调研总结](https://juejin.cn/post/7081273509690736653)。

### 3.4 电视（10 英尺界面）

- 四边留出安全边距（左右 48、上下 27，约屏幕的 5%），必须一直可见的元素放在里面。
- 每个页面有明确的默认焦点，所有元素都能用方向键到达，焦点状态清楚。
- 字大、对比高、元素少、间距大。
- 来源：[Build TV layouts](https://developer.android.com/training/tv/playback/compose/layouts)、[Build adaptive apps for TV](https://developer.android.com/develop/adaptive-apps/guides/tv/build-adaptive-apps-for-tv)。

### 3.6 impeccable 设计规范中适用的部分

参考 [pbakaus/impeccable](https://github.com/pbakaus/impeccable)。本应用是“操作型”界面（Operate 模式），适用的规则：

1. **一致的组件词汇**：同一个动作在各处长得一样（v3 的关注按钮就有两种样子）。
2. **每个交互组件的状态都要有**：默认、悬停、焦点、按下、禁用、加载、出错。
3. **加载用骨架屏**，不要在内容中间转圈；**空状态告诉用户下一步能做什么**，不只写“没有内容”。
4. **动效只表达状态变化**：常规 150–250 毫秒；不做装饰性动画，不做开场编排。
5. **对比度**：正文至少 4.5:1、图标和控件至少 3:1；彩色背景上的次要文字不用灰色。
6. **Android 规范**：触控目标至少 48×48，间距至少 8；系统返回和预测返回始终可用；内容避开状态栏、导航栏、刘海和键盘；暗色是独立设计的一套，不是简单反色。
7. **要避免的通病**：千篇一律的同尺寸卡片网格当页面结构、卡片套卡片、渐变文字、装饰性毛玻璃、彩色粗边框条、用 emoji 或 Unicode 字符代替图标。

之前试做的三个“新风格方向”效果图（影院、转播、平台变色）不再采用。

来源：归档分支 `archive/v4` 的 [`docs/rewrite/PLAN.md`](https://github.com/wzgrx/pure_live/blob/archive/v4/docs/rewrite/PLAN.md) 第 07 节（信息架构与操作逻辑）、08 节（多尺寸动态适配）、09 节（视觉系统与美术）、10 节（性能极致优化），以及第 2 阶段定稿的 `spec/design/principles.md`（本机 `~/ref/pure_live_archive/spec/design/`，含 157 组对比度检查 `tokens.json`、`contrast-report.txt`）。归档 v4 是“另起炉灶、重新设计界面”的方案，用户已改为以 v3 为基线，所以分两类处理：

- **直接采用**（不改变 v3 的布局和操作，只提高质量）：

  - 直播间展示状态只有一个枚举，视频画面只挂载一个、切换时移动不重建（第 8 节）；

- **和 v3 不同的改动，列为候选，逐条请用户确认**（第 15 节）：
  - 信息架构合并（“发现”“我的”）；
  - 图标统一为 Material Symbols；
  - 新品牌蓝和纯黑主题；
  - 字号合并为一个“文字大小”；
  - 卡片去掉头像；
  - 双指缩放代替比例按钮、长按画面出快捷面板；
  - 竖屏上下滑换台、剧场模式等。

## 4. 设计原则（做决定时按这个顺序）

1. **v3 的功能和操作习惯不能少**：入口位置、操作方式、手势、快捷键、设置项都保留，3.x 的设置照旧生效。
2. **v3 的布局和图标是默认答案**：控件的位置、顺序和图标照 v3；要改，必须在对比图里列出理由并经用户确认。
3. **修 v3 的问题**：截断、溢出、对比度不够、点击区域太小、同屏重复、状态不清、宽窄屏错乱，以及结构问题（整页重建、硬编码颜色、按设备型号判断布局）。
4. **补全缺的状态**：加载、空、出错、受限、离线、权限被拒，各界面统一用 `live_ui` 的状态组件。
5. **增强只做有明确收益的**：信息更清楚、操作更少、更流畅；不做为好看而改的风格变化。
6. **同一件事全应用只有一种做法**：一个动作一个图标、一个组件、一套文字。

## 5. 代码结构（已确认）

### 5.1 目录

| 位置 | 放什么 | 对应 v3 |
|---|---|---|
| `packages/live_ui/lib/src/theme/` | 颜色角色、字号角色（对应 v3 字号设置）、间距、圆角、阴影、动效时长，深浅两套 | `lib/common/style/` |
| `packages/live_ui/lib/src/icons/` | 图标统一入口 `AppIcons`：按用途命名（关注、弹幕开、小窗……），底层是 v3 在该位置用的 Remix / Material / CustomIcons / 弹幕 SVG | 各页面散用的 `Remix.*`、`Icons.*`、`CustomIcons.*`、`assets/images/video/*.svg` |
| `packages/live_ui/lib/src/widgets/` | 通用组件：房间卡片、头像、状态页、标签栏、分页、设置行、按钮、对话框和底部面板外壳、骨架屏 | `lib/common/widgets/` |
| `apps/pure_live/lib/features/<功能>/` | 由 `pages/` 改名，目录名和 v3 的 `lib/modules/<模块>` 相同 | `lib/modules/<模块>/` |
| `features/<功能>/<功能>_page.dart` | 入口页面 | `pages/*_page.dart` |
| `features/<功能>/logic/` | 视图模型（控制器）、状态、纯逻辑；不引用界面组件，可以单独测试 | `controllers/`、`states/` |
| `features/<功能>/widgets/` | 本功能的界面块；大功能按 v3 再细分（直播间：`layout/`、`player/`、`danmaku/`、`buttons/`） | `widgets/<子目录>/` |
| `features/<功能>/dialogs/` | 本功能的对话框和底部面板 | `dialogs/` |
| `apps/pure_live/lib/shared/` | 跨功能、依赖应用服务的界面块（卡片长按菜单、分享、分页取数） | `lib/common/utils/` 等 |
| `apps/pure_live/lib/tv/` | 电视外壳和页面，同样按功能分目录；逻辑复用 `features/*/logic/` | （pure_live_TV） |
| `apps/pure_live/test/features/<功能>/` | 测试和代码目录对应；外观截图测试放 `test/goldens/` | `test/modules/` |

### 5.2 门禁新增的检查

1. 功能目录之间不互相引用内部文件，只能通过路由、`shared/` 或 `live_ui`。
2. `features/` 和 `tv/` 里不直接写颜色值（`Color(0x…)`、`Colors.*`）和图标常量（`Icons.*`、`Remix.*`），一律走 `live_ui` 的主题和 `AppIcons`；视频上的白色控件等少数例外用主题里的固定角色（例如“画面上的前景色”）。
3. `logic/` 里不引用 `package:flutter/material.dart` 的界面组件。

### 5.3 迁移步骤

1. **U.0**：一次“只搬文件、不改行为”的提交：`pages/` → `features/`，直播间等大功能按 v3 子目录拆分，改 import，门禁通过后推送。
2. 暂停中的分支照新结构处理（见第 11 节）。

## 6. 设计系统（`live_ui`）

### 6.1 颜色

- Material 3，用户主题色作种子（默认蓝色，3.x 设置照旧），支持动态取色。
- v3 的问题：默认蓝 `#2196F3` 配白字对比只有 3.1:1，不满足正文 4.5:1；`fromSeed` 默认方案把主色压灰。候选修正见第 15 节 C-3（归档 v4 的 `#2E6FE0` + fidelity 方案，白字 4.7:1）。
- 语义色固定、不随主题变：“直播中”红底白字（`#D92D20`，4.8:1，必须带“直播”二字，不只靠红点）、录制中、成功、警告（归档 v4 已验算对比度）。
- 画面区域（播放器、全屏、多画面、画中画、小窗）在所有主题下都是黑底白字。
- 用角色而不是色值：表面（页面）、表面容器（低/中/高，用于卡片、面板、对话框）、主色、主色容器、轮廓、错误；深浅两套分别检查。
- 修 v3：卡片、弹幕行改用表面容器角色，不再硬编码白和 `grey[900]`。
- 画面上的控件（视频上的白色图标和文字）单独一组角色：前景白、阴影、渐变底，保证亮画面上也看得清。

### 6.2 文字

- 五个字号角色对应 v3 的五个字号设置（12、13、14、15、20），用户调整照旧生效；系统字体放大照常生效。
- 修 v3：`AppTextStyles.t12/t13…` 和主题字号两套并存 → 统一成主题角色，页面只用角色名（标题、正文、说明、标签）。
- 主次分明：同一处的主信息和次信息至少差一档字号或字重（例如直播间顶栏主播名和“平台 / 分区”）。
- 字重只用 400（正文）和 600（标题、强调）：微软雅黑只有细、常规、粗三档，500 会落回常规，层级就没了。
- 最小字号 12（Windows 规定常规字重最小 12px）；中文行高不低于字号的 1.4 倍。
- 人数、码率、时长、时钟、倒计时用等宽数字（`tabularFigures`），刷新时位置不跳；人数写成“1.2万”“3.4亿”，不做数字滚动动画。
- 画面上控制层的文字随系统放大最多 1.3 倍，避免挡住画面；弹幕字号单独设置。

### 6.3 间距、圆角、阴影

- 间距按 4 的倍数（4、8、12、16、24、32）；同组紧、组间松。
- 圆角沿用 v3：卡片 16（房间卡片的圆角跟随设置）、按钮 12、列表行 12、输入框 12、底部面板和对话框 24。
- 阴影沿用 v3 的“无阴影 + 表面层次”，需要浮起的（浮动按钮、悬浮小窗）用一种统一的阴影。

### 6.4 图标（`AppIcons`）

- 先从 v3 代码整理出“位置 → 图标”对照表（清单附录），`AppIcons` 按用途命名，每个用途对应 v3 在该位置用的图标。
- 需要的图标库：Remix（`remixicon` 包，v3 用的同一个）、Material 图标、v3 自带的 `CustomIcons.ttf`、`assets/images/video/danmu_*.svg`。
- 修 v3：同一个图标在两处表示不同含义的（`Remix.apps_2_line` 既是“分区”又是“直播间菜单”），在对比图里提出替换方案请用户确认。

- 画面上的控制层图标比列表里的粗一档、带阴影，保证亮画面上看得清。

### 6.5 通用组件（对应 v3 `lib/common/widgets/`）

房间卡片、头像、状态页（加载骨架、空、出错、受限、离线）、标签栏、分页、设置行（开关、选择、滑块、跳转）、菜单按钮、顶栏通用按钮、对话框和底部面板外壳、二维码。每个组件都有默认、悬停、焦点、按下、禁用、加载状态；电视下有焦点放大和描边。

### 6.6 动效

- 时长：即时反馈 100–150 毫秒，常规状态变化 150–250 毫秒，页面和面板切换 250–350 毫秒；退出比进入快。
- 曲线：减速曲线；不用回弹。
- 页面切换沿用 v3（Android、Windows 用 `FadeForwards`）。
- 跟随系统“移除动画/减少动态效果”：去掉位移，保留表示状态的淡入淡出。

## 7. 性能、流畅度和刷新率

### 7.1 刷新率策略

**v3 的做法**（`lib/common/widgets/adaptive_refresh_rate_scope.dart`、`display_mode_service.dart`，v4 已照搬）：

- 设置“界面刷新率”分三档：
  - 省电：交给系统；
  - 均衡：手指按下、滚动时切到最高刷新率，停下 1.5 秒后放回，避免一秒内反复切换造成掉帧；
  - 性能：一直最高。
- 进后台时释放；画中画时保持。

**增强**（每项写进对比图，用户确认后做）：

| 场景 | 策略 |
|---|---|
| 浏览页（滚动、切页、动画） | 保持 v3 的均衡策略 |
| 直播间播放中 | 按视频帧率选显示模式：30/60 帧选 60 或 120 赫兹（能整除的一档），25/50 帧（网络电视常见）选 50 或 100 赫兹（屏幕支持时）；Android 11 起对视频画面声明内容帧率（传准确值，`FIXED_SOURCE`），默认只在无缝时切换；暂停、退出直播间时清除 |
| 直播间里操作（拖面板、滚弹幕列表） | 临时高刷，停下后回到按视频帧率的档位 |
| 飞行弹幕 | 速度按时间计算，不按帧数，60/90/120/144 赫兹下速度一致 |
| 电视盒子 | 可选“匹配内容帧率”（类似 Kodi、SmartTube 的自动帧率），切台时按新流的帧率切换；允许不无缝的切换（电视上黑一下可以接受） |
| Windows、Linux | 只读显示器刷新率，在设置里显示；不改系统设置；动画和弹幕跟随显示器节拍 |

设置：保留 3.x 的三档和键名；新增“播放时匹配视频帧率”（手机默认开、只在无缝时切）和“电视匹配内容帧率”（电视默认开）。

### 7.2 流畅度要求（每个界面重构时都要做到）

1. **局部刷新**：状态变化只重建用到它的小部件（`ListenableBuilder`、按字段选择），不整页重建。
2. **列表**：懒加载；卡片高度可预估；图片按显示尺寸解码；滚动中不做重活；分页加载不打断滚动。
3. **分层**：视频、飞行弹幕、控制层、页面各自独立重绘；大面积模糊、半透明叠层、裁剪只在必要处用并限制范围（例如竖屏流两侧的封面模糊只解码小图、只画一次）。
4. **重活不在界面线程**：弹幕解码和过滤（`live_danmaku` 已在后台）、大 JSON 解析、图片处理。
5. **启动**：首帧前只做必要的事，其余延后（M12 已做）。
6. **内存**：图片缓存有上限；直播间进出 20 次后内存不持续增长；弹幕列表和飞行层有条数上限。

### 7.3 弹幕渲染选型（U.2h）

- 候选：v4 现在的自绘层、`canvas_danmaku`、`flame_barrage`。
- 基准：K90 上 120 赫兹，每秒 50 条（含表情图片和描边），持续 2 分钟。
- 比较：帧时间、内存、功能（滚动/顶部/底部、描边、透明度、区域、点按和长按命中、表情图片、按时间算速度）。
- 选用最好的；自绘层的已知优化方向：每条弹幕只画一次存成图层再平移，描边和填充合成一次。

### 7.4 性能对设计的约束（采用归档 v4 的 15 条，摘要）

1. 视频上方不用模糊，也不常驻会开离屏层的效果（`BackdropFilter`、`Opacity`、`ShaderMask`、`ColorFilter`）；控制层下面是黑色线性渐变，全屏聊天浮层是 70% 黑纯色；控制层淡入淡出只在 200 毫秒动画期间用一个透明度层。
2. 整个应用不用模糊背景（顶栏、导航栏也不用）。
3. 视频、弹幕、控制层各自隔离重绘；控制层显隐不让视频层和弹幕层重绘；人数等高频字段单独订阅。
4. 视频不圆角、不裁剪、不加边框阴影；多画面格子之间 2 像素黑色间隙，声音焦点用描边加扬声器图标。
5. 画面尺寸变化的动画只做合成层变换，结束后再按新尺寸通知内核；看不见的画面暂停解码；多画面小格自动降画质。
6. 列表卡片高度按当前文字缩放算出，不写死；封面按显示宽度 × 像素比解码；支持尺寸参数的平台图片 CDN 请求接近显示尺寸的图；图片缓存限总大小。
7. 未开播的关注不加载封面（用头像行）——候选 C-5，和 v3 的显示方式不同，需要确认。
8. 骨架屏静态、没有扫光；加载指示器只在可见时运行；静止界面可以降刷新率。
9. 不做人数滚动动画；表情按 20～24 解码。（v3 的“本地互动”礼物特效是否保留，在直播间对比图里确认。）
10. 弹幕只提供描边，不提供模糊阴影；透明度直接用文字颜色的透明度绘制，不用 `Opacity` 包住弹幕层。
11. 圆角用装饰的 `borderRadius`，头像用图片填充的圆形装饰，不用 `ClipRRect`、`ClipOval` 包图片。
12. 播放器只有一份：小窗、画中画、直播间共用同一个播放器和弹幕引擎。
13. 多画面的最大格数按设备内存和硬件解码能力决定，超出时提示。
14. 阴影只用于浮层，卡片用色调层级。
15. Windows 不用 Mica 和亚克力（Impeller 在 Windows 上有已知性能问题，效果越简单越稳）。

### 7.5 性能指标（采用归档 v4 第 10 节，先测 v3 基线再校准）

| 指标 | 测量方式 | 目标 |
|---|---|---|
| 冷启动到首帧 | `adb shell am start -W`、`--trace-startup` | 中端机不超过 v3 的 60% |
| 首页可交互（有缓存） | 集成测试打点 | ≤1 秒 |
| 点击直播间到画面出现 | 集成测试 + 播放器首帧事件，固定网络 | 不超过 v3 的 70% |
| 滚动帧耗时 | `traceAction` 时间线 | 120 赫兹设备构建加光栅化 P90 ≤8 毫秒，掉帧率 <1% |
| 弹幕高密度 | 回放录制的弹幕流，每秒 200 条 | 不掉帧；界面线程占用 ≤3 毫秒/帧 |
| 内存 | `dumpsys meminfo`、DevTools | 单直播间和 4 格多画面各设上限；连续进出 50 个直播间不增长 |
| 耗电与发热 | 连续播放 30 分钟 | 比 v3 低；静止画面降刷新率 |

v3 的基线（归档 v4 `BASELINE.md` 实测）：Windows 首页空闲私有内存 481 MB、一个直播间 801 MB、3 格多画面 1054 MB；Android 直播间 PSS 462 MB。

### 7.6 验证

1. 每个界面重构完，profile 模式看一次帧时间（性能叠加层）。
2. 基准场景写成集成测试（记录帧时间并输出 JSON 报告），每批界面推送前在 K90 和 Windows 上各跑一次；功能全部完成后改为每晚在 K90 上跑，和上一次比较，任何指标变差超过 10% 就报警并附时间线文件：
   - 热门页快速滚动 200 张卡片；
   - 直播间每秒 50 条弹幕；
   - 多画面 4 路；
   - 设置页滚动；
   - 进出直播间 20 次（看内存）。
3. 目标：K90 120 赫兹 99% 的帧在 8.3 毫秒内，没有连续 3 帧以上掉帧；Windows 144 赫兹同样；内存不持续增长。

## 8. 多平台和多形态适配

### 8.1 尺寸分档（采用归档 v4 定稿的规则）

**判定**：

1. **电视模式**：检测到电视（电视界面模式或 leanback 特性）时自动进入，也可以在设置里手动开关；电视模式下不再按宽度分级。
2. **宽度分档**（和 Android 窗口尺寸分档一致）：紧凑 <600、中等 600–839、展开 840–1199、大 1200–1599、超大 ≥1600。
3. **高度分档**：紧凑 <480、中等 480–899、展开 ≥900。**高度紧凑优先**：横屏手机宽约 850–930，按宽度属于“展开”，但高度紧凑，必须按“横屏手机”布局。
4. **折叠屏姿态**：半开的桌面姿态和书本姿态单独处理，控件和文字避开铰链。
5. 页面只读父组件给的约束（`LayoutBuilder`），不读整屏尺寸；窗口尺寸变化时切换布局，但保留滚动位置和播放状态，不重建播放器。

v3 用 680 一个分界（`Get.width`，读整屏），窗口缩放时有的页面不跟随——这是要修的问题。分档后紧凑竖屏手机的布局保持 v3 的样子；中等以上在对比图里逐个确认。

**各页面布局**（以 v3 为基础；带“候选”的是和 v3 不同、需要确认的）：

| 页面 | 紧凑 | 中等 | 展开 | 大 / 超大 |
|---|---|---|---|---|
| 导航 | 底部导航栏（v3） | 侧边导航栏（v3 宽屏） | 侧边导航栏 | 侧边导航栏，候选：可展开显示文字 |
| 卡片网格 | 2 列 | 按公式 | 按公式 | 按公式 |
| 直播间 | 画面在上、标签和弹幕在下；竖屏流三档面板（v3） | 画面在上，聊天可折叠 | 画面 + 右侧聊天栏（v3 的左右分栏，聊天栏宽约 34%，300–400） | 同展开，聊天栏可拖宽（候选） |
| 多画面 | v3 | v3 | v3 | v3，候选：3×3 |
| 设置 | 分级页面（v3） | 分级页面 | 候选：左侧分类 + 右侧内容 | 同左，内容区不超过 720 |

**网格列数**（修 v3 按固定断点 2/3/4/5 列的问题，窗口拖动时卡片忽大忽小）：列数 = clamp(⌊(内容区宽度 + 间隙) ÷ (最小卡宽 + 间隙)⌋, 2, 8)，最小卡宽紧凑 160、中等和展开 180、大和超大 200；393 宽的手机仍是 2 列（和 v3 一致）。

**直播间的展示状态**只有一个枚举：内嵌、全屏、竖屏全屏、画中画、应用内小窗（候选：剧场）。视频画面只挂载一个，切换状态时移动它，不重建。

**大屏的方向锁定**：面向 Android 17 的应用，在最短边 ≥600 的设备上方向锁定会被系统忽略。平板和折叠屏上的“横屏全屏”“竖屏全屏”只能按当前方向布局；锁方向只在手机上生效。

**桌面窗口**：最小窗口 360×400（可落到紧凑布局）；记住大小、位置和最大化状态；按显示器缩放比例渲染；有悬停态、带快捷键的提示、右键菜单、细滚动条；键盘焦点框只在使用键盘时显示。标题栏沿用 M12.3 照 v3 做的自绘标题栏（归档 v4 曾决定改用系统标题栏，列为候选 C-10）。

### 8.2 输入方式

| 输入 | 要求 |
|---|---|
| 触摸 | 点击区域至少 48×48；画面手势（亮度、音量、双击全屏）照 v3 |
| 鼠标 | 悬停状态；右键等于长按；滚轮调音量（直播间，照 v3）；控制层随鼠标移动显示、静止后隐藏 |
| 键盘 | v3 的快捷键全部保留：Space 和媒体键暂停、R 刷新、↑↓ 音量 ±5%、F 和双击全屏、Esc 依次关弹层/退全屏/返回。候选补充（归档 v4）：M 静音、D 弹幕开关、Q/L 画质/线路菜单、P 小窗、Ctrl+F 搜索、Ctrl+V 打开剪贴板链接、? 快捷键帮助。焦点框只在用键盘时显示；Tab 顺序和视觉顺序一致 |
| 遥控器（电视） | 每页有默认焦点；方向键能到所有元素；返回键逐级退出；长按 OK 打开菜单（M14） |

### 8.3 系统环境

- 刘海和安全区、全面屏手势条、键盘弹出、分屏、画中画、折叠屏开合、横竖屏切换都要正常。
- 系统字体放大到 1.3 倍和 1.5 倍不截断、不重叠。
- 深浅两套主题都单独看过。
- Windows、Linux 窗口最小尺寸内任意缩放都不乱，标题栏和托盘照 M12.3。

### 8.4 电视

以 pure_live_TV 的界面为参考（M14），采用归档 v4 定下的电视细则：

- **画布** 960×540；左右 48、上下 28 安全边距，背景和可滚动内容可以延伸到边缘。
- **导航**：左侧收起的导航轨（只显示图标），获得焦点时展开显示文字，盖在页面上不挤压。
- **网格**：4 列；按行列记忆焦点，返回列表时焦点回到原来那张卡片。
- **焦点**：卡片放大 1.05 倍加 3 像素近白描边；按钮底色加深并加描边；低端盒子可选“只描边不缩放”。
- **字号**：比手机大一级，正文不低于 14（1080p 下约 28 像素）。
- **主题**：只有深色（和纯黑，若采用 C-4）。
- **直播间**：始终全屏。
  - 上下键（和频道加减键）切换同一列表的上一个/下一个；
  - 左键打开直播间列表，右键打开播放设置（弹幕、画质、线路、比例）；
  - 确认键显示/隐藏信息栏，长按确认等于菜单键（新款遥控器没有菜单键）；
  - 返回键逐级退出，一级页面先回到导航轨，再按一次退出，不弹确认。

## 9. 每个界面的流程

照 `docs/PLAN.md` 第 7 节，界面版：

1. **读**：v3 的代码和测试；v4 现在的实现；参考项目里对应的部分。
2. **审查**：在清单里写清 v3 的样子、v3 的问题（根因和位置）、v4 的偏差、文件对照。
3. **对比图**（第 10 节）：v3 还原和 v4 方案并排，逐条标注保留、修改、增强，附性能要点。
4. **用户确认**：每条改动单独可选同意或否决；确认结果记在该界面的记录里。
5. **实现**：在新结构里改 `features/<功能>` 和 `live_ui`；先还原 v3 布局，再加确认过的改动。
6. **测试**：
   - widget 测试固定控件的顺序、图标和位置（例如直播间下栏从左到右是哪几个按钮）；
   - 外观截图测试锁定外观：紧凑和宽两档、深浅两套，用真字体；改外观时截图变化要在提交里说明；
   - 逻辑测试照旧。
7. **性能**：profile 模式看帧时间；涉及列表、弹幕、动画的跑基准。
8. **门禁**：`tools/gate/gate.sh --all`。
9. **上传**：一个界面（或一组相关界面）推送一次；`docs/PLAN.md` 第 6 节的 U 行更新进度。

## 12. 验收标准（每个界面）

- [ ] 清单里有该界面的 v3 样子、v3 问题、v4 偏差、文件对照。

## 13. 风险和对策

| 风险 | 对策 |
|---|---|
| 工作量大（v3 界面代码约 6 万行，41 个路由，加上状态和对话框上百个界面） | 按优先级分批；直播间先行；通用组件先统一，后面的页面大量复用 |
| 按代码还原的 v3 图和实际有出入 | 还原时引用文件和行号；拿不准的地方标出来，请用户对照手机上的 3.x 指出 |
| 搬目录和暂停分支冲突 | U.0 前先把暂停分支里能独立合的逻辑部分合进来；界面部分照新结构重做 |
| 性能目标在某些设备上达不到 | 先找根因（重绘范围、图片解码、弹幕绘制）；必要时给低端设备降级（降低弹幕条数、关闭模糊） |
| 刷新率切换在某些手机上黑屏 | 默认只在无缝时切换；设置里可关 |
| 截图测试跨平台字体差异导致不稳定 | 截图测试只在 Linux 上用固定字体生成和比较 |

来自归档 v4 的设计和本次调研。默认按 v3 做；用户同意的才进入对应界面的方案。每条都会在相关界面的对比图里画出来。

| 编号 | 内容 | 理由 | 建议 |
|---|---|---|---|

## 附录 A：必须保留的旧操作习惯（回归测试清单）

来自归档 v4 `spec/design/principles.md` 第 6.4 节（依据 v3 代码和诊断），每条在对应界面重构时写成测试：

1. 手机单击画面：控制层可见且在播放 → 隐藏；暂停中 → 显示并继续播放。桌面单击只显示控制层。
2. 控制条范围内的点击不触发弹幕命中。
3. 双击：竖屏源进入竖屏全屏，其余进入全屏；在全屏中先退出。
4. 左侧上下滑调亮度、右侧调音量；锁定按钮锁住所有手势。
5. 竖屏直播间的三档面板；拖过最低档或点把手进入竖屏全屏；竖屏全屏时在底部上滑退出。
6. 点击或长按命中的弹幕，打开复制和屏蔽菜单。
7. 返回键层级：弹层 → 全屏 → 普通 → 离开；Esc 走同一条链。
8. 应用内小窗：有弹层时隐藏；手机上第一次点击显示控件，再点回到直播间；只有有画面且没有加载错误时才转为小窗。
9. 切换画质和线路不重建播放器，以最后一次选择为准。
10. 进入直播间不改设备音量（全局静音除外）。
11. 强制横屏全屏退出后恢复竖屏（手机）。
12. 可选的“默认全屏”：进入直播间后自动全屏。
13. 多画面：四宫格等布局中点格子切换声音焦点；一大多小中点小格晋升为大画面、点大格显示控制；长按或右键打开格子菜单；点空格选直播间。
14. 卡片长按或右键 = 操作菜单。
15. Windows：在新窗口打开直播间；小窗可选置顶。
16. 键盘：Space 和媒体键暂停，R 刷新，↑↓ 音量 ±5%，Esc 链。
17. 回到前台时识别剪贴板中的分享口令（兼容旧格式）。
18. 定时关闭。
