## 做法

- **接口和输出沿用 v3**：`LiveSite`、`LiveRoom` 等模型和 3.x 的 JSON 不变。v3 实现过的可选能力全部保留：原生目录（`LiveSiteDirectoryPager`）、目录范围说明（`LiveDirectoryNotice`，文字键 `weibo_directory_scope`）、可取消的搜索（`LiveCancellableSearch`）、刷新（`LiveSiteRoomRefresher`）、录制详情（`LiveSiteRecordRoomResolver`）、取流（`LivePlayUrlResolver`）、恢复时重新取流（`LivePlayRecoveryResolver`）。另加 `LiveSiteLinks`。
- **请求照 v3**：两个匿名 GET，都在 `weibo.com/l/!/2/wblive/` 下，请求头 `Referer: https://weibo.com/l/wblive/`、UA `Mozilla/5.0`，不跟随跳转，地址的写法与 v3 逐字相同。
  - 推荐快照 `pc_recommend/list.json?count=10&uid=`：平台给 9 条，没有翻页、状态和人数；
  - 房间 `room/show_pc_live.json?live_id=<查询编码的场次号>`。
- **目录照 v3**：一个“微博直播”分类，下面一个“公开推荐”分区（`areaType: 'recommendation'`、`areaId: 'live'`），不发请求；推荐和这个分区都是同一个快照，只有一页，第 2 页起为空且不发请求。v3 的 `getRecommendRooms`、`getCategoryRooms` 只校验每页条数，不切片，照旧。
- **卡片照 v3**：房间号是场次号 `liveid`，`userId` 是主播 uid；昵称兼作标题；有封面、没有头像和人数；状态是“未知”（快照不说状态）；公告是 `weibo_room_scope` 的文字（“收藏跟踪当前直播场次……”）。
- **搜索照 v3**：场次号或直播链接直接查这个房间（只有第 1 页）；其他关键词在推荐快照里按昵称过滤（去空白、不区分大小写，取前 `pageSize` 条），一个请求。
- **房间照 v3**：`show_pc_live` 一个请求，进房、关注刷新、录制都是它。
  - 标题、昵称、头像（`profileImageUrl`）、封面，没有人数，公告同卡片；
  - 状态：`play_switch` 为 0 或 `watch_limit` 不为 0 时是“未知”，公告前加 `weibo_restricted` 的文字；否则 `status` 1 是直播，3 是回放，其他（5 等）是“未知”；
  - 回答的场次号必须等于请求的，否则 `ApiChanged`；字段检查照 v3（`status`、`watch_limit`、`width`、`height` 是非负整数，`pay_live_status`、`play_switch` 是 0/1，标题、昵称是字符串，公开直播时两个地址字段是字符串且非空地址是普通的 http(s)），不合格报 `ApiChanged`，不给残缺的房间；
  - 主播 uid、状态码、`watch_limit`、访问限制和公开直播的地址放进 `WeiboRoomData`（不存储）。
- **房间身份与 v3 一致**：v3 的详情返回请求时的场次号（`_id` 只校验，并要求回答的 `liveId` 等于它），卡片的房间号是行里的 `liveid`。新代码相同，样本对照里所有 `roomId` 都与 `expected.json` 一致。主播 uid 不是身份，只用于核对“同一场次还是同一个主播”。
- **画质照 v3**：一个画质“原始流”（id `original`）。取流、恢复、录制每次都重新读一次房间（1 个请求，v3 同样如此），要求还是同一个主播、仍然可播，线路是它的 FLV（HLS 字段通常就是同一个 FLV 地址，只留一条；真是 m3u8 时作为第二条）。
- **线路**：请求头为空（v3 的 `PlaybackHeaderResolver` 没有微博分支，播放器和录制器发的都是自己的默认值；2026-09-28 实测不带 UA、带 `Mozilla/5.0` 或 `libmpv`、不带 Referer 都能拉到 FLV），格式按扩展名，编码按流名（`_wb720avc.flv` 是 H.264，实测 FLV 头的 video codec id 为 7），线路编号取路径第一段（`alicdn`），没有时取主机名。地址不带签名和过期参数，没有租期。
- **不能播放时在取流时报错**：受限（仅好友、付费、仅 App）报 `NeedsLogin`；播放关闭、回放、状态未知、直播中却没有地址报 `StreamUnavailable`。房间已知不能播时，取画质和取流都不发请求。
- **没有 Cookie、登录和弹幕**：v3 的微博全部匿名，弹幕是 `EmptyDanmaku`，所以没有弹幕参数类，也不注入 `CookieVault`。

## 样本与 v3 的冻结输出

归档没有微博的 `expected.json`：归档的旧版对照工具只做了前五个平台，v3 应用现在也构建不了。本模块用 `fixtures/weibo/legacy_expected.dart` 生成：

- 把 v3 的 `WeiboApi`、`WeiboLink`、`WeiboSite` 和 `request_scope.dart` 的 `withRequestCancellation` 原样搬进一个纯 Dart 脚本。v3 本来就把传输做成可注入的函数（`WeiboRequest`），所以只换了它：按方法、主机、路径和查询读样本；状态码不是 200 时正文为空（同 v3）；没有样本的请求抛 StateError，并由 `_scope` 原样抛出，不会被记成 v3 的“传输失败”。只在网络路径上用到的 `_defaultRequest`、`readBody` 没有搬。
- `i18n` 换成用到的五个键的中文（`zh.json`）；基类声明、`@override` 和弹幕 getter 去掉；v3 的 `LiveRoom` 等只搬用到的部分（3.x 的 `toJson` 写的是原始的 `isRecord` 字段）。
- `S01-recommend` 是归档用 `count=100` 录的；v3 请求 `count=10`，脚本对 S01 忽略 `count` 作答（v3 的解析不读它），这样 v3 的解析器跑过全部 51 行。`S03-recommend` 就是 v3 的原请求。
- 输出格式同旧版工具（`roomProjection`、`errorProjection`、`{generator, value}`），每个调用还记下了它发出的请求。
- 重新生成：在仓库根目录运行 `dart run fixtures/weibo/legacy_expected.dart`。

8 个样本都有 `expected.json`：

- `S01-recommend`、`S03-recommend`：分类（第 1、2 页）、推荐页（第 1、2 页）、分区页、`getRecommendRooms` 的三种页码和条数、`getCategoryRooms` 的两页；9 个关键词、条数 3、第 2 页、别的链接、`Re:Zero`、空白的搜索。
- `S02-*`、`S03-live`（同时读 `S03-recommend`，给 v3 认不出场次号时退回的昵称过滤作答）：进房、刷新、录制；按场次号、网页链接、手机链接（`%3A`）搜索；开播状态；`WeiboLink.parse`、`WeiboLink.url`；画质、地址、取流、恢复。

| 2 | 不存在的场次（27401）是 `NotFound`，精确搜索为空 | 问题 2 |

## 保持 v3 行为、没有采用归档 v4 或上游做法的地方

- **推荐仍请求 10 条（平台给 9 条）**。归档 v4 用 `count=100`（51 条），列表内容会变。
- **推荐卡片的状态仍是“未知”**。归档 v4 标成直播中。
- **房间状态照 v3**：受限或播放关闭是“未知”加限制说明，状态 3 是回放，5 和其他是“未知”。归档 v4 把 3、5 都算未开播、受限照常算直播、未知状态报 `ApiChanged`，这些都会改变用户看到的状态和分组。
- **保留昵称搜索**（在推荐快照里过滤）。归档 v4 去掉了搜索，只认链接。
- **保留“微博直播 / 公开推荐”分类**。归档 v4 没有分类。
- **画质名称仍是“原始流”**（id `original`）。归档 v4 叫“原画”（id `origin`）。
- **头像仍用 `profileImageUrl`**（50 px）。归档 v4 优先用 1024 px 的 `avatar`。
- **标题、昵称不解码 HTML 实体**。归档 v4 解码；样本里没有实体。
- **请求头照 v3**：UA 仍是 `Mozilla/5.0`；线路没有请求头。归档 v4 的接口和线路都用 Chrome 140 UA。
- **严格校验照 v3**（问题 16）：一行坏数据整页失败，房间缺字段整个失败。归档 v4 跳过坏行、只看用到的字段。
- **`getRecommendRooms`、`getCategoryRooms` 不按条数切片**，第 1 页就是整个快照。
- **开播状态照 v3**：直播 true，回放 false，其他状态不给答案（报错）。3.x 里没有地方调用它。
- 上游 pure_live_TV 与 v3 相同，没有要采用的修复。
