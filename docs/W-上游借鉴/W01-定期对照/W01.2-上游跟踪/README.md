让上游的修复和新功能每周都有人看：每周一次，拉取五个上游仓库，从上一次看到的提交接着看，逐条对照 4.x，结论写成一份新的对照记录（W01.n），要做的开成任务。这个任务是“跟踪”本身：建立每周的节奏、第一次按新流程做一遍；之后每周的对照各自登记成 W01.n。

## 方案

- c1 每周一次（建议固定在周一），照 [brief.md](brief.md) 的步骤：拉取 → 列提交 → 逐条对照 → 写对照记录 → 登记任务。
- c2 每次对照新登记一个任务 W01.n（维护者在登记表加：`id`、`title = "<日期> 上游对照：pure_live N 个、……"`、`type = "工程"`、`status`、`date`），文件夹 `W01.n-<日期>上游对照`，README 照 W01.1 的格式（看了哪些、4.x 也有的问题、可以借鉴的新功能、已经有的、不适用、结果、验证、留下的问题）。
- c3 开出的任务一律写 `from = "上游 <仓库> <提交>"`；可借鉴的新功能进 V01（D-027）。
- c4 没有新提交的一周也记一份很短的对照记录（“五个仓库都没有新提交”），保证“上次看到”连续。
- 本任务（W01.2）在第一次按新流程做完、维护者确认节奏可行后改“完成”；以后的每周对照都是 W01.n，不再挂在 W01.2 下。

## 验证
