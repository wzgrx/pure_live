# 直播间录制动作弹窗布局与事务审计（2026-09-12）

## 范围与基线

- 基线：`06603babdf475555f51ab659aa78438f7db5b9da`。
- 范围：直播间标题栏录制按钮、录制动作弹窗、监控/启动/停止/移除提交、进入录制中心的路由衔接及窄屏大字号布局。
- 本批使用真实 Widget、受控录制控制器和路由回调；没有连接手机、启动真实录制、构建安装包或发布版本。

## 稳定复现与根因

1. 旧 `AlertDialog` 使用不可滚动的五项 `Column`。320×480 / 3.0 倍英文下稳定向底部溢出 **1819 像素**，后部动作不可达；标题还强制单行省略，弹窗没有显式取消动作。
2. 弹窗打开时一次性捕获任务和运行状态。等待选择期间若同一房间任务已经由其他入口加入，点击“立即启动录制”仍按旧空状态再次走 `addTask`，没有对提交瞬间的权威任务复核；原始行为测试未调用现存任务的启动入口。
3. 录制按钮没有动作所有者。弹窗关闭后，添加监控、启动或进入录制中心尚在等待时按钮已经可再次触发；停止和移除调用也未等待完成。
4. 添加监控无论控制器返回任务还是空结果都会提示“已添加”；进入录制中心的注释要求避开对话框反向动画，实际代码却在 `DialogRoute` 返回结果后同帧发起新路由。
5. 非紧凑标题按钮被固定为 38 像素高，放大文字时无法按内容自然增高。

## 修订

- 录制按钮改为自有 State 与单一 `_busy` 事务；从打开弹窗到动作完成期间禁用重复入口，系统返回或取消后统一释放。
- 动作提交前按房间平台和 ID 重新读取当前任务及状态；现存任务走启动入口，过期的停止/移除动作安全结束，避免按弹窗旧快照提交。
- 启动、添加、停止和移除全部等待控制器结果；仅在添加返回有效任务时显示成功提示。
- 进入录制中心前等待标准反向动画时长，随后再由播放器控制器隐藏原生视频层并导航，避免两个路由过渡重叠。
- 弹窗改为视口有界布局：标题按宽度和字号响应式堆叠，五项动作位于弹性滚动区，底部 SafeArea 取消固定可达；非紧凑标题按钮保留 38 像素最小高度并允许大字自然增高。
- 房间和任务从 `dynamic` 收敛为 `LiveRoom?` / `LiveRecordTask?`，让状态复核与动作合同由静态类型约束。
