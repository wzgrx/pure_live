# E02.14 小红书推荐对游客为空

- 编号、状态、档位、规模：以登记表为准，见[子分类页](../README.md)和 [STATUS.md](../../../STATUS.md)
- 类型：平台
- 来源：E07.1 第一轮巡检（2026-10-08）：P1 两次都是第 1 页为空，没有报错；P4、P6～P12 因此没测到
- 相关：[E02.7](../E02.7-小红书/README.md)（小红书平台，“仅链接，照 v3”）；[E07.1](../../E07-平台巡检/E07.1-平台巡检工具/README.md)（巡检工具）、[CHECKS.md](../../E07-平台巡检/CHECKS.md)
- 记录：[record.md](record.md)

## 目标

弄清小红书推荐为空是不是平台失效；不是的话，让巡检不再把它报成失败，并且仍能查到小红书能查的部分。

## 3.x 和现状

| 方面 | 3.x | 现在（文件:行） | 结论 |
|---|---|---|---|
| 推荐和目录 | 永远是空的，热门页显示目录说明（网页的直播列表要登录签名 `x-s`，匿名拿不到） | `xiaohongshu_site.dart:91-100`：照 3.x，空目录、不发请求；目录说明键 `xiaohongshu_directory_scope`（E02.7） | 不是失效，是设计如此；应用里热门页显示说明“小红书没有公开的直播列表……” |
| 在播房间 | 按房间号或分享链接进 | 同 3.x | 实测正常（下面“结果”） |

## 结果

- 不改应用和适配器。根因在巡检的对象表：小红书的 P1 应是“不支持”，CHECKS.md 写成了要测；P4 “按房间号查”取推荐的第一个房间号，推荐为空就没有关键词。
- c1 `tools/live_cli/lib/src/patrol/targets.dart`：小红书的 P1 标“不支持”（写明原因）；P12 加固定链接（已结束场次的分享页）。
- c2 `tools/live_cli/lib/src/patrol/checks.dart`：“按房间号查”的平台没有推荐时用第一个固定房间号搜。
- c3 [CHECKS.md](../../E07-平台巡检/CHECKS.md) 第 2 节 P4 和对象表的小红书一行同步改。
- 复测：`patrol xiaohongshu` 正常 4、失败 0、没测到 4（P6、P9～P11：匿名拿不到在播房间）、不支持 5。在播房间用 `probe` 手工查（房间号取自结束页里平台推荐的另一场直播）：详情、一档“原画”、3 条 FLV 和 1 条 HLS 都通。

## 验证

- 自动测试：`tools/live_cli/test/checks_test.dart` 加 2 个（没有推荐时按固定房间号查、在播各项没测到而不是失败；小红书一行 P1 不支持）。
- 真机：不需要（应用没有变化）。

## 留下的问题

- 巡检测不到小红书的在播取流（P6、P9～P11），要手工 `probe`。巡检要自动测，得从结束页的 `nextRoomInfo` 取在播房间号，适配器按 E02.7 的决定不读它；需要时另开任务给巡检工具加这一步。
