# 音频模式按钮响应式审计（2026-09-06）

## 来源与根因

- 本轮起点：`745dc25c5c435e45c8508be7d18e4fc27dfb0012`。
- 在线核对上游 master 仍为 `c6c9bd70aedc503c003110dae10a83ad0bb891d8`；没有合并。
- 分类 `fork-regression`：按钮来自 `a340cc774`，模式图标来自 `9850eea10`，
  busy 状态来自 `f3121c5b7`。冻结上游也保留同一缺陷，并非本次新合并造成。
- `AudioOnlyButton.build` 在普通 StatelessWidget 中读取 `audioModeSwitching` 和
  `audioOnlyState`，没有建立自己的 Rx 订阅。父级 Obx 创建子 Widget 时并不执行其 build，
  因此父级的依赖收集不覆盖这里。状态改变后，按钮可能保留过时的禁用状态、图标和提示，
  直到其它事件偶然重建它。
- 第一处错误是“状态已变、按钮没有订阅”，不是媒体 URL、解码器或线路续签。
  控制器已有 busy 拦截，旧按钮看起来可点击也不等于实际重复开流。

## 修复合同

1. 在按钮内部使用 Obx，同时读取切换状态与音频模式；仅重建此按钮。
2. 保留原耳机图标、颜色、提示与控制器调用，不更改音轨策略、取流或全屏布局。
3. busy 进入后按钮禁用；成功或失败退出 busy 后恢复；外部模式变更也立即更新。
4. 多个挂载表面订阅同一状态，卸载时交由 Obx 正常释放；不增加轮询、延时、播放器重开。
