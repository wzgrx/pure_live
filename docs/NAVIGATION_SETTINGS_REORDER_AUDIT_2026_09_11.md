## 修改前复现

旧页面同时用 `savedMenuIds` 表示“可见项及其顺序”，但仍为隐藏行保留拖动把手。把底部菜单隐藏至仅剩
Favorites 后，四行设置仍都可开始拖动；隐藏的 Record 行触发 `(oldIndex: 3, newIndex: 0)` 时，回调直接对仅有
一个元素的 `savedMenuIds` 执行 `removeAt(3)`，稳定得到：

`RangeError (length): Invalid value: Only valid value is 0: 3`

同一回调把唯一可见项拖过隐藏区时，插入下标也可能超过剩余列表长度。首次产品红灯已直接捕获上述 RangeError；
其后组合测试使用真实 Hive 响应列表时，在失败用例遗留异步写入，夹具清理等待未终止，正式回归改用内存响应列表隔离该测试时序。

配置导入和旧本地值还会原样接受空列表、未知 ID、重复项及带空格/大写的 ID，使主页可能没有可用页签，
或让设置页的显示顺序与实际导航不一致。

## 修订

- 增加统一菜单 ID 归一化：去除首尾空格、转小写、过滤未知项、稳定去重；结果为空时保留 Favorites 作为可用页签。
- 启动、当前配置解析、备份字段抽取和显示开关统一使用该规则，避免异常数据绕过“至少一个页签”约束。
- 隐藏行以及仅剩一个可见页签时不再显示拖动把手；回调再次校验来源行，只对可见 ID 排序。
- 可见项拖过隐藏区时把目标位置限制到当前可见列表边界，仍可安全移动到首项或末项。
- `320×480` / 3.0 倍文字下，页签标题使用完整可用宽度，开关和拖动把手堆叠到标题下方；常规宽度保持横排。
- Widget 回归覆盖隐藏行与唯一可见行无把手、两个越界拖动回调、四项正常排序、最后页签保护，以及四行大字号边界。
