# A03.3 直播间拖动手感：真机验证

- 设备：Redmi K90 Pro Max（Android 17，120 Hz）；构建：`com.mystyle.purelive.v4dev` profile，提交 `9e84b6f7b`
- 日期：2026-10-08；验证人：Claude
- 做法：`adb shell input motionevent DOWN/MOVE` 按住拖到一半截图，再 `UP` 松手截图；快甩用 70～90 毫秒的 `input swipe`。截图在 `verify/`。

| 步骤 | 期望 | 结果 | 截图 |
|---|---|---|---|
| 1. 竖屏主播（YY）进竖屏全屏，打开“竖屏全屏上下滑换台”，在画面中间三分之一上下滑 | 跟手，快滑一下就换，松手不顿 | 通过：拖到一半整个画面跟着手指走，下一个房间的模糊封面和“松手换到这个直播间”跟在下面；慢拉 500 像素、速度为 0 松手弹回原房间；快甩松手后 250 毫秒截图时已经停在新房间、开始连接，约 3 秒出画面 | 1-swipe-drag、1-swipe-fling |
| 2. 滑到最后一个房间再往上拉 | 橡皮筋 | 真机上碰不到：换台列表是循环的（`room_playlist.dart:29`，两个房间时上下都是另一个），只有一个房间时不换台（中间三分之一当音量手势）。橡皮筋只有自动测试覆盖 | — |
| 3. 竖屏拖三档面板，快甩、慢拉 | 跟手、松手顺滑地吸到一档；拖动时画面不闪不卡 | 通过：面板位移 = 手指位移减去起拖阈值，没有跳；拖动时画面一直在播；慢拉一小段松手弹回本档，快甩进竖屏全屏 | 3-panel-drag |
| 4. `flutter run --profile` 看 DevTools 帧图 | 没有红帧 | 没做：要电脑连 DevTools；自动测试里拖 2 秒 `RoomPlayer` 重建 0 次 | — |
| 5. 详情面板按住把手往下拖 | 好按，跟手，松手弹回或关闭 | 通过：拖 200 像素面板正好跟着下移 200 像素，松手超过阈值关闭 | 5-details-drag |

## 结论

第 1、3、5 步通过；第 2 步在真机上不会出现（列表循环），第 4 步留到有电脑连 DevTools 时。

## 另外看到的

- 中间三分之一是不是换台取决于设置和列表：设置关着或列表只有一个房间时，整块右半边是音量。测试时音量被拉到 97%，用音量键调回 0（`cmd media_session volume --set` 在这台 HyperOS 上不起作用）。
