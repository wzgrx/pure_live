# I03.1 分区：分区列表、分区房间、热门分区（平台显示）

- 日期：2026-10-01
- 目录：`apps/pure_live/lib/features/areas/`、`lib/pages/area_rooms/`、`lib/pages/hot_areas/`
- 路由（I01.1 的表，没改）：`/areas`（也是首页的“分区”标签）、`/favoriteAreas`（同一个 `AreasPage`，按路径分开）、`/area_rooms`（参数 `[LiveSite, LiveArea]`）、`/hot_areas`
- v3 来源（标签 `v3.2.11`）：`lib/modules/areas/`（11 个文件）、`lib/modules/area_rooms/`（3 个）、`lib/modules/hot_areas/`（3 个），以及它们用到的 `common/base/`（分页控制器、`BasePageView`）、`plugins/area_pic_mapper.dart`、`common/utils/category_artwork.dart`、`common/widgets/room_card.dart` 的长按菜单

## 做法

- **取服务**：照 I01.1 的“页面怎么取服务”。平台 `sitesProvider`（`availableIds(hotAreasList)` 给出平台标签），设置 `watchSetting`，关注分区 `storeProvider.followAreas`（`watchAll()` 经页面自己的 `StreamProvider` 让卡片、按钮跟着变），关注房间 `follows`，跳转和提示 `AppNavigator`。
- **分区列表**（`areas_page.dart`、`platform_areas_view.dart`、`area_catalog.dart`）：
  - 每个平台一个 `AreaCatalog`（`ChangeNotifier`，对应 v3 `AreasListController`）：`getCategories(1, 1000)` 一次拿全；刷新期间并发的请求合并；选中的分类按 id 保留；刷新失败保留已显示的分区，错误显示在上方。
  - 平台标签照 v3：保存的顺序、首次打开定位到 `preferPlatform`、平台列表改了就重建（当前平台还在就留在它上面）；平台标签只能点击切换，分类标签可左右滑（v3 为了避免两层横滑抢手势）。当前平台加载完 0.8 秒后预取下一个平台（v3 的预热）。
  - 首页后台回来 15 秒以上（`HomeSignals.resumedAfterBackground` 是 `areas`）刷新当前平台（v3 `refreshCurrentData`）。
  - 点分区：网络电视的频道直接进直播间，CC 官方入口用浏览器打开（`AppNavigator.toCategoryDetail` 已处理），其他进分区房间。
  - 分区图片：自己的图，没有就借同名（不分大小写）、别名表、名字互相包含的分区的图（`AreaPictures`，v3 `AreaPicMapper`）；学到的图存在 `meta` 表的 `areas.pictures`，重启后还在。猫耳的两态图标只显示彩色那一半，也不借给别的平台（v3 `categoryArtworkAlignment`）。
- **关注分区**（`favorite_areas_view.dart`）：“全部”加平台列表里的平台，每个标签一格网格；切换平台列表后按 id 留在原标签（v3 `resolveFavoriteAreaSiteIndex`）。
- **分区房间**（`area_rooms_page.dart`、`room_feed.dart`、`room_cards.dart`、`follow_area_button.dart`）：
  - `AreaRoomFeed` 一页接一页：有原生目录的平台（`LiveSiteDirectoryPager`、CC 的 `categoryDirectory`、游标平台 AcFun/CHZZK/17LIVE）按平台说的“还有没有”；其他平台按页号请求，某页没有新房间就到底。房间按身份去重，房间的分区名设成当前分区（v3 同样做）。下拉刷新从第 1 页重来，成功了才替换列表；翻页失败保留已有房间，底部可重试。
  - 每页请求个数：SOOP、TwitCasting 60（SOOP 上限、TwitCasting 整个窗口），其余 30（v3 的默认值；斗鱼、虎牙、抖音等固定页长的平台忽略它）。
  - 卡片用 `live_ui` 的 `RoomCard`：外观按设备（手机用手机的卡片设置，桌面用桌面的，同 v3 `RoomCardSettingsController.resolve`），高度随字号设置；人数按“优先显示在线人数”设置（`audienceValue`/`audienceType`），中文过万显示“万”、英文过千显示“K”（v3 `readableCount`）；受限房间卡片标出类型。
  - 点卡片进直播间；长按（右键）是卡片菜单：主播、标题、房间号、受限说明、关注/取消关注（取消前确认）、复制链接。
  - 右下角“关注分区”按钮照 v3：没关注时是“图 + 关注 · 分区名”，关注后缩成图；取消要确认。
  - 平台有目录说明（`LiveDirectoryNotice`）的显示在顶部（同 v3 `pageNotice`）。
- **平台显示**（`hot_areas_page.dart`）：开关显示哪些平台、拖动排序（只排显示的平台）；至少留一个（提示 `at_least_one_platform_required`）；首选平台被隐藏时改为第一个显示的平台（v3）。纯函数 `toggleHotArea`、`reorderHotAreas`、`preferredAfter` 单独测。

## 界面改进

（2026-10-01 用户授权：界面、布局、操作和视觉反馈可以改进；下面每条写了为什么。）

- **抖音分区改成分类标签**：C-12 之后“游戏”下有 156 个分区，v3 把所有分类合成一页会有两三百个格子，很难找。现在和其他平台一样按一级分类分标签；只有一个分类的平台（AcFun 等）不再显示单个标签，只显示分类名。
- **分区筛选**：分类行右边加搜索按钮，输入文字在本平台所有分类里筛选（名字、简称、上级分类，空格分词都要匹配）。分区多的平台（抖音、虎牙、Twitch）不用一个个分类翻。
- **刷新按钮**：分区页分类行、分区房间页标题栏各加一个刷新按钮。桌面用鼠标不能下拉刷新，v3 靠浮动按钮里的“回顶部再点一次刷新”，不直观。
- **加载中、失败的反馈**：刷新时顶部细进度条，保留旧内容；失败时在上方（分区）或底部（翻页）显示具体原因（网络、请求太频繁、要登录、地区、平台接口变化）和“重试”，不再整页变成错误。
- **关注状态看得见**：分区卡片右上角心形表示已关注；长按（右键）分区卡片直接关注/取消关注，结果用提示告诉用户；“关注分区”按钮显示已关注的数量；关注分区页每个平台标签带数量；分区房间页的关注按钮关注后头像加心形角标。
- **不能播放的直播**：按统一原则，分区房间默认隐藏付费、密码、私密、订阅专属、仅限 App、地区受限、平台不给流的直播（需要登录和年龄确认的照常显示，登录后可能能看）；页面顶部写“已隐藏 N 个……”，点“显示”在本页显示出来，卡片上标出受限类型。设置 `showUnplayableInDiscover` 打开时一律显示。
- **桌面也用连续加载**：v3 桌面端是页码翻页（每页个数、跳页），手机是连续加载，两套逻辑；分区房间现在都是滚到底自动加载下一页（底部有“加载更多/已经到底了”），回到顶部按钮仍受 `page_show_scroll_top` 设置控制。页码相关设置（每页个数、跳页按钮）在分区房间页不再使用，留给热门、搜索页决定。
- **平台显示页分组**：显示的平台在上（可拖动），未显示的在下面单独一组；标题显示“首页显示的平台（N / 总数）”；加“恢复默认”（全部显示、默认顺序，先确认）。平台名用 `site_<id>` 翻译、标志用 `PlatformLogo`。
- **没有平台时**：分区页不再是空白页，提示“没有显示的平台”并给“平台显示”入口。
- **卡片长按菜单**：加受限说明、复制链接；关注成功、取消关注都有提示。

## 有意差异

| 差异 | 原因 |
|---|---|
| 借图不做相似度匹配（v3 用 `string_similarity` 的 Dice 系数兜底） | 同名、别名、包含已覆盖常见情况；相似度兜底容易借到不相干的图，也省一个依赖 |
| 分区房间最多保留 5000 个（v3 原生目录 20000） | 连续加载时列表一直留在内存里，5000 个已远超实际浏览量 |
| 学到的分区图存在 `meta` 表 `areas.pictures`，不读 3.x 的 `cached_area_pics` | 只是缓存，打开分区页就会重新学到；J02.1 导入时也把这个键当缓存丢弃 |

## 留给后续

- **需要协调者加的共享部分**（本页先在自己目录里做了最小实现，热门、搜索、关注页大概率也要）：
  - 房间卡片的数据转换和长按菜单（`area_rooms/room_cards.dart`：`roomCardData`、`watchCardAppearance`、`readableCount`、`showRoomMenu`）和受限类型文字（键 `area_rooms_restriction_*`）——建议移到共享位置，键改成通用前缀；
  - 分页加载（`area_rooms/room_feed.dart`：`AreaRoomFeed`、`hiddenInDiscovery`）——热门页可以直接复用（推荐用 `getDirectoryPage(category: null)`/`getRecommendRooms`）；
  - 错误说明 `describeLoadError`（键 `areas_error_*`）。
- **卡片菜单的分享、设置标签**：v3 的分享走 `ShareCommandHandler`（分享口令），标签是 `TagManagementController` 的选择框，都属于别的页面（分享导入、标签管理），暂时用“复制链接”代替分享；做好后加进 `showRoomMenu`。
- **图片请求头**：v3 给哔哩哔哩图片加 Referer（`networkImageHeaders`），I01.1 的 `LiveUiConfig` 没有设置 `imageHeaders`，哔哩哔哩分区图和封面可能 403；应在 `lib/app/app.dart` 设置（不在本页目录）。
- **目录说明文字**：`*_directory_scope`（如 `chzzk_directory_scope` 的“包含边界项的游标分页”，20-6、14-6 等）是共享键，按规则本页不改；改写成用户看得懂的说明留给协调者（统一原则“说明文字”）。
- 热门页、搜索页的 A-4、10-5、19-1、24-5、26-1 余下部分。
- Windows 实机检查（鼠标滚轮、右键菜单、刷新按钮）和 Android 真机检查：本次没做（不往手机装）。
