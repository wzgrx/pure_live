# HLS 已发布分片的有限排空（2026-09-09）

源码提交 `56b139f39e2c394fb555a49cb179c19a50aaa859`，起点 `df1acc3f`，接续[生产预取接入审计](HLS_PRODUCTION_PREFETCH_AUDIT_2026_09_09.md)。本批只处理 opt-in 预取停止生命周期，保留默认关闭、原有非预取停止规则和用户数据。

## 根因与复现

上一批两个真实 native 场景都连续交付视频 0–13，但停止后视频在约 28 秒结束，音频约 36/34 秒，tailDiscarded=true。实际冻结清单包含尚未完成的视频，relay 仍在一个 target duration（夹具 2 秒）后关闭全部上游下载。此前用于旧按需暂存的截止，与并行预取的已发布依赖不匹配；本分支新增功能的 `fork-regression`，不归因于上游或擅自同步上游。

新增两个确定性 HTTP 复现分别延迟响应头和响应体：先确认请求进入，再停止，超过 target duration 后释放完整媒体。`published-tail-red` 的 **234 PASS / 2 FAIL** 均为期望 200、实际 410，非夹具等待超时。原生旧证据与独立 HTTP 红测相互支持。

## 停止合同

- 立即冻结各路最后实际发布的清单与本地 URI，不刷新、不准入新资源、不重试失败分片。
- 调度器收集各路最后发布、尚未交付的媒体及 MAP/KEY 依赖，只等待池内已准入 ticket；已超过容量而未准入的依赖明确返回未完成，不临时扩大池。
- 完整体封口就立即结束下载阶段，后续从就绪缓存交付。不固定睡满一个延时；待结束集合与实际完成事件均明确。
- 下载阶段使用原响应总预算并加独立 20 秒停止上限，已有单请求空闲/总时限继续有效。超时主动取消实际请求，pool/close 继续持有并等待迟到响应清理。
- native 的既有清单重载与封装排空时间另行保留；默认 target=2 时总上限 26 秒，而不是旧 6 秒。它是最大等待预算，非所有停止操作固定耗时；完整输入实际完成后即可提前结束。
- 返回值表示缓存完整度，不表示 native 消费确认。失败即记录尾部丢弃，即使 native 没有再请求那个缺失分片；用户停止之后不另发活动缺片警告。
- 调度器排空 Future 幂等，relay 关闭等待该所有者；未曾发布的路不拖住停止，已就绪初始化资源仍可从缓存读取。

## 验证与剩余项

新增调度器用例覆盖完成即返回、重复调用、超时取消与迟到响应所有权、缺少准入不新建下载、未发布路立即结束。原生控制保持同一 6 秒窗口和 12 秒慢媒体/响应头；提升门禁，要求 tailDiscarded=false、起止音视频包时间差各小于 50 ms，原有序号连续、正常结束及关闭池零占用仍保留。
