# OPENREC / mellow-fan 应用接入（2026-09-09）

## 范围与实现

从 `cd20a60b62719ebbf5e26313449375ac9809c409` 接续
[底层合同](OPENREC_API_AUDIT_2026_09_09.md)，新增应用入口而非复制参考项目的旧 HTML 正则。
版本仍为 3.1.8+4121，没有合并上游、更新依赖或 Root/LSP 模块。

- 注册 `openrec` 为 mellow-fan (OPENREC)，热门与分类绑定真实目录控制器；单一公开直播目录
  不伪装成全站分类。分页仅由空原始页终止，不以去重后的频道卡数量推断尾页。
- 收藏、播放、刷新与录制使用 `{publicId}@{openrec_user_id}` 复合键。大小写保留的公开 ID
  用于查询，数字身份用于核对；重分配或不一致报 identity，避免收藏悄然转到其他主播。
  官方外部打开只解码为 `/user/{publicId}`，忽略过期或导入的任意 room.link。
- 老 OPENREC 与新 mellow-fan 的频道/广播分享都经过异步 API 身份核验后导入；超时、取消
  丢弃迟到结果。裸 public ID 不是持久收藏键，入口为公开目录或分享链接；频道改名需重新核验，
  尚未实现自动改名跟踪。同步网页搜索解析器不生成缺少数字身份的伪有效房间。
- 详情刷新只取元数据，不访问 CDN；只有明确离线返回离线。多个当前广播显示范围说明，
  播放报告 ambiguous，不猜第一场。目录同频道多场卡片不使用首场标题或相加观看人数；
  同一公开 ID 出现冲突数字身份时报错。
- 播放与严格录制解析重新读取频道、当前广播及主列表；恢复时重新获取全部输入并匹配原画质
  稳定 ID，不回用旧签名 URL，也不把请求对象中任意 data 作为播放地址。
- 三个 HLS 源族共用 20 秒解析批次与取消作用域；单族访问/网络失败可保留成功族并显示说明，
  schema、身份、受限模式与取消错误终止。致命失败取消并行读取，迟到错误仍被消费。
- 播放器和 FFmpeg 使用同一 User-Agent、Referer、Origin；不注入 Cookie，不修改系统代理，
  也不把代理失败悄悄切至 DIRECT。

## HLS 与设置合同

`openrec_hls.dart` 从实际主列表的 STREAM-INF 属性和紧随 URI 生成菜单；正确处理带逗号的
CODECS、相对 URI、重复 CDN，以及分辨率/FPS/源族对应的稳定标识。带宽、签名路径变化
不改变已知分辨率的 ID；低延迟与公开源保留独立身份。实测夹具为普通 5 档、公开 1 档、
低延迟 1 档，共 7 个选项；这些是主列表声明，不代表解码测量或每个房间固定有 7 档。

滚动媒体列表保持 Auto；声明外置音轨时保留 master，避免直接选 video child 丢音轨。
ENDLIST/VOD 是媒体不可续接，不推导频道离线；加密是尚待集成的观看模式，未改写明文。
这些语义参照 [RFC 8216](https://www.rfc-editor.org/rfc/rfc8216.html) 的媒体列表与多音轨说明。
解析有 2 MiB 和 1000 档上限，校验变体/音轨/分片引用 authority；不是所有 HLS 标签的完整解析器，
也未宣称子列表所有嵌套请求都经过此处验证。

平台目录迁移 9→10、在线人数迁移 5→6 只追加新平台一次，保留其他平台关闭和顺序；
重开真实 Hive 后保留用户关闭 Openrec 的选择。备份保留复合键、数字身份、标签与顺序。
在线人数设置增加实际开关与中英文说明；隐藏人数保留未知，不把累计观看当在线数。
搜索与弹幕能力明确保持未接入，特殊房间也不因增加平台菜单就记为完成。
