# 0037 界面先复刻 3.x，再逐项升级

- 状态：已接受（取代 spec/design/principles.md 中与 3.x 外观和布局冲突的部分，见“影响”）
- 日期：2026-09-28

## 背景

- v4 按 spec/design/principles.md 重新设计了界面：
  - 四个一级入口：关注、发现、搜索、我的；
  - Material 3 默认配色；
  - 精简的卡片（封面加一行文字，不显示头像）；
  - 去掉了大部分外观自定义（主题色、分项字号、卡片样式）；
  - 图标换成 Material Symbols。
- 第一次构建后用户实际使用 Windows 版，反馈“界面和布局不如老版本”。对照 3.x 源码（legacy/lib）：
  - 3.x 的卡片信息更多：头像、主播名和标题分行、平台徽标；
  - 导航更直接：关注、热门、分区、录制中心都在底部栏；
  - 可自定义的地方更多：主题色和透明度、5 个分项字号、字重、卡片布局、圆角、头像、徽标；
  - 品牌蓝色更鲜明。
- 用户要求：先按老版本的界面完全复刻，再在此基础上升级优化。

## 决定

1. **v4 的界面层以 3.x 为蓝本重做**。
   - 范围：导航结构、页面布局、卡片、直播间（竖屏、横屏、全屏、桌面）、设置页和各级菜单、对话框和弹层、主题（主题色、透明度、字体和字号、圆角、间距）、图标、文案，全部按 legacy/lib 的实现复刻。
   - 手机、平板、桌面三种布局沿用 3.x 的 mobile_view 和 tablet_view 划分。
2. **v4 的内核不动**：live_core、live_net、live_media、live_player、live_danmaku、live_record、live_iptv、live_store、live_cast，以及应用的 provider 和路由逻辑都保留。复刻只换界面，不回到 GetX；状态仍用 Riverpod，路由仍用 go_router。
3. **3.x 没有的 v4 功能**用 3.x 的视觉语言放进去，不另起风格。这些功能包括：电视模式、多选、搜索历史、设置搜索、骨架屏、插画空状态、按原因说明的错误提示。电视模式整体保留 v4 的实现（3.x 没有电视界面）。
4. **图标**：复刻阶段用 3.x 的 Remix 图标。`LiveIcons` 的语义目录保留，只把字形映射换成 Remix，以后要换回或再换只改一处（ADR 0036 的轴规则在复刻阶段暂停）。
5. **文案**：3.x 有的界面文字沿用 3.x 的中英文说法，繁体按 ADR 0034 的台湾用语译出。
6. **复刻不是照搬**（用户 2026-09-28 补充）：外观、布局和操作逻辑对齐 3.x，代码全部重写。
   - 按 v4 的方式实现：Riverpod、go_router、slang、live_ui 组件、`LiveIcons`。不搬 GetX 的写法，也不照抄旧文件结构。
   - 复刻时直接修掉 3.x 的问题，例如溢出、写死的尺寸、深色模式配色错误、缺少无障碍标签、状态不同步。
   - 不改变外观和操作习惯的增强可以同时做，例如响应式、电视焦点、快捷键、骨架屏和错误说明、动画、性能。
   - 会改变外观或操作习惯的升级先记为候选，放到第 7 条的“再升级”阶段。
   - 每一项的重写要点、修掉的问题和增强，都记在 docs/rewrite/v3-replica.md。
7. **顺序**：
   - 先复刻：基础外观 → 各页面 → 直播间 → 设置和菜单；
   - 截图测试全部重新生成，与 3.x 逐页对照；
   - 再升级：只把用户确认的改进（例如多尺寸适配、错误说明、性能）逐项加回，每项单独记录。

## 放弃的做法

- 在现有 v4 设计上局部修补，比如只加回头像、只加回主题色：用户要的是熟悉的整体界面，零碎修补很难对齐。
- 把 3.x 的界面代码整体搬回来：它依赖 GetX 和旧的服务层，和 v4 的内核接不上。

## 影响

- spec/design/principles.md 中关于一级入口、卡片、主题色、字号、图标的条目在复刻阶段不再约束实现；复刻完成后按升级的结果重写。
- ADR 0036（Material Symbols）在复刻阶段暂停，`LiveIcons` 映射改为 Remix。
- 截图测试（apps/pure_live/test/screenshots）的 golden 全部重做。
