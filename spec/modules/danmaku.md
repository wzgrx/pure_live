# 弹幕模块规格（danmaku）

- 状态：第 1 阶段草案，2026-09-27
- 范围：弹幕的连接、解码、统一消息、过滤、抽样、画面弹幕渲染、弹幕列表、醒目留言与在线人数的下发；单直播间、画中画/小窗、多画面共用
- 不含：各平台协议细节（在 `spec/sites/*`）、直播间手势优先级（在直播间规格）、录制时保存聊天（在录制规格）
- 依据：旧代码行号已在 2026-09-27 对照 master 工作树核对；提交哈希来自第 0 阶段诊断（[03-live-room](../../docs/rewrite/diagnosis/03-live-room-multiview-danmaku.md)）
- 本规格只规定行为和契约，不规定类名和代码拆分

**缩写**：DC = `lib/modules/live_play/controllers/danmaku_controller.dart`；GATE = `lib/modules/live_play/controllers/danmaku_message_gate.dart`；REP = `lib/modules/live_play/controllers/repeated_danmaku_filter.dart`；SIM = `lib/modules/live_play/controllers/danmaku_similarity_filter.dart`；LPC = `lib/modules/live_play/controllers/live_play_controller.dart`；VC = `lib/modules/live_play/widgets/video_player/video_controller.dart`；LIST = `lib/modules/live_play/widgets/danmaku/danmaku_list_view.dart`；BE = `plugins/flame_barrage/lib/src/core/barrage_engine.dart`；BW = `plugins/flame_barrage/lib/src/widget/flame_barrage_widget.dart`；MSG = `lib/common/models/live_message.dart`；DS = `lib/common/services/settings/danmaku_settings_controller.dart`；WS = `lib/core/common/web_socket_util.dart`。

**验收方式**：【单元】纯 Dart 单元测试（假时钟）；【样本】回放录制的真实弹幕流（脱敏）；【性能】性能套件测帧耗时；【真机】K90 或 Windows 实机记录。

## 1 统一消息模型

主线程只接收下列五类消息，不接收任何平台原始结构。

**公共字段**（每类都有）：

| 字段 | 说明 |
|---|---|
| 类型 | chat / gift / superChat / online / system |
| 房间键 | `平台:房间号`，用于防串房 |
| 会话令牌 | 本次连接的令牌（§2 CONN-4） |
| 消息 ID | 平台提供的稳定 ID，加平台前缀（如 `douyu:<cid>`）；没有则为空 |
| 发送时间 | 平台时间戳，可为空；为空时按接收时间排序 |
| 接收时间 | 本机单调时钟 |
| 是否本地 | 本机生成的消息（本地互动、发送回显），不受过滤和抽样影响 |

证据：MSG:68-122；`lib/core/danmaku/douyu_danmaku.dart:130-146`（ID 前缀、时间戳秒/毫秒换算）。

**各类字段**：

- **chat**：用户 ID、用户名、文本、颜色（RGB）、用户等级、粉丝牌等级、粉丝牌名；本地消息可带样式（位置：滚动/顶部/底部，字号、字重、描边、阴影、停留时长，默认停留 4 s）。颜色解析兼容 4、6、8 位十六进制，8 位时忽略 alpha。
  证据：MSG:28-66、68-122、124-157。
- **gift**：用户 ID、用户名、礼物 ID、礼物名、数量、价值、图标地址。[待确认：旧版没有任何平台产出礼物（MSG:5-6“暂时不支持”），只有本地互动会产生；首批 5 个平台中哪些要解码礼物、价值的币种与单位]
  证据：MSG:5-6；LPC:594。
- **superChat**：消息 ID、用户名、头像、文本、价格、开始时间、结束时间、背景色、底部背景色。相等判断：双方都有消息 ID 时只比 ID；都没有时比（用户名、文本、价格）；不按开始时间判断（有的平台每次轮询都按倒计时重算开始时间）。
  证据：MSG:159-200。
- **online**：指标种类（人气 / 在线人数 / 累计观看）+ 数值。不同种类不能互相顶替；平台只给数字时由站点适配器声明种类（B 站为人气，其余为在线人数）。
  证据：MSG:15-26；LPC:541-566。
- **system**：状态码 + 参数，界面按语言映射文案，不传自然语言。状态码至少包括：连接中、已连接、重连中、已断开（终态）、连接超时、平台不支持弹幕、录像模式提示、B 站游客昵称被打码提示。
  证据：DC:147-176、191-246、284-294；`test/danmaku_controller_lifecycle_test.dart:141、161`。

**验收**：【单元】每个平台至少一份样本解码为上述结构，字段逐项断言（沿用各 `*_danmaku_protocol_test.dart`）；【单元】superChat 相等规则、颜色解析。

## 2 连接管线（后台 isolate）

- **CONN-1 全部在后台完成**：连接（WebSocket 或 HTTP 轮询）、心跳、解压（zlib、brotli、gzip）、解码（JSON、protobuf、TARS、STT）、协议层过滤、过滤链、抽样都在后台 isolate；协议代码是纯 Dart，不依赖 Flutter 和应用层。主线程只接收批次。
  证据：诊断 03 ①.4、②（`web_socket_util.dart:214、264`；kuaishou:6、bilibili:8、huya:4、twitch:77 依赖 Flutter）。[待确认：一个 isolate 承载全部会话，还是每个会话一个]。验收：【单元】协议包用 `dart test` 运行；【性能】回放 200 条/秒，主线程占用 ≤ 3 ms/帧。
- **CONN-2 按批次送到主线程**：有消息时，距上一批满 64 ms 必须发送；消息稀少时可以在 16 ms 后提前发送以降低延迟。一批包含：列表消息、画面弹幕候选、醒目留言、在线人数（每种指标只保留最新值）、系统消息、本批丢弃计数。一批最多 200 条列表消息，超出丢最旧的并计数。
  证据：LPC:97-104、499-525（旧版在主线程按 64 ms 合批，最多 200 条）。验收：【单元】假时钟下的批次时间和上限。
- **CONN-3 连接参数**：
  - 启动超时 20 s，停止超时 5 s（停止卡住不能阻塞退出房间）；
  - 单次连接超时 10 s；
  - 无消息超时 = max(3 × 心跳间隔, 90 s)，超时视为断开；
  - 断开后重连：多个服务器地址时先快速换下一个地址；每轮试完所有地址后退避加长（基础 1 s × (完成轮数 + 1)，最多 6 倍）；最多连续 8 次；收到任何消息都把次数清零；
  - 超过次数进入终态：释放房间键，手动刷新时重新建立连接，不挂在死连接上。

  证据：DC:22-23、165-176、229-238；WS:112、124、170、253-293。验收：【单元】`test/danmaku_controller_lifecycle_test.dart:46、65、161`。
- **CONN-4 会话令牌与房间键**：
  - 同一房间只允许一个连接会话；连接、断开、换房串行执行；
  - 每次断开或新建连接都换新令牌；后台回调和主线程收到的批次都要同时满足：令牌是当前的、连接对象是当前的、房间键与当前或正在连接的房间一致，否则丢弃；
  - 换到不同房间：清空画面弹幕和去重、合并、相似度缓存；
  - 同一房间且连接健康（如画中画返回）：不重连；同一房间但已断开：重建连接但保留已显示的历史；正在连接同一房间时，重复请求不打断握手；
  - 平台不支持弹幕：只提示一次，不假装连接，也不反复启动。

  证据：DC:13-18、111-181、248-250、296-306；`test/danmaku_controller_lifecycle_test.dart:14、31、85、102、122`。验收：【单元】快速切房 A→B→A，B 的迟到消息不得出现在 A。
- **CONN-5 协议层防串房**：数据包自带房间号且与当前房间不同就丢弃（斗鱼 `rid`）。
  证据：`lib/core/danmaku/douyu_danmaku.dart:124-125`。验收：【样本】。
- **CONN-6 连接随开关启停**：弹幕显示和画中画弹幕都关闭、或平台被排除（IPTV、CC）时断开连接；任一开启时连接。
  证据：DC:322-351。验收：【单元】。

## 3 过滤链

过滤在后台按以下顺序执行，便宜的在前。本地消息和系统消息不过滤。规则只有一份实现，单直播间、画中画、多画面共用。

- **FLT-1 去重闸门**（总是开启，只对 chat）：
  - 有发送时间且已超过 45 s：丢弃（重连后的积压）；发送时间比本机晚 10 分钟以上：视为格式错误，丢弃；
  - 有消息 ID：10 分钟内同 ID 只收一次；
  - 没有消息 ID：按（类型、用户 ID、用户名、文本）2.5 s 内只收一次（窗口故意短，观众重复发的同样内容仍能显示）；
  - 最多记 4096 条，超出淘汰最旧的；换房清空。

  证据：GATE:9-64。验收：【单元】`test/danmaku_message_gate_test.dart`。
- **FLT-2 屏蔽用户和关键词**（总是开启）：用户名规范化后精确匹配；关键词规范化后子串匹配。规范化（去首尾空白、转小写）在名单变化时对名单做一次，对每条消息做一次，两边一致。用户屏蔽某人或某词后，已显示的列表条目和待发队列里匹配的条目一并移除。[待确认：是否增加按用户 ID 屏蔽；是否做全角半角等 Unicode 规范化]
  证据：DC:252-270；LPC:527-532；`lib/modules/live_play/widgets/danmaku/danmaku_message_actions.dart:38、76`。验收：【单元】含大写字母的屏蔽词在单直播间、画中画、多画面都生效。
- **FLT-3 重复合并**（可选，默认关闭）：文本去首尾空白、连续空白合并为一个、转小写后比较；窗口 1–30 s，默认 5 s；窗口按最后一次出现滑动（刷屏期间一直合并）；最多记 1024 条。
  证据：REP:11-44；DS:74-75。验收：【单元】`test/repeated_danmaku_filter_test.dart`。
- **FLT-4 相似度过滤**（可选，默认关闭）：阈值 50–100，默认 85；缓存时长 1–60 s，默认 3 s；缓存 20–1000 条，默认 100；每条消息最多和最新的 96 条比较；完全相同先走快速路径。算法自写，替换 fuzzywuzzy（GPL-2.0-only，ADR 0006），在样本集上与旧的 partial ratio 结果一致或差异经过评审。[待确认：自写算法的具体形式]
  证据：SIM:9-147；DS:36-39、105-111、125-127。验收：【单元】样本集对比；【性能】单条最坏耗时。
- **FLT-5 疑似机器人**（斗鱼，协议层，默认关闭）：没有 `dms` 且 `if` 不为 1 视为疑似机器人；只有用户打开开关才过滤。默认保持完整。
  证据：`lib/core/danmaku/douyu_danmaku.dart:128-129`；DS:31-35；提交 31ee5cd7、4cbb43ba。验收：【样本】`test/douyu_danmaku_protocol_test.dart`。
- **FLT-6 设置即时生效**：过滤设置变化后立即作用于之后的消息，不需要重连。
  证据：DC:59-72；`lib/modules/multiview/danmaku/multiview_danmaku_session.dart:209-219`。验收：【单元】。

## 4 抽样

- **SMP-1 只抽画面弹幕**：列表接收所有通过过滤的消息（受 CONN-2 每批上限约束）；画面弹幕候选在后台按渲染预算抽样，保证送到主线程的候选速率不超过画面能发射的速率的 1.5 倍 [初始值，待用 200 条/秒样本校准]，主线程不为注定丢弃的弹幕排版。
- **SMP-2 均匀抽样**：超出时按时间均匀保留，不是只保留最早或最新的一段。本地消息不抽样。
- **SMP-3 预算随界面变化**：画中画、小窗、多画面焦点格用各自的预算（REN-6），主线程把当前预算告诉后台。

证据：PLAN §06“按密度抽样在后台完成”；VC:953-956 注释（16 ms 发射时热门房间排版和发热过高）。验收：【单元】抽样率；【性能】200 条/秒不掉帧。

## 5 画面弹幕渲染

- **REN-1 画布直绘**：一个画布绘制所有弹幕，不为每条弹幕建组件；滚动层与固定层（顶部、底部）分开；排版结果和绘制结果缓存复用。
  证据：PLAN §06；BE:413-490（旧版按内容缓存排版结果）。验收：【性能】。
- **REN-2 没有弹幕时停止绘制**：没有在屏弹幕、也没有待发弹幕时，停止帧回调，不再重绘；有新弹幕时恢复。按设定帧率推进（跟随显示同步，低帧率用累加器跳帧）；单步时长最多 3 个帧间隔。
  证据：BE:26-31、120-190。验收：【单元】空闲时帧回调数为 0；【性能】静止房间无重绘。
- **REN-3 帧率**：自动模式随界面刷新率策略：省电时房间 ≤ 60、画中画 ≤ 30；平衡时都为 60；最高时跟随设备最大刷新率。手动 30–240（画中画 15–240）。
  证据：DS:135-160。验收：【单元】`test/danmaku_refresh_rate_policy_test.dart`。
- **REN-4 密度上限（初始预算）**：
  - 每 50 ms 最多发射一条；
  - 同屏最多 48 条；
  - 待发队列最多 120 条，超出丢最旧的；
  - 待发超过 5 s 丢弃；
  - 每帧最多上屏 2 条，每帧排版次数不超过当帧上屏条数；
  - 一个 96 条的文字缓存（按内容和样式复用排版结果）。旧版的“排版缓存 320、绘制缓存 96、对象池 72”三层缓存不再沿用：弹幕进屏时才排版，同屏最多 48 条，96 条已覆盖同屏加重复内容；按条光栅化的图片缓存等真机数据证明段落绘制是瓶颈时再加（ADR 0020）。

  超出上限只降低密度，不掉帧。
  证据：VC:951-978；BE:321-336、408-416。验收：【性能】回放 200 条/秒，120 Hz 设备构建和光栅化 P90 ≤ 8 ms，主线程 ≤ 3 ms/帧。
- **REN-5 轨道与区域**：轨道高度 = 字号 × 1.55，限制在 24–64；显示区域百分比只应用一次；顶部、底部留白加上安全区；固定弹幕居中，占用轨道到过期；速度是单一的像素/秒值，横竖屏和桌面一致。
  证据：BE:72-104、466-480；VC:974、214-216。验收：【单元】旋转前后可用轨道数不变。
- **REN-6 各表面独立预算**：房间画面、画中画/小窗、多画面各有独立的渲染器与预算。画中画默认：同屏 6 条、每 350 ms 一条、30 fps、字号 12、区域 50%、速度 90。多画面只在焦点格（大画面或声音焦点格）显示弹幕，页面级开关。
  证据：VC:481-482、226-259；DS:20-29；诊断 03 ①.5。验收：【单元】`test/pip_danmaku_preview_test.dart`、`test/compact_danmaku_metrics_test.dart`。
- **REN-7 只有 chat 上屏，且只在播放时**：画面弹幕层只显示 chat（superChat、gift、online、system 不上屏）；非本地弹幕只在播放中送入画面（暂停、缓冲、起播时不送）；本地消息总是显示；列表不受影响。
  证据：DC:193-218；VC:179-183。验收：【单元】。
- **REN-8 点击与长按**：点击或长按在屏弹幕打开操作（复制、屏蔽），两项都有开关，默认开启；长按后 1 s 内的点击忽略；操作面板打开期间弹幕层暂停，新弹幕暂存（受待发上限约束），关闭后继续。
  证据：VC:132-149、217-222、262-267；BE:106-118、192-200。验收：【单元】。
- **REN-9 释放**：表面卸载时立即停止帧回调、释放绘制缓存，不等垃圾回收。
  证据：BW:82-89。验收：【真机】Windows 反复进出房间和画中画 20 次，堆内存不增长。

## 6 弹幕列表、醒目留言、在线人数

- **LST-1 环形缓冲**：房间历史为容量 500 的环形缓冲；每批只通知增量（追加的范围、按条件移除、清空），不整表复制。
  证据：LPC:97、515-525（旧版每批复制最多 500 条再整体替换）。验收：【单元】通知内容；【性能】高密度下列表更新耗时。
- **LST-2 跟随与冻结**：默认跟随最新；用户开始滚动时停止跟随，冻结当前快照，显示新消息计数（上限 9999）；回到底部或点提示后恢复跟随并刷新到最新。排队中的“滚到底”在用户手势开始时作废（否则会打断拖动）。界面刷新节流 80 ms；本地消息立即显示并滚到底。
  证据：LIST:33-49、122-152、169-228。验收：【单元】`test/danmaku_list_scroll_policy_test.dart`、`test/danmaku_list_resume_test.dart`。
- **LST-3 冻结时屏蔽**：冻结期间屏蔽某人或某词，只移除匹配的条目，保留其余条目和用户的滚动位置。
  证据：LIST:88-97。验收：【单元】`test/danmaku_frozen_filter_test.dart`。
- **LST-4 画中画返回补刷**：进入画中画时列表会被移出界面树。返回时由房间级状态发出“展示已恢复”通知，同时补刷积压的批次；列表据此回到最新。连接修复在画中画真正结束后进行（等待 180 ms 合并多次返回信号，失败 120 ms 后重试），连接健康时不重连。
  证据：LPC:195-220；`lib/modules/live_play/controllers/danmaku_presentation_recovery.dart:10-70`；LIST:111-119。验收：【单元】`test/danmaku_presentation_recovery_test.dart:7、30、50`；【真机】K90 进出画中画 20 次列表不停。
- **LST-5 醒目留言**：与弹幕列表分开显示；按 §1 superChat 的相等规则去重；到结束时间自动移除（按最近的到期时间设一个计时器）；同一房间重新加载元数据时保留，换房清空。
  证据：LPC:330-386。验收：【单元】。
- **LST-6 在线人数**：每批只取每种指标的最新值；单独订阅，不触发整页重建。
  证据：LPC:541-566；诊断 03 ①“观众数更新让整页重建”。验收：【单元】。
- **LST-7 系统消息**：同一状态 3 s 内只显示一次。
  证据：DC:284-294。验收：【单元】。
- **LST-8 礼物**：不进画面弹幕层；在弹幕列表里显示为一行（“用户 送出 礼物 ×N”），与聊天按到达顺序排列，受屏蔽用户过滤（2026-09-28 按 principles §5.2“礼物只显示为列表里的一行”定稿）。
  证据：PLAN §06“交互”。验收：【单元】。

## 7 键盘焦点

- **KEY-1 弹幕层不抢焦点**：画面弹幕层不可获得焦点（不自动聚焦、不可用 Tab 或点击聚焦），但仍响应点击和长按；Esc、空格、媒体键由播放器处理；同时挂载多个弹幕表面时，输入框的焦点和输入不被抢走。
  证据：BW:92-100；提交 1c22bffe；`test/danmaku_keyboard_focus_test.dart:20、68`。验收：【单元】全屏时按 Esc 退出全屏；弹幕层挂载后输入框仍能输入。
