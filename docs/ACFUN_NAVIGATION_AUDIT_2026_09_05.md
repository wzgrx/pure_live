1. `GET https://live.acfun.cn/api/channel/list`：`count`、不透明 `pcursor`、可选 JSON `filters`。
   `channelListData.result=0`，`liveList` 是目录房间列表，条目本身没有 `result`；
   `pcursor=no_more` 表示结束。页码与 cursor 分开处理；游标丢失后禁止重放第一页。

   `filterType=1`，全部 0、虚拟偶像 4、游戏 1、娱乐 3、其他 2。
   实测游戏筛选返回的房间 `type.categoryId=1`；不使用 `/api/header` 的视频/文章导航冒充直播分区。
3. `GET https://www.acfun.cn/search`：`keyword`、`type=user`、一基 `pCursor`、
   `quickViewId=up-list`、`reqID=1`、`ajaxpipe=1`。官方搜索分页步长为 **30**，过滤后实际条目可能少于 30。
   Content-Type 为 `application/octet-stream`，实际是 UTF-8 JSON 加
   `/*<!-- fetch-stream -->*/` 分隔符；只读取首段 JSON 的 `html`，不执行 js/scripts。
4. `.search-up` 的 `data-up-exposure-log.up_id` 与 `/u/<id>` 绑定主播身份。
   `is_on_live` 在开播时是 liveId 字符串，未开播时是空字符串，不按 bool/int 强转。
   `.total-num[data-total]` 给出结果数；无结果样本的 data-total 是空字符串，另有
   `共0条结果` 和 `.empty-page`。越界页样本 data-total=100、无条目、有 empty-page。
   只有完整的空结果证据才返回空列表；拦截页面/字段缺失保留错误。
5. 搜索提供粉丝数，不提供当前在线数。在线人数保持未知，进入房间后重新读取实时状态。
   搜索包括未开播作者，不承诺每位 AcFun 作者都是主播。

## 设计与回归边界

- 目录状态按筛选和 pageSize 隔离，实例重建后复用共享分页服务；第一页刷新替换代次，
  旧请求不回写新游标。同一页在途合并，已知结束不再请求；查询和游标数量都有上限。
- 搜索按实际条目填满应用页；下一页只保留未消费的官网页余量，不猜测绝对条目偏移。
  最多保留 8 个查询、每查询不足 30 条余量；单次应用页最多请求 4 个官网页，总时限 8 秒。
  失败不提交游标和余量；重复请求合并，刷新/容量淘汰取消旧请求，迟到结果不写回。
- 分类名称/图片来自官网，不新建硬编码分类表；缺失分类合同保留错误，而非显示空白成功页。
- 远端弹幕尚未接入；平台入口如上线必须同时注明此限制。本地互动和远端弹幕分别处理。
- 覆盖目录身份、游标结束/重复/丢失、跨分类、刷新竞态、容量回收；搜索 liveId 字符串、
  离线/未知、HTML 实体、请求编码、30/20 边界、空结果、错误页、取消和超时。

  第一版“每页数量必须等于总数推算值”的校验过严，固定偏移切片还会让 20 条应用页提前结束。
  现按实际条目消费，测试覆盖稀疏页、整页被过滤、错误重试不丢余量、刷新取消、并发请求和容量回收。
- 新平台若直接使用空弹幕引擎，会继承本分支“正在连接”但从未收到 onReady 的状态。
  接入前补齐空引擎能力说明：没有伪造远端连接成功，不重试空引擎；本地互动仍独立可用。
  正常 WebSocket、PiP 保持连接与跨平台切换继续走原有路径，并有相邻回归。
