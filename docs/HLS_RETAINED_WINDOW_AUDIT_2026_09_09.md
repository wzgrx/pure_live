# HLS 清单保留元数据层（2026-09-09）

实现 `89879fc69b6b316e7386f1ed343ae8d620f140cd`，起点 `8ae4e60f`。承接[原生预取对照](HLS_NATIVE_PREFETCH_AUDIT_2026_09_09.md)。**这是有界预取的基础组件，尚未接入生产 relay、轮询、媒体下载、缓存发布或播放器，真实录制缺口仍未修复。**

## 为什么需要这一层

上一轮固定源已证明完整暂存延后了 native 下一片请求；直接移除暂存又失去半片保护。独立预取需要在短窗口刷新后仍准确记住旧分片及依赖，按简单 URI 行拼接会丢失隐式字节偏移、初始化段所属密钥、连续性编号等状态。本批实现不可变分片描述与原子窗口合并，为后续下载调度提供明确身份与淘汰结果，而非立即改变线上输入。

这属于修复既有 **fork-regression** 的新基础实现，不是另一个已发布版本 Bug 的红绿修复。完整暂存来源、冻结上游/merge base 比较在前篇，本批没有同步上游。静态引用检查显示目前只有新测试导入新组件；其限制没有改变原有播放、录制或 TTing 接口行为。

## 已实现的合同

`lib/recorder/services/hls_retained_window.dart`：

- `HlsMediaSnapshot` 提取完整媒体清单的序列、单片时长、discontinuity、显式或推算 PDT、gap，以及媒体、初始化和密钥引用。键值与列表不可变；错误信息不包含源地址或密钥内容。
- 隐式媒体 BYTERANGE 只接续同一 URI 的前一有范围分片，解析时转成绝对 offset/length。没有基准、换 URI 或数值溢出时失败，避免旧前缀淘汰后请求错字节。MAP 的省略 offset 暂按歧义拒绝，未猜测基准。
- MAP 捕获创建时的密钥集合；后续媒体密钥轮换或 METHOD=NONE 不改变初始化依赖。多个 KEYFORMAT 分别保留；属性顺序、同等相对/绝对 key URI 不产生假冲突。这里只存引用，不取得或解密媒体。
- discontinuity 清除推算时间，但保留同一待输出分片此前已有的显式 PDT。无时区、日历归一化的非法日期和超界时区拒绝，避免用 DateTime 的自动归一化制造时间。推算以微秒取整，显式/推算标志分别保留，不作为音画同步证明。
- `HlsRetainedWindow` 一实例绑定一个选中媒体清单 URL 和一个来源代次。相邻刷新可保留之前连续分片；同 sequence 的 URI/范围/密钥/MAP/discontinuity/时长冲突、PDT 冲突、序列空档、旧范围回退、来源或 targetDuration 改变均在提交新状态前失败。
- ENDLIST 是终态，拒绝重新打开、追加及旧短清单提前终结已有尾部。包括空清单终态刷新；重复匹配终态不改变历史。
- 按片数和序列化元数据字节两个预算淘汰最旧描述，返回不可变的淘汰列表；该淘汰结果不是媒体已下载、已播放或应删除被租用 spool 的指令。消费租约需要后续缓存所有者实现。

[RFC 8216 的范围、密钥/MAP、PDT 和 discontinuity 定义](https://www.rfc-editor.org/rfc/rfc8216.html#section-4.3.2)指导这些状态归属；完整清单的序列也只在同一 rendition 内使用，不跨音视频按同序号对齐。本组件不是完整 RFC 校验器或重写器。

## 明确的容量及兼容边界

- 清单输入最多 4 MiB UTF-8，默认最多 512 分片；解析调用参数范围 1–4096。单片及其依赖的序列化描述上限 64 KiB，密钥格式数最多 16，避免大依赖状态随分片大量重复计算。
- 保留窗口默认 64 片、1 MiB 序列化元数据；可配置最高 512 片、8 MiB。预算不是 Dart 堆占用精确测量，更不是媒体缓存预算；媒体下载的并发、内存、落盘和完成缓存上限仍待共同设计。
- 仅接受可解析的 HTTP(S) 引用，整数范围限制在本机有符号 64 位；歧义和超界显式失败。真实源请求头、Cookie、查询参数策略及请求取消仍应由现有 relay 持有，本层不发请求。
- Master 与 delta SKIP 清单直接拒绝，避免错误分片编号。其他尚未理解的 EXT 标签收集为 unhandledTags，窗口禁止直接合并；包括 LL-HLS PART 等扩展。尚无未知标签原文 round-trip、日期范围/广告元数据重写、LL-HLS 控制、预加载和跳过重建能力。标准但本层暂未实现的全局标签也可能进入该集合。
- 尚未接线，故这些边界不是对全平台目标的收缩，也不应拿来移除既有能力。接入前必须补齐目标真实清单合同，尤其 TTing 的 LL-HLS 相关标签及带 token 刷新的身份处理。当前不同签名 URI 仍视为冲突，禁止默认为同一可复用媒体。
