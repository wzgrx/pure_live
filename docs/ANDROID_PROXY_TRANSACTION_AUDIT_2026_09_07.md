## 根因与复现

维护分支本地验收工具缺陷（fork-regression），不是应用代理实现或外部直播接口故障，也没有合并上游。

- 旧代理脚本的 Invoke-Adb 未检查前台；内存假执行器证实一次点击前没有前台观察。
- 旧快速开关路径连续使用同一 XML 的两个坐标，两次点击后才验证一次；实际函数提取复现见 `local-artifacts/android-proxy-transaction-20260907/baseline.json`，真实设备命令 0。
- 源码还确认：配置直接 rebind 端口、清理无条件移除 reverse，未区分既有映射和本次创建；代理 wrapper 允许自定义端口，但 restore 入口固定默认7897；在设置/恢复中自动 force-stop/monkey，并以历史坐标连续操作。这些操作与共享重要测试手机的边界不一致。
- 旧端点检查仅在所有可见文字中寻找127.0.0.1/端口，未区分应用层和播放器两组输入框，也未排除提示文字。

## 当前合同

`android_proxy_session.ps1` 为无加载副作用的辅助层；三个原入口保留为串行编排。

1. **目标**：明确Serial，先只读核对25102RKBEC/myron。复用精确当前u0前台解析；每次点击、滑动、UI dump和应用启动前复核，dump拉回后再次复核。输入/观察失败后停止本次UI，不重放、换目标、重启server或抢回其他应用。
2. **导航**：移除旧设备坐标快速路径、monkey启动与重复冷启动。按新XML中的菜单/设置/网络代理节点导航；滚动由观察到的唯一可滚动区域决定，停滞和次数均有界。调用者应先把Pure Live置于可识别的首页或代理页；不从任意未知页面盲按返回键。
3. **开关与字段**：每个开关分别查找、必要时点击、重新读取并验证；缺少checked/checkable或标签歧义不视为关闭。开启后分别检查对应开关下方的两个EditText实际text值；不修改地址/端口文字，不把hint当值。现有测试配置需预先为127.0.0.1和本次端口，否则回滚开关并报告。
4. **反向转发**：同端口不同目的地在任何导航前报错；已存在且目的地一致的映射只借用，结束不删除。新映射用`reverse --no-rebind`，命令明确成功才记录ownedReverse。建立结果含糊时保留reverseUncertain及cleanup-pending，不把后来观察到的同端口映射据为己有。
5. **事务记录**：首次改变开关前保存本地session.json，包含明确设备/包、实际端口、两个原开关状态、映射所有权、UI可能变化及状态。临时文件写完再替换记录；既有session路径禁止覆写启动。partial setup和录制失败均把同一session传给恢复入口，未产生session的预检失败不盲清理。
6. **清理**：先移除仍匹配的本次ownedReverse，再恢复两个原开关。原状态均false时回到DIRECT；原有混合开关状态则分别保留。已借用/后来被改到其他目的地的映射保留；一旦观察到被替换，永久放弃旧session的删除权，后来目的地恢复相同也不重新认领。恢复状态不明时保存cleanup-pending，输出session路径，不报告清理成功。有效记录的恢复步骤只允许目标应用或明确查询到的HOME作为重新进入前台条件，其他应用前台停止UI。
7. **无session的旧restore入口**：只关闭已在前台的目标应用两个开关，不推断任何reverse所有权，不删除固定7897或其他端口。带session时端口完全来自经检查的记录；自定义端口不会丢失。

本机ADB help实际确认了`reverse [--no-rebind] REMOTE LOCAL`和`reverse --list/--remove`语法；这是主机帮助调用，不是设备修改。

## 后续原生验证与限制

工具合同已推进到可做受控原生补证的阶段，尚未证明新脚本在当前手机完整成功。下一次先确认明确型号/代号、轮次和前台，再保留数据覆盖安装现有候选；首轮只做代理开启/恢复及session对账，然后才运行Picarto短录和完整解码，不直接把所有长时场景合并执行。
