## 目标

3.x 的多画面在 4.x 里完整可用：四种布局、一大多小加格、每格独立播放、只有一格出声、每格音量 / 画质 / 线路、小格省流、选台、页级弹幕、沉浸和全屏、安全退出；每格的恢复规则和直播间一致（不再各写一套）；修掉 3.x 多画面的 8 个问题。

## 结果

- 提交：`6ac31a036`（2026-10-01 合并）。当时 4 个文件约 2500 行；A13.2 之后拆成 `logic/` 和 `widgets/` 共 10 个文件约 4000 行。
- 做了什么（详见 [record.md](record.md)“做法”“与 v3 的功能对照”）：
  - c1 逻辑和界面分开：`MultiviewController`（`ChangeNotifier`）对应 3.x 的 `MultiviewController` + `MultiviewDanmakuSession`，依赖全部从构造参数传入；格子只有五个阶段，播放中的细分直接看会话的 `PlaybackState`。
  - c2 选台：取详情 → 发现画质 → 首选清晰度（不再固定最高档）→ `resolvePlayUrls` → `PlaybackPlan.of(preferH264:, onDemand:)` → `session.open`；每次分配有序号，晚到的丢掉。
  - c3 声音：只有一格出声；静音的格音量 0；房间音量和直播间共用 `roomVolumes`；3.x 的规则照旧（新起播的格成为声音来源，一大多小里往小格选台不抢声音，关掉出声的格声音转到第一个在播的格）。
  - c4 画质、线路、小格省流照 3.x；平台实际给的画质不同时按实际显示并提示。
  - c5 弹幕：页级开关默认关；只连一个房间（一大多小是大画面，其他布局是出声的格）；经 `DanmakuMessageFilter`；飞行层和弹幕设置面板复用直播间的。
  - c6 布局和显示模式：四种布局、一大多小在桌面加到 9 格、`GlobalKey` 让晋升时视频整体搬移不重建；沉浸、全屏（手机隐藏系统栏并转横屏）；返回和 Esc 先回到正常；安全退出。
  - c7 上次的画面：`meta` 的 `multiview.session`，再次打开时询问恢复。
  - c8 修了 8 个 3.x 问题（record“审查发现的 v3 问题”）。
- 偏差：弹幕的次要设置（帧率、字体、表情图片）当时同直播间留给后续——字体和纯文字之后自动有了（`danmakuLookOf`），帧率没传（N01.2），表情没传（N01 已知问题）；Windows 焦点小列的可见性当时缺 `setPresentationVisible`，A13.2 用会话的 `setPresentationVisible` 和 `setAudioOnly` 做完（“看不见的格只留声音”）。
- 测试：当时 7 个（控制器 5、页面 2）；现在 `test/features/multiview/` 共 17 个（控制器 6、页面 7、几何 4）。
