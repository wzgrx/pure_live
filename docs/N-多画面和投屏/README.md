# N 多画面和投屏

多画面和投屏的功能。界面在 A13。

两个“把直播放到别处”的功能：**多画面**（一个页面里同时看 1～4 个直播间，电脑上最多 9 个，声音只出一路、弹幕只连一路）和**投屏**（把当前直播的地址经 DLNA 投到同一局域网里的电视或盒子）。排在网络电视之后：两者都是少数用户偶尔用的增强功能，逻辑独立；但多画面同时解码 4 路，最考验播放层的稳定和性能，出问题时用户感受很直接。

## 范围

- 管什么：
  - **多画面**（N01）：`apps/pure_live/lib/features/multiview/logic/`（`MultiviewController`：格子、布局、选台、声音焦点、每格音量和画质和线路、小格省流、看不见的格只留声音、页级弹幕、上次的画面）、`multiview_page.dart` 里的逻辑部分（显示模式、全屏的方向和系统栏、安全退出、格子里的飞行弹幕参数）。
  - **投屏**（N02）：`packages/live_cast`（SSDP 搜索、设备描述、AVTransport 控制、`DlnaCastController` 的流程）和它在直播间里的接法（`features/live_play/dialogs/stream_dialogs.dart` 的 `CastDevices`：组播锁、本地网络权限、投给电视的标题）。
- 不管什么：
  - 多画面页、格子、工具栏、选台面板、投屏列表长什么样 → [A13.2](../A-界面设计/A13-网络电视和多画面界面/A13.2-多画面/README.md)（多画面界面）、A07.6（直播间里“投屏”所在的取流弹窗）。
  - 每格的播放会话、恢复规则、帧看门狗 → G（`PlaybackSession`，多画面每格一个）；飞行弹幕层怎么画 → D03；弹幕帧率设置的规则 → D05。
  - 投屏入口所在的直播间菜单和取流流程（选画质、选线路）→ C03；Android 的组播锁、本地网络权限 → O、O04；屏幕常亮的原生部分 → O05。
  - 电视端（手机投到“纯粹直播电视版”）的同步 → J03 的同步到电视，不是 DLNA。

## 风险和注意

- **性能**：手机同时解码 4 路是这一组最重的场景；改多画面的任务要在 K90 上看帧时间（`adb shell dumpsys gfxinfo com.mystyle.purelive.v4dev`），看不见的格要真的停解码（A13.2 的 `setOffscreen`）。格数上限：手机 4、电脑按处理器数 4 / 6 / 9（`multiview_geometry.dart:10`）。
- **投屏的设备差异**：DLNA 渲染器（小米电视、乐播、Kodi、各种盒子）的实现差别很大；改 `live_cast` 时保留 3.x 的成功路径（先设地址再播放、MX 和轮次、`AVTransport:1` 的报文），只在 3.x 会失败的地方加重试；测试用 `packages/live_cast/test/` 的三份设备描述样本。
- **局域网**：投屏要 Android 17 的“本地网络”权限、很多手机要组播锁（`MulticastLock`）；开着 VPN（Clash TUN）时组播要按网卡发（N02.1 问题 4）。
- **规则**：多画面的弹幕和直播间用同一组设置（3.x 同）；多画面房间音量和直播间共用 `roomVolumes`（3.x 的键）；投屏只投 http/https、不带用户名密码的地址（3.x 的校验）；会话型的流（niconico、BIGO、FC2 只有“配方”没有地址）不进投屏（C03）。
