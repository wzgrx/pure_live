## 实现和身份边界

1. `KilakilaSite` 实现原生目录分页能力。热门与新人分别使用已验证 type=0/107，固定原生页大小 10，保留服务器 page/isLastPage，而不是按过滤后的条目数猜末页。热门与分类实际工厂均选择 `LiveDirectoryController`，完整页先缓冲，再按两端界面页大小显示；页内/跨页按 UID 去重，避免同主播跨广播重复收藏。旧列表接口保留显式 page/pageSize。
2. 应用 `LiveRoom.roomId` 和 `userId` 均为主播 UID；单次广播 ID 和展示房间号不作为收藏身份。元数据刷新只读当前主播卡片，省去媒体请求；播放、录制与错误恢复每次重新取 UID→当前广播→匹配主播的详情，无旧广播缓存。画质 ID 是 flv/hls，不以签名 URL 为 ID。
3. 主页明确空卡片表示未公布当前广播，应用保留 unknown，不新增下播证明。陌生状态同样保留 unknown；网络/结构/历史回放/收费/媒体缺失错误继续传播。严格详情只接受免费、status=4、已验证主机/路径的服务器媒体地址；本批没有实现受限直播访问或原生签名期限推导。
4. `LiveUrlTool` 在解析前保留原始 URL 字符串，避免 URI 规范化改变分享校验对象。主播链接直接提取 UID；广播链接异步查真实主播后才返回应用身份。外部取消与 12 秒默认总期限只取消该解析持有的请求 token，不关闭全局 HTTP 客户端。同步网页解析器只接收主播身份，不把广播 ID 当 UID。
5. 官网打开按 UID 生成已核对的主播主页，不使用导入的任意 link。持久化沿用 `LiveRoom.toJson`：UID 保留、临时媒体与 link 不保存；重新打开时主页可由 UID 重建。分享命令按实际处理器显式携带 room.link；未改动通用模型的序列化格式。
6. 设置目录版本 7→8 仅追加克拉克拉，保留已隐藏站点与顺序；关掉新站点后重开 Hive 仍关闭。旧版本升级链路的预期同步扩展，备份中的大小写、重复 ID 和首选站点按既有规则处理。
7. 播放、多画面、音频与 FFmpeg 复用 `PlaybackHeaderResolver` 中的匿名 Referer/User-Agent。watchNumber 没有验证为实时在线人数，保持未声明；搜索与弹幕未接入，界面目录说明及实际搜索控制器不宣称支持。
