## 先复现的八个缺陷

### 1. 旧会话释放新会话的采样锁

旧会话文件读取仍在等待，新 startAck 重置 task ID 对应的忙标志并启动新读取。
旧读取结束后，finally 无条件删除同一个 task ID 的忙标志，下次计时器又开始新读取。
状态化分片跟踪器本来要求顺序采样，实际出现两个同时运行的 sample；存在重复统计和错乱风险。
首个失败断言明确观测 `maximumActive = 2`，期望为 1。

### 2. 服务关闭后，迟到读取继续修改任务

取消 Timer 和 Stream 不会取消已经执行到 await 的文件读取。旧实现关闭时保留 active session ID，
读取结束后仍通过 session 校验。测试在关闭后释放 100 字节快照，任务从 0 被写成 100。

### 3. 旧终止事件在 await 后停止新会话

终止事件只在读取前校验 session。读取期间新会话已接管；旧事件恢复后仍删除新会话计时器、
active ID、租约信息，并把新任务改为 stopped。测试实际得到 stopped，期望为 running。

### 4. “强制最后采样”在忙时直接返回

原 forcePersist 只控制持久化，忙标志依然让函数立即返回。终止处理随后撤销会话，
正在读取的最后结果也被丢弃。测试先阻塞周期采样，再结束原生写入，旧实现提前进入 stopped。
正确行为是等待已有采样，再读一次包含最后写入的快照；100 → 150 字节均有独立断言。

### 5. 关闭订阅后，调度任务等待永远不会到达的终止通知

`_runTask` 先等待原生 start Future，再等待逻辑 lifecycle；onClose 取消事件订阅，
却没有解除后者。测试让原生真正结束且不再投递事件，调度占用仍为 1，目录保护未释放。
这会留下任务/控制器引用和缓存租约；本次没有将其等同于测出了客户端内存增幅。

### 6. 原生已经结束时，取消提前释放仍在收尾的任务

取消处理以“没有原生会话”直接判定整个录制流程完成，忽略已派发、仍在等待文件操作的收尾。
加入关闭阶段的反向验证后，实际调度占用提前变为 0，而收尾还停在受控 measure 中。
目录保护和排他任务槽都应保持到收尾退出，而不是只等原生停止。

### 7. 补读原生统计没有核对 native session ID

监测器虽然有 session 校验，但 `ffmpeg.getSession(taskId)` 返回的是原生当前实例，
事件投递与 native Map 更新之间有时序差。测试让 Map 已指向另一会话，旧监测从自己的
100 字节错误变成另一会话的 1000 字节；时长同样串入。补读现仅接受同一 native ID。
来源是本分支 `a718199de` 的原生统计补读。

### 8. 释放目录时重新查找全局服务，释放了另一个实例的租约

任务开始通过旧 CacheService 保护目录，关闭/服务重建期间全局注册被替换；
旧原生写入完成后的 finally 再查 `CacheService.to`，实际释放新实例的保护，旧实例仍保留引用。
测试同时验证原实例应解除保护、新实例应保留保护；旧实现第一项直接失败。
开始任务及恢复未完成录制都捕获真正取得目录租约的对象，finally 归还同一个对象。
这与第 5 项的未完成生命周期是两类独立问题。

## 设计与实现

```text
任务调度所有权
  → 取流与保护目录
  → 原生写入 Future
  → 最后采样（同一 monitor，顺序执行）
  → 待收尾分片登记 / 收尾 Future
  → 完成逻辑生命周期
  → 释放目录与调度槽
```

- 每个监测实例持有 task 对象、native session ID、tracker、Timer、采样完成栅栏、
  终止标志和速率基线。不再用多个 task ID 集合拼接异步所有权。
- 每次 await 后复核监测实例、task 对象、session 和服务关闭状态；旧实例只清理自己的采样栅栏。
- 终止标志先阻止新周期采样及重复终止事件，再等待当前采样，随后补一次新快照。
  终止函数在最终清理前再次复核所有权。
- 关闭先停止新工作、取消订阅并隔离快照；若已有收尾，等它退出后才完成逻辑栅栏。
  没有收尾时可以解除逻辑等待，但 runner 仍先等待原生 Future，保持正在写入文件的保护。
- 收尾跨文件 await 后观察关闭状态，保留未完成 TS 和待处理记录，不在服务已关闭时新开合并。
- 取消仅在没有原生会话、未处理终止会话和收尾 Future 时直接完成生命周期。
- 原生计数补读核对 native ID；目录保护捕获服务实例，不在退出时重新查全局注册。
- 不增加依赖、线程、缓存预算、录制码率、重试次数或全目录定时扫描。
  生产采样仍为每秒一次，常规持久化仍限频到 10 秒，分片跟踪仍走增量路径。
  不同录制任务互不占用对方的采样锁。
