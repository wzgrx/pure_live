# S03 统一验证

Android 4.x 的整体验收：A 组的界面任务都合并以后，把所有界面和主要流程按“确认的改动”在各种形态（K90 竖屏和横屏、模拟的宽屏和分屏、平板、深色、大字号）下从头到尾走一遍，再附一份基准测试报告。它是“4.x Android 版做完了”的最后一道检查。

## 范围

- 包括：
  - A06～A15 每个完成的界面任务（约 45 个）README 里“确认的改动”表（c1、c2……）逐条核对：保留的还在、修改的是新样子、增强的有、去掉的没了；`page/` 里的对比页导出图作参照。
  - 形态：K90 竖屏和横屏（869×400 dp，“横屏手机”布局）；`adb shell wm size 1600x2560`、`wm density` 模拟的宽屏分栏（≥840 dp）和窄横屏（740×360）；分屏（上下、左右）；有平板时真平板；深色主题；系统字号最大和应用文字大小 150%（A04.1 合并后）。
  - S02 各任务看不到或没有归属的：设置各页（A11.1～A11.5 的大部分）、宽屏首页（A06.2）、宽屏左右分栏（A07.5）、下载对话框和启动页的观感（A06.3、A06.4）、A07.13 的平板布局、A14.1 的跟主题模式的启动画面（宽屏）；以及 CHECKLIST 里“由谁验证”写“S03.1（回归）”的条目。
  - 基准测试报告：用 R01.1 的 `apps/pure_live/integration_test/perf_test.dart` 在 K90 上跑一遍，和 R01.2 的判定一起写进报告。
- 不包括（归哪里）：
  - 单个改动的真机验证（S02.5 的 18 个、S02.6、S02.4）——S03.1 只回归它们，不重复第一次验证。
  - 3.x 覆盖安装 → S04；数据迁移内容 → J06.1。
  - Windows（A16.1、X01.1）、电视（A17、X03）、苹果平台（A18）：按 D-004 现在只做 Android，这些客户端开工时在各自的组登记验收任务。
  - 发现的问题在哪个组修就开到哪个组（界面问题开 A 组新任务，标题写“接 A0x.y”）。
