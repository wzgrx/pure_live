## v3 的样子（`~/ref/v3ref`，`v3.2.11`）

- **三档**（`lib/common/models/app_refresh_rate_mode.dart:1-22`）：省电（默认，交给系统）、均衡、最高（设备上限）。文字和说明见 `general_settings_page.dart:173-209`；行 `:24-39`，对话框 `:195-260`（A11.4 已还原）。
- **控制器**（`lib/common/widgets/adaptive_refresh_rate_scope.dart:15-86`）：均衡：按下要最高（`:42-47`），滑动保持（`:49-53`、`:134-143`），松手或滚动结束 1.5 秒后交还系统（`:21`、`:55-58`、`:74-77`）；最高：前台一直最高；进后台释放，画中画（Flutter 报 inactive）保持（`:115-125`）；请求排队只发最后一个（`:22-24`）。
- **原生**（`android/app/src/main/kotlin/com/mystyle/pure_live/MainActivity.kt`）：`setHighRefreshRate`（`:128-134`）→ `applyPreferredDisplayMode`（`:309-339`）：在同分辨率的模式里取刷新率最高的，只设 `window.attributes.preferredRefreshRate`（高 = 最高，否则 0 = 系统决定），`preferredDisplayModeId` 固定 0（注释：只改刷新率时官方推荐这样，避免重的模式切换，`:324-327`）；显示变化 160 毫秒合并后重新应用并通知 Dart（`:61-71`、`:300-303`）；信息：当前、最高、支持列表、分辨率（`:341-377`）。
- **弹幕帧率跟随**（`common/services/settings/danmaku_settings_controller.dart:135-162`）：省电 = min(设备最高, 60)，均衡 = 60，最高 = 设备最高。
- 没有按视频帧率选刷新率，也没有告诉系统画面里是视频。

## 可选方案

| 方案 | 做法 | 好处 | 坏处 | 性能 |
|---|---|---|---|---|
| A（建议） | Android 11 起：播放时对 Flutter 的画面声明内容帧率（`Surface.setFrameRate(视频帧率, FIXED_SOURCE, 只在无缝时切换)`）；同时最高档、均衡档操作时把“希望的刷新率”改成视频帧率整数倍里最高的一档。Android 6～10 只改希望的刷新率 | 系统选模式，不闪屏；省电档也能落在整数倍上（通常是 60，更省电）；和 v3 的做法同一条路 | 声明对整个 Flutter 画面生效，界面动画也跟着这个刷新率（所以均衡档操作时临时升到整数倍里最高）；要从原生拿到 Flutter 画面的 Surface | 调用本身很轻；看直播不操作时 60 赫兹比 120 省电 |
| B | 直接指定显示模式（`preferredDisplayModeId` 选 60 或 120 的模式） | Android 6 起都能用，结果最确定 | 有的屏切模式会黑一下或卡一帧，v3 注释里专门避开（`MainActivity.kt:324-327`） | 切换时可能掉帧 |
| C | 不做（照 v3） | 没有风险 | 90、144 赫兹屏看直播不匀；最高档费电 | — |

## 什么时候用哪个刷新率

见 [v4-policy.jpg](v4-policy.jpg)。要点：

- 帧率来源：mpv 先读 `container-fps`，读不到用 `estimated-vf-fps`（稳定几秒后）；23.976→24、29.97→30、59.94→60。读不到时不声明。
- 选法：在当前分辨率支持的刷新率里，选视频帧率整数倍（误差 0.5% 内）的。省电：声明视频帧率，由系统选；均衡：不操作时整数倍里不超过 60 的那档（30/60 帧用 60，25/50 帧用 50，没有就不动），操作时整数倍里最高（120 或 100），停 1.5 秒回落；最高：整数倍里最高。
- 暂停、退出直播间、进后台清除声明；画中画保持（照 v3）；开关关掉时直播间和列表一样（照 v3）。
- 弹幕每个刷新周期都动、帧率上限取刷新率的整数分之一（D03.1 c3），刷新率变了速度不变。

## 拿不准的地方

1. K90 支持哪些刷新率（有没有 50、90、100、144）没查，图里按 60 / 120 画。
2. Flutter 画面声明 `FIXED_SOURCE` 和窗口的“希望的刷新率”（均衡档操作时）同时存在时系统怎么取舍，各厂商不同，要真机看；不行就操作时临时撤掉声明。
3. Flutter 的 Android 嵌入用 SurfaceView 还是 TextureView 会影响怎么拿 Surface，开发时确认 v4 用哪种。
4. FLV 直播流的元数据不一定有帧率，`container-fps` 读不到时等 `estimated-vf-fps` 稳定，等多久开发时定。
5. 新加的文字（“播放时匹配视频帧率”和说明、“这台设备只有 60 Hz，用不上”）是新写的，`zh.json` 里没有。

## 4.0.x 修订（R02.2，2026-10-02）

依据：[调研报告](../../../V-需求和反馈/V03-审查和调研/V03.2-流畅度、刷新率、分辨率调研/README.md) 第 1 节（R1～R4、R6，含 K90 实测）；任务单 [R02.2](../R02.2-刷新率策略修正/brief.md)；记录 [R02.2](../R02.2-刷新率策略修正/record.md)。

### 为什么改

- Android 文档写明：用 `Surface.setFrameRate` 声明过帧率的 Surface 会忽略窗口的 `preferredRefreshRate`。上面的 c3 在播放时既在 Flutter 画面上声明了视频帧率，又在均衡档操作时把窗口提示改成“整数倍里最高”，后一步对 Flutter 画面不起作用，触摸时能不能升到 120 全靠系统的触摸加速（K90 是 1.5 秒）。
- K90 只有 60 / 90 / 120 Hz：24 帧只有 120 是整数倍，25、50 帧没有整数倍。原来的选法在这时返回“不动”，交给系统（多半 60，25 帧在 60 Hz 下 2、3 交替）。
- K90 的 `frameRateCategoryRate` 是 normal=60、high=90：按类别投票，HIGH 只给 90。HyperOS 还有自己的投票（`PRIORITY_MIUI_REFRESH_RATE`），应用压不过它，用户也无从得知。

### 新旧策略对比

| 情况 | 旧（R02.1） | 新（R02.2） |
|---|---|---|
| 播放，省电 | 画面声明视频帧率（`FIXED_SOURCE`，只在无缝时切换），系统选 | 不变 |
| 播放 30/60 帧，均衡空闲 | 画面声明视频帧率；窗口提示 60 | 画面声明 60（`FIXED_SOURCE`）；窗口提示清零 |
| 播放 30/60 帧，均衡操作中、最高 | 画面声明视频帧率；窗口提示 120（对已声明的画面无效） | 画面声明 120（`FIXED_SOURCE`）；均衡档松手 1.5 秒后回到 60 |
| 播放 24 帧（K90） | 声明 24；窗口：空闲交给系统，操作中 120 | 空闲、操作中都声明 120（只有它是整数倍）；144 Hz 屏空闲 120、操作中 144 |
| 播放 25/50 帧（K90） | 声明 25/50；窗口：空闲交给系统，操作中最高 | 空闲、操作中都声明设备最高（K90 120） |
| 不播放，均衡操作中、最高 | 窗口提示最高 | Android 16 起：画面 `setFrameRate(最高, AT_LEAST)`，窗口提示清零；8～15 照旧用窗口提示 |
| 不播放，省电、均衡空闲 | 交给系统 | 不变 |
| Android 8～11 播放中 | 窗口提示（整数倍） | 不变：这些版本声明帧率时不能限定“只在无缝时切换” |
| 系统把应用压在 60 Hz | 用户不知道 | 设置“界面刷新率”下面一行提示，去系统设置调高；恢复后消失 |
| 投票方式 | 具体数值 | 不变：只投数值，不投类别；清单不声明 `appCategory=game`（Android 15 起游戏默认 60 Hz），有测试检查 |

规则：

- 优先选整数倍；均衡空闲取不超过 60 的那档，没有就取最低的整数倍；操作中和最高档取最高的整数倍。
- 没有整数倍时取设备最高：每帧多停或少停一个周期，周期越短越不明显（25 帧在 120 Hz 下误差约 21%，60 Hz 下约 42%）。
- 所有播放中的请求都只走画面上的帧率声明，窗口提示清零；声明的值始终是具体数值。

K90（60/90/120 Hz）上看直播：

| 视频 | 省电 | 均衡：空闲 / 操作中（旧） | 均衡：空闲 / 操作中（新） | 最高（新） |
|---|---|---|---|---|
| 30、60 | 声明，系统选（多半 60） | 60 / 系统触摸加速 | 60 / 120 | 120 |
| 24 | 声明 | 系统 / 系统触摸加速 | 120 / 120 | 120 |
| 25、50 | 声明 | 系统 / 系统触摸加速 | 120 / 120 | 120 |

### 手感和耗电的变化

- 均衡档看 30/60 帧直播：拖聊天、面板时由我们自己的声明升到 120，不再只靠系统的触摸加速；松手 1.5 秒回到 60，和以前一样。
- 均衡档看 24/25/50 帧（网络电视、部分直播）：空闲时从系统选的 60（2、3 交替）变成 120（25 帧 5、5、5、5、4），更匀，也更耗电；144、165 Hz 屏上 25/50 帧空闲时也是 144、165。
- 列表等不播放的页面（Android 16 起）：均衡档触摸时改成“至少最高”的声明，效果应和窗口提示一样，要真机确认。
- 最高档、省电档的行为不变。
- 厂商限制检测只在用户操作时（按下或松手 1.5 秒内）计时：画面静止时系统本来就可能降频，不算限制。

## 实现和验证
