# V04.1 还原哔哩哔哩访客看到的打码昵称（平台为隐私打码，见 D-013）

- 编号、状态、档位、规模：以登记表为准，见[子分类页](../README.md)和 [STATUS.md](../../../STATUS.md)（不做，2026-10-02）
- 类型：功能（不做）
- 来源：用户 2026-10-02 的问题 04“哔哩哔哩的弹幕没有用户名字”（[V02.2](../../V02-用户反馈和issue/V02.2-用户10月2日的问题/README.md)）；全面审查 A-04（[V03.1](../../V03-审查和调研/V03.1-全面审查/README.md)）
- 相关：决定 **D-013**（访客看到的打码昵称不去还原，做登录引导；打码昵称不能“屏蔽此用户”）；替代的 [D01.32](../../../D-弹幕/D01-平台弹幕协议/D01.32-哔哩哔哩访客昵称和粉丝牌/README.md)、[D02.1](../../../D-弹幕/D02-过滤和屏蔽/D02.1-打码昵称不能屏蔽/README.md)

## 是什么

没登录哔哩哔哩时，直播间弹幕的昵称显示成“观***”这样。“还原”指想办法让访客也看到完整昵称（换字段、换接口、用别的身份连弹幕服务器等）。

## 为什么不做

- **拿不到**：服务器按连接身份打码，不是客户端显示的问题。V03.1 解码仓库里访客（uid=0）的录制 `fixtures/bilibili/danmaku/S13-protover2-paired`、`S13-live`：`info[2]` 是 `[0, "观***"]`，富文本字段也打码，`dm_v2` 是空的；访客帧里没打码的只有头像 `user.base.face`、粉丝牌 `user.medal{name, level}`、财富等级和发送者哈希 `info[0][7]`。4.x 的取名顺序（`packages/live_danmaku/lib/src/sites/bilibili.dart:574` 的 `_chat` → `_userName`、`_richName`）和 3.x（`v3.2.11:lib/core/danmaku/bilibili_danmaku.dart:449` 的 `_preferredBilibiliUserName`）一样，不是退化。
- **不该拿**：平台明说为保护隐私打码（D-013 的依据）；用别人的登录身份或抓网页去拼全名，既违反平台规则，也会把用户卷进风险。
- 决定：D-013（2026-10-02，维护者）。

## 做了什么替代

- [D01.32](../../../D-弹幕/D01-平台弹幕协议/D01.32-哔哩哔哩访客昵称和粉丝牌/README.md)（`2eea8022a`，待真机）：聊天列表顶部常驻“ⓘ 访客模式下哔哩哔哩会隐藏昵称　去登录”，登录后自动重连、昵称完整；Cookie 失效时提示“登录已失效”；解析粉丝牌（名字前的“牌子名 等级”）、卡片样式显示头像。
- [D02.1](../../../D-弹幕/D02-过滤和屏蔽/D02.1-打码昵称不能屏蔽/README.md)（`40dc22279`，待真机）：打码昵称不能“屏蔽此用户”（以前屏蔽一个“观***”会把所有昵称以“观”开头的观众永久屏蔽），已存的打码屏蔽第一次打开屏蔽页时清掉并提示。

## 验证

- 不做的事没有测试；替代的两个任务的真机步骤在 S02.5 阶段 2（2A-01～2A-09）。

## 以后在什么条件下重新考虑

- 哔哩哔哩对访客不再打码，或者公开给出访客能合法拿到全名的字段（例如弹幕协议的新版本）——到时 D01 的上游对照或平台巡检（E07）会看到，重新登记成 V01 提议。
- 用户要求“按发送者哈希只在本场屏蔽某个打码观众”（V03.1 B-1 提过的另一条路）：这不是还原昵称，可以单独在 V01 提议。
