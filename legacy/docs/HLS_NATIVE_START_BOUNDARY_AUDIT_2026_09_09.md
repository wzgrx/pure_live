# HLS 原生起点与边界控制实验（2026-09-09）

源码 `83157905d7523fb045420f80ae621caa4e402845`，起点 `437ef551`。承接 [初始清单获取审计](HLS_PREFETCH_PREPARATION_AUDIT_2026_09_09.md)，本轮仅新增 opt-in 原生控制实验，没有修改生产起点、窗口、停止策略或默认预取开关。

## 问题与实验设计

上一轮真实 TTing 音频 15296–15299 四片中，native 从 15297 起读；视频从 15174 起读，实际首次请求的 PDT 相差 1.248 秒，与成品音轨晚起相同。此处将媒体字节、源窗口和网络固定，单独改变序号命名空间与 native 起点设置。

- 固定 60 秒 CMAF 夹具及 SHA，仍使用真实 `FFmpegManager → Service → production relay/prefetch → FFmpegKit 0.11.1-20260831`；没有实验 HTTP 中间层替代生产路径。
- 每场只发布固定前三片视频、前三或四片音频，媒体序号可共用 0 起点，或分别从 video=1000/audio=2000 起点。每片约两秒，字节、PTS 和 PDT 不随序号命名空间改变。
- 每场有界运行四秒后显式停止，freeze/缓存排空仍走生产逻辑；只对零起点实验在原生输入前传 `-live_start_index 0`。其余场景不设置此参数。
- 用实际本地 GET 请求而非源端预取请求确认 native 首个选片，再用独立 ffprobe 取 PTS/包数，并单独全文件解码及逐包 payload SHA 比较。

## 首次反证与修订

首次三场实验得到两个统计测试通过、一个原生实验断言失败。预期不等长窗口只跳音频首片，但共用序号空间下实际 **音频、视频都从 1 起读**，视频也少 60 包。原始证据完整保留于 `local-artifacts/hls-native-start-20260909/controls/start-1788968113539093`。

这是夹具没有隔离序号空间导致原先假设不完整，不是被修订代码的回归。最终保留共用序号场景，并增设与 TTing 相同的独立序号空间；没有改变媒体字节或直接修改断言掩盖晚起问题。

## 独立解码与 payload 证明

`retained-decode/summary.json`、各文件 packet hashes 和 input hashes 单独留存：

- 四份 TS 的独立全量 `-xerror` 解码均退出 0，stderr 均为 0 字节。
- 独立序号默认场景的 180 个视频 packet payload，与显式零起点场景逐一相同。
- 默认音轨正好缺少显式零起点音轨开头 **94 个 packet**；后续全部 281 个 payload 是其严格相同的后缀。不是靠移动 PTS、填充静音或转码制造通过。
- 共用序号的不等长默认场景，还缺少显式零起点视频开头 **60 个 packet**；剩余 120 个视频 payload 也是相同后缀。
- 所有场景的现有 `inputCoverageIncomplete` / `inputTailDiscarded` 都为 false，说明这些局部传输标志不证明 native 从已提供的第一片开始，更不证明 A/V 两端相齐；逐包和实际选片证据应保留为独立门禁。

## 来源、生产设计与下一步

[FFmpeg HLS 选片实现](https://ffmpeg.org/doxygen/trunk/hls_8c_source.html#l02116)包含默认倒数起点及在可用范围内复用当前序号的路径；[选项定义](https://ffmpeg.org/doxygen/trunk/hls_8c_source.html#l03130)默认值为 -3。本轮固定运行时实验验证了两种情形，不再只根据上游文档推断。

FFmpeg 行为是上游既有选片机制；与维护分支新增“保留首批完整媒体”的录制假设组合后，缺少明确起点适配，按 `integration-conflict` 记账，不把上游低延迟播放默认称为自身缺陷。冻结主项目上游没有本分支预取保留组件，本轮没有同步上游。

下一步是在**实际通过原子准入的有界录制缓存**与 native 输入设置之间建立明确起点协议，保留未准入、多变体与长 DVR 原路径；不对所有 HLS 全局添加零起点。单独改变起点已恢复可用音频前缀，但没有改变不同来源窗口的首时间差，更没有解决共同停止边界。本轮不把约两秒尾部差当作已修复，也不改真实探针旧 40 秒门槛来获得 PASS。后续持续刷新序号缺口仍待解决。

回滚本提交只移除/回退探针扩展，不涉及生产行为、设置、版本、APK 或设备数据。默认预取保持 false，未联网采集直播、操作手机、变更 Root/LSP、构建或发布；宏观仍为 20 PASS / 32 RUN / 10 NOT RUN，42 项未闭环。全平台 3.2.0 继续以完整验收为前置条件。
