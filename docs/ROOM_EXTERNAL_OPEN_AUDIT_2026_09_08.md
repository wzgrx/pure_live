# 直播间外部打开：YY 与相邻启动错误（2026-09-08）

## 来源与复现

[上游 #857](https://github.com/liuchuancong/pure_live/issues/857)报告 v3.1.2、Windows 11，YY 播放菜单的打开直播间动作打开 system32。修订前维护分支为 `07579aa3`；只读比较本地冻结上游 `c6c9bd70aedc503c003110dae10a83ad0bb891d8` 与共同基线 `527fea1b40885e3621d53c9646b523dd8522290c`，三处 `openNaviteAPP()` 都缺少 YY 分支，并存在同样的无条件弹幕参数转换及异常重试。归类 **upstream-existing**，没有 fetch、merge 或推送，不称冻结引用为此刻远端 HEAD。

第一个错误状态：nativeUrl/webUrl 默认为空，YY/未知站点未赋值，随后直接传入系统启动器。该菜单方法的真实调用在本机 MethodChannel 捕获到空 URL；这证明启动输入错误，不等同于已在 Windows GUI 重现文件夹弹出。

首个测试器因对同步 `Get.reset()` 使用 await 而编译失败，记录 `20260907T232747508Z-room-external-open-red.json`；它不是行为红测。去掉该 await、应用代码保持不变后，**11 项中 9 个有效红项、2 个通过**，记录 `20260907T232946261Z-room-external-open-red.json`：

- YY 官方网页目标错误；未知站点/IPTV 及三个缺失房间身份输入把空 URL 交给 OS。
- 桌面抖音、虎牙没有弹幕参数时，在构建原生深链阶段抛类型异常，独立网页动作也被阻断。
- 浏览器抛错后，旧实现再次打开同一个 URL，第二个异常向调用者传播。

原始红测、测试器失败、输入 SHA、三份源码快照与来源判断分别保存在忽略目录 `local-artifacts/room-external-open-20260908/`，不混淆失败类别。

## 设计与影响面

源码提交：`1e2ffb6a735373a36a18faecd5a5441e62aabd17`。仅本地提交，未推送或发布。

把目标解析与有界启动提取为 `RoomExternalOpener`，实际菜单方法委托它处理；这是现有动作的局部重写，不修改播放器来源、暂停意图、解码、录制状态或页面布局。

- YY 使用项目 YY API 已采用的官方 `https://www.yy.com/<数字房间>`，Android 同样使用网页，不猜测 YY 深链协议。
- 目标先解析后启动，未知站点/IPTV/空或损坏身份返回 unavailable，不把导入的媒体/文件地址当官方网页。所有已注册直播站点仍有明确网页分支；映客继续复用已验证 UID/广播分享链接及官方首页处理。
- 弹幕参数仅在类型与所需字段成立时提供 Android 深链；抖音/虎牙网页不再依赖弹幕元数据。其他已存在的原生协议不假装经过新一轮设备验证。
- Android 原生启动返回 false 或抛错时，只尝试一次不同的网页目标；网页失败返回 failed，不重复启动同一目标，也不遗漏第二个异常。新中英文提示分别说明地址不可用及启动失败。
- 控制器按用户动作保留房间快照，单次启动在途时抑制重复输入。离页或房间替换后的完成结果不向新房间提示，也不继续旧房间的浏览器请求；finally 释放本动作标记。
- 快手分享值逐字段编码，避免值中的 `&path=` 覆盖既有协议字段；CC 缺少用户 ID、快手缺少分享值时仅保留网页，而不是发出含 null 的深链。
