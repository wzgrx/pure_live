## 结果

### 核对方法

1. **功能清点**：对每个功能点，（1）读它“依据”列写的 v4 文件和类，用脚本把依据里的路径和标识符逐个在 `apps/pure_live/lib`、`packages/` 里找（找不到的 4 处：`features/settings/log_page.dart` 实际在 `features/backup/log_page.dart`；`features/live_play/dialogs/room_switcher.dart` 已被 A07.13 换成 `switch_room/room_switch_panel.dart`）；（2）读对应任务的 `record.md`（逐条对照、没验证的、要在 K90 上看的）；（3）对照真机记录：S02.2（K90 冒烟）、S02.3（K90 验证）用的构建是 `288fec0ec`（2026-10-02 01:34），用 `git log --ancestry-path 288fec0ec..HEAD` 查出之后才合并的任务（C02.1、C03.1、G04.1 的 `7b37e6f5f`，H01.3 的 `d145aa930`，J04.1 的 `c168fdb99`，E06.1），这些任务的改动没有上过真机。
2. **状态的规则**（写进了清点的“怎么读”和 D-029）：“完成”要有 K90 结果，或者关键部分不靠原生、系统服务、联网，单元测试能覆盖；代码已合并、关键部分靠原生或系统服务、K90 上没看过的是“没验证”，并写明由哪个任务验证。
3. **设置项**：脚本解析 `packages/live_store/lib/src/settings/settings.dart` 的每个 `static const xxx = …Setting('键', …)`（218 个），和 `Settings.all`（`:1413`）对数；在 `apps/pure_live/lib`、`packages/*/lib`（不含测试）里找 `Settings.<名字>`，区分设置页（`features/settings/`）内外；3.x 的键从 `git archive v3.2.11 lib` 里取 `hive*('键', …)`、`RecorderKeys`、`HivePrefUtil` 的键，和 v4 比键名；默认值按 3.x 的 `hive*('键', 默认值)` 调用比了一遍（括号按层次配对，跨行的调用也算；结果留给 J01.2）。
4. **已批准升级**：222 条主表和附录 B（26 条）、附录 C（22 条）逐行看状态列；状态列里引用的 82 个标识符（类、方法、文件、翻译键）用脚本在代码里找，都在；凡是写“余下 → …”“未排”的，读代码确认余下的部分是不是还没做（例：6-1 查 `app/platforms.dart:160` 建 `YySite` 时没传 `flvFirst`；23-2 查 `YouTubeSite` 实现了 `LiveSiteDirectoryPager`、推荐页按 `popularSourceFor` 走 `DirectorySource`，余项其实已经做完）；旧编号按 [MAPPING.md](../../../MAPPING.md) 和各平台记录的“升级落地”“附录 C 落地”“后续升级”几节换成新编号（T02.U → 这一行的平台任务，M5.F → 那个平台的弹幕任务 D01.x，T02.D2 → 平台任务，M13 → 实际做的页面任务）。
5. **登记表**：对每个没完成的任务，看它要做的点在清点和升级表里的现状；V02.1 用 `gh api repos/wzgrx/pure_live/issues/36`、`/37` 查了 issue 的状态和回复。
