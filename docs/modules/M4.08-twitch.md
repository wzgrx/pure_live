## 做法

照 M4.1 哔哩哔哩：解析写成纯函数，请求编排单独一层，用样本对照 v3 的输出，差异逐条说明。

- **接口和输出沿用 v3**：`LiveSite`、`LiveRoom` 等模型和 3.x 的 JSON 不变。v3 实现过的可选能力都保留：刷新（`LiveSiteRoomRefresher`）、录制详情（`LiveSiteRecordRoomResolver`）；另加 `LivePlayUrlResolver`（线路带请求头）、`LivePlayRecoveryResolver`（恢复时重新取流）和 `LiveSiteLinks`。
- **请求照 v3**：同样的持久化查询哈希、变量和请求头（Chrome 137 的 UA、`Client-ID`、每个适配器一个 `Device-Id`、`Accept-Language: en-US`）；分区房间只看中文和韩语直播；推荐是 Just Chatting 分区；usher 用 v3 的全部参数。变化只有两处：详情换成一个原始 `user` 查询（差异 2），分类的各页合并成批量请求（差异 5）。（M4.U 已改：请求中文名、不按语言过滤、推荐改为全站热门、usher 声明编码，见文末“升级落地（M4.U）”。）
- **解析照 v3 的取值**：图片经 `i2.wp.com`，列表封面带 `?&t=<秒>`，详情封面是头像，画质名称、id、排序和 v3 的 `parseMasterPlaylist` 一致。错误改为类型化，缺字段按空处理。（M4.U 已改：图片直连，直播中详情封面用截图，见文末。）
- **取流**：先取播放令牌（`PlaybackAccessToken`），再请求 usher 的主播放列表。画质的 `data` 仍是 v3 的变体地址列表；取流时直接把它们变成线路，带上 v3 `PlaybackHeaderResolver` 里 Twitch 的请求头（UA、`Origin`、频道页作 `Referer`、用户 Cookie）。变体地址比 20 分钟的令牌活得长，线路不设租期；恢复时重新取令牌和播放列表。（M4.U 已改：媒体请求不再带用户 Cookie，线路带编码，见文末。）
- **会话**：用户的 Cookie 由构造参数注入的 `CookieVault` 提供，只随播放令牌请求发送（`Cookie` 和 `Authorization: OAuth <auth-token>`）；被拒（401 或完整性质询）就改匿名，并且在 Cookie 换掉之前不再发送。
- **房间号保持请求时的写法**（大小写不变，关注的身份不变）；请求一律用它的小写形式。Twitch 不需要别的编号，所以没有 `TwitchRoomData`。
- **弹幕**只输出 `TwitchDanmakuArgs`：频道登录名（小写），和同一份 Cookie 里的聊天登录（`login` 与 `auth-token` 都有时）；这正是 v3 的 `TwitchDanmaku.joinRoom` 自己去设置里读的东西。`toString` 仍是 v3 的 `danmakuData`（频道名），不含令牌。
- **海外站点**：所有请求（GraphQL、usher）的 `site` 都是 `twitch`，代理路由由应用的 `ProxyPolicy` 决定；媒体请求的代理由播放层决定（M7）。

## GraphQL 传输的接口约定（给 M12）

v3 在 Android 上遇到过：某些代理在 HTTP CONNECT 之后会断开 `dart:io` 的 TLS 连接，而同一代理在浏览器里正常。它的做法是先用 `dart:io` 发，失败或被要求完整性令牌时改走 Android 系统 TLS 栈（`core/common/android_native_http.dart`，MethodChannel `pure_live/native_http` 的 `postTwitchJson`，只放行 `gql.twitch.tv`），再不行就在无界面 WebView 里发（`core/utils/twitch/twitch_web_integrity.dart`）。平台层不能依赖 Flutter，所以适配器只认注入的 `LiveHttp`：

```dart
TwitchSite(http, cookies: vault, gqlFallbacks: [androidSystemTls, browser]);
```

- **顺序**：每个 GraphQL 请求先交给 `http`；它抛出 `TransportFailure`（取消除外）、回 HTTP 5xx，或 Twitch 回的是完整性质询（错误信息含 `failed integrity check`、`integrity token`，或有 `extensions.challenge`），就把同一个请求依次交给 `gqlFallbacks`，用第一个不是这三种情况的应答。都不行时报最后一次的错误：`NetworkFailure` 或 `RiskControl`。401、429、其他 4xx 不换传输。
- **请求**：备用传输收到的 `LiveRequest` 与 `http` 收到的完全相同：`site: 'twitch'`（应用据此选代理，v3 把应用代理的主机和端口传给原生通道）、`POST https://gql.twitch.tv/gql`、小写的请求头、JSON 正文（一个操作或一个批量数组）、`timeout`（默认 20 秒，同 v3 的 `timeoutMillis`）和 `cancel`。
- **应答**：返回真实的状态码和解压后的正文（`LiveResponse`），任何状态码都是应答；没有应答时抛 `TransportFailure`，`cancel` 触发时抛 `TransportReason.cancelled`。适配器只用 `send`，不用 `open`。
- **范围**：只有 `gql.twitch.tv` 会交给备用传输；usher 走 `http`，媒体走播放器。
- **完整性令牌**：适配器不发 `Client-Integrity`，也不自己取令牌。v3 在原生通道被质询后先用 WebView 取令牌、再带着它用原生通道重发（`twitch_site.dart:131-134`），最后才把整个请求放进 WebView；这些都属于浏览器环境，由 M12 在各自的传输里实现（比如浏览器传输自己缓存令牌）。纯 HTTP 请求 `/integrity` 拿到的令牌实测仍被拒（规格 §8），不移植。
- v3 只在 Android 上有系统 TLS 通道（`AndroidNativeHttp.isSupported`），WebView 只在 Android、iOS、macOS 上有；Windows 不注入备用传输，与 v3 一样。

## 保持 v3 行为、没有采用归档 v4 或上游做法的地方

（下面的推荐、语言过滤、中文名、图片代理、详情封面和简介、`rerun`、`supported_codecs`、媒体请求头几条已在 M4.U 按用户的决定改掉，见文末“升级落地（M4.U）”；其余照旧。）

- **推荐仍是 Just Chatting 分区**（中文、韩语），不改成全站人数最多的 30 个直播（v4 的原始 `streams` 查询，样本 S03）。
- **分区房间仍只看中文和韩语直播**。v4 去掉了语言过滤，那会改变列表内容。
- **分类不加“热门”**（v4 的 `top`），标签名仍用 `tagName`，无名标签也保留（`tagName` 为空时才用 `localizedName`）。`Accept-Language` 仍是 en-US，分类和分区名是英文；v4 用 zh-CN 得到中文名。
- **每个标签每页 30 个，满页就照 v3 继续翻**。v4 只取第一页。
- **分区 id 仍是游戏的数字 id**，slug 放在 `shortName`。v4 用 slug 作 id，会改变已关注分区的身份。
- **图片仍经 `i2.wp.com`，列表封面仍带 `?&t=`**。搜索卡片的封面仍用 `previewImageURL`（214×120）；v4 换成 440×248 的模板地址。
- **详情的封面仍是头像，简介和公告仍为空**，标题取上次直播的标题，区域取游戏的 `name`。v4 用直播截图作封面、`description` 作简介。
- **列表卡片一律算直播中**（包括 `rerun`），详情只有 `type == live` 才算直播中，不在播时观众数写 `'0'`。v4 把 `rerun` 标成回放。
- **usher 参数照 v3**（`acmb`、`play_session_id`、`player_version`、`transcode_mode` 等），不加 v4 的 `supported_codecs=avc1`。
- **画质名称、id 和排序照 v3**。v4 用 `EXT-X-MEDIA` 的 `NAME`（“1080p50 (source)”）。

### 按统一原则补的

| 事项 | 做法 |
|---|---|
| 开播时间 | 详情在播（直播或重播）时取 `stream.createdAt`；推荐卡片取 `createdAt`；搜索卡片取 `lastBroadcast.startedAt`，只在它和 `stream` 是同一场（`id` 相同）时填。分区卡片用的持久化查询 `DirectoryPage_Game` 不返回开播时间，不填；未开播不填。时间是带 `Z` 的 ISO 8601，按 UTC 读，读不出或不晚于 1970 年的不填 |
| 受限类型 | 详情和推荐的查询加了 `stream.restriction { type }`：为 null 填 `none`；`type` 含 `SUB`（订阅专属直播 `SUB_ONLY_LIVE`）填 `subscribersOnly`；其他非空值分不清种类，按 M2.1 填 `unplayable`。回答里没有这个键（分区、搜索的持久化查询，旧样本）留 null。未开播不填。受限的直播仍是直播中、分在直播中一组；取流时 Twitch 拒绝这个观众（令牌 `forbidden` 或 usher 403，且不是地区原因），受限房间报 `StreamUnavailable`，原因写 `restricted stream (subscribersOnly)`；地区原因仍报 `RegionBlocked`；没有标受限的房间照旧报 `NeedsLogin` |
| 受限直播改为直播中 | 不涉及：本平台从来没有把受限直播标成封禁或状态不明 |
| 占位信息 | 没有占位文字。列表卡片没有显示名时用登录名，是真实的频道名，照旧 |
| 回放拿不到地址 | 不涉及：重播有流（8-9） |
| 房间身份 | 不变：登录名，M2.1 已把 `twitch` 放进不分大小写的平台 |
| 容错 | 已按行跳过坏数据；分页续取失败只让那一页失败，游标保留，重试接着取 |
| 画质命名 | 本平台没有改名、合并的条目，画质名称、id、排序照 v3 |
| 按主播关注、说明文字 | 不涉及：Twitch 本来就按频道关注；没有目录说明 |

## WebView 传输（M12，UPGRADES X-1，2026-10-01）

`apps/pure_live/lib/platform/twitch_webview_http.dart` 的 `TwitchWebViewHttp`：在无界面 WebView 里发 GraphQL，实现 `LiveHttp`，作为 `gqlFallbacks` 的最后一个注入（Android 才注入，同 v3）。顺序是 `[AndroidNativeHttp, TwitchWebViewHttp]`：dart:io 失败、5xx 或被要求完整性令牌 → 系统 TLS → WebView。

- **做法**（v3 `TwitchWebIntegrityProvider.postGraphQl`）：打开 `https://www.twitch.tv/twitch` 的空白页（Android 上真的导航到这个地址，只把主文档换成空页面：有的 WebView 版本用 `loadDataWithBaseURL` 时来源是合成的，KPSDK 永远不就绪），在页面里用 `fetch` 发同一个请求。Twitch 回完整性质询时，页面加载 Kasada 的 KPSDK（`k.twitchcdn.net/…/p.js`），等 `kpsdk-ready` 后请求 `/integrity` 拿令牌，再带 `Client-Integrity` 发一次；还被质询就失败。页面脚本返回 `{status, body, integrity}`，传输按 Twitch 的状态和正文回答，由 `TwitchSite` 照常判断（5xx、质询、各类错误）。
- **只放行** `POST https://gql.twitch.tv/gql`；其他地址、方法是 `TransportFailure(protocol)`，不进页面。
- **令牌缓存**：传输自己按 client id + device id 保存 `/integrity` 的令牌（`expiration` 毫秒），过期前 1 分钟内不再使用；之后的请求一开始就带上它，省掉 KPSDK 一轮。令牌和 `Device-Id` 绑定，所以换设备 id 不共用。
- **会话**：只把 `client-id`、`device-id` 放进页面（v3 同样不把账号带进无界面浏览器），`cookie`、`authorization` 不进页面；走到这一步的播放令牌是匿名的。
- **代理**：`ProxyPolicy.routeFor('twitch', …)` 是 HTTP 代理时用 Android WebView 的 `ProxyController` 覆盖，页面结束后清除；覆盖是进程级的，所以所有页面排队一个一个跑（v3 `WebViewProxyScope`）。WebView 用它自己的 UA（与它的 TLS 指纹一致，v3 的说法）。
- **超时和取消**：页面整体受 `LiveRequest.timeout`（默认 20 s）限制，超时是 `TransportFailure(timeout)`；取消立即结束请求（页面在后台跑完后丢弃）；页面或脚本出错是 `TransportFailure(connect)`。
- **可测**：浏览器在接口 `HeadlessBrowser` 后面（`InAppHeadlessBrowser` 是 flutter_inappwebview 的实现），测试用假的浏览器。

测试 `apps/pure_live/test/platform/twitch_webview_http_test.dart` 7 个：只放行 GraphQL；页面拿到的请求体、请求头、来源、代理、超时，回答的状态和正文，账号 Cookie 不进页面；令牌按设备保存、再次发送、快过期不用；页面失败、超时、空回答、坏回答的传输失败类型；取消；`TwitchSite` 在 dart:io 和系统 TLS 都失败时经它取到详情（S05-detail-offline）；只在 Android 注入。

没有验证：真机上 KPSDK 是否仍能就绪、`/integrity` 令牌是否被 GraphQL 接受（本次不往手机安装）。Windows 不注入（WebView2 可用，但 v3 没有、X-1 只要求 Android）。
