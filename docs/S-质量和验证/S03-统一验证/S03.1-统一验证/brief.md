# S03.1 统一验证：所有界面和流程走一遍：任务书

## 背景

- 来源：界面重构计划的最后一步（旧编号 U.16）：所有界面重做完以后，逐个界面按设计核对，并出一份基准测试报告。D-004 定了现在只做 Android，所以本任务是 **Android 4.x 的整体验收**；Windows、电视、苹果平台的验收在各自客户端开工时登记。
- 现象：没有坏现象；问题是“完成”的界面任务大多只有组件测试和布局测试，真机上只在 S02.2、S02.3 冒烟时看过一部分；各组 v2 核对（2026-10-07）列出了一长串登记完成但没有真机结果的任务，手机上能单独看的已经分给 S02.4、S02.6，剩下需要“全部尺寸一起看”的（设置各页、宽屏首页、宽屏分栏、平板布局）和整体的设计一致性在这里。
- 为什么是第二档：不阻塞用户日常使用，但它决定 4.x Android 版能不能算做完；要等改全局样子的任务合并后做，否则看完又要重看。
- 已经做过的：S02.2、S02.3 冒烟；每个界面任务的布局测试（竖屏、横屏、宽屏各至少一个）；R01.1 的基准代码。

## 目标和验收

1. 开工条件满足（见下“开工前”）：A01.2、A01.3、A03.3、A04.1 已合并或明确改成“不阻塞”；S02.5、S02.6 有结果。
2. A06～A15 每个完成的界面任务（下面“方案和阶段”表列的）都有一张核对表：README“确认的改动”的每个 c 编号一行，结果是“符合 / 不符合（现象、截图）/ 看不了（原因）/ 已验证（S02.x，日期，抽查通过）”。
3. 每个区域都在这些形态下看过：K90 竖屏；K90 横屏（“横屏手机”）；`wm size 1600x2560` 模拟的宽屏（≥840 dp 分栏）；窄横屏（`wm size` 模拟 740×360 dp 的比例）；上下分屏；深色主题；应用文字大小 150% 加系统字号最大。看不了的写原因。
4. 主要流程各走一遍并记结果：冷启动到首页 → 热门进直播间 → 全屏 → 切换直播间 → 录制 → 返回；搜索 → 进房；关注 → 下拉刷新；设置改一项 → 回直播间生效；备份 → 恢复；网络电视 → 节目单 → 回看；多画面 2×2。
5. 必须保留的 3.x 操作习惯（`docs/specs/UI.md` 附录 A）每一条都有结果。
6. 基准报告：K90 上跑一次 `integration_test/perf_test.dart`，每个场景的 build/raster P90、P99、卡顿率、最长连续卡顿，和 R01.1 记录第 1 节的判定对照；JSON 文件名和提交号写进报告（JSON 本身不进仓库）。
7. 每个不符合的都开了任务（编号写进核对表）；每个任务 README 的“实现和验证”加一行统一验证的结论。
8. 本文件夹写 `verify-1.md`～`verify-5.md`（按阶段）和 `record.md`（汇总：区域、任务数、符合率、开的任务、基准结论、验收结论）。

## 风险和注意

- 依赖没合并就开始会白做：阶段 0 先确认；A04.1 改字号上限前后的大字号结果不同，必须在它合并后看。
- `wm size`、`wm density`、`cmd uimode`、系统字号都会影响用户在 K90 上的其他应用：每个阶段结束都恢复，`adb shell wm size`、`wm density` 核对。
- 基准会覆盖测试包（`.v4dev`）的安装，数据保留；跑完重新装平时的包。
- 核对表很长：每个阶段单独提交，避免一次丢失。
- 用户的 3.x 和正式包不碰（D-019）。
