# 布局断点与分页事务审计（2026-09-10）

## 范围与根因

起点 cfa1344d，承接[页大小事务审计](PAGE_SIZE_TRANSACTION_AUDIT_2026_09_10.md)。修改公共 [BasePageScrollAndStateBone](../lib/common/base/base_page_scroll_bone.dart)，并让全量、固定、远程和原生目录四类网络分页暴露当前任务供布局等待。未更新平台接口、版本或数据格式。

旧 checkAndNotifyLayoutChange 立即设置分页模式、pageSize/currentPage，只将 refreshData 延迟 120 ms。因此已发出的请求仍可能按新模式解释返回值；连通性检查未结束时，请求参数也可提前改变。短暂跨断点后返回原布局仍改变页大小并触发额外刷新。关闭后的布局回调还可重新安排计时器、修改状态。

源码来源为 **upstream-existing**：冻结 c6c9bd70 中具有同样的立即写状态结构；模式和尺寸写入源自 c2144e10，4191c5b6 的 debounce 只覆盖刷新，没有推迟状态提交。此次只读取本地冻结提交，没有同步上游。

## 修订

- 保存待提交的布局模式，重复观察同一目标不重新延长 debounce；返回已提交布局则取消整个待处理意图。
- 保留既有 120 ms debounce。到期后等待当前分页任务，并在等待者醒来时重新读取最新任务；未稳定的请求不被中途改维度。
- 用布局版本标记隔离已取消的等待者；退出时取消计时器、清除意图并递增版本。旧 Future 仍被观察到终态，但不提交布局或启动刷新。
- 四类网络分页通过只读 activePageOperation 接入；远程包含补数，原生目录优先包含 pendingRepage，不只看可见 loading 标志。
- 提交桌面页号映射时采用实际旧 pageSize，而不是硬编码 20；提交后按既有刷新策略获取/投影新布局数据。

没有新增固定等待常量、轮询网络、取消用户请求、关闭响应式布局或禁用操作来规避问题。当前请求仍按旧尺寸完成，随后只提交最新有效布局。

## 边界与后续

activePageOperation 的默认值为空，适合没有在途任务的同步本地投影；本批明确接入上述四类网络分页。LocalReactivePageController 的独立外部刷新及其派生 PopularLocalReactiveController、用户管理的 Firebase 专属请求仍需各自审计，不因公共基类修订就宣称所有异步任务已受保护。

实际网络迟延、Android 窗口/横屏、Windows 快速拖窗、分类 Tab 嵌套布局及跨断点时其他用户输入仍待原生/组合验收。布局变更的等待并非网络取消；原生目录自己已有的取消/代次策略没有被替换。

回滚本批公共布局逻辑和四个只读 getter 即可，无数据迁移。Android 152cf151 / Windows 2fb471d3 候选保持，尚未包含最近生命周期/事务修订；本批未操作 ADB/MT/LSP/Root、未构建或发布。

宏观仍 20 PASS / 32 RUN / 10 NR，42 组未完成，8 组参考平台未注册。3.2.0 继续等待完整原生、平台与交付验收，不以新增用例数量替代验收组闭环。
