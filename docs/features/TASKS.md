- 共 17 个任务。每个任务一个文件夹 `docs/features/<编号>/`（README、功能对比页 `page.json`），记录在 `docs/features/records/<编号>.md`。

## 1 编号、档位、规模、状态

- **编号**：`F.<类>` 加小写字母。类见计划第 5 节。
- **档位**（按日常使用频率）：**必须**（不做就影响天天用的功能或 3.x 数据）、**应该**（常用但有替代办法）、**可以以后**（冷门或增强）。额度不够时先做完“必须”。
- **规模**（开发代理的时间，含测试和记录，不含等用户评审）：**小** 约 1 小时以内；**中** 1～3 小时；**大** 3 小时以上。验证任务按真机时间算。
- **状态**：未开始 → 对比页待确认 → 已确认 → 开发中 → 待验证 → 完成（写验证日期）。真机有问题的写“验证有问题”和现象。

## 3 顺序

先基础后上层、先“必须”后其他；同档按使用频率。几个任务可以并行开发，合并后一起装机验证（PROCESS 第 8 步）。

1. **F.0a**（必须）——后台播放、录制的通知权限是看直播和录制的前提；
2. **F.1a**、**F.2a**（必须）——天天用的两个“设置不生效”；F.2a 等 U.2h；
3. **F.0b**（必须）——上面三个合并后装一次 K90，冒烟主流程，找出界面重构后的真机问题，分进任务；
4. **F.9a → F.9b → F.9c**（必须）——按使用频率逐批验证；
5. **F.4a**（必须）——用户选好迁移验证方式后做；
6. **F.1c、F.1b、F.2b**（应该），**F.9d**（应该）；
7. **F.1d、F.2c、F.3a、F.4b、F.5a**（可以以后）。

“必须”共 8 个：F.0a 中、F.0b 小、F.1a 小、F.2a 中、F.4a 中、F.9a 中、F.9b 中、F.9c 小，合计 3 个小、5 个中，约 8～18 小时（不含等用户评审和 U.2h）。
