# 项目计划

- 更新：2026-10-03（第 2 版：docs v1，20 组按优先级排字母，界面设计第一）
- 进度：[STATUS.md](STATUS.md)；做法：[PROCESS.md](PROCESS.md)；任务：[TASKS.md](TASKS.md)；决定：[DECISIONS.md](DECISIONS.md)

## 1. 目标

- **4.x 是 3.x 的改进版。** 在 3.x（`v3.2.11`）的代码上逐块审查、重构、完善、增强：功能一个不少，3.x 用户的操作习惯不变，代码质量、稳定性、性能、安全明显更好，并补上 3.x 缺的功能。
- **覆盖安装 3.x，数据全部保留**：关注、历史、设置、账号自动导入（[J06](J-设置和数据/J06-3.x数据迁移/README.md)）。
- **客户端顺序**：Android（手机、平板）→ Windows → 电视 → Linux → 苹果平台。4.0.0（Android）已在 2026-10-02 发布（[Y01](Y-发布和运营/Y01-版本签名和发布/README.md)）。

## 2. 原则（做决定时按这个顺序）

1. **3.x 的行为和习惯是基线。** 功能以 3.x 为准；改变外观或操作习惯的改动要有依据，并写进 [DECISIONS.md](DECISIONS.md)。3.x 实际运行的样子比 3.x 代码里写的更重要（例如标题位置，见 D-011）。
2. **先找根因再改。** 修问题时先写一个改之前会失败的测试，再改代码；原因写进任务记录。
3. **各处一致。** 同一个功能在竖屏、横屏、平板、电脑上是同一个组件、同样的操作，屏幕大小只决定放在哪。
4. **天天用的先做。** 同一档里按使用频率排；国内平台优先；速度（起播、滑动、响应）优先。
5. **安全和隐私。** 不收集数据；密钥、签名文件、Cookie、真实账号不进仓库；样本脱敏（[specs/ENGINEERING.md](specs/ENGINEERING.md)）。
6. **能分阶段就分阶段。** 每个阶段能单独合并、单独验证；额度或时间不够时停在阶段边界，写清怎么接着做（[PROCESS.md](PROCESS.md) 第 5 节）。

## 3. 20 组

全项目分成 20 组、107 个子分类，组按优先级排字母（A～Z，跳过旧编号用过的 B、F、M、P、T、U）。每组管什么见 [README.md](README.md#20-组按优先级)，每组的子分类和进度见各组页面。分组规则：

- **界面优先**：看得见的样子和交互（设计系统、组件、动效和手感、尺寸适配、无障碍、每个区域和每个客户端的界面）都在 [A 界面设计](A-界面设计/README.md)，排第一；行为和数据在各功能组（C～O）。
- **支撑和流程**放在后面：网络（Q）、性能（R）、质量和验证（S）、需求和反馈（V）、上游借鉴（W）、多端客户端（X）、发布和运营（Y）、工程文档和维护（Z）。
- 每段代码、每个功能点、每个设置项、每个平台、每个原生插件，只归一个子分类（清点脚本见 [Z03](Z-工程文档和维护/Z03-清点和归属/README.md)）。
- 横跨多组的事以主要的那样为准，在任务里写明关联；客户端专属的工作在 X，客户端的界面在 A16～A18。
- **新功能**先在 [V01](V-需求和反馈/V01-新功能提议/README.md) 提议，确认要做后在目标组开任务（[PROCESS.md](PROCESS.md) 第 6 节）；**上游的更新**每周在 [W01](W-上游借鉴/W01-定期对照/README.md) 对照一次（第 9 节）。

## 4. 优先顺序

每个没完成的任务都有档位（[STATUS.md](STATUS.md#按档位还没完成的任务)）：

| 档位 | 什么样的任务 | 现在的重点 |
|---|---|---|
| 第一档 | 影响已发布的版本、会丢数据、天天用的功能坏了 | 3.x 迁移的真机验证（[J06.1](J-设置和数据/J06-3.x数据迁移/README.md)、[S04.1](S-质量和验证/S04-覆盖安装验证/README.md)）；这一批改动的真机验证（[S02.5](S-质量和验证/S02-真机验证/README.md)）；录制下播后无限重试和空分段合并失败（[H01.5](H-录制/H01-录制核心/README.md)）；国内五大平台巡检（[E01.6](E-直播平台/E01-国内五大平台/README.md)、[E07.1](E-直播平台/E07-平台巡检/README.md)）；起播速度和弱网（[G03.1](G-播放/G03-起播速度和弱网/README.md)）；回复 issue（[V02.1](V-需求和反馈/V02-用户反馈和issue/README.md)） |
| 第二档 | 这一轮的收尾和常用功能的余项 | 暂停的三个任务（[A03.3](A-界面设计/A03-动效和手感/README.md)、[A04.1](A-界面设计/A04-尺寸和适配/README.md)、[E06.2](E-直播平台/E06-平台层升级/README.md)）；各组功能清点里的缺失和没验证的；K90 上跑基准、启动速度 |
| 第三档 | 新客户端、冷门功能、增强 | Windows 和 Linux（X01、X02）、电视（X03、A17）、苹果平台（X04、X05、A18）、无障碍（A05）、耗电（R05）、新功能提议（V01） |

额度紧时只做第一档；第一档里优先做验证类任务（改代码少、发现的问题影响大）。

## 5. 版本路线

版本号在发布时才定（[DECISIONS.md](DECISIONS.md) D-007），下面是计划：

| 版本 | 内容 | 主要的组 |
|---|---|---|
| 4.0.x | Android 修整：第一档、第二档 | A、C、D、E、G、H、J、R、S |
| 4.1 | Windows | X01、A16 和各组的桌面差异 |
| 4.2 | 电视 | X03、A17、L03 |
| 4.3 | Linux | X02 |
| 以后 | iOS、iPadOS、macOS | X04、X05、A18 |

## 6. 风险和对策

| 风险 | 对策 |
|---|---|
| 平台改接口，看不了直播 | 定期巡检（E07），国内五大优先修；平台记录里写清接口和样本 |
| 3.x 数据迁移出错，用户丢关注和设置 | 覆盖安装真机验证（J06.1、S04.1）；迁移有单元测试；失败的部分单独记录不影响其余 |
| 改动大但真机验证不够 | “待真机”状态单独列出（[STATUS.md](STATUS.md)）；完成必须写真机结果 |
| 额度或时间不够，任务做一半 | 按阶段做，停在阶段边界，写接手说明（PROCESS 第 5 节） |
| 换人或换 AI 接手时上下文丢失 | 任务书自包含；决定写进 DECISIONS；记录写清根因和偏差（PROCESS 第 7 节） |
| 并行开发互相冲突 | 同一组同时只开一个开发；合并时两边都保留后重跑测试（PROCESS 第 8 节） |
| 厂商限制刷新率、权限 | 读回实际值，限制时提示用户（R02、O04） |
| 正式签名 | 现在用维护者调试密钥（和 3.x 同一证书）；正式密钥方案见 Y01.4 |
| 上游修了而我们不知道的问题 | 每周对照上游（W01，PROCESS 第 9 节） |
| 新功能越加越多、偏离 3.x | 新功能先提议、评估、用户确认（V01，PROCESS 第 6 节） |
