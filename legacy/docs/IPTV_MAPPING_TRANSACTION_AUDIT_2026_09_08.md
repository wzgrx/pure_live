## 尚未闭环的覆盖导入问题

本轮还读取了 importer、sync engine、M3U/TXT parser 的完整相关路径；以下是**源码已定位、端到端文件/HTTP/DB 复现尚待补齐**的独立问题，记录在 `pending-replacement-review.json`，没有记为已修复：

1. `forceUpdate` 跳过同名来源选择，新建 provider ID；非强制确认前解析器已使用新 ID，确认后却可能写入旧 provider，频道身份前缀不一致。
2. `_saveToDatabase` 先覆盖缓存文件、删除 provider/channels，再按默认值重建，尚未以全程事务保留来源设置、频道收藏和引用。当前自动映射事务只保护映射；它抛错后外层返回 false，外层此前的 provider/channel 写入并未随之回滚。
3. `syncPlaylist` 在成功解析并写入前按名称删除旧来源，临时文件名固定，导入返回 false 时仍可能显示成功提示。
4. M3U/TXT 使用 `String.hashCode` 生成频道 ID；M3U 同一 TVG ID 的多线路可能相互覆盖，TXT URL 变更会改变 ID，仍需明确持久身份和重复条目规则。

下一批先给导入器增加可注入的缓存目录解析以隔离真实测试数据，补真实文件/SQLite 的覆盖、迟发失败和用户字段保留回归；再设计来源/频道身份选择与缓存提交/清理，覆盖网络同步、确认返回和同名并发。不初始化测试进程的真实 AppPathManager，也不借此修改用户缓存。
