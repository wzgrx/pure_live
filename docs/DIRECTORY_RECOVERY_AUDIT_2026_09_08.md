# 原生目录恢复操作与网络预检审计（2026-09-08）

起点 `e3700d433d18c79b3aec02645a62d9a94676cce3`、版本 `3.1.8+4121`；承接[原生分页](MISSEVAN_DIRECTORY_UI_AUDIT_2026_09_08.md)，本轮优先本机源码与 Widget。仅为选择候选平台只读核对手机连接与身份，没有安装或前台输入。

## 原因与范围

1. **重试退回第一页**：`BasePageView` 的空列表错误按钮固定调用 `refreshData`；连续空页触及请求预算后，按钮再次从原生第一页开始。桌面失败跳页也丢失最后请求的目标页。用户主动“刷新”应重建目录，而“重试”应延续未完成动作。
2. **容量状态与显示脱节**：`_capacityReached` 保留，但下一次缓存翻页/修改条数先清空错误，又因容量标志跳过请求循环，最后将这次操作报成功。已有卡片时仅短暂 Toast，缺少持续可见的恢复入口。
3. **网络预检先写入、调用方后判断代次**：`BaseController.checkNetworkBeforeRequest` 在异步读取连接状态后立即更新错误/蜂窝提示；`LiveDirectoryController` 的 `_owns(epoch)` 在其返回后才执行。目录请求本身已隔离，系统预检回调仍会在刷新、改条数或关闭后写入旧状态。

前两项是维护分支 `52f3f0bc` 引入的可选原生分页接入缺口（`fork-regression`）；没有该接口的旧分页器保持旧重试合同。第三项的直接连接查询实现已存在于 merge base `527fea1b40885e3621d53c9646b523dd8522290c`；冻结上游 `c6c9bd70aedc503c003110dae10a83ad0bb891d8` 已转为 MeteredNetworkService，不能把维护分支的所有效果机械归为其现状。目录特有代次遗漏仍由本分支接入修订处理，本轮没有合并上游。

## 修订

- 公共错误按钮调用可覆写的 `retryData`，旧分页默认仍调用刷新。原生目录记住最后请求的 UI 页，延续原生失败游标；在途重试复用已有 Future。显式刷新仍重建第一页，容量耗尽时恢复动作明确显示“刷新”。
- 容量标志在缓存回看和调整条数后仍产生同一错误，保留已加载卡片和未知总数，而非伪装成目录结束。仅原生目录选择常驻行内提示，恢复按钮独立排列，长文最多三行且保留完整语义文本；旧分页的内容展示默认不变。
- 基础网络预检在异步读取前捕获归属判断，在读取结束、错误与放行请求前再次核对。原生目录加入自身代次/关闭状态；当前移动网络、用户隐藏提示、Wi-Fi 和插件读取失败策略保留，过期回调不写入旧视图。
- 这仍是可选原生目录路径的修订，不称所有继承 BaseController 的请求状态机均已验收。刷新失败时旧桌面页码与列表的对应关系、极端输入及完整原生长时组合继续审查。
