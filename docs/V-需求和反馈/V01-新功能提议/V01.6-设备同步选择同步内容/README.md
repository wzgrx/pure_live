## 目标

设备同步现在是整份发过去：对方确认后，关注、历史、分组、屏蔽、设置、WebDAV、网络电视……全部按发过来的恢复。用户常见的需求是“只把关注同步到平板”“只同步屏蔽词”，现在做不到（要么全覆盖，要么别同步）。提议：发送前和接收前都能勾选同步哪几类，只发、只应用勾选的；**保留 6 位配对码**（上游去掉了，但同步里可能带登录 Cookie，同一个 Wi-Fi 不等于可信）。

做不做：用户 2026-10-07 同意做（D-036）。2026-10-08 补完评估、定了设计（见文末“评估结论”“设计选择”，按 D-003 由维护者按建议定），实现开在 [J05.1](../../../J-设置和数据/J05-设备同步/J05.1-同步前勾选内容/README.md)。下面“3.x 和现状”“方案（评估初稿）”是 2026-10-07 的初稿，保留作对照；和文末不一致的以文末为准。

## 评估结论（2026-10-08）

读了：上游 `git show 9483ccf03`（`remote_sync_page.dart` 的 `_pickSections`，`remote_sync_protocol.dart` 的 `settingsPacket`，`remote_sync_service.dart` 的 `applyRemoteSettings` `:638-647`、`exportSectionNames` `:999`、`syncToAddress`）；3.x 的导入 `git show v3.2.11:lib/common/services/settings/backup_controller.dart`（`importAllSettings` `:170`、`_importV2` `:239-285`）；4.x 的 `LegacySnapshot.fromBackup`（`packages/live_store/lib/src/legacy/legacy_snapshot.dart`）和 `BackupService.restoreAll`。

1. **3.x 收到缺分区的包，会把缺的分区重置成默认。** `_importV2` 对每个分区都调 `fromJson(data['app'] ?? {})`（`:241`）、`fromJson(data['favorite'] ?? {})`（`:255`）等，`FavoriteRoomController.fromJson`（`favorite_room_controller.dart:565-571`）用空分区解析出空列表，关注和屏蔽词就被清空了。所以**不能给 3.x 设备发只含部分内容的包**。上游的做法是只打包勾选的段，这样的包发给 3.x 或上游设备时，对方没勾的设置全部回到默认，关注也被清空。
2. **上游接收端的过滤其实没有生效。** `applyRemoteSettings`（`:638-647`）在包里的 `settings` 对象中找 `sections`，可 `sections` 放在包的顶层，所以收到什么就整份应用什么。再加上第 1 条，上游设备之间只勾一部分时，接收方没勾的分区同样会被重置。另外，上游的勾选项直接显示备份顶层键的原文（连 `backupVersion`、`sensitiveDataIncluded` 也列出来），没有翻译。
3. **上游这个提交的服务端仍然检查配对码**（`remote_sync_service.dart:504`），发送端不带码会被拒（403），所以“去掉配对码”只做了一半。4.x 保留配对码，不受影响。
4. **4.x 恢复时只替换文件里有的部分。** `LegacySnapshot.fromBackup` 对每个设置和列表看文件里有没有这个键，没有就记成 null，`restoreAll` 只替换有的部分（J02.1 有意和 3.x 不同）。所以 4.x 收到只含部分内容的包是安全的，还没有这个功能的旧 4.x 也一样。
5. **勾选要按内容分，不能按顶层分区分。** 4.x 的分区和上游一样，是 3.x 的顶层分区（`app`、`player`、`favorite` 等），但一个 `favorite` 分区里同时放着关注的直播间、关注的分区、屏蔽词、屏蔽用户，还有几个设置（`hotAreasList`、`preferPlatform`）。按顶层分区勾，做不到“只同步屏蔽词”。所以勾选按内容分，打包时按键把分区拆开。
6. **勾选项只列设备同步实际带的内容。** 设备同步传的是 `BackupService.exportAll`（3.x 的分区），不含搜索记录、网络电视列表和多画面（J05 的已知问题）。

### 互通表

| 发送方 → 接收方 | 会怎样 |
|---|---|
| 4.x（有 J05.1）→ 4.x（有 J05.1） | 发送前先问对方的 `/status`。对方声明了 `syncParts`，就能勾选，只发勾选的部分，包里带 `sections`（留下的顶层分区）。对方的确认框里还能再按部分勾选，只应用勾选的，其余不变 |
| 4.x（有）→ 旧 4.x、3.x、上游 | 对方的 `/status` 没有 `syncParts`（或者连不上）：勾选框全部勾上并锁住，写明“对方是 3.x 或较早的版本，只能发送全部内容”。发出的包和以前一字不差（不带 `sections`） |
| 旧 4.x、3.x → 4.x（有） | 包里没有 `sections`，当作全量。确认框原来只有“拒绝 / 允许”，现在会列出会改什么，每部分一个勾选框，默认全勾 |
| 上游（9483ccf03 以后）→ 4.x（有） | 包里的 `sections` 是顶层分区名，4.x 只读列出的分区（和上游同名同义），再在确认框里按部分勾选。上游不带配对码时，4.x 拒绝（保留配对码） |
| 4.x（有）从任何设备接收 | 对方整份给（3.x 和 4.x 的 GET 都不认识勾选），本机在预览里按部分勾选，只应用勾选的 |
| 任何设备从 4.x（有）接收 | 不变，整份给，由对方自己挑；带不带账号仍然看本机的“同步账号 Cookie” |

## 设计选择（D-003：维护者按建议定，用户随时可以推翻）

| 编号 | 问题 | 选了什么 | 为什么 |
|---|---|---|---|
| S1 | 勾选按什么分 | 按内容分 9 类：设置、关注的直播间、关注的分区、观看历史、关注分组、屏蔽词、屏蔽用户、WebDAV 服务器、账号 Cookie。后两类只在打开“同步账号 Cookie”时出现。名字沿用恢复预览的叫法 | 用户要的是“只同步关注”“只同步屏蔽词”；按顶层分区（上游的做法）拆不开 `favorite`；叫法和备份恢复的预览一致 |
| S2 | 设置要不要再细分（播放、弹幕、外观……） | 不细分，算一类 | 先满足常见需求；细分要给 200 多个设置逐个定归属，改动大。以后有人要，再开任务 |
| S3 | 怎么和 3.x 设备兼容 | 只有 `/status` 里声明了 `syncParts` 的设备，才会收到只含部分内容的包。其他设备（3.x、上游、旧 4.x、连不上的）一律整份发，勾选框锁住并说明原因 | 3.x 和上游会把包里缺的分区重置成默认（评估第 1、2 条），发部分包等于清空对方的数据。旧 4.x 其实能收部分包，但分不清它和 3.x，宁可整份发（和现在一样） |
| S4 | 包里写什么 | 只有勾掉了东西时才加 `sections`（留下的顶层分区名，和上游同名同义）；全勾时和现在一字不差。接收方按 `sections` 过滤，没有就当全量 | 上游和 3.x 都能读；默认全勾时线上格式不变 |
| S5 | 接收方能不能比发送方勾得少 | 能。主动接收时的预览、对方发来时的确认框，都是每部分一个勾选框，默认全勾 | 照提议的建议。对方发来时原来只有“拒绝 / 允许”，现在能先看到会改什么（A12.6 留下的问题） |
| S6 | 回执要不要带“应用了哪些” | 不带，回执照旧是 `true` | 3.x 的回执就是 `true`，改格式 3.x 读不了；接收方是自己勾的，知道应用了什么；发送方的提示仍然是“配置发送成功” |
| S7 | 要不要记住上次的勾选 | 不记，每次都全勾 | 默认值要让老用户感觉不到变化（D-036）；记住了，下次同步会悄悄少东西；“同步账号 Cookie”开关也不记；这样也不用加新设置（D-018） |
