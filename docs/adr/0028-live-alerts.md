# 0028 开播提醒与节目提醒：检测规则、存储、通知插件和进程内定时

- 状态：已接受（许可证判断经主会话确认：Classpath Exception 不属于 GPL-2.0-only）
- 日期：2026-09-28

## 背景

产品清单 F-NEW-01 要求“关注房间开播时通知，并承载 IPTV 节目提醒”（F-IPTV-09 并入，P2）；设计原则 §4.1 要求在关注页“逐个设置开播提醒”。3.x 没有这个功能，IPTV 节目提醒在 3.x 只有表和增删接口、没有调用方。需要定下来的有：什么算“开播”、同一场直播怎么只提醒一次、开关和记录存在哪、用什么发系统通知、应用不在前台时怎么检查。

## 决定

1. **开关**：设置注册表新增 `alerts.live`（布尔，默认关，作用域 `device`：通知权限属于这台设备，备份只在同一平台家族之间恢复）。每个关注房间可以单独关闭：房间偏好 `room_prefs` 的键 `liveAlert`，只存 `false`，没有这一行就跟随全局开关。全局关时一律不提醒，单个房间的开关只能“在全局开启时关掉某个房间”。不给 `follows` 加列，因此没有 drift 迁移；房间偏好已经在备份（`roomPrefs` 分区）里，取消关注后偏好随房间行保留，重新关注时仍然生效。
2. **检测**：每次关注刷新（启动时、回到前台、定时器、手动）写入新状态之后，把刷新前 store 里保存的状态（`rooms.last_status`）和这次看到的状态比较：**之前是已知的非开播（未开播或轮播）、这次是开播**才算开播。之前未知（从没检查过）或已经是开播的不提醒；IPTV 频道一直在播，不参与开播提醒。冷启动的第一次刷新用的是上一次运行保存的状态，所以和运行中的刷新是同一条规则。
3. **一场直播只提醒一次**：每个房间最近一次提醒记在 `meta` 表的 `alerts.liveRecords`（JSON，键为 `平台:房间号`，值为提醒时间和平台给出的开播时间），不备份。再次满足条件时：两边都有开播时间且相差不超过 2 分钟 → 同一场，不提醒；缺开播时间时，距上次提醒不到 30 分钟 → 不提醒。记录先于通知写入，进程在两者之间退出也不会在重启后重复；超过 7 天或已取消关注的记录在下次提醒时清掉。两次刷新重叠时，提醒处理按顺序执行，后一次能看到前一次的记录。
4. **合并规则**：一次刷新有 1–3 个房间开播，逐条通知（标题“某某 开播了”，正文“平台 · 直播标题”，同一房间的新通知替换旧的）；超过 3 个合并成一条“某某等 N 位主播开播了”，正文列出前 6 个名字。点单条通知进入对应直播间；点合并通知打开关注页的“开播”标签（`/follows?filter=live`，附一个时间戳参数，重复点击也会切回“开播”）。
5. **后台检查**：开播提醒打开时，关注刷新的定时器一直运行（即使“定时刷新关注的开播状态”没开），间隔用“定时刷新间隔”（设置页新增滑块，5–120 分钟，默认 30）。应用启动后不必进入关注页也会开始刷新。进程存活期间（前台或后台）定时器照常触发；**进程被杀后不检查**，见“影响”。
6. **通知插件**：用 `flutter_local_notifications` 22.3.1（BSD-3-Clause，Android、Windows 两端都有实现；连带的 `_windows`、`_linux`、`_platform_interface`、`_web` 和 `timezone` 都是 BSD 许可证）。应用只通过 `AlertNotifier` 接口发通知和接收点击，测试用假实现。平台按真实操作系统选择：Android、Windows 用插件；Linux、macOS 等其它平台用空实现，静默跳过（开关显示“这个系统上不支持通知”，节目单不显示“提醒我”）。
   - Android：两个通知渠道，“开播提醒”（`live_alerts`）和“节目提醒”（`programme_reminders`），重要性高；小图标用启动图标的单色层 `ic_launcher_monochrome`。`POST_NOTIFICATIONS` 由插件的清单合并进来，应用清单不改。插件要求应用开启 core library desugaring（`desugar_jdk_libs` 2.1.5）。
   - 权限：Android 13+ 在用户打开开关时申请；拒绝则开关保持关闭并提示去系统设置允许。启动时如果开关是开的、但系统里通知已被关闭，开关自动改为关闭（与系统状态一致）。
   - Windows：用插件的 WinRT toast，AppUserModelID 为预览包的 `com.mystyle.purelive.next`，激活 GUID 为 v4 新生成的 `80b8bd95-5a1b-451f-91bf-f0ca23a581a1`，与 3.x 的 `com.mystyle.purelive` 互不干扰。插件首次初始化时在 `HKCU\Software\Classes\AppUserModelId\<AUMID>` 写入显示名和激活器。
   - 只在需要时初始化插件：开播提醒开着、或有待触发的节目提醒、或用户正在打开开关/设置提醒。这样从没用过通知的用户在 Windows 上不会写注册表。
7. **IPTV 节目提醒（F-IPTV-09）**：节目单面板里未开始的节目显示“提醒我”，设置后在开始前 1 分钟通知，点击进入该频道。提醒列表存在 `meta` 表的 `alerts.programmeReminders`（JSON 数组：频道、标题、开始、结束），不备份；进程存活期间用定时器触发，触发后从列表删除。启动时恢复列表：开始时间未到的重新定时（已进入前 1 分钟的立即通知），已开始的丢弃。

## 备选方案与放弃理由

- **给 `follows` 加 `alert` 列**：要做 schema 3 迁移和迁移测试，而且 IPTV 已经占用 schema 2，其它会话同时改 schema 容易撞号；备份格式也要加字段。房间偏好本来就是“每个房间的偏好”，已有备份和级联删除。
- **每房间三态（跟随 / 开 / 关）**：可以做到“全局关、只提醒某几个人”，但需求是“默认跟随全局、可以对单个房间关掉”，三态让开关的含义难以解释。以后需要时可以在同一个键上加 `true`。
- **只比较“这次开播、上次内存里不是开播”**：冷启动时内存为空，要么全部不提醒，要么全部提醒；用 store 里的快照才能在冷启动时正确判断。
- **用“状态变化时间”代替记录**：`rooms.last_live_at` 每次看到开播都会更新，区分不出新旧两场；平台给的开播时间更可靠，缺失时才退回按提醒时间的静默期。
- **用插件的 `zonedSchedule` 让系统到点提醒（节目提醒）**：进程被杀后也能响，但 Android 需要精确闹钟权限（`SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`）和开机广播接收器，Windows 的定时 toast 需要应用身份；清单改动和权限说明都更多。需求只要求进程存活期间有效，先用定时器。
- **自己写通知通道（MethodChannel + Kotlin）**：`MainActivity.kt` 正由其它工作修改，Windows toast 还要自己写 WinRT/COM 代码；插件两端都成熟。
- **其它插件（awesome_notifications 等）**：没有 Windows 实现，或许可证、体积不合适。
- **开关作用域用 `synced`**：换设备恢复后开关是开的却没有权限，通知静默失败；`device` 至少限制在同一平台家族，启动时还会按系统状态校正。

## 影响

- **已知限制**：进程被系统杀死或用户划掉后，不再检查开播，也不会触发节目提醒；Android 12+ 的后台冻结和省电策略也可能让进程在后台时定时器停摆。点击通知时如果应用已退出：开播提醒开着时，冷启动会打开对应页面；只剩节目提醒触发过的通知时，应用正常启动，不跳转。Windows 上通知没有自定义图标（未传 `iconPath`），应用关闭后点击 toast 不会启动应用（插件只注册了进程内激活器）。
- **以后的方向**：进程被杀后的检查可以用 Android WorkManager（周期不短于 15 分钟，由系统调度）在后台 isolate 里跑一次轻量刷新，需要把刷新和提醒规则做成不依赖界面的入口，并处理 Android 15 的后台限制；节目提醒可改用系统闹钟（精确闹钟权限、开机恢复）。Windows 可以在关闭窗口时驻留托盘继续检查。
- **许可证**：`desugar_jdk_libs` 是 OpenJDK 代码，许可证为 GPL-2.0 加 Classpath Exception；该例外允许与任意许可证的独立模块链接并以任意条款分发，不属于宪法原则 11 所禁的“GPL-2.0-only”情形。发布时在第三方许可证清单里列出它。
- **Android 构建**：`apps/pure_live/android/app/build.gradle.kts` 开启 `isCoreLibraryDesugaringEnabled` 并加 `coreLibraryDesugaring` 依赖；本草稿写成时没有构建 APK 验证，第一次 Android 构建时确认。
- 设置页“通用”分组新增“定时刷新间隔”和“通知 › 开播提醒”；关注页卡片菜单新增每房间的“开播提醒”开关；节目单面板的未开始节目新增“提醒我”。
- 存储规格（store.md §3 `room_prefs` 键、`meta` 键）和 iptv.md §9 第 3 条随本记录更新。
