## 夹具与独立对照

复用固定 rolling CMAF 的最前三个视频与音频分片，不重新编码。每路将 13 字节前缀、初始化段、三个媒体分片拼成同一个 bundle.mp4：MAP 从非零绝对偏移开始，第一媒体范围显式指定偏移，后两片只指定长度并继承偏移。同一上游 URI 对应四个不同范围，验证本地资源身份并非只按 URL 合并。

直接对照采用原始独立 MAP/媒体文件和手工保留的 EXTINF/URI 行；不是用待测保留清单渲染器生成两边。原生 ffprobe 提供逐包时间戳、大小、标记、流归属、payload SHA-256 与 codec 信息。

生产侧实际启用 FFmpegHlsInputRelay，获取两路选择与八个本地资源。用 HEAD 等待每个完整缓存封口，避免把预热误记作 native 消费；核对源站每路只收到四个精确绝对 Range 请求。随后冻结并关闭 origin，两次通过生产缓存 URI 运行 ffprobe，逐包比较除容器位置 pos 外的全部字段；最后再用 CLI 实际解码两路音视频。

## 范围与所有权

- 测试的是生产 relay 与桌面原生 ffprobe/FFmpeg 的标准 CMAF BYTERANGE 输入合同，不是新的 Android/Manager 实机录制验收。
- 八个 cache identity、非零 MAP、显式与隐式媒体偏移、重复 native 读取、源站消失后读取均单独断言。
- 源站请求日志有数量上限，所有服务请求 Future、订阅与客户端在 finally 收尾。
- 原生子进程有 30 秒期限；仅结束本探针自己创建的超时进程，并等待其退出和输出流，不中断其他任务。
- 不覆盖任意客户端的多区间/后缀 Range、高效整对象随机 seek、加密媒体、LL-HLS PART 或真实平台。
