# 页大小与加载事务顺序审计（2026-09-10）

## 范围与复现

基于 5b07d5e2，接续[固定/远程分页退出审计](FIXED_REMOTE_LIFECYCLE_AUDIT_2026_09_10.md)。只修改 [ServerFixedPageController](../lib/common/base/server_fixed_page_controller.dart) 和 [ServerRemotePageController](../lib/common/base/server_remote_page_controller.dart)，版本保持 3.1.8+4121。

已确认 [CompactPageSizeSelector](../lib/common/base/desktop_components.dart) 在加载期间仍接受选择，所以请求中调整页大小是实际 UI 可达操作，不只是测试替身能力。首轮 14 项为 2 PASS / 12 FAIL：

- 初始页大小 2，请求未完成时选择 4 再选 3，旧实现提前改变请求使用的 pageSize/currentPage。固定分页按旧范围拼装却以新页大小发布，远程分页可清掉缓存后直接因 loading 返回。
- 连通性检查尚未结束、loading 仍为 false 时也可修改请求尺寸；移动加载更多连续调用会将页号由预期 2 推到 3。
- 远程页大小补数不在 _activeLoad 内，刷新或另一次补数可同时发出请求。红测在第二个响应尚未完成时，实际请求总数已达到 3，连通性窗口中达到 4，而串行合同应仅为 2。
- 排队选择在页面关闭前已立即改值，随后退出检查只保护响应，未保护该选择的提交时机。

“改选回原尺寸”两项初始对照已通过，保留作为取消待处理意图的回归。

## 修订

1. setPageSize 保存最新待处理值，当前请求终态后才提交尺寸、页号及缓存重建。连续选择合并为最后一个值，包括重新选择当前尺寸；小于 1 或空值不进入计算。
2. 等待时每次重新观察 _activeLoad，而不是只等待进入方法时捕获的一个 Future。另一个等待者启动新任务后，刷新/尺寸提交继续等待，避免跨任务清缓存和重设游标。
3. 远程补数经 _startLoad 注册在同一活动任务中，涵盖连通性检查阶段。普通加载、跳页、刷新及加载更多都可识别该任务。
4. 加载更多在活动请求期间返回同一任务的完成结果，不在 loading 标志置位之前重复增加页号。

保留每个既有加载 Future 的独立终态；没有将最初加载和所有后续刷新合成一个不断延长的 Future。正常缓存切片、当前首行定位、远程补数、移动追加与刷新替换、关闭保护、部分结果保留维持既有语义。不通过禁用整个页大小选择器、加固定延迟、重复刷新或取消网络请求来规避竞争。

来源为 **upstream-existing**：冻结上游 c6c9bd70 的 setPageSize 立即写尺寸/缓存和远程独立补数结构相同；主要代码可追溯至 913a075f。当前分支 4191c5b6 引入的活动加载句柄已串行普通请求，但尚未覆盖补数及所有等待者。本批本地适配既有事务，不合并上游。
