# S 质量和验证

管“怎么证明 4.x 真的能用”：自动测试的稳定和覆盖、K90 真机验证、所有界面走一遍的统一验证、用 3.x 数据覆盖安装的验证。它不产出功能，但每个功能任务从“待真机”变成“完成”都要经过这里（[PROCESS.md](../PROCESS.md) 第 3.2 节：完成必须有真机结果），所以排在各功能组和性能组之后、需求组之前。

## 范围

- 管什么：
  - **自动测试的稳定和覆盖**（S01）：13 个工作区成员的 `test/`（`apps/pure_live/test/`、11 个 `packages/*/test/`、`tools/check_latest/test/`）能稳定通过、不随机失败；各包有多少测试、哪里没测（覆盖清单）。时间炸弹检查 `tools/timeshift/run.sh` 也在这里用。
  - **K90 真机验证**（S02）：界面重构后的冒烟（S02.2）、按清单逐项看（S02.3、S02.4、S02.6）、把一批“待真机”任务编成一张清单一起看（S02.5）、给“登记完成但没有真机结果”的任务补验（S02.4、S02.6）、真机上发现的问题回收和修复（S02.1 这类）。清单是 [S02-真机验证/CHECKLIST.md](S02-真机验证/CHECKLIST.md)，每条写“由谁验证”。
  - **统一验证**（S03）：A 组的界面都合并以后，所有界面和流程按确认过的设计在各种尺寸下走一遍，附基准报告，做 Android 版本的整体验收。
  - **覆盖安装验证**（S04）：在模拟器或另一台设备上装 3.2.11 和一份数据，用 4.x 正式包覆盖，核对安装本身（签名、版本号、首次启动、导入只跑一次、3.x 原文件不动、回退）。
- 不管什么（归哪里）：
  - 门禁脚本本身（`tools/gate/gate.sh`、`check_*.py`、`ui_baseline.json`）归 [Z02 门禁](../Z-工程文档和维护/Z02-门禁/README.md)；本组只用它的结果。
  - 某个功能自己的测试由那个功能任务写（修 bug 先写改前会失败的测试），S01 只管测试整体的稳定和缺口。
  - 基准测试的工具和数字（`apps/pure_live/integration_test/perf_test.dart`）归 [R01 基准和测量](../R-性能和流畅度/R01-基准和测量/README.md)；S02.5、S03.1 只跑它、引用结果。
  - 3.x 数据迁移的代码（`packages/live_store/lib/src/legacy/`、`apps/pure_live/lib/app/iptv_legacy.dart`）和数据内容的逐项核对归 [J06](../J-设置和数据/J06-3.x数据迁移/README.md)（J06.1）；S04.1 只管安装这一层，两者是同一次覆盖安装。
  - 单个任务的 `verify.md` 由那个任务自己写；S02.5 只是把 4.0.0 构建号 5001 里的 18 个任务排成一次走完的顺序。
  - 其他组自己的验证任务（O02.1 画中画、O04.1 本地网络权限、O06.1 ColorOS 返回、K02.1 加密存储、H01.4 录制、R01.2 基准、J06.1 迁移）在各自的组；可以和 S02 同一次上机。
  - 发现的问题在哪一组修就开到哪一组（例如录制清晰度标签在 H01.3 修），本组只记现象、根因线索和去向。

## 风险和注意

- **手机规则**（D-019、AGENTS.md）：只点测试包 `com.mystyle.purelive.v4dev`，每次输入前确认前台；不碰用户的 3.x 正式包 `com.mystyle.purelive` 和它的数据。`~/tools/pl-adb.sh` 第 7 行默认的 `PL_APP` 还是旧的 `com.mystyle.purelive.next`，用之前先 `export PL_APP=com.mystyle.purelive.v4dev`。上机前用 `adb logcat -d | grep "adbd service requested"` 看有没有别的自动化程序在操作手机（2026-09-28 出过一次）。
- **断网只断测试包**：K90 的 adb 走 Wi-Fi，关 Wi-Fi 就连不回来；用 `iptables -m owner --uid-owner` 只拦测试包（S02 子分类说明第 5 步），用完删规则。
- **K90 看不到平板分栏**：K90 横屏是 869×400 dp，高度不到 480，按 `features/live_play/logic/room_layout.dart:66` 走“横屏手机”布局；宽屏分栏要宽 ≥840。宽屏条目用 `adb shell wm size`、`wm density` 临时模拟（测完必须 `reset`），或者留给平板。
- **基准会覆盖测试包**：`flutter drive --profile` 会把 profile 版装成 `.v4dev`，跑完要重新装平时的测试包。
- **录制失败的提醒**：H01.5 修好前“断网等重试用完”造不出录制失败，要先关“自动断线重连”（S02.5 任务书 4B）。
- **随机失败的测试**：先找根因再改（PROCESS 第 12 节），不靠重跑；测试里的定时器至少 1 秒、不访问真实平台（D-017）。S01.1 的教训：真实时间的固定预算在机器忙时不够，要按条件等。
- **覆盖安装**：Android 上同一个包名的代码是所有系统用户共用的，在 K90 上开第二个用户装 3.x 再覆盖也会升级用户自己的 3.x，所以 S04.1 必须用另一台设备或模拟器；电脑上同时连着 K90 和模拟器时，每条 `adb` 都要带 `-s`。
- 门禁运行时不要在同一份代码里构建正式包（PROCESS 第 8 节第 5 条）。
