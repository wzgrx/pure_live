## v3 的样子（`~/ref/v3ref`，`v3.2.11`）

**引擎**：本地补丁版 flame_barrage 0.0.4（`pubspec.yaml:60-61`，`plugins/flame_barrage/`），一个 FlameGame，Flame 自己的计时器停掉，改由弹幕层自己的 Ticker 按设定帧率推进（`core/barrage_engine.dart:26-31`、`:133-181`）；没有弹幕时停（`:127-131`）。

**默认设置**（`common/services/settings/danmaku_settings_controller.dart:7-16`）：字号 16、字重 500、描边开、描边宽 1.5（黑色）、速度每秒 120 像素、透明度 100%、占用 100%、顶部留白 0、底部留白 0.5、帧率 60、跟随刷新率开。颜色用平台给的颜色。

**直播间传的参数**（`modules/live_play/widgets/video_player/video_controller_panel.dart:786-811`，改设置时 `video_controller.dart:949-978`）：每 0.05 秒最多放一条（`emitInterval`）、同屏最多 48 条、排队最多 120 条、最久 5 秒、轨道高 字号 × 1.55（24～64）、表情 字号 × 1.3、缓存 96 / 72 / 320。竖屏流的“上四分之一 / 缩小”模式把占用限制在 25% / 50%（`:775-780`）。

**轨道**：实际轨道高 = max(轨道高, 字号 + 10)，16 号字是 26（`scheduler/track_manager.dart:14`）；文字框高 字号 × 1.15（`layout/mixed_layout.dart:280`），在轨道里上下居中（`core/barrage_engine.dart:471-474`）。竖屏画面（393 × 221）8 条轨道，横屏全屏（852 × 393）15 条。选轨道：先找空的，否则找最后一条已经离开右边缘 40 像素以上、条数和速度加权最小的（`scheduler/track_allocator.dart:24-36`）；后面的比前面的快时减速避免追尾（`scheduler/speed_strategy.dart`）。

**速度**：每条弹幕 x 减去 速度 × 经过时间（`core/barrage_engine.dart:363-366`），时间来自引擎时钟，取整到毫秒（`core/engine_clock.dart:6`）。

**画法**：每条弹幕排版一次（填充、描边两段文字），录成一张 Picture，按内容和样式缓存（`core/barrage_engine.dart:464-469`、`:589-611`）；每帧只平移后画这张 Picture（`:543-559`），不开离屏图层；透明度直接进文字和描边颜色，描边按透明度的平方根，淡了也看得清（`layout/mixed_layout.dart:10-13`、`:107-110`）。表情代码（`[笑哭]`）换成图片夹在文字里，纯文字模式不画（`layout/rich_parser.dart`、`layout/mixed_layout.dart:175-221`）。

**帧率**：跟随时按“界面刷新率”档位：省电 = min(设备最高, 60)，均衡 = 60，最高 = 设备最高；手动 30～240（`danmaku_settings_controller.dart:135-162`）。

**暂停和交互**：视频没在播时不放新弹幕（本地弹幕除外，`video_controller.dart:183`）；点或长按一条弹幕打开操作面板，弹幕层暂停到面板关闭（`:132-149`）；画面手势层把命中的位置转给弹幕层（`core/barrage_engine.dart:227-239`）。

**去重**：在连接层（重复包闸门、合并相同弹幕、相似过滤），不在渲染层；v4 已经搬到 `packages/live_danmaku/lib/src/filters/`。

## v4 现在的实现

`apps/pure_live/lib/shared/danmaku/danmaku_overlay.dart`（一个 CustomPainter，不用 Flame），直播间、小窗、多画面、电视共用（`player_view.dart:269-273`、`mini/compact_danmaku.dart:149`、`multiview_page.dart:861`、`tv/room/tv_live_play_page.dart:464`）。`packages/live_danmaku` 只管连接和过滤，不管画。

- 按时间走：位置 = 速度 × (这一帧的时间 − 出现时间)，时间是 Ticker 的微秒（`:402-405`）；外面套了 RepaintBoundary 和 ClipRect（`player_view.dart:269-273`）。
- 每条弹幕收到时排版两次（填充、描边），不缓存（`:200-226`）；每帧对每条画两段文字（`:424-431`）。
- 透明度用 `Opacity` 包整层（`:374-377`）。

## 速度按时间算吗

v3 和 v4 都按时间算（像素/秒 × 经过的时间），所以 60、90、120、144 赫兹下平均一样快；不一样的是“匀不匀”：v3 的帧率上限不是刷新率的整数分之一时步子不均（H1），时钟取整到毫秒（H2）；v4 每个刷新周期都画，均匀但每帧花得多（V3、V4）。新做法：每条弹幕带自己的出现时间和速度，位置 = 速度 × (这一帧的垂直同步时间 − 出现时间)，微秒；帧率上限取刷新率的整数分之一（c3）。

## 高密度（每秒 200 条）不掉帧的做法

1. 入场：没空轨道就排队（最多 120 条、最久 5 秒，满了丢最旧的，照 v3）；每帧最多放 4 条，把突发分到几帧；同屏最多 48 条（照 v3）。
2. 排版缓存：同内容同样式只排版一次（最近 320 条，照 v3）；排好录成 Picture，每帧只平移。K90 上实测 Picture 不够快，同一个缓存换成图片（方案 C 的做法）。
3. 只描边、不加模糊阴影；透明度进颜色，不用整层 `Opacity`。
4. 分层：弹幕层单独一个 RepaintBoundary，视频和控制层不跟着重绘；没有弹幕、暂停、隐藏时 Ticker 停。
5. 过滤在连接层（重复包、合并相同弹幕、相似过滤、屏蔽词），已在 `live_danmaku`。

## 拿不准的地方

1. Impeller 下回放带描边文字的 Picture 每帧要多少光栅时间，没有实测（按要求这次不做实验），H-B 的建议以开发时实测为准。
2. v3 竖屏时 `safeArea` 是否会把状态栏高度算进弹幕区（`core/barrage_engine.dart:72-86` 读 `MediaQuery.paddingOf`），图里按画面内没有内边距画。
3. 每帧最多放 4 条是估计值（K90 上排版一条约零点几毫秒），开发时按实测调。
