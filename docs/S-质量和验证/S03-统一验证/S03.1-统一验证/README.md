## 目标

Android 4.x 的整体验收：A06～A15 每个完成的界面任务按“确认的改动”逐条核对，在 K90 的竖屏和横屏、模拟的宽屏和窄横屏、分屏、深色、大字号下都看一遍，主要流程从头走到尾；附一份 K90 上的基准测试报告。做完以后能回答“4.x Android 版每个界面是不是确认过的样子、在各种尺寸下能不能用、流畅度达不达标”，发现的问题都开成任务。

## 方案

不改代码，五个阶段（2026-10-07 已登记）：

| 阶段 | 区域 | 任务 |
|---|---|---|
| 1 | 首页、浏览、小页面 | A06.1～A06.4、A09.1～A09.10、A15.1、A15.2 |
| 2 | 直播间和弹幕 | A07.1～A07.13、A08.1～A08.5 |
| 3 | 录制、设置、账号和数据 | A10.1～A10.3、A11.1～A11.5、A12.1～A12.6 |
| 4 | 网络电视、多画面、系统界面 | A13.1、A13.2、A14.1 |
| 5 | 宽屏和平板汇总、基准报告、验收结论 | 全部（`wm size` 模拟和平板）；R01.1 基准 |

- 每个阶段：先从各任务 README 的“确认的改动”表和“实现和验证”抄出核对表（只抄编号和一句话），再上机逐条看；S02.x 已经通过、之后没改过的条目写“已验证（S02.x，日期）”只抽查。
- 结果按区域写进本文件夹的 `verify-1.md`～`verify-5.md`（照 [templates/verify.md](../../../templates/verify.md)，一行一个 c 编号），截图放 `verify/`；每个任务 README 的“实现和验证”加一行“统一验证（S03.1，日期）：符合 / 有 N 条不符合（去向）”。
- 不符合的开到 A 组（界面）或功能组（行为），标题写“接 A0x.y”。
