## 虎牙实际观察与上游区别

重新阅读了 [上游取流提交 c5944dd5](https://github.com/liuchuancong/pure_live/commit/c5944dd5a529cd93eb29486500abd5d496618f80)、
[Issue 808](https://github.com/liuchuancong/pure_live/issues/808)、
[Issue 816](https://github.com/liuchuancong/pure_live/issues/816)。上游关键是 WUP 原生令牌，不是更频繁
重开播放器。本地已适配原生 FLV 优先、HLS 独立合同、健康连接只预取、活动线路身份及恢复所有权。
前序 A/B 的 120.841 秒网页 EOF / 原生 AL、TX 各 420 秒持续读取证据，见
[原生取流审计](HUYA_NATIVE_LEASE_FIX_2026_09_05.md)。该结果不外推为所有 CDN 的固定服务器限制。

本次从热门页选择虎牙主机游戏公开房间（界面主播“狂鸟、楚河-90327”），蓝光 30M、线路 1、
`tx.flv.huya.com`，没有登录。01:31:06 开始 playing；普通页、双击进入全屏、双击退出全屏后
画面与真实弹幕列表均持续更新，随后约 01:39 主动返回热门页。整个观察阶段超过八分钟，
`PlayerRecovery` 仅有启动四条状态记录，没有自然中断引发的恢复、主动换源或重开记录。
此为分时画面及事件观察，没有连续声音/逐帧录制，证据不支持每一帧、每个房间都无卡顿的结论。

## 资源采样口径

使用 `tool/sample_windows_runtime.ps1` 对本测试 PID 采集，首个无差分 CPU 基点已排除。
CPU 为 24 逻辑核整机归一百分比，working set 与 private bytes 分开；不使用异常 GPU 计数。

| 场景 | 样本数 | CPU 平均 | 工作集首→末 MiB | 私有字节首→末 MiB |

| 实际虎牙播放，约 120 秒 | 13 | 3.1690% | 421.3945→426.4648 | 866.2930→859.3398 |

直播窗口内私有字节没有单调增长，线程 245→241，句柄 1708→1695。这只是短窗口，不证明
长时无泄漏；CUA、前台状态、热门卡片数量与原生无障碍观察者也影响 CPU，禁止直接用不同页面
或不同观察条件的旧样本计算“优化百分比”。显示器报告 200 Hz 不是应用实际帧率。

返回热门页时没有浮窗；退出后采样跨过管理器 45 秒闲置释放边界，记录到 VideoOutput 析构、
线程 235→153、句柄 1658→1299。随后通过标题栏关闭与应用确认退出，操作系统查询 PID 42920
已消失；未强停此可见实例或用户主客户端。剩余私有字节高于空关注启动基线，不解释成零缓存，
也不从这 65 秒窗口推导长期内存趋势。
