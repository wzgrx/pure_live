# 虎牙原生令牌与连续播放修复（2026-09-05）

## 来源和先于实现的结论

本地基线 `2ffb9519`，只读参考上游 `baab0eb4`，没有合并上游。
来源：`db7d0df3` 中网页模板优先和全虎牙短连接假设，以及 Windows 固定 40 秒提前换播放器属于本仓库定制；分类 `fork-regression` 与取流契约兼容问题。

此前“地址能读首包”被误当成“适合长时间播放”，并用短周期替换播放器处理后续 EOF。第一个问题发生在取流策略选择，不只在渲染层。

## 同条件探测

房间 660000、AL-game FLV、ratio=500、相同 HYSDK 媒体请求头；无用户登录、无手机操作。每条地址只打开一次，不预检后重复消费同一地址，不保存令牌。

WUP 返回 `ctype=huya_pc_exe`，请求有效期字段为 300 秒，但已经建立的连接在 420 秒仍正常。**新连接凭据有效期不等于现存连接的强制截止时间。**WUP 样本最大读取间隔 0.316 秒；这是网络到达间隔，不是实际视频掉帧统计。

证据目录 `local-artifacts/diagnostics/huya-continuity-20260905/`，`probe_wup_compare.py`、`wup-660000-summary.json`、`web-660000-summary.json`。最初探针漏写默认 t 参数的 403 属于探针错误，已纠正后重新完整取样，不作为上游失效证据。

参考：上游 `c5944dd5` 中 WUP 取令牌逻辑；biliup 的 Huya/Tars 实现及 Streamlink Huya 源码用于交叉核对，不直接复制其自行延长 wsTime 或硬编码其他客户端参数的策略。

## 修复设计

| 位置 | 上游做法 | 旧本地做法 | 本次处置 |
|---|---|---|---|
| FLV 取流 | WUP 原生凭据优先 | 网页模板有效则优先使用 | 经真实长读验证后适配原生契约 |
| HLS 凭据 | 原生返回字段只有 sFlvToken，照搬存在协议混用风险 | 独立 HLS 模板 | 保留本地协议隔离 |
| 连接期限 | 不把本地 40 秒计时当服务端要求 | Windows 40 秒提前换播放器，100/125 秒短租约套用所有虎牙 | 仅网页/未知家族保留旧保护；原生连接只预取、不主动重开 |
| 播放竞态和缓存 | 与本地定制存在差异 | 上轮已修播放意图代次及 native 缓存预算 | 保留独立修复，不整文件覆盖 |

另外，上游 Android IJK 的自动启动适配曾在后续提交撤回；该项不作为本次原生令牌修复一起引入。取流短连接与纹理/自动启动属于不同故障层。

1. FLV 有签名模板时优先请求原生 WUP 凭据；请求字段与已验证的上游契约一致，使用 HTTPS、有限超时并释放 HTTP 客户端。保留网页模板与原来的 Web WUP 恢复作为失败后备。
2. HLS 仍使用 HLS 模板，禁止把只返回 sFlvToken 的接口强行套给 HLS；网页及未知令牌保留已有短连接保护。
3. 将原生 `huya_pc_exe/t=100` FLV 与短连接家族分开。其凭据按服务端期限更新，但正常播放不因 40/100/125 秒计时器重开；到期只预取下一次恢复所需地址。
4. 真正网络失败时仍消费有效预取地址并重开；同 URL 死连接恢复、用户暂停/关闭代次、线路回退保持。
5. 已知签名模板可能被播放/录制同毫秒消费，使用单实例单调签名时刻保证每次生成独立地址；显式测试时钟保持确定性。

6. 冷启动尚未加载远程播放配置时，播放与录制共享已验证的 HYSDK 媒体请求头，避免原生令牌配上浏览器回退头；已有显式远程配置仍保留。

## 影响范围与回滚

- Android/Windows、普通/全屏/小窗/音频共用 HuyaSite 取流；不改 UI、比例识别或模式状态机。
- 录制共用新的取流和请求头入口，但本次长读不是 FFmpeg 输出文件/封装验收。
- HLS 不套用 FLV 原生凭据；网页后备保留旧短租约保护。其他平台的 Windows 预热行为保持原样。
- 每次仅合并同一 streamName 的正在进行的原生令牌请求，无永久令牌缓存；HTTP 客户端在成功、异常、超时后关闭。
- 回滚本次定向提交即可恢复先前取流策略；保留此前独立的缓存预算及播放意图竞态修复。回滚也会重新暴露本次已复现的短连接/定时切换问题。

## 验收边界

本次证据针对取流和管理器契约，不代表所有房间、全部 CDN、解码器、网络状态永远无卡顿。按普通/全屏/小窗/音频共同使用的入口修复，不改比例和弹幕 UI。HLS 与外部网络中断仍是单独风险项。3.2.0 总体验收尚有其他阻断，不提前发布为完整稳定版。
