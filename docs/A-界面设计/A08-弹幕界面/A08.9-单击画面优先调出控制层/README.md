## 3.x 的样子和问题

- 3.x 和 4.x 现在一样：设置“点按弹幕”默认开，单击时先问弹幕层这个点上是哪条，点中了就停住弹幕、打开长按弹幕面板，没点中才显示或隐藏控制层（`apps/pure_live/lib/features/live_play/player/player_view.dart:653-657` 的 `onTapDown` 记下 `_danmakuAt`，`:333-358` 的 `_onTap` 有命中就 `_tapMessage`）。
- 问题（K90，哔哩哔哩热门房间）：弹幕多的时候画面上到处是飞行弹幕（点中范围每边还放宽 4），单击几乎总会点中一条，想调出控制层（暂停、全屏、清晰度）却打开了弹幕面板；横屏全屏里同样。要连点好几次、或者找没有弹幕的角落。

## 设计

按 D-003 由维护者定（选建议 A，D-038），不另出评审页：

- c1（建议 A）：**控制层没显示时，单击一律只调出控制层**；控制层显示时，点中弹幕才打开面板（这时用户已经在“操作画面”，不会和调出控制层抢）。长按照旧（长按开关开着时，长按弹幕任何时候都打开面板）。
- 备选 B：单击永远不问弹幕，只有长按才打开面板（等于把“点按弹幕”默认改关；3.x 的设置键 `enableDanmakuTapInteraction` 含义不变、只改默认值会违反 D-018 的“3.x 用户感觉不到变化”，所以不选）。
- c2：设置里“点按弹幕”开关的说明改成“控制条显示时点按画面上的弹幕打开操作面板”（zh、en）。
- c3：暂停状态（A07.10）照旧：单击只显示或隐藏控制层。

## 实现和验证

- 未开始。改 `player_view.dart` 的 `_onTap`：`hit != null && shownBefore` 时才 `_tapMessage(hit)`，否则 `_tapControls()`；双击全屏逻辑不变。
- 测试：`apps/pure_live/test/features/live_play/` 里画面点按的测试（A08.4 加的那组）补两条：控制层隐藏时点中弹幕只显示控制层；控制层显示时点中弹幕打开面板。
- 真机：K90 哔哩哔哩热门房间，竖屏和横屏全屏各点 5 次画面，控制层都能一下调出来。
