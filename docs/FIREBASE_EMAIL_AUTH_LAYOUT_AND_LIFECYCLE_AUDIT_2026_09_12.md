# Firebase 邮箱认证布局与生命周期审计（2026-09-12）

## 范围与基线

- 基线：`eab239ff49e495d9ee547c73466a4ad9cbda7bb8`。
- 范围：Firebase 邮箱登录、注册、密码重置、GitHub 登录入口及登录页完成回调。
- 本轮只做源码、确定性单元/Widget 回归、静态分析与仓库审计；未连接手机、访问真实 Firebase/GitHub、构建安装包或发布版本。

## 复现与根因

加入可注入认证后端接缝后，有效红测为 **1/7 PASS**：

1. 密码重置入口被限制在 Android，维护中的 Windows 桌面端没有入口。
2. 注册自定义元数据可覆盖规范 `email` 和 `created_at`，破坏账号身份与注册时间。
3. 认证请求进行中仅主按钮失效，邮箱、密码、元数据、密码显示、忘记密码和模式切换仍可改动，提交快照与界面状态可能分裂。
4. 密码校验使用原始文本，提交却裁剪首尾空格，导致校验通过的密码被静默改写。
5. 登录页退出后，迟到失败仍会触发可见回调；成功回调也未被等待，云端配置同步与返回路由之间缺少完整事务边界。
6. 密码重置失败在未注入错误回调时没有可见提示；其余认证失败直接展示后端原文。固定 46 像素按钮也缺少随可访问字号增高的余量。

## 修订

- 增加 `FirebaseEmailAuthBackend` 注入接缝，统一邮箱、GitHub、注册资料与密码重置调用；所有维护平台均按后端能力呈现密码重置入口。
- 注册资料通过纯函数构造：规范邮箱与注册时间由组件独占，保留字段不会被自定义元数据覆盖；其余键和值统一裁剪。
- 认证动作使用单一活动事务和请求代次；请求期间锁定所有会改变提交语义或认证模式的控件，退出后迟到结果不再产生界面回调。
- 密码按用户输入原样提交，邮箱继续规范化；成功回调升级为可等待的 `FutureOr<void>`，加载态覆盖后续同步与路由收尾。
- 登录页等待配置同步，检查挂载状态后再使用本地 `Navigator` 返回，避免依赖迟到的全局上下文。
- 密码重置、邮箱和 GitHub 认证补齐双语通用失败提示，精确异常仍通过注入错误回调交给诊断方；GitHub 用户取消保持静默。
- 认证按钮改用最小高度，密码显示按钮增加双语 tooltip；320×480 / 3.0 倍英文下所有入口仍可滚动到达。
