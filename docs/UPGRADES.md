# 升级决定

2026-09-28 用户对 M4 汇总的 222 条升级候选答复“全部采用，所有决定你自行判断，可以增加对应的选项功能设计”。所以这些条目的界面和行为变化都已批准；有多个方案的条目，方案由我选，写在“落地方式”一列；需要保留 v3 旧行为时做成设置开关。候选之外的新改动仍按 AGENTS.md 的规则先问用户。

原始清单和逐条说明见各平台记录 `docs/modules/M4.*.md` 的“后续升级候选”；决定页：https://claude.ai/artifact/9RbQCAwUHXwHsygAbrDtWp 。

## 统一原则

| 事项 | 决定 |
|---|---|
| 受限、付费、私密、仅限 App、地区受限、密码房 | 列表和详情照常显示为直播中，卡片标出受限类型（新增房间字段，M2.1）；播放时说明原因（`NeedsLogin`、`RegionBlocked`、`StreamUnavailable` 带原因）。发现页默认隐藏不能播放的直播，设置里可以打开；关注和搜索照常显示 |
| 回放、轮播、重播 | 平台给回放地址就播放回放；拿不到的标“不可播放”，关注分组归入未开播。哔哩哔哩轮播、Twitch 重播作为单独状态显示 |
| 画质命名 | 表里有改名或合并条目的平台：源画质叫“原画”，同一档的不同格式或 CDN 合成一档的多条线路，互为备用，存下的画质偏好在 M9 按各平台给的旧 id → 新 id 对照迁移。表里没有这类条目的平台保留 v3 的画质名（v3 的画质偏好按名字匹配，改名会让已存的偏好选错档）；新增的画质（例如虎牙回放）直接叫“原画” |
| 默认编码 | 设置加“优先 H.264”，默认开；M7 在高通真机验证硬解后再评估默认值 |
| 开播时间 | `LiveRoom` 加可选字段 `startedAt`（M2.1，3.x JSON 兼容：旧数据没有就是空）。所有能取到的平台都填，包括 TwitCasting、niconico、SHOWROOM、LOOK |
| 按主播关注 | niconico、YouTube 改为关注主播/频道；小红书、微博找到接口后同样处理。旧的单场关注在 M9 换成主播身份 |
| 占位信息 | 平台回答里的占位名字、标题、封面不覆盖关注里存下的值（M2.1 的合并规则） |
| 房间身份 | 比较时不区分大小写（M2.1），旧关注在 M9 合并重复项 |
| 容错 | 一行坏数据只跳过这一行，一个坏地址只让那一档不可用 |
| 翻页 | 目录和搜索翻页共用 20～30 秒内的同一份快照，下拉刷新再取新的；时间线跨页去重 |
| 弹幕 | v3 的 8 个平台之外，候选里的 21 个平台都接入（M5）。要签名或抓包的放在 M5 后段，接不上的在文档里写明原因 |
| Kick | 先在 Android 和电视版恢复（M12 的原生网络层），Windows 用 WinHTTP 通道随后恢复 |
| 说明文字 | 所有开发说明式的公告、目录说明改成用户看得懂的中文，M13 做多语言时一起改 |

## 执行顺序

1. **M2.1 模型扩展**：`startedAt`、受限类型、轮播和“不可播放”状态、房间身份比较、合并时不被占位值覆盖。3.x JSON 保持兼容。
2. **M4.U 平台层升级**：按平台把下表里标 M4.U 的条目做进 `live_core`，一个平台一次推送，并行进行。
3. **M5 弹幕**：先框架（M5.0），再 v3 的 8 个平台，然后是新增的平台。
4. M7、M9、M12、M13 到对应模块时照表执行。

各模块的条目数：M12 1 条、M13 24 条、M2.1 28 条、M4.U 214 条、M5 23 条、M7 12 条、M9 20 条、已完成 1 条。
