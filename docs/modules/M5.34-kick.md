# M5.34 弹幕（恢复）：Kick

- 日期：2026-10-01
- 目标：`packages/live_danmaku/lib/src/sites/kick.dart`
  - `KickDanmakuConnection`：连接（M5.0 的 WebSocket 运行时）；
  - `KickDanmakuProtocol`：地址、握手请求头、订阅和心跳帧、参数检查、帧的解读，不做 I/O；
  - `KickFrame`：一帧的含义（会话建立、加入、服务器 ping、错误、消息）。
- 参数：`live_core` 的 `KickDanmakuArgs(chatroomId, channelId, slug)`（M4.34），进房详情给出，不多发请求。
- 规格来源：pure_live_TV `kick_danmaku.dart`（e1cca224）；v3 的审计记录 `KICK_PUBLIC_CHAT_AUDIT_2026_09_23.md`；本次录制 `fixtures/kick/danmaku`（以录到的帧为准）。审核、通知类事件没有录到，按公开客户端库（kick-wss 等）写的形状实现，用合成帧测试。

## 协议

| 项 | 内容 |
|---|---|
| 地址 | `wss://ws-us2.pusher.com/app/32cbd69e4b950bf97679?protocol=7&client=js&version=8.4.0&flash=false`（Kick 网页的 Pusher 应用，不在 Kick 的 Cloudflare 后面，dart:io 正常） |
| 握手头 | `origin: https://kick.com`、桌面 Chrome 140 UA |
| 会话 | 服务器先发 `pusher:connection_established`（`socket_id`、`activity_timeout: 120`），之后客户端订阅 |
| 订阅 | `{"event":"pusher:subscribe","data":{"auth":"","channel":…}}`：`chatrooms.<chatroomId>.v2`（聊天、审核、通知）和 `channel.<channelId>`（直播本身的事件，比上游多） |
| 加入 | 收到 `chatrooms.<id>.v2` 的 `pusher_internal:subscription_succeeded` |
| 心跳 | 客户端每 30 s 发 `pusher:ping`（上游）；服务器的 `pusher:ping` 回 `pusher:pong` |
| 错误 | `pusher:error`、`pusher_internal:subscription_error` → 重连（带 `protocolError` 提示） |
| 事件 | `data` 是 JSON 字符串；事件名 `App\Events\…` 取最后一段 |

## 消息

| 事件 | 输出 | 说明 |
|---|---|---|
| `ChatMessageEvent`（`type` 为 `message`、`reply` 或空） | 聊天 | 内联表情 `[emote:<id>:<名字>]` 显示为名字；名字、用户 id、颜色（`identity.color`）、消息 id、时间（`created_at`）、Kick 等级（`badges_v2` 的 `level`，填 `userLevel`）；别的聊天房间、空文字、其他类型不显示。旧形状（消息在 `message` 里、`ChatMessageSentEvent`）照上游也认 |
| `MessageDeletedEvent` | 撤回（按消息 id，`message.id`） | 合成帧 |
| `UserBannedEvent` | 撤回（按用户，`user.id`），临时和永久都撤 | 合成帧，同 Twitch 的 CLEARCHAT |
| `ChatroomClearEvent` | 撤回全部 | 合成帧 |
| `SubscriptionEvent` | 订阅通知“<名字> 订阅了 N 个月” | 合成帧 |
| `GiftedSubscriptionsEvent` | 订阅通知“<赠送者> 赠送了 N 个订阅”/“向 <名字> 赠送了订阅” | 合成帧 |
| `StreamHostEvent` | 突袭通知“<主播> 带着 N 位观众来了” | 合成帧 |
| `PinnedMessageCreatedEvent` | 系统通知“置顶了 <作者> 的消息：…” | 合成帧 |
| `KicksGifted`（Kick 的付费 Kicks） | 有留言是醒目留言（金额 `gift.amount` Kicks，`priceText` “500 Kicks”，显示 `pinned_time` 秒，没有就按金额 1/2/5/30 分钟）；没留言是礼物行 | 没有录到，形状来自公开客户端库，待真机核对 |
| `channel.<id>` 的 `StopStreamBroadcast` | 系统通知“直播已结束” | 录到（S08） |
| `PollUpdateEvent`、`PinnedMessageDeletedEvent`、其他 | 不显示 | 投票没有界面 |

在线人数：Pusher 不推送观看人数，房间的人数仍来自详情（M4.34），`audience.dart` 不变。

## 连接和时序

| 项 | 这里 | 上游 |
|---|---|---|
| 运行时 | `DanmakuSocketConnection`，代理随应用设置 | 自己的 `WebSocketUtils` |
| 加入计时 | 10 s（`joinTimeout`），超时重连 | 10 s |
| 心跳 | 30 s，静默超时 max(3×30 s, 90 s) = 90 s 换连接 | 30 s |
| 重连 | 运行时的退避和上限，每次重连都重新等会话建立、重新订阅 | 有限重连 |
| 就绪 | 聊天频道订阅确认后才报 `DanmakuReady`、才上报消息 | 同 |
| 停止后 | 不再有事件 | 同 |

## 与上游的差异

| 项 | 上游 | 这里 | 原因 |
|---|---|---|---|
| 聊天房间 id | 连接时再请求一次频道 | 进房详情给出 | 少一个请求，平台层没有网络调用 |
| 订阅 | 只订 `chatrooms.<id>.v2` | 加订 `channel.<id>` | 下播通知（录到 `StopStreamBroadcast`） |
| 只认聊天 | 是 | 加上撤回、通知、Kicks | M5 的统一规则（撤回和通知、醒目留言） |
| 等级 | 不读 | `userLevel` | 网页显示等级徽章 |
