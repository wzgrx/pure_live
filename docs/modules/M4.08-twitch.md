## 做法

照 M4.1 哔哩哔哩：解析写成纯函数，请求编排单独一层，用样本对照 v3 的输出，差异逐条说明。

- **接口和输出沿用 v3**：`LiveSite`、`LiveRoom` 等模型和 3.x 的 JSON 不变。v3 实现过的可选能力都保留：刷新（`LiveSiteRoomRefresher`）、录制详情（`LiveSiteRecordRoomResolver`）；另加 `LivePlayUrlResolver`（线路带请求头）、`LivePlayRecoveryResolver`（恢复时重新取流）和 `LiveSiteLinks`。
- **请求照 v3**：同样的持久化查询哈希、变量和请求头（Chrome 137 的 UA、`Client-ID`、每个适配器一个 `Device-Id`、`Accept-Language: en-US`）；分区房间只看中文和韩语直播；推荐是 Just Chatting 分区；usher 用 v3 的全部参数。变化只有两处：详情换成一个原始 `user` 查询（差异 2），分类的各页合并成批量请求（差异 5）。
- **解析照 v3 的取值**：图片经 `i2.wp.com`，列表封面带 `?&t=<秒>`，详情封面是头像，画质名称、id、排序和 v3 的 `parseMasterPlaylist` 一致。错误改为类型化，缺字段按空处理。
- **取流**：先取播放令牌（`PlaybackAccessToken`），再请求 usher 的主播放列表。画质的 `data` 仍是 v3 的变体地址列表；取流时直接把它们变成线路，带上 v3 `PlaybackHeaderResolver` 里 Twitch 的请求头（UA、`Origin`、频道页作 `Referer`、用户 Cookie）。变体地址比 20 分钟的令牌活得长，线路不设租期；恢复时重新取令牌和播放列表。
- **会话**：用户的 Cookie 由构造参数注入的 `CookieVault` 提供，只随播放令牌请求发送（`Cookie` 和 `Authorization: OAuth <auth-token>`）；被拒（401 或完整性质询）就改匿名，并且在 Cookie 换掉之前不再发送。
- **房间号保持请求时的写法**（大小写不变，关注的身份不变）；请求一律用它的小写形式。Twitch 不需要别的编号，所以没有 `TwitchRoomData`。
- **弹幕**只输出 `TwitchDanmakuArgs`：频道登录名（小写），和同一份 Cookie 里的聊天登录（`login` 与 `auth-token` 都有时）；这正是 v3 的 `TwitchDanmaku.joinRoom` 自己去设置里读的东西。`toString` 仍是 v3 的 `danmakuData`（频道名），不含令牌。
- **海外站点**：所有请求（GraphQL、usher）的 `site` 都是 `twitch`，代理路由由应用的 `ProxyPolicy` 决定；媒体请求的代理由播放层决定（M7）。

## GraphQL 传输的接口约定（给 M12）

v3 在 Android 上遇到过：某些代理在 HTTP CONNECT 之后会断开 `dart:io` 的 TLS 连接，而同一代理在浏览器里正常。它的做法是先用 `dart:io` 发，失败或被要求完整性令牌时改走 Android 系统 TLS 栈（`core/common/android_native_http.dart`，MethodChannel `pure_live/native_http` 的 `postTwitchJson`，只放行 `gql.twitch.tv`），再不行就在无界面 WebView 里发（`core/utils/twitch/twitch_web_integrity.dart`）。平台层不能依赖 Flutter，所以适配器只认注入的 `LiveHttp`：

```dart
TwitchSite(http, cookies: vault, gqlFallbacks: [androidSystemTls, browser]);
```

- **顺序**：每个 GraphQL 请求先交给 `http`；它抛出 `TransportFailure`（取消除外）、回 HTTP 5xx，或 Twitch 回的是完整性质询（错误信息含 `failed integrity check`、`integrity token`，或有 `extensions.challenge`），就把同一个请求依次交给 `gqlFallbacks`，用第一个不是这三种情况的应答。都不行时报最后一次的错误：`NetworkFailure` 或 `RiskControl`。401、429、其他 4xx 不换传输。
- **请求**：备用传输收到的 `LiveRequest` 与 `http` 收到的完全相同：`site: 'twitch'`（应用据此选代理，v3 把应用代理的主机和端口传给原生通道）、`POST https://gql.twitch.tv/gql`、小写的请求头、JSON 正文（一个操作或一个批量数组）、`timeout`（默认 20 秒，同 v3 的 `timeoutMillis`）和 `cancel`。
- **应答**：返回真实的状态码和解压后的正文（`LiveResponse`），任何状态码都是应答；没有应答时抛 `TransportFailure`，`cancel` 触发时抛 `TransportReason.cancelled`。适配器只用 `send`，不用 `open`。
- **范围**：只有 `gql.twitch.tv` 会交给备用传输；usher 走 `http`，媒体走播放器。
- **完整性令牌**：适配器不发 `Client-Integrity`，也不自己取令牌。v3 在原生通道被质询后先用 WebView 取令牌、再带着它用原生通道重发（`twitch_site.dart:131-134`），最后才把整个请求放进 WebView；这些都属于浏览器环境，由 M12 在各自的传输里实现（比如浏览器传输自己缓存令牌）。纯 HTTP 请求 `/integrity` 拿到的令牌实测仍被拒（规格 §8），不移植。
- v3 只在 Android 上有系统 TLS 通道（`AndroidNativeHttp.isSupported`），WebView 只在 Android、iOS、macOS 上有；Windows 不注入备用传输，与 v3 一样。

## 保持 v3 行为、没有采用归档 v4 或上游做法的地方

- **推荐仍是 Just Chatting 分区**（中文、韩语），不改成全站人数最多的 30 个直播（v4 的原始 `streams` 查询，样本 S03）。
- **分区房间仍只看中文和韩语直播**。v4 去掉了语言过滤，那会改变列表内容。
- **分类不加“热门”**（v4 的 `top`），标签名仍用 `tagName`，无名标签也保留（`tagName` 为空时才用 `localizedName`）。`Accept-Language` 仍是 en-US，分类和分区名是英文；v4 用 zh-CN 得到中文名。
- **每个标签每页 30 个，满页就照 v3 继续翻**。v4 只取第一页。
- **分区 id 仍是游戏的数字 id**，slug 放在 `shortName`。v4 用 slug 作 id，会改变已关注分区的身份。
- **图片仍经 `i2.wp.com`，列表封面仍带 `?&t=`**。搜索卡片的封面仍用 `previewImageURL`（214×120）；v4 换成 440×248 的模板地址。
- **详情的封面仍是头像，简介和公告仍为空**，标题取上次直播的标题，区域取游戏的 `name`。v4 用直播截图作封面、`description` 作简介。
- **列表卡片一律算直播中**（包括 `rerun`），详情只有 `type == live` 才算直播中，不在播时观众数写 `'0'`。v4 把 `rerun` 标成回放。
- **usher 参数照 v3**（`acmb`、`play_session_id`、`player_version`、`transcode_mode` 等），不加 v4 的 `supported_codecs=avc1`。
- **画质名称、id 和排序照 v3**。v4 用 `EXT-X-MEDIA` 的 `NAME`（“1080p50 (source)”）。
- **媒体请求头照 v3**：UA、`Origin`、`Referer` 和用户 Cookie。v4 只带 UA。
- **UA 仍是 Chrome 137**。
- **弹幕参数保留用 Cookie 登录聊天的信息**。v4 一律匿名。
- **链接保留大小写**。v4 统一转小写，那样用大写链接关注过的房间会变成另一个身份。
- **`searchAnchors` 仍为空**，页大小按调用方给的（1–100）。

- **中文分类名**：`Accept-Language` 改为 zh-CN，分类、分区名变成中文（样本就是这样录的）。
- **去掉分区的语言过滤**，或推荐改成全站热门（样本 S03）。
- **详情显示频道简介**（`description`，样本里就有）。
- **详情封面用直播截图**（直播中时）。关注卡片刷新后会从头像变成截图。
- **不存在的分区报 `NotFound`**：现在照 v3 显示为空列表。
- **图片不经 `i2.wp.com`**、**媒体请求不带用户 Cookie**：前者是第三方图片代理，后者把登录 Cookie 发给了 CDN。
- **请求 `supported_codecs=avc1`**，或按播放器能力请求 HEVC/AV1 增强广播。
- **`rerun` 的处理**：标成回放或不可播放（样本里没有重播，Twitch 可能已停用这个功能）。
- **分区页一次取 100 个再本地分页**（同 v3 的热门页），属于 M13。

## 回归条目的覆盖

  - 003：详情的观众数取自 `stream.viewersCount`（S05-user-live 为 23169）；
  - 004、005：移植 v3 的 `twitch_playback_parser_test`；
  - 006：详情、列表不带会话；播放令牌带会话，401 和质询后改匿名，同一份 Cookie 不再发送，换了再试；usher 从不带会话；
  - 007：详情和开播状态请求失败时报错，不返回未开播；
  - 008：移植 v3 的 `parseConnection` 用例（缺 `pageInfo`、坏的边、没有连接）；
  - 010：分类的批量请求每个至多 35 个操作（41 个标签分成 35 + 6）。
- 009（原始 `streams` 查询的 `first` 最大 30）不适用：推荐照 v3 用 Just Chatting 分区，不发这个查询。
