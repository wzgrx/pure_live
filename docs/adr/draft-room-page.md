# 草案：直播间页面的结构、手势层与平台插件

- 状态：提议（编号由合并时确定）
- 日期：2026-09-28

## 背景

`spec/modules/live-room.md` 和 `spec/design/principles.md` §5.2、§6 规定了直播间的展示状态、手势、返回链和控制层，`spec/modules/danmaku.md` §6 规定了弹幕列表。实现时有几处规格没写到具体做法，还有几项功能在旧版依赖插件（亮度、设备音量、电量、系统分享、相册），v4 要决定是否引入。

## 决定

1. **一个展示状态，副作用由它派生。** 页面只保存 `RoomPresentation`（内嵌、剧场、全屏、竖屏全屏）；系统栏、方向锁、桌面窗口全屏在每次切换时由 `applyPresentation` 一次算出。切换串行（INV-ROOM-07），但平台调用 1 s 不返回就放行，否则一次无响应的平台调用会让之后所有切换都被忽略。手机横屏（高度紧凑）即使状态是内嵌也按全屏布局显示（principles §5.2）。
2. **一个视频表面。** `PlayerView` 带 `GlobalKey`，所有布局分支都恰好放它一次；切换房间也在同一页面内进行，复用播放会话和表面，只换源和弹幕连接。
3. **手势层放在按钮之下。** 双击识别器会把竞技场挂起到双击超时，包住控制层时每个按钮的点击都要等约 300 ms。手势层是 `Stack` 里控制层下面的一层，控制层的渐变遮罩不接收指针，空白处的点击落到手势层，由它判断 ZN-1。单指上下滑和双指缩放都用一个缩放识别器，按指针数区分，避免拖动和缩放识别器互相抢。
4. **手势判定是纯函数。** 点击、长按、双击、滑动分区、缩放、竖屏面板档位都在 `gestures.dart` 里，单元测试逐条对应 T-01 到 T-10、ZN-1 到 ZN-3、PS-4。
5. **弹幕按房间一个对象，全应用一个后台 isolate。** `RoomDanmaku` 持有连接、500 条历史、醒目留言板、在线人数和画面弹幕的喂入；屏蔽先在本地立即生效（列表删除匹配行、后台过滤链更新），再写入 `store.blockRules`，存储回来的列表重复应用时不产生变化。页面通过 `DanmakuSource` 接口拿连接，测试用假实现，不启动 isolate。
6. **不引入新插件。** 亮度用画面上的纯色暗化层（只能调暗）；音量只调播放器，不写设备音量；全屏顶栏只显示时间，不显示电量；分享口令在所有平台都复制到剪贴板；截图写入应用目录而不是相册。

## 备选方案与放弃理由

- `screen_brightness`、`volume_controller`、`battery_plus`、`share_plus`、相册插件：各自多一个原生插件和权限面，它们补的都是 P2 体验；暗化层和剪贴板已经覆盖基本用途。需要时可以在 Android `MainActivity` 加一个小的原生通道实现窗口亮度和系统分享，不必引入整包插件。
- 手势检测器包住整个画面（旧版和 v4 初稿的做法）：按钮点击被双击识别器延迟，并且渐变遮罩会吞掉空白处的手势。
- 切换直播间时推一个新页面：两个页面在转场期间同时挂载，同一个会话会出现两个视频表面（ADR 0018 决定 8 的断言），还会重新创建播放器。
- 弹幕连接放进 Riverpod 的 family provider：连接的生命周期要跟随“显示弹幕”开关、房间切换和页面卸载，由页面持有一个普通对象更直接，测试也更简单。

## 影响

- `spec/modules/live-room.md` 修订 T-06（缩放只在适应和填充之间）、D-06 与 §3.6（Esc 和返回会退出剧场）、INV-ROOM-03（v4 不写设备音量），新增 §8 实现记录；`spec/modules/danmaku.md` 定稿 LST-8（礼物是列表里的一行）。
- 缺口：窗口亮度、电量、系统分享、相册、定时关闭和剧场聊天栏宽度的持久化（`live_store` 需要新设置项）、画中画和小窗、TV、换台，见 live-room §8。
- 打开直播间的组件测试要覆盖 `danmakuSourceProvider`（否则会启动真实的弹幕 isolate）和 `blockRulesProvider`（drift 的流在假时钟下留下计时器）。
