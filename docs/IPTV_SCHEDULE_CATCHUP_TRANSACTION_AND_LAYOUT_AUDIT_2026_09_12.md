# IPTV 节目单回看事务、来源隔离与大字号布局审计（2026-09-12）

## 结论

本轮从本仓库基线 `0d99051933c3fa62f167ebe35ad47cdb2b787124` 审查 IPTV 播放页节目单。冻结的本地上游对象 `c6c9bd70aedc503c003110dae10a83ad0bb891d8` 含有相同缺陷，因此归类为 **upstream-existing**；本轮没有 fetch、merge 或用上游覆盖维护仓库。

节目单读取现按请求代次、EPG 来源和控制器生命周期提交；回看点击与播放器切换成为可等待、单一活动事务；时间边界和 URL 生成集中到纯策略；加载、失败、空列表及切换中状态可区分。节目单从播放控制面板中拆出，并在 320×480、3.0 倍文字下保持标题、重试、当前节目、长节目名和关闭操作可滚动到达。

这属于源码与确定性 Widget/控制器回归，不改变数据库结构、用户数据或发布版本。

## 修改前的首个无效状态

1. `loadFullChannelSchedule` 没有请求代次、来源快照或销毁栅栏；较慢的来源 A 可在来源 B 之后覆盖列表，控制器退出后也可能写入 Rx。
2. 数据库读取绕过注入的设置服务，直接读取全局 `SettingsService.to`，使测试实例和实际所有权可能分裂。
3. 查询窗口常量单位是天，日志却标为小时。
4. 默认 URL 直接拼接字符串，可能把查询参数写到 `#fragment` 后；`Uri.queryParameters` 又会折叠重复参数。offset 模式重复读取系统时钟且可产生负值。
5. 列表高亮把节目停止时刻算作当前节目，点击分支却把它算作历史，精确边界行为不一致。
6. `room.link!` 可在空链接上抛错；点击处理是 `void async`，回看切换未等待 `startCatchUp`、未传结束时间，并在播放器真正接受请求前提示成功。
7. 回看进行中没有 single-flight 门禁，连续点击可重叠关闭播放器和创建新播放器；失败会越过原调用边界。
8. 加载、失败与真正空节目单共用空列表画面，没有原位重试。
9. 自动滚动标志只写不读，每次响应式重建都可能再次排队动画；旧索引定位依赖可变高度列表，在大字号下不能可靠把当前节目带入视口。
10. 弹窗依赖全局 `Get.context`，路由未被等待，播放控制栏没有在弹窗期间稳定持有菜单状态。
11. 固定 `ListTile` 在 320×480、3.0 倍英文中先后复现标题区向右溢出 131 像素、节目状态行向右溢出 11 像素；重试按钮也可能落到当前视口外。

## 修订内容

### 1. 来源与生命周期事务

- 每次读取递增 `_epgLoadEpoch`，快照化规范 EPG ID、选中来源和一次时间窗口。
- 结果仅在控制器仍存活、代次仍为最新且来源仍匹配时提交；来源变化但没有替代读取时，由当前代次释放 loading，不留下永久转圈。
- 数据库解析显式接收 `sourceId/start/end`，不再从异步深处重读全局来源。
- 空 EPG ID/空来源、加载、读取失败、成功空列表分别落到确定状态；失败保留重试入口。
- 销毁时推进代次，隔离迟到数据库结果。

### 2. 共用时间边界与 URL 策略

- `classifyIptvProgramme` 统一使用半开区间 `[start, stop)`：开始瞬间为当前节目，停止瞬间进入回看。
- `buildIptvCatchupUrl` 统一 default、playseek、offset 三种旧格式；保留 fragment 和重复查询参数，只替换本策略拥有的键。
- offset 使用调用方提供的一次时钟快照并将未来开始时间限制为零；空地址、相对地址和非正节目区间在关闭节目单前被拒绝。

### 3. 可等待的回看切换

- `onProgrammeTapped` 返回明确结果枚举，未来、当前、回看、忙碌、无效地址和失败均可观察。
- 全局 `catchUpSwitching` 门禁在关闭旧播放器之前建立；后续点击合并为 busy，不再启动第二条销毁/创建链。
- 回看开始同时传递节目开始与结束毫秒值，完整等待 `startCatchUp`；成功反馈只在底层调用完成后出现，异常被记录并转成可见失败结果，门禁在 `finally` 释放。
- 当前节目只关闭节目单；未来节目和无效地址保留节目单，方便继续选择或修正输入。

### 4. 路由、滚动和 3.0 倍文字

- 节目单抽取为独立有状态 Widget，路由使用调用点的 `BuildContext` 并被 `await`；弹窗期间播放控制栏保持打开，关闭或异常退出后再恢复自动隐藏。
- 头部在窄屏大字号时上下排列关闭按钮与标题；加载/错误/空状态主体可滚动，重试按钮可通过滚动到达。
- 节目行改为 `Material + InkWell + LayoutBuilder`，窄屏或大字号使用堆叠内容；时间和状态使用 `Wrap`，不再依赖固定 `ListTile` 槽位。
- 同一文字缩放下所有节目使用可计算的固定列表步长，当前节目按像素位置一次性定位；响应式重建不再重复启动滚动。
- 正常直播按墙钟更新状态；处于回看房间时仍按 `catchUpStart` 定位正在观看的节目，但历史/未来图标按当前墙钟计算，避免把旧节目误标为实时直播。
