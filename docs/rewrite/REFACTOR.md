# v4 重构方案：在 v3 代码上审查、优化、完善、增强

> **状态**：执行中（2026-09-28 起），依据 [ADR 0039](../adr/0039-v4-refactors-v3.md)。它取代 [PLAN.md](PLAN.md) 中“另起炉灶新写应用”的部分。进度见 [STATUS.md](STATUS.md)。

## 目标

- v4 就是 v3 的改进版。界面、布局、操作逻辑和功能以 v3（v3.2.11 加归档前的修复）为准。
- 代码质量、稳定性、性能、安全和许可证合规要明显好于 v3，并补上 v3 缺的功能。
- 正式版覆盖安装 3.x，保留用户数据。

## 原则

1. **行为不变**：
   - 每次改动前后对照 v3 的行为：v3 原有的测试、平台样本、Windows 和手机实机。
   - 改变外观或操作习惯的改动，先征得用户同意。
2. **小步可用**：每一步都能构建、能用；每修一处都跑门禁、提交、推送。
3. **先找根因**：每个问题先写清根因，再改。
4. **按模块接入 v4 的包**：
   - 重构到哪个模块，就评估对应的 v4 包：更好且行为能对齐的，在 v3 的内部接口后面替换，界面不动；
   - 否则直接重构 v3 原来的代码。
5. **GetX 逐步收缩**：只在正在重构的模块里把依赖改成注入，不做一次性替换。
6. **参考上游**：做相关模块前，先 `git pull` 本机 `~/ref/` 下的 4 个仓库（pure_live_TV、flame_barrage、media_core、flv_lzc，见 ADR 0038）。借鉴代码时注明来源。

## R0 细节

1. **目录**：
   - `legacy/` 中的 v3 应用恢复为 `apps/pure_live`，加入 workspace，这样能按模块依赖 `packages/*`；
   - 原 v4 应用移到 `archive/v4_app/`，不再构建；
   - v3 的原生插件补丁（`plugins/`、`third_party/fvp`）随应用一起移动。
2. **依赖**：v3 的依赖和 workspace 里各包的依赖一起解析。有冲突时优先保持 v3 的行为，必要时升级 v3 的依赖，并逐个验证。
3. **测试包和正式包**：
   - 测试包：Android 包名加 `.next`，应用名加“预览”，和手机上的 3.x 并存；Windows 测试版放在工作目录。
   - 正式包：包名不变。
4. **门禁**：`tools/gate/gate.sh` 纳入 v3 应用的 analyze 和测试。先跑一次 v3 原有的测试并记下基线：通过数，失败的逐条登记；只能在 Windows 上跑的测试另外列出。
5. **构建和冒烟**：
   - Android 在 WSL 构建，Windows 在主机构建；
   - 在 Windows 和 K90 上跑一遍主要流程（首页、分区、搜索、直播间、弹幕、关注、录制、多画面、设置），和 3.2.11 对照。
6. **文档**：README、STATUS、AGENTS/CLAUDE 按新方向更新；原 v4 界面的截图测试随原应用归档。
