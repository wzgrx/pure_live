## 目标

国内五大平台（哔哩哔哩、斗鱼、虎牙、抖音、快手）的推荐、分类、分区、搜索、进房、清晰度和线路、弹幕定期用真实接口跑一遍，平台改了接口或加了风控时，在用户发现之前修好。做完一轮后，每个平台有一份当天的检查结果表（哪些正常、哪些失效、原因），失效的都有修复提交和改之前会失败的样本测试。这个任务是持续的：每轮在 record.md 追加一节，三个阶段做完算一轮完成，以后每次重复。

## 方案

- c1 写巡检清单：五个平台 × 功能（推荐两页、分类、分区两页、搜索房间和主播、详情在播 3 个 / 未开播 1 个 / 不存在 1 个、清晰度、每条线路的开头字节、租期、弹幕 120 秒），每条写用哪个房间、怎么算正常（例如“分区第 1 页 30 个、第 2 页不重复”“FLV 以 `FLV` 开头、TS 以 0x47 开头”）。放在本文件夹 `CHECKLIST.md`；E07.1 定了检查项格式后照它的格式写。
- c2 逐个平台跑一遍：有 E07.1 的工具就用工具，没有就照 2026-10-01 的做法写临时程序（不进仓库）。匿名、只读、直连、不发言；媒体每条线路只读开头几 KB；每个平台联网合计不超过 10 分钟。结果按各平台 record.md“真实环境检查”表的格式写进本文件夹的 record.md。
- c3 修复失效的：每个失效先录样本（脱敏）、写改之前会失败的测试，再改对应平台的 `packages/live_core/lib/src/sites/<平台>/`；弹幕协议的失效开到 D01 对应任务，连接凭据的问题可以在这里一起修。修完回到 c2 重跑这一项。

## 验证

- 自动测试：每个修复有样本测试（`packages/live_core/test/sites/<平台>_api_test.dart`、`_site_test.dart`）；测试不访问真实平台（D-017）。
- 真实接口：c2 的结果表就是验证；修复后的项重跑一次写进同一张表。
- 真机：修复合并后在 K90 上进一个对应平台的直播间看一眼（[S02 的 CHECKLIST.md](../../../S-质量和验证/S02-真机验证/CHECKLIST.md) 第 1 节第 1 条）。
