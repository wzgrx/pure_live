- `ToolBoxController` 在首次 await 前没有动作门禁；同一按钮以及两个工具都可进入并行处理。房间解析结束时不核对控制器关闭、用户编辑或来源页面状态，迟到结果仍发起导航。
- 空白输入仍进入解析，部分身份结果直接访问第 2 项，解析异常未由工具箱收口。部分身份属于注入边界测试，不声称现有解析器正常输出该畸形结果。
- 旧 `LiveUrlTool.getLivePlayUrl` 用全局 Loading，跨多个 await 没有页面所有权检查；线路空列表仍打开空对话框，复制未 await 就关闭弹窗并显示成功。播放器菜单的已知房间取流/投屏另有入口，本轮先明确划分，未混写成整个播放器通过。
- 冻结上游 `c6c9bd70aedc503c003110dae10a83ad0bb891d8` 的工具箱有相同缺少门禁/离页核验等根因，归类 **upstream-existing**。本轮未合并上游。AppNavigator 自身已有导航门禁；重复解析和调用入口的证据不等同真实打开两层播放器。

## 修订与所有权

- 两个工具共用一个动作状态，首次 await 前占用；两个按钮同步禁用，当前按钮显示进度并提供取消。输入内容保留；编辑当前动作对应字段即取消，另一字段独立。
- 每个动作独有 scope 和取消令牌；关闭、显式取消、编辑会结束等待，旧结果不导航、不打开选择器、不更新新动作。网络和剪贴板阶段默认 12 秒，用户选择及等待播放器返回不设倒计时。每个等待的 Timer 在完成/取消/失败时释放。
- 短链解析新增调用者取消接口，取消时释放其专属客户端；直播平台的共享请求仅停止本次等待及后续操作，不强行关闭其他页面使用的 HTTP 客户端。已被系统执行的剪贴板写入不作回滚承诺。
- 移走只有工具箱调用的旧 `getLivePlayUrl` 流程，形成可验证的 `ToolBoxDirectLinkFlow`；房间/清晰度/线路请求保持原站点适配器，空和重复线路使用既有 normalizeResolvedPlayUrls。空清晰度/线路有明确失败反馈，取消选择不请求下一阶段。
- 选择器使用页面提供的 context 与独立 DialogRoute；取消只移除自己持有的路由，不弹出其他页面/对话框。一次选择只执行一次，避免退场中的重复回调误弹底层页面。离开来源页后不呈现迟到选择器。
- 等待 Clipboard.setData 真正完成后才提示成功；失败使用新增中英文 `toolbox_copy_failed` 文案。移除工具箱对全局 Loading 的干预，其他应用入口的加载态不因本次取消而被清理。
