## 维护者已经定下的

- 主列表手感选调研报告的方案 A：能下拉刷新的列表照 v3 两端回弹 + 经典下拉头，其他列表保持 Android 拉伸（P02）。
- 刷新率：没有整数倍时取设备最高刷新率；播放中只用帧率声明（P01）。
- 快滑阈值：v3 来的保留，v4 自己定的 600 dp/s 改成 700（P03、P04）。
- 要出设计的任务（B04、B05、B07），对比页里“需要你选的”按建议 A 直接做，记录里写明。
- 哔哩哔哩访客昵称是服务器打码的，不去绕过；做登录引导（B06）。

## 哪些能同时开

同一组的任务改同一批文件，**一组同时只开一个会话**，按箭头顺序做：

- 直播间：B02 → B05 → B07 → B09 → P04
- 组件：B03 → U02 → U01 → P06
- 手感和性能：P02 → P03（P04 要等它）；P02 → P05
- 弹幕：B01 → B06；B08 单独（和直播间组都会改 `room_controller.dart`、`chat_list.dart`，和正在做的直播间任务错开）
- 录制：B04（和 B05 都会碰顶栏按钮，尽量错开）
- 刷新率：P01（随时）
- 功能：F01（和 B06 都改聊天行，错开）、F02（随时）

## 建议顺序（每批的会话可以同时开）

1. 第一批：**B01、B02、B03、B04、P01、P02**
2. 第二批：B05、B06、U02、F02、P03、P05
3. 第三批：B07、B08、F01、U01
4. 第四批：B09、P06
5. 第五批：P04

每批合并后维护者在 K90 上看一遍，再开下一批。前一批没合并就开下一批，云端会基于旧的 master 做，合并时冲突更多。
