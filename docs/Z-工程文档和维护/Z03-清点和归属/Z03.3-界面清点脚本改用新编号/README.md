## 方案

- c1 对照表：建议 A——脚本读 `docs/tasks.toml`（`tomllib`），用每个任务的 `old` 建 `{旧编号: 新编号}`，规则表保持 U 编号不动，输出时换；好处是规则表和 MAPPING 一致、改动最小。B——把规则表里 55 个 U 编号直接改成新编号，删掉对照；规则表更直观，但以后看历史提交要查 MAPPING。规模小，可以按 D-003 用 A。
- c2 排序：`order` 改成按新编号的“组字母、子分类两位数、任务序号”排。
- c3 版本：输出开头一行写 `v3.2.11`（`~/ref/v3ref` 的提交）和电视版的提交（读 `<tv>/.git` 的 HEAD）；加 `--tv-ref <提交>` 时用 `git -C <tv> show` 读那个提交的文件（不改工作区）。
- c4 重新生成：用 `b9d2f739`（和现在的清单一致）重新生成 UI.md、UI_FILES.md，diff 应该只有顺序；再用最新的电视版生成一次，把多出的文件列给 A17.6，由维护者决定清单用哪个版本。
- c5 最小测试：`tools/gate/tests/test_inventory.py`：对照表从 `old` 正确建出、找不到对照时报错、排序。
