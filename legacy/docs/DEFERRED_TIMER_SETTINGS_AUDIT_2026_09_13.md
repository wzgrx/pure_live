# 应用退出与 IPTV 自动同步计时设置审计

## 范围与根因

本轮以 `f2bf42d5` 为基线，修订提交为 `d68db3d7`。范围限通用设置中的应用定时退出、IPTV 自动同步间隔及其持久化/备份边界；没有构建安装包、操作手机或执行 Windows GUI，Computer Use 与 Astra Light 使用均为 **0 次**。

源码审查确认两个同类缺口：

1. 应用退出分钟数只在界面上检查“大于 0”，持久化值、当前/旧版备份和控制器公开写入都没有统一上界。损坏值可直接送入应用退出计时器，界面也会接受 `525601` 这类超出产品合同的输入。
2. IPTV 自动同步页面只提供 2～72 小时选项，但持久化值、备份值和调度器使用点没有共享边界。零值/负值会把全部资源视为已过期，极大值则会让自动同步长期失效。

应用退出控制器还同时保留“公开动作立即重启计时”和两个 500 ms 持久化观察器。一次保存或启用会先启动计时，随后又被观察器重置，实际截止时间比用户动作晚约半秒。

## 修订

- 为应用退出建立 **1～525600 分钟**的单一合同，并用于启动时持久化修复、运行时写入、当前/旧版备份解析、导出和计时器入口。
- 自定义输入同步拒绝超出范围的值，保留弹窗与原值，并将中英文提示改为明确范围。
- 记录已应用的计时状态；显式保存同一时长仍按产品文案重新计时一次，随后两个观察器只确认同一状态，不再二次延后截止时间。
- 为 IPTV 自动同步建立 **2～72 小时**合同，并用于启动修复、备份边界、导出和调度器最终入口。即使其他调用方直接写入异常值，真正查询过期资源前也会重新归一化并持久化。
