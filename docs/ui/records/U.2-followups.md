## 1. 投屏只在 Android（U.2c、U.2d）

| 内容 | 做到 | 说明 |
|---|---|---|
| 电脑（Windows、Linux、macOS）的直播间菜单去掉“投屏” | ✅ | 原来菜单按“不是 iOS 就放”，电脑上还有；上栏的投屏按钮早已只在 Android。现在两处都看 `castSupported(platform)`（`buttons/room_menu_button.dart`，只有 Android 为真），`topBarSlots` 也改用它，以后只改一处 |
| iOS | ✅ | 照旧没有（U.17a） |
| Windows 的“在新窗口打开” | ✅ | 不变，仍在第二组最后 |

- 为什么：U.2c“各客户端”写“投屏只有 Android”，U.2d 的按钮表写“投屏只有 Android 平板有”，计划书第 4 节“投屏（只有 Android）”。和 v3 的差别：v3 菜单在所有平台都有投屏（`live_play_menu_button.dart:193`），这是设计确认过的改动。
- `roomMenuGroups` 的 `cast` 参数改成必填，调用处必须说明这个平台有没有投屏。
- 测试：`live_play_layouts_test.dart` 新增“the room menu on each platform”：Android、iOS（393×852），Windows、Linux、macOS（1280×800）各打开一次顶栏菜单和全屏上栏的菜单，固定整份菜单的顺序（分组线、投屏只在 Android、在新窗口打开只在 Windows、本地互动一组），并确认全屏上栏的投屏按钮只在 Android。`live_play_popups_test.dart` 里 `roomMenuGroups` 的调用补上 `cast:`，多一条“没有投屏时第二组从获取直链开始”。

## 2. 多画面点击区域补到 48（U.8）

| 内容 | 做到 | 说明 |
|---|---|---|
| 选中格控制区五个按钮（看起来 40） | ✅ | 每个按钮放在 48×48 的点击区域里（`MaterialTapTargetSize.padded`，所有平台一样；桌面主题原来会缩成 40），圆和图标大小不变 |
| 工具条开关（看起来 38） | ✅ | 同上，48×48；弹幕、弹幕设置、全部静音、小格省流 |
| 看起来的大小、位置 | ✅ | 圆的大小不变；圆旁边的内边距减去点击区域多出的那一圈（按钮 4、开关 5），所以第一个按钮的圆仍在 12，工具条最后一个开关的圆仍离边 8（宽屏 16），工具条高度仍是 56。相邻两个圆之间的空隙从 2 变成 8（按钮）、10（开关），这是 48 的点击区域不重叠所必需的 |

点击区域变大后一行要多占地方，下面几处跟着调整（测试里用 Roboto 和思源黑体渲染后量的数）：

| 位置 | 之前 | 现在 |
|---|---|---|
| 竖屏 393 宽：按钮和音量一行 | 按钮占 12～220，滑块（含两侧留白）97，滑轨约 73 | 按钮占 8～248（点击区域），滑块 73，滑轨约 49；音量图标离最后一个圆仍是 8 |
| 竖屏窄于 384（例如 360）| 一行，滑轨约 40 | 一行放不下五个 48 再加一个能用的滑块（留白后滑轨至少 40），音量换到下一行，图标和头像对齐（同横屏右栏的排法）；控制区高 48 |
| 工具条的布局分段按钮 | 放不下时整体缩小（393 宽的 1+3 缩到 0.92，360 宽缩到 0.96，360 宽的 1+3 缩到 0.78） | 先把每段从 56 收窄到 48 再缩小：393 宽不变；393 宽的 1+3 缩到 0.95；360 宽不缩；360 宽的 1+3 仍是 0.78。只在手机工具条（不带图标）上收窄 |
| 横屏手机右栏 | 最窄 240（740×360 时就是 240） | 最窄 256，五个 48 的按钮一行放得下，两边各 8；740×360 时画面区从 500 宽变成 484 宽；852×393 不变（260） |
| 宽屏右栏、全屏格子面板 | 360 | 不变；按钮仍一行 |

- 为什么：计划书第 5.4 节“点击区域至少 48×48，间距至少 8”；U.8 记录偏差 4 写的“按钮 40、工具条开关 38，比 48 小”这次补上。
- 窄于五个按钮的地方（一般不会出现）按钮换行，不会溢出。
- 测试：`multiview_page_test.dart` 新增“tap targets (UI_PLAN 5.4)”：竖屏 393（工具条三个开关、控制区五个按钮都是 48 的点击区域、圆是 38 和 40 且在正中、互不重叠在一行；第一个圆在 12、最后一个开关的圆离边 8、工具条高 56；音量在同一行且离最后一个圆至少 8；点在圆外、点击区域边上也能切换“全部静音”和暂停）；1+3（小格省流也是 48，分段收窄）；竖屏 360（音量换到下一行，按钮仍一行，分段收窄）；740×360 横屏（右栏 256，五个按钮一行，第一个圆离右栏左边 12）；1280×800 宽屏（最后一个开关的圆离边 16）。原有 5 个页面测试不用改就通过。

## 4. 平台名统一（SOOP、网易CC）

先查了 v3 的 `assets/translations/zh.json` 和平台自己的写法：

| 平台 | v3 的写法 | 平台官方 | 账号页（U.10a） | 统一成 |
|---|---|---|---|---|
| SOOP | `site_soop`“Soop”；另外 5 处都是“SOOP”（`soop_cookie_hint`、`soop_cookie_tip`、`local_badge_soop`、`audience_metric_support_detail`、`toolbox_support_content` 的“SOOP直播”） | SOOP（2024 年 AfreecaTV 改名，全大写） | SOOP | **SOOP** |
| 网易 CC | `site_cc`“网易CC”、链接说明“网易CC直播”；只有 `audience_metric_support_detail` 一处“网易 CC” | 网易CC直播（不带空格） | 网易 CC | **网易CC** |

- 改的文字（键不变）：中文 `site_soop`“Soop”→“SOOP”、`account_site_cc`“网易 CC”→“网易CC”、`audience_metric_support_detail` 里的“网易 CC”→“网易CC”；英文 `site_soop`“Soop”→“SOOP”（英文 `site_cc`、`account_site_cc` 本来都是“NetEase CC”）。平台列表、直播间“在<平台>打开”、账号页、Cookie 页标题（“网易CC账号”）现在都是同一个写法。
- 偏差：任务书写“v3 和账号页不一致时用 v3 的”。SOOP 这一条 v3 自己就不一致（只有 `site_soop` 写“Soop”，其余 5 处“SOOP”），按 v3 多数的写法和官方写法用“SOOP”，账号页不用改。如果要“Soop”，改回 `site_soop` 一处，并把账号页和那 5 处一起改。
- `account_platforms.dart` 里账号页自己的名字键（`nameKey`）保留，注释改成“和平台列表同一个写法”。
- 测试：`account_page_test.dart` 新增一条：中英文下 `site_soop` 是“SOOP”、`site_cc` 是“网易CC”/“NetEase CC”，账号页每个平台的名字都等于平台列表的名字；原测试里的“网易 CC”“网易 CC账号”改成“网易CC”“网易CC账号”。
