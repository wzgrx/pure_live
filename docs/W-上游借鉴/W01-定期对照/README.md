# W01 定期对照

每周看一次上游五个仓库的新提交，逐条对照 4.x 现在的代码，判断是“4.x 也有这个问题”“可以借鉴”“已经有”“不适用”，把要做的开成任务，结论和看到的提交范围写成一份对照记录（下次从这里接着看）。

## 范围

- 包括：
  - 五个上游仓库（清单和本机副本见 [W02](../W02-参考仓库/README.md)）：手机版 pure_live（主仓库的远程 `upstream`）、电视版 pure_live_TV、播放核心 media_core、弹幕引擎 flame_barrage、flv_lzc。
  - 每次对照一个任务（W01.n），任务的 `README.md` 是对照记录：看了哪些（仓库、起止提交、提交数）、4.x 也有的问题、可以借鉴的新功能、已经有的、不适用的。
  - 对照出的任务登记（目标组的修复、V01 的提议）和它们的 `from`（上游仓库和提交）。
- 不包括（归哪里）：
  - 参考仓库本身的维护（加仓库、远程、许可证）→ [W02](../W02-参考仓库/README.md)。
  - 修复和实现 → 目标组；新功能 → [V01](../../V-需求和反馈/V01-新功能提议/README.md)（D-027）。
  - 照搬上游的架构（例如上游把播放换成 media_core）：不做，只借鉴修复的思路和行为（PROCESS 第 9 节第 5 条）。

- **怎么做一次对照**（PROCESS 第 9 节）：
  1. 拉取：主仓库 `git fetch --no-tags upstream master`；`~/ref/pure_live_TV`、`media_core`、`flame_barrage`、`flv_lzc` 各 `git pull`。
  2. 看提交：`git log --oneline <上次看到的提交>..upstream/master`；其余仓库在各自目录 `git log --oneline <上次>..HEAD`。上次看到的提交写在上一份对照记录的“看了哪些”表里。
  3. 逐条对照：只看修复和新功能；每条先在 4.x 代码里找对应位置（文件:行），判断四类之一。
  4. 记录：新登记一个 W01.n（标题“<日期> 上游对照：<仓库> N 个……”），README 写对照表和提交范围。
  5. 登记任务：4.x 也有的问题开到目标组（`from` 写上游仓库和提交）；可借鉴的新功能进 V01。
  6. 借鉴代码时：AGPL-3.0 的注明来源仓库和提交，MIT 的保留版权声明。

## 3.x 基线

- 手机版上游就是 3.x 的作者在 `v3.2.11` 上接着做的（W01.1：`git log v3.2.11..upstream/master`），所以上游的修复多半对应 4.x 的同一个功能点；对照时先看 3.x 那段代码（`git show v3.2.11:lib/...`）和 4.x 现在的实现差在哪。
- 3.x 没有定期对照上游的流程（3.x 的作者就是上游）。
