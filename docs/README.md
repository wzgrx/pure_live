# 文档

纯粹直播（Pure Live）4.x 的全部文档。项目分成 20 组（T00～T19），每组若干子分类，每个子分类里是一个个任务；所有编号、状态和进度都登记在 [tasks.toml](tasks.toml)，其余索引由脚本生成。

## 先看这几个

| 文件 | 内容 |
|---|---|
| [STATUS.md](STATUS.md) | **总进度**：全项目、按档位、按组的进度条，正在做的、暂停的、待真机的、下一步 |
| [PLAN.md](PLAN.md) | 项目计划：目标、原则、20 组、优先顺序、版本路线、风险 |
| [PROCESS.md](PROCESS.md) | 做法：编号、任务类型、状态和阶段、一个任务怎么做、分阶段完成、交给其他 AI、合并审查、真机验证、发布、文档规范 |
| [TASKS.md](TASKS.md) | 全部任务（生成） |
| [DECISIONS.md](DECISIONS.md) | 定下来的事和依据 |
| [MAPPING.md](MAPPING.md) | 旧编号（M、U、F、B、P）和旧文档对照（生成） |
| [GLOSSARY.md](GLOSSARY.md) | 术语 |

## 目录

```text
docs/
  README.md      本页
  STATUS.md      总进度（生成）
  PLAN.md        项目计划
  PROCESS.md     做法
  TASKS.md       任务清单（生成）
  MAPPING.md     旧编号对照（生成）
  DECISIONS.md   决定
  GLOSSARY.md    术语
  tasks.toml     登记表：唯一要手改的进度来源
  specs/         长期有效的规范：界面、工程、已批准的升级
  inventory/     清点：v3 界面、逐项界面、界面文件、功能点和平台能力
  templates/     模板：设计、功能说明、任务书、记录、真机验证、合并审查、评审页
  T00/ … T19/    20 组；每组一个 README（生成）和若干子分类
    T05/T05h/        子分类：README（生成）和这个子分类的资料
      T05h.2/        任务：README.md 设计或说明、brief.md 任务书、record.md 记录、
                     verify.md 真机验证、review.md 合并审查；界面任务还有 page.json、src/、效果图、page/
```

## 编号速查

- **组** `T05`，**子分类** `T05h`，**任务** `T05h.2`，**逐项界面** `T05h.2-08`。
- 状态：未开始 → 设计中 → 待确认 → 已确认 → 开发中 → 待真机 → 完成；另有暂停、受阻、不做。
- 档位：第一档（马上做）、第二档（应该做）、第三档（以后）。

## 怎么改

1. 改 [tasks.toml](tasks.toml)：加任务、改状态、记阶段。
2. 运行 `python3 tools/docs/docs.py`，重新生成 STATUS、TASKS、MAPPING 和各组、各子分类的 README。
3. 门禁（`tools/gate/gate.sh`）会检查生成的文件是不是最新、链接是不是都能打开、代码里写的 `docs/` 路径是不是存在。

任务文件夹里的设计和记录是当时写的，引用的旧文件都已换成新路径、旧编号已换成新编号；2026-10-02 整理前的旧文档全文在 git 标签 `docs-archive-2026-10-02`。
