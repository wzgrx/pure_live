## 目标

1. 屏蔽词可以写正则：以 `/` 开头、以 `/` 结尾的当正则（不分大小写），其余照旧“包含即屏蔽”。写错了当场提示，不加进去。
2. 两个新开关：“屏蔽只有表情的弹幕”“屏蔽超过 N 字的弹幕”（默认都关）。
3. 直播间里看得到“本场已屏蔽 N 条”，知道屏蔽在起作用。

## 方案（V03.6 第 5.6 节，做法 A，D-003 维护者选 A）

- c1 正则：`/…/` 包起来的屏蔽词在 `DanmakuBlockList` 构造时编译一次（`caseSensitive: false`）存起来；编译不过的跳过（不抛异常）。添加时（屏蔽管理、长按面板的“屏蔽关键词”第二页）先编译，失败在输入框下面提示“正则写法不对”，不加进去。正则最长 **200 字**（普通词仍 40 字）；每条弹幕只拿前 200 个字去匹配，防止慢正则拖住。
- c2 屏蔽表格式不变：正则就是一个以斜杠包起来的普通关键词，存储（`packages/live_store/lib/src/block_lists.dart`）、备份、3.x 导入都不用改；覆盖回 3.x 时只会当普通词，不出错。
- c3 两个新开关（`section: 'danmaku'`，默认关）：`blockEmoteOnlyDanmaku`（去掉表情代码和表情图以后没有字的整条不显示）、`blockLongDanmaku` + `blockLongDanmakuLength`（默认 30，10～100）。放在弹幕设置的“重复弹幕”一组或屏蔽管理里（实现时照 A08.3 的布局放，在 A08.3 的 README 补一条）。键名开发时定。
- c4 本场计数：过滤链被屏蔽（屏蔽表、两个新开关）的条数在控制器里计数（不存、换直播间清零）；弹幕设置的“屏蔽管理”标签显示“本场已屏蔽 N 条”（角标或标签里第一行，照 media_core “被哪条规则拦下”的思路只记数，V03.6 第 3.5 节）。
- 不选 B（单独一张“正则”列表）：两张表用户分不清加在哪；3.x 和导入导出都只认一张表。
- 不做：按等级、按类型屏蔽（V03.6 E19，丙档）；批量导入导出（E12，留在报告里）。
