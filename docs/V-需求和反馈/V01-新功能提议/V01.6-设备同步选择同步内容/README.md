## 目标

设备同步现在是整份发过去：对方确认后，关注、历史、分组、屏蔽、设置、WebDAV、网络电视……全部按发过来的恢复。用户常见的需求是“只把关注同步到平板”“只同步屏蔽词”，现在做不到（要么全覆盖，要么别同步）。提议：发送前和接收前都能勾选同步哪几类，只发、只应用勾选的；**保留 6 位配对码**（上游去掉了，但同步里可能带登录 Cookie，同一个 Wi-Fi 不等于可信）。

本文件是**评估初稿**，由执行者补完、出图、发评审页，**由用户决定做不做**（D-026）。

## 方案（评估初稿）

| 编号 | 改什么 | 目标组 |
|---|---|---|
| c1 | 协议：`settingsPacket` 加可选 `sections`（字符串列表，名字用备份文件里的段名）；读包时没有就当全量；3.x 设备发来的包照旧 | J05 |
| c2 | 发送：选好设备、输完配对码后先出勾选页（12 类，带每类的数量，默认全选；“账号”一类只在“同步账号”打开时出现）；只打包勾选的段 | J05、A12.6 |
| c3 | 接收：预览页每类前加勾选框（默认跟发送方勾选的一致）；确认后只恢复勾选的类（`packages/live_store/lib/src/backup/backup_service.dart:91` 的 `BackupService.restoreAll` 加一个“只恢复这些类”的参数；导出 `:34` 的 `exportAll` 同样加） | J03、J05、A12.6 |
| c4 | 从对方拉取（`fetch`）也走同样的勾选 | J05 |
| c5 | 配对码不变 | — |

规模：小到中（协议和恢复的过滤半天，勾选页和预览改动要出图评审）。

和备份恢复的关系：备份恢复的预览（A12.4）也可以用同一套“只恢复这些类”，但不在本提议（另提或随 c3 顺带，由用户定）。

## 验证（做了以后怎么验证）

- 自动测试：`apps/pure_live/test/features/remote_receiver/remote_sync_test.dart` 加：只勾关注时对方只多了关注、设置没变；没有 `sections` 的包当全量；配对码错时仍被拒；3.x 格式的包照旧能收。
- 真机：S02.4 第 3 阶段的两台设备，只同步关注、只同步屏蔽词各一次。

## 留下的问题

- 需要用户决定：做不做；接收方能不能比发送方勾得更少（建议能）；备份恢复要不要也加勾选。
- 上游 pure_live `a7783b525`、pure_live_TV `699b74e9`（W01.3）已经让本地备份、WebDAV、设备同步、扫码推送共用一个“勾选模块”页：导出只写勾选的，导入只覆盖勾选的，没勾的保持本机现有设置。可以照这个思路一次做全。
