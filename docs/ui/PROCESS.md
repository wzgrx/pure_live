# 界面重构：每个任务的做法

第 2 版（2026-10-01）。照 U.2a 竖屏直播间和 U.2f 直播间弹窗走过的流程整理，补上效果图工具、评审页和修改流程。每个任务（[TASKS.md](TASKS.md) 的一行）都按下面十步做；任务文件夹 `compare/<编号>/` 的 README 随每一步更新状态。

## 总览

| 步 | 做什么 | 产出 | 谁 | 大约用时 |
|---|---|---|---|---|
| 1 | 读代码、清点界面 | 清单一节、界面清点表 | 我 | 0.5–1 小时 |
| 2 | 还原 v3 | `src/v3-*.html` → `v3-*.jpg` | 我 | 0.5–1 小时 |
| 3 | 设计新方案 | `src/v4-*.html` → `v4-*.jpg`、`v4-*-n.jpg` | 我 | 1–2 小时 |
| 4 | 对比评审页 | `page.json` → claude.ai 页面 | 我 | 0.5 小时 |
| 5 | 评审 | 每条“满意 / 不满意 / 再想想”和意见 | 用户 | 随时 |
| 6 | 修改、出下一版 | 同一个页面地址，第 N+1 版 | 我 | 按意见多少 |
| 7 | 定稿上传 | `page/`、单张图、README、TASKS；推送 | 我 | 0.5 小时 |
| 8 | 开发任务书 | 任务书 | 我 | 0.5 小时 |
| 9 | 开发和测试 | 代码、测试、`records/<编号>.md` | 开发代理 | 1–3 小时 |
| 10 | 合并验收 | 门禁、推送、状态更新 | 我 | 0.5 小时 |

一批 2～4 个相关界面放一个评审页；一批定稿后，开发（第 8～10 步）和下一批设计（第 1～6 步）同时进行。

## 准备（每台机器一次）

```bash
flutter pub get                 # remixicon 字体来自 pub 缓存
bash tools/ui/mock/fetch.sh     # 下载字体和示意图片到缓存，链接到 tools/ui/mock/.cache/
```

另需：Playwright 的 `chrome-headless-shell`、`ffmpeg`、系统字体 Noto Sans CJK SC。工具说明见 [tools/ui/mock/README.md](../../tools/ui/mock/README.md)。

## 1. 读代码、清点界面

1. 在 [INVENTORY.md](INVENTORY.md) 找到这个任务的逐项界面（页面、对话框、面板、菜单、覆盖层），在 [TASK_FILES.md](TASK_FILES.md) 找到对应文件；全部读完，再读 v4 现在的实现和参考项目的对应部分。
2. 在任务 README 写**界面清点表**：每个用户看得到的界面一行（合并组件和调用处的重复项；补上代码里找不到入口的，例如提示条、加载和出错状态），写它从哪里打开、有哪些形态（竖屏、横屏、宽屏、电视、小窗）、有哪些状态。这张表就是这一批要出的图的清单。
3. 在任务 README 写“v3 的样子”一节（并行设计时不改共享文件；[V3_UI_INVENTORY.md](V3_UI_INVENTORY.md) 只放索引，链接到各任务 README）：v3 的样子（结构、控件顺序、图标原名、文字、尺寸、颜色角色、手势和快捷键、按宽度分支的地方）、v3 的问题（编号、根因、文件:行）、v4 现在的偏差、文件对照。
4. 功能有多种状态的，先把全部状态和数据从代码里列出来（例如录制任务的 9 种状态），再设计。
5. 文字一律从代码取：`python3 tools/ui/strings.py <v3 文件>` 列出这个文件用到的全部文字（键名、中文、行号）。

## 2. 还原 v3

- 每张图一个 HTML：`compare/<编号>/src/v3-<内容>.html`，用 `tools/ui/mock/kit/kit.css` 的组件（顶栏、画面、上下栏、菜单、对话框、面板、开关、滑块……），头里写尺寸 `<meta name="mock-size" content="393x852@3">`。
- 尺寸、图标、文字、顺序、颜色照代码；颜色用 kit 里 v3 的颜色角色。画面和头像用示意图片，图上标“示意图片”。
- 长面板画完整内容（尺寸写 `393x2400@2 crop`，自动裁到内容末尾）。
- 每个形态、每个状态一张。
- 生成：`python3 tools/ui/mock/render.py docs/ui/compare/<编号>/src/`，图出在任务文件夹里。

## 3. 设计新方案

### 3.1 先对照原则

计划书第 3 节，尤其：

- v3 为准：位置、顺序、图标、弹法照 v3；每处改动对应一个 v3 问题编号或用户的要求。
- 不先定统一规则再套：逐个看 v3 好不好用。
- 功能一项不少：v3 的每个动作、设置在新设计里都找得到；挪了位置的列对照表。
- 状态齐全；性能约束（计划书第 9.3 节）。

### 3.2 各客户端怎么出

同一个组件、同样的操作，只调整位置（计划书第 3 节第 7 条）。每个任务按这个顺序出图：

| 顺序 | 客户端 | 出什么 |
|---|---|---|
| 1 | Android 手机 | 竖屏；有全屏的再出横屏（852×393）和窄横屏（740×360，检查按钮会不会挤掉） |
| 2 | 宽屏（平板、Windows、Linux、iPad、macOS 共用） | 1280×800；内容区可能太宽的再出 1920×1080；桌面专属的悬停、右键、快捷键在图上标出 |
| 3 | 电视 | 有电视版的任务：1920×1080，同一组件的电视样式（焦点放大、字号大一级）；没有的写“电视不适用” |
| 4 | 苹果平台 | 只写差异（安全区、滑动返回、Cmd 快捷键、macOS 窗口按钮和菜单栏）；没有差异写“同宽屏”。差异多的集中到 U.17 出图 |

深色：确认后补出深色图（`render.py --dark`），检查对比度。

### 3.3 按钮编号示意图

在新设计的 HTML 里给每个可点的控件加 `data-n="编号"`（可选 `data-tag="chg|add|keep"` 表示修改、增强、保留），`render.py --annotate` 会多出一张 `-n.jpg`：控件加虚线框和编号圆点。对比页“每个按钮是干什么的、怎么用”一节用这张图，表格的编号和图上一致。

## 4. 对比评审页

1. 写 `compare/<编号>/page.json`（模板见 [templates/page.json](templates/page.json)），章节固定：
   1. 说明（改版时写“这一版改了什么、上一版为什么不行”）；
   2. 对比（左 v3、右新设计，各形态、各状态）；
   3. v3 的问题（编号、问题、位置）；
   4. 改了什么（每条带编号 `c1`、`c2`…，类型是保留、修改、增强、去掉，对应问题编号）；
   5. 每个按钮是干什么的、怎么用（编号示意图 + 表）；
   6. 各客户端（宽屏、电视、苹果平台的图或差异说明）；
   7. 需要你选的（每处 A 是建议、B 是另一种）；
   8. 性能要点。
2. 生成：`python3 tools/ui/mock/page.py docs/ui/compare/<编号>/page.json`（图片嵌进页面，输出到 `~/ref/design/compare/<编号>.html`）。
3. 发布成 claude.ai 页面，声明 `db` 能力（评审按钮要用）；第一次发布记下地址写进 README，以后每一版都更新同一个地址。

## 5. 评审（用户）

- 页面上每条改动下面有“满意 / 不满意 / 再想想”和一行意见；每个选择有“选 A / 选 B”；最后有“整体意见”。点了就自动保存。
- 也可以直接在聊天里说；两边都算。
- 没有表态的条目按建议做，定稿时在 README 注明。

## 6. 修改、出下一版

1. 我读评审结果（页面数据库的 `review` 集合：每条 `{verdict 或 pick, note, ver}`），整理成三类：满意的不动；不满意的逐条找原因（是 v3 还原不对、违反了原则、还是设计本身不好）；再想想的补充说明或给两个方案。
2. 改 `src/*.html`，`render.py` 重新生成；改 `page.json`：版本号加一、“说明”里写这一版改了什么和上一版的问题；`page.py` 重新生成，发布到同一个地址。
3. 页面上已表态的条目会显示“第 N 版：满意 / 不满意 · 意见”，新一版需要重新表态的只有改过的条目。
4. 用户指出的问题如果是通用的（例如“各客户端要一致”“还原要从代码取”），写进计划书第 3 节，避免下一个任务再犯。
5. 每一版都导出一次（第 7 步的前两条），GitHub 上能看到最新版和历史。

## 7. 定稿上传

1. `python3 tools/ui/export_compare.py ~/ref/design/compare/<编号>.html docs/ui/compare/<编号>/page`：按章节导出图片。
2. 单张效果图、编号示意图、深色图已在任务文件夹里（`v3-*.jpg`、`v4-*.jpg`、`v4-*-n.jpg`、`v4-*-dark.jpg`），源文件在 `src/`，评审页源在 `page.json`。
3. 写 README（模板见 [templates/README.md](templates/README.md)）：状态、确认日期、各版经过和教训、章节链接、单张图表、确认的改动清单、按钮用法、各客户端、待选和决定。
4. 更新 [TASKS.md](TASKS.md) 的状态、计划书附录 B、`docs/PLAN.md` 的 U.x 行。
5. `tools/gate/gate.sh --all` 通过后推送。

## 8. 开发任务书

模板见 [templates/dev_brief.md](templates/dev_brief.md)。要写清：

- 范围：任务 README、导出图、清单一节；v3 和 v4 的文件。
- 逐条改动清单（照 README），每条做到什么样；各客户端的位置规则。
- 不能动的：别的任务的界面、原生部分（需要时写明）、版本号、用户的 3.x 安装。
- 代码放哪、门禁规则（计划书第 10 节）。
- 测试要求和记录要求。

## 9. 开发和测试（开发代理，在独立的 git worktree 里）

- 先还原 v3 布局，再加确认过的改动。
- widget 测试固定控件的顺序、图标和位置；竖屏、横屏、宽屏至少各一个布局测试；和原有测试冲突的按设计改，原因写进记录。
- 实现记录 `docs/ui/records/<编号>.md`：逐条对照表（做了没有、偏差和原因）、新设置项、`ui_baseline.json` 的变化、测试数量。
- 涉及列表、弹幕、动画的，profile 模式看帧时间。
- 只提交到 worktree 分支，不推送。

## 10. 合并验收

- 合并开发分支；照计划书第 12 节的验收标准逐条检查；`tools/gate/gate.sh --all` 通过后推送。
- 门禁基线只减不增。
- 更新 TASKS、计划书附录 B、`docs/PLAN.md`。
- 有真机条件时（K90、Windows）对照效果图看一遍，偏差记进记录。

## 怎么更快

- **组件复用**：kit 里的组件（顶栏、画面、上下栏、菜单、面板……）和 U.2a、U.2f 的源文件可以直接复制改；同类界面（设置子页、列表页）先做一个，其余套用。
- **脚本出变体**：同一界面的多个状态、多个尺寸，用一个小脚本生成多份 HTML（U.2c 的四种尺寸就是这样出的），改一处全部重新生成。
- **文字不手抄**：`tools/ui/strings.py` 直接列出 v3 文件里的中文。
- **评审不来回问**：评审页逐条表态，我一次读完再改；选择题给建议，没表态就按建议。
- **并行**：一批定稿就开开发代理，同时做下一批设计。
