接续[全量目录退出审计](SERVER_ALL_LIFECYCLE_AUDIT_2026_09_10.md)，以 4fbca8c1 为起点，检查 [ServerFixedPageController](../lib/common/base/server_fixed_page_controller.dart)、[ServerRemotePageController](../lib/common/base/server_remote_page_controller.dart) 以及分类房间、热门列表的四个派生实现。版本仍为 3.1.8+4121。

受资源守卫保护的全 lib 调用者搜索还找到第五个派生类 [UserServerRemoteController](../lib/modules/auth/user_server_remote_controller.dart)。其云端统计、搜索游标和权限查询有自己的异步副作用，本批只保护它继承的分页发布，未修改或验收这些 Firebase 专属逻辑；不将四个直播派生类的测试推广为全部五个派生类已验收。

## 根因与修订

初始 45 项测试得到 **6 PASS / 39 FAIL**。正常分类房间标签/登录状态六项对照通过；失败包括：

1. 加载期间删除控制器，第一批或后续批次成功/失败仍提交列表、缓存、页号和 loading 状态。
2. 服务分批返回时，关闭页面后继续发起下一批网络请求；已有部分结果时，内层 catch 仍允许旧页面发布部分列表。
3. 连通性检查已识别页面关闭，分页调用者仍完成刷新提示；缓存命中、加载更多或页大小入口也可更新已关闭页面。
4. 远程分页的页大小补数是独立异步路径，旧实现仍重建缓存、发布列表和调用 update。
5. 分类房间派生类先修改响应对象标签或 notLogin；热门派生类在返回后重新访问设置进行排序，父类的最终检查来不及保护这些副作用。

公共分页在每个网络 await 的成功/异常出口和连通性返回处检查 isClosed，阻止后续批次、缓存写入和页面发布；catch/finally 只服务仍存活的页面。缓存分页、页大小、刷新、加载更多入口保护关闭状态。远程补数路径采用相同关闭检查。

[分类房间](../lib/modules/area_rooms/area_rooms_controller.dart) 在标签写入和特殊错误处理前检查关闭状态；[热门列表](../lib/modules/popular/popular_grid_controller.dart) 在当前响应返回后、读取设置前检查。正常站点分页参数、TwitCasting 完整窗口、排序、部分成功保留规则及登录分类均保持。

底层请求没有取消接口，本批是结果归属和后续工作边界修订，不宣称中止已经在途的 HTTP 请求。主加载 Future 仍被观察到终态，排队刷新在退出后不再启动。

来源为 **upstream-existing**：冻结 c6c9bd70 的固定批次缓存写入、远程普通加载及独立补数均缺少关闭检查；派生标签和排序也在 await 后执行。本分支 783f1f79 的部分成功保留扩大了错误返回的处理路径，所以本批明确测试“已有部分结果后退出且下一批失败”。修订保留存活页面的部分成功，不通过移除功能让测试通过。只读取本地冻结提交，没有同步上游。
