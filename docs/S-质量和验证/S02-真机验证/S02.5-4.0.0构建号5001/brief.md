### 上机前（每个阶段都做）

```bash
source ~/tools/purelive-env.sh
cd apps/pure_live && flutter build apk --profile --target-platform android-arm64
adb connect 192.168.1.2:5555            # 端口会变；连不上先问维护者
adb -s 192.168.1.2:5555 logcat -d | grep "adbd service requested"   # 有别的自动化程序就先请用户停掉
adb -s 192.168.1.2:5555 install -r build/app/outputs/flutter-apk/app-profile.apk
export PL_APP=com.mystyle.purelive.v4dev; source ~/tools/pl-adb.sh
adb -s 192.168.1.2:5555 shell am start -n com.mystyle.purelive.v4dev/com.mystyle.purelive.MainActivity
```

- 只用 `tap`、`key`、`text`、`swipe`、`tapl` 输入（每次先检查前台是测试包）；截图 `shot <名字>`，看之前缩到宽 540。
- **只断测试包的网（不断 adb）**：K90 是 root 的。`UID=$(adb -s 192.168.1.2:5555 shell dumpsys package com.mystyle.purelive.v4dev | grep -m1 -o 'userId=[0-9]*' | cut -d= -f2)`；断：`adb -s 192.168.1.2:5555 shell su -c "iptables -I OUTPUT -m owner --uid-owner $UID -j REJECT; ip6tables -I OUTPUT -m owner --uid-owner $UID -j REJECT"`；恢复：同一条命令把 `-I` 换成 `-D`。不要用 `svc wifi disable`（adb 走的就是 Wi-Fi，断了就回不来）。维护者手里拿着手机时，也可以直接开关飞行模式。
- 临时系统设置（用完必须恢复，见每条）：去掉动画 `adb shell settings put global animator_duration_scale 0`（恢复 `1`）；关画中画权限 `adb shell appops set com.mystyle.purelive.v4dev PICTURE_IN_PICTURE ignore`（恢复 `allow`）；模拟宽屏 `adb shell wm size 1600x2560`（恢复 `adb shell wm size reset`）；放大显示 `adb shell wm density 600`（恢复 `adb shell wm density reset`）。
- 直播间的准备：一个人多的哔哩哔哩直播间（英雄联盟比赛这类）、一个斗鱼或虎牙直播间、一个 YY 直播间、一个抖音竖屏主播、一个有醒目留言的哔哩哔哩直播间；关注里至少 8 个在播的直播间和 1 个未开播的；观看记录里有几条。

## 风险和注意

- 断网只断测试包（防火墙规则），不要关 Wi-Fi：adb 走 Wi-Fi，断了就连不回来。规则用完立即删，`adb shell su -c "iptables -S OUTPUT"` 确认没有残留。
- 基准（3B）和 `flutter run --profile`（阶段 2）都会覆盖装 `.v4dev`；测试包的数据保留，但要重新装回平时的包再接着做。
- 临时改的系统设置都要恢复：动画、`wm size`、`wm density`、系统刷新率、画中画权限；做完 `adb shell wm size`、`adb shell settings get global animator_duration_scale` 核对。
- 4B 会造出“失败”的录制任务和通知：测完在录制中心删掉，通知清掉，“自动断线重连”改回开。H01.5 合并以后，4B 也可以改回“开着自动断线重连、断网等重试用完”再看一遍（那时它就是 H01.5 的验证）。
- 扫码登录的哔哩哔哩账号、Cookie 不进截图和记录。
- 不在 18 个任务的设计 README 里改结论；结果只写 `verify.md` 和记录。
