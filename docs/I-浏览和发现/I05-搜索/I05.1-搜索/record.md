# I05.1 页面：搜索

- 日期：2026-10-01
- 目标：`apps/pure_live/lib/features/search/`（路由 `RoutePath.kSearch`、`RoutePath.kWebSearch`，类名 `SearchPage` 和构造参数不变）
- v3 来源：标签 `v3.2.11` 的 `lib/modules/search/`（10 个文件，2331 行：`search_controller.dart` 654、`search_page.dart` 370、`search_capability.dart` 164、`search_platform_strip.dart` 105、`search_ranking.dart` 69、`web_search_controller.dart` 550、`web_search_page.dart` 215、`web_search_room_parser.dart` 186、两个 binding）
- 用到的模块：E04.1（`LinkParser` 链接解析）、E/M4.U（各平台 `searchRooms`、`searchAnchors`、`LiveSearchPaginationPolicy`、`LiveCancellableSearch`）、J02.1（设置、关注、`MetaStore`）、A01.1（`RoomCard`、`AppStatusView`、`PlatformLogo`、滚动）、I01.1（provider、`AppNavigator`、`i18n`）

## 做法

| 文件 | 内容 |
|---|---|
| `search_page.dart` | 路由入口：`kWebSearch` 给 `WebSearchView`，其余给 `SearchView`（参数是字符串时作为初始关键词立即搜索） |
| `search_model.dart` | `SearchModel`（`ChangeNotifier`，对应 v3 `SearchController`）：平台选择、房间/主播两种模式、全平台并发（同时最多 12 个，每个平台每页 12 秒）、每个平台各自翻页、换平台或新搜索时取消旧请求（代号 + `CancelToken`）、筛选和排序 |
| `search_capability.dart` | 各平台搜索能力表（v3 `LiveSearchCapabilities`，按 E/M4.U 核对改正）、网页搜索地址、平台显示名、说明文字 |
| `search_ranking.dart` | 排序和“包含未开播”筛选（v3 `LiveSearchRanking`） |
| `search_history.dart` | 搜索历史（新增），存在 `LiveStore.meta` 的 `search.history`（JSON 列表，最多 20 条） |
| `search_cards.dart` | `LiveRoom` → `RoomCardData`（观众数简写、受限标签、`//` 开头的图片地址）、按屏幕类型读卡片外观设置 |
| `search_widgets.dart` | 平台条、筛选栏、搜索范围面板、历史、骨架屏、主播结果行 |
| `search_room_sheet.dart` | 卡片长按菜单：详情和简介、进入、关注/取消关注、复制链接 |
| `search_view.dart` | 页面：搜索框（粘贴、清除、识别链接）、结果网格（列数同 v3：>1280 五列、>960 四列、>640 三列、其余两列）、空状态、失败横幅、底部加载 |
| `web_search_view.dart` | 网页搜索路由：校验 v3 的 `{'url', 'platform'}` 参数，用系统浏览器打开 |

取服务照 I01.1：`storeProvider`（设置、关注、`meta`）、`sitesProvider`（平台）、`appServicesProvider.http`（链接解析的短链请求）、`AppNavigator.toLiveRoomDetail`、`AppNavigator.toast`、`AppNavigator.openExternal`。平台列表是用户的平台显示设置（`hotAreasList` → `SiteRegistry.availableIds`），页面打开时取一次快照（同 v3，免得平台条、选中项和翻页状态错开）。

## 与 v3 的功能对照

| v3 功能 | v4 |
|---|---|
| “全部”和单个平台；平台条选中项自动滚到中间 | 有，芯片加了平台标志 |
| 全平台并发搜索，最多 12 个同时，每平台 12 秒超时，先回来的先显示 | 有 |
| 翻页：滑到距底 480 像素自动加载、“加载更多”按钮、“已加载全部结果”；平台不能翻页、本页失败或为空就停，连续 2 页没有新结果也停；按关键词决定能否翻页（`LiveSearchPaginationPolicy`） | 有 |
| 跨平台去重（平台 + 房间号） | 有，用房间身份（E05.2：忽略大小写的平台按规则比较） |
| “包含未开播”开关 | 有，回放不再算未开播（见问题 4） |
| 四种排序（综合、平台优先、观众、粉丝） | 有 |
| 观众数口径跟随设置（优先真实在线人数、平台列表），设置改变时重排 | 有 |
| 部分平台失败的横幅（继续网页搜索、关闭） | 有，加“重试” |
| 无结果时的按钮：显示未开播 / 重试 / 继续网页搜索 | 有，各情况分开说明 |
| 选中的平台不能搜索时说明原因 | 有 |
| 搜索能力说明（单平台一句；全部平台一段长文字可展开） | 有，改为一行摘要 + 搜索范围面板 |
| 网页搜索：应用内 WebView，检测到房间链接后确认进房；Windows 检查 WebView2；Linux 用系统浏览器 | 改为系统浏览器（缺 WebView 插件，见“留给后续”）；进房靠把链接粘贴回搜索框 |
| 回车和搜索按钮同一帧触发只搜一次；换平台、换关键词取消旧请求 | 有 |
| 空关键词提示 `please_input_keyword`；搜索时收起键盘、滚到顶部 | 有 |
| 卡片点击进房；长按菜单：关注、标签、分享 | 点击进房；长按菜单有进入、关注/取消关注、复制链接、简介；标签和分享留给共享的卡片菜单 |
| 返回按钮在搜索框里 | 有 |

v3 没有的：主播搜索、搜索历史、粘贴链接直接进房、粘贴按钮、骨架屏（见“界面改进”）。v3 搜索页没有存储任何数据，没有需要迁移的内容。

## 审查发现的 v3 问题

| # | 问题 | 位置 | 根因 | 处理 |
|---|---|---|---|---|
| 1 | YY、TwitCasting 标着“能搜到未开播”，实际关键词搜索只返回直播中的（UPGRADES A-5） | `search_capability.dart:129,132-135` | 能力表没跟着平台接口核对 | 改为“只搜直播中”；TwitCasting 另说明“粘贴频道链接可查到未开播” |
| 2 | YouTube 标着“只能精确查频道”，T02.U 后已能按关键词搜直播并翻页（23-2） | `search_capability.dart:64-68` | 能力表停在 v3 的平台实现 | 改为“关键词只搜直播中、可翻页，频道链接可查未开播” |
| 3 | 说明文字是开发说明（“App 内原生搜索覆盖 33/34 个平台……”“精确 UID/官网用户关键词分页；搜索资料未给当前直播状态时保持未知”），全部平台时拼成一大段 | `search_controller.dart:440-498`，翻译 `search_coverage_*` | — | 新写用户看得懂的说明（`search_scope_*`），全部平台只显示一行摘要，细节放进面板（统一原则“说明文字”） |
| 4 | “包含未开播”关掉后，能播放的回放也被隐藏，排序时回放和未开播排在一起 | `search_ranking.dart:18,52` | 只认 `isLiveNow` | 筛选看 `isPlayableNow`；排序：直播 > 回放 > 其余 |
| 5 | TwitCasting 的关键词超过 100 字（比如粘贴一整段分享文字）时适配器抛 `ArgumentError`，被当成“部分平台请求失败：TwitCasting” | E03.4 `searchRoomsCancellable` | 其他平台在平台层自己截断（13-4、15-5、20-5、33-5），TwitCasting 没有 | 页面里先截到 100 字再发给 TwitCasting（平台层改了以后可以去掉） |
| 6 | 粘贴别的平台的直播链接搜索，只有能认出自己链接的少数平台有结果，其余平台白跑一遍；进房要去工具箱 | `search_controller.dart:176-198` | 搜索页不认链接 | 识别到支持的链接时直接打开直播间（`LinkParser`，含短链），认不出才按文字搜索 |
| 7 | Windows 每次打开搜索页都启动两次 `reg.exe` 检查 WebView2 | `search_controller.dart:146-175,616-630` | 为应用内 WebView 做的检查 | 不再需要（网页搜索走系统浏览器） |
| 8 | 网页搜索地址带跟踪参数（哔哩哔哩 `spm_id_from` 等、斗鱼 `dyshid`），未知平台落到带十几个参数的百度搜索 | `search_controller.dart:100-142` | — | 只留搜索参数；没有网页搜索的平台不给地址 |
| 9 | 每次比较观众数都读一次设置单例 | `search_controller.dart:500-508` | — | 页面缓存两个设置值，设置变化时更新并重排 |

## 界面改进

（2026-10-01 用户授权的统一原则。）

| 改了什么 | 为什么 |
|---|---|
| 搜索框提示改为“搜索直播间、主播，或粘贴直播链接”；有字时显示清除按钮，没字时显示粘贴按钮（只在点按时读剪贴板） | 让粘贴链接这个用法看得见；手机上清空、粘贴更顺手 |
| 识别到直播链接时在筛选栏下显示“识别到直播链接 / 进入”横幅，回车或点“进入”直接打开直播间；解析中显示进度；认不出时提示并按文字搜索；已下线平台的链接提示“已下线” | 粘贴链接直接进房（问题 6） |
| 搜索历史：未搜索时显示最近 20 条，点按再次搜索，单条删除、清空；链接进房不记入历史 | v3 没有历史，常搜的词每次要重新输入 |
| “直播间 / 主播”切换：主播模式搜 7 个有主播搜索的平台（哔哩哔哩、斗鱼、虎牙、快手、网易 CC、YY、AcFun），结果是头像、名字、平台、直播状态的列表，点按进房；选了不支持的平台时说明 | 平台层早就有 `searchAnchors`，v3 界面没有用上；能搜到未开播的主播 |
| 平台芯片加平台标志 | 34 个平台只看文字不好找 |
| 搜索范围：筛选栏下一行摘要（单平台是该平台的说明），点开是“各平台的搜索范围”面板，按“能搜到未开播 / 只搜直播中 / 在推荐里筛选 / 只能精确查找 / 本机频道”分组，每个平台写明是否支持主播搜索、网页搜索 | 替代 v3 一大段可展开的说明（问题 3） |
| 首次加载显示骨架卡片（主播模式是转圈），还有平台没回来时显示“还有 N 个平台在搜索…”和细进度条 | v3 只有一个转圈和一条细线，看不出在等谁 |
| 空状态分四种：没有结果（换关键词或平台，可网页搜索）、全部失败（错误样式 + 重试）、结果都是未开播被隐藏（显示未开播）、选中平台不支持 | v3 几种情况共用一个标题 |
| 部分失败横幅加“重试” | v3 只能关掉或去网页搜索 |
| 卡片标出受限类型（付费、私密、仅限 App、地区受限等）；长按菜单显示简介、房间号，可进入、关注/取消关注、复制链接 | 统一原则“卡片标出受限类型”；12-5、11-5 |
| 网页搜索在系统浏览器打开，并提示“找到直播间后复制链接，粘贴到搜索框即可进入”；网页搜索路由页同样说明 | 应用暂时没有 WebView 插件（见“留给后续”） |
| 路由参数是字符串时作为初始关键词直接搜索 | 方便其他页面做“搜索这个主播” |

默认值没有改：默认“全部”平台、房间模式、包含未开播、综合排序（v3 也不保存这些选择）。

## 留给后续

| 内容 | 去向 / 需要什么 |
|---|---|
| 应用内网页搜索（v3：flutter_inappwebview，看到房间链接时询问是否进房；Windows 需要 WebView2；Cookie 落盘） | 需要应用加 `flutter_inappwebview` 依赖和 Android/Windows 原生配置（I01.1 记录里 Twitch 的无界面 WebView、网页登录也要它）。加上后在 `web_search_view.dart` 里接回 v3 的逻辑：只放行 http(s)、拒绝不受信任的证书、用 `LinkParser`（或 `RoomPaths`）识别房间链接后确认进房、返回键先后退网页 |
| 卡片到 `RoomCardData` 的转换、卡片外观、受限标签、观众数简写 | 现在在 `search_cards.dart`；关注、热门、分区、历史页也要，建议合并时挪到共享位置（例如 `lib/app/` 下）统一一份 |
| 卡片长按菜单的标签和分享（v3 `RoomCard.onLongPress` 的分享口令、标签选择） | 共享卡片菜单（M13），本页的菜单只做了进入、关注、复制链接 |
| 卡片上显示简介（11-5） | `live_ui` 的 `RoomCardData` 加简介字段 |
| TwitCasting 超过 100 字的关键词 | 平台层改为自己截断（同 13-4 等）后，去掉 `search_model.dart` 的 `_queryFor` |
| 搜索历史进备份 | 现在在 `meta`，不在备份里；要进备份需要备份服务带上这个键或改成设置项 |
| 分享和深链收到的链接、剪贴板自动识别 | 链接解析/工具箱页面（I01.1 记录“分享和深链的接收”）；本页只在用户点粘贴时读剪贴板 |

## 测试

`apps/pure_live/test/search_test.dart`，12 个（加速流程，只覆盖主要路径）：

- 能力表（3）：所有平台都有条目，YY、TwitCasting 只搜直播中（A-5），主播搜索平台，网页搜索地址与能力一致；排序和筛选（直播 > 回放 > 未开播，隐藏未开播保留回放）；卡片转换（观众数简写、受限标签、`//` 图片地址、空昵称用平台名）。
- 模型（3）：全平台合并排序、失败平台记名、只有能翻页的平台再请求、没有新结果后停止；超时算失败、换平台搜索草稿、草稿为空时清空；主播模式只搜支持的平台、单个不支持的平台给出说明。
- 历史（1）：新的在前、忽略大小写去重、上限 20、删除、清空、重开后读回。
- 页面（4，假平台 + `LiveStore.memory`）：搜索出卡片和失败横幅、点卡片进房、长按菜单关注写进关注列表、回到初始状态显示历史；粘贴链接（中文标点结尾）直接进房且不发搜索；主播模式列出主播并进房、不支持的平台的空状态；网页搜索用浏览器打开该平台的地址。
- 网页搜索路由（1）：v3 参数格式、非 http(s) 和带用户信息的地址被拒、打开系统浏览器。

`flutter analyze`（apps/pure_live）没有问题；`i18n_test.dart` 照常通过（中英文都加了同样的 56 个键）。
