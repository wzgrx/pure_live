# 0024 IPTV 的包结构、数据位置和频道身份

- 状态：已接受（部分取代 0003 中“IPTV 沿用现有数据库”）
- 日期：2026-09-28

## 背景

ADR 0003 决定 IPTV 不再算直播站点，从 `live_core` 移出，作为独立的本地数据源模块，并写了“沿用现有数据库”。实现 IPTV（product.md §10，规格 [spec/modules/iptv.md](../../spec/modules/iptv.md)）时，还有几处会长期影响数据格式和代码结构的选择：代码放在哪、数据放在哪、频道用什么做房间号、多个源怎么变成线路、回看的时间按什么时区。

## 决定

1. **新包 `packages/live_iptv`**（纯 Dart，只依赖 `live_core`、`live_net`，`check_deps.py` 登记）。里面是播放列表和节目单解析、频道匹配、回看地址规则、下载器，以及实现 `live_core` 能力接口的 `IptvSite`（平台 id `iptv`，名称“网络电视”）。它通过 `IptvRepository` 接口读数据，自己不碰存储；应用用一个几十行的适配器把 `live_store` 的记录接到这个接口上（`live_store` 只能依赖 `live_core`）。这样 IPTV 频道走和其它平台完全相同的发现、关注、直播间、播放路径。
2. **数据放进主库**（`live_store` schema 2：`iptv_playlists`、`iptv_channels`、`iptv_guide_sources`、`iptv_guide_channels`、`iptv_programmes`），不再沿用旧 IPTV 库。旧库 `IPTV_CACHE/pure_live_tv/pure_live_tv.db` 以后只读导入（来源地址、节目单源），不升级它的结构。这修订了 ADR 0003 的“沿用现有数据库”和 store.md 的“原位沿用、继续编号升级”。
3. **频道 = 名称**。房间号就是频道名（去首尾空白、连续空白并成一个；会被 `RoomRef` 当成占位符的 `0`、`null` 等加 `#` 前缀）。所有播放列表里同名的条目都是这个频道的线路，顺序为播放列表顺序、再按文件顺序；每条线路带自己的请求头和回看属性。条目按文件原样存（一行一个流），频道在查询时按名称归并。
4. **节目单匹配不落库**：每次按当前节目单的频道表建索引（按节目单版本缓存在内存），四步匹配、只接受唯一答案。没有手动匹配。
5. **节目只存有限窗口**：同步时只保存 [现在 − 2 天, 现在 + 2 天)，过期的在启动和同步时删除。
6. **备份只带网址来源**：v4 备份的 `iptv` 分区是网址播放列表和网址节目单源；文件来源、频道、节目不进备份。恢复时替换网址来源、保留本机文件来源。
7. **回看时间**：playseek 规则、`{Y}{m}{d}{H}{M}{S}`、`${(b)…}` / `${(e)…}` 用本机时区的当地时间；`{utc:…}` 这类带格式的写法用 UTC；数字占位符都是 Unix 秒。

## 备选方案与放弃理由

- **解析器和站点放在 `live_core/src/sites/iptv/`**：ADR 0003 已经决定 IPTV 不是站点；而且 IPTV 的依赖（XML 解析）和变化节奏与平台适配器不同。
- **`live_store` 直接依赖 `live_iptv`、自己实现 `IptvRepository`**：会让存储层依赖一个功能包，破坏“存储只依赖 live_core”的方向；适配器放在应用里只多几十行转换。
- **沿用旧 IPTV 库并继续升级结构**：旧版遇到更高的 schemaVersion 直接抛错（REG-STORE-021），回退到 3.x 后 IPTV 全部失效；两个库还要分别备份、迁移和做事务。主库一次迁移就能加表，旧库只读导入，回退无副作用。
- **频道身份用 `播放列表 id + 名称` 或 `tvg-id`**：前者删除并重新导入播放列表后关注全部失效，也做不到“同名频道跨播放列表合并成线路”；`tvg-id` 很多列表不写，或者给不同频道写同一个值。名称的代价是列表里改名后关注失效，这和用户看到的一致。
- **导入时把多个源合并成一行存储**：同步时要维护合并结果，播放列表之间还会互相影响；按条目存储、查询时归并更简单，删除播放列表也只是级联删除它的条目。
- **节目单匹配落库（旧版的 EpgMappings）**：旧版没有手动匹配入口，自动结果每次都能重算；落库还要在切换节目单、同步播放列表、同步节目单时分别维护。
- **保存完整节目单**：常见节目单有上千个频道、一周数据，一次写入十几万到几十万行；界面只看前 2 天到后 1 天。
- **备份里嵌入文件来源的内容**：播放列表可能有几 MB，备份文件会变得很大，而且大多数用户用的是网址。

## 影响

- `live_core` 的 `StreamFormat` 只有 flv / hls：IPTV 的 MPEG-TS、RTSP、UDP 等线路暂标为 flv（没有租期，直连播放，不影响播放）。录制接入 IPTV（record.md §8 的连续 TS）前要在 `live_core` 增加格式。2026-09-28 起加了 `StreamFormat.other`，`.ts`、udpxy 等 HTTP 线路标为 other 并可以录制（ADR 0035 修订）。
- 存储迁移（store.md §6）需要补一步：从旧 IPTV 库只读导入播放列表来源和节目单源。
- `xml` 的工作区覆盖升到最新稳定版 7.1.0，`live_iptv` 直接依赖它（ADR 0008 的覆盖说明不变：media_kit 只用到未变化的接口）。
