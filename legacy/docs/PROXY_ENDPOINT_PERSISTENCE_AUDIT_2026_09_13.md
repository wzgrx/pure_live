# 代理端点持久化与备份边界审计

## 范围与根因

本轮以 `9f21fc46` 为基线，修订提交为 `abc0d714`。范围限应用代理与播放器代理的主机/端口持久化、当前/旧版备份和导出边界；没有发起直播站点生产网络探针、构建安装包、操作手机或执行 Windows GUI，Computer Use 与 Astra Light 使用均为 **0 次**。

源码审查确认界面虽已拒绝半成品和超出 1～65535 的端口，但控制器边界仍存在三个缺口：

1. 启动时直接接受 Hive 中的 `proxyPort` / `appProxyPort`，损坏值会在代理观察器之外保留，并继续流向应用、播放器和录制消费者。
2. 当前/旧版备份直接接受任意整数端口；主机字段还通过 `.toString()` 宽松转换，使数值等畸形字段变成可用文本，而不是在导入预检阶段终止。
3. 控制器字段和旧版提取默认端口为 7897，当前备份解析默认端口却为 1080；直接写入控制器的异常端口也可原样导出。

## 修订

- 在共享代理路由层建立默认端口 7897、合法范围 1～65535、合法性判断和持久值修复函数；界面输入解析与最终代理指令构建复用同一合同。
- 控制器安装任何应用代理观察器前，先归一化并持久化两组主机和端口，避免修复过程触发不必要的连接重建。
- 当前与旧版备份对主机保持严格字符串类型、对端口保持严格整数类型；合法值原样保留，越界整数统一回落到 7897。
- 导出时再次归一化两组端点，使测试、插件或其他调用方的直接异常写入不会泄漏到下一份备份。
