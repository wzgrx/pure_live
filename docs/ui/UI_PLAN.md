## 1. 目标

1. **以 v3 为基线**：界面、布局、操作逻辑、功能以 v3.2.11 为起点；功能一个不少，3.x 的设置和数据照旧生效。
2. **修掉 v3 的问题**：每个问题写清根因和代码位置，在重构里修。
3. **优化、完善、增强**：每一项在对比页里列出，用户确认后才做。
4. **所有客户端一致**：Android（手机、平板、折叠屏）、Windows、Linux、电视、iOS / iPadOS、macOS 上，同一个功能是同一个组件、同样的样子和操作，只随屏幕大小调整位置。
5. **多尺寸动态适配**：任意窗口大小、横竖屏、折叠开合、分屏、字体放大、不同像素密度和刷新率下都好用；尺寸变化时布局跟着变，播放不中断。
6. **流畅**：K90 120 赫兹时 99% 的帧在 8.3 毫秒内；Windows 144 赫兹同样；没有连续掉帧（第 8 节）。
7. **好维护**：外观集中在 `live_ui`，页面按功能分目录、和 v3 一一对应；界面测试固定关键布局；效果图有源文件，改了能一键重新生成。

## 2. 背景

- M13 的页面按“界面可以自行设计”写成，没有逐个控件对照 v3，用户看到成品时偏差已经很大（直播间最明显：竖屏上栏不见了、按钮挪了位置、图标换了）。根因：任务没要求“先还原 v3 再列改动”，没有统一的图标入口和组件约束，没有界面测试固定布局，用户看到时已写完。
- 2026-10-01 起改为本计划：先还原 v3，再逐条列改动请用户确认，确认后才写代码。
- 已走完一遍的样板：U.2a 竖屏直播间（确认、开发、合并、推送）；U.2f 直播间弹窗（五版才定稿，教训写进第 3 节第 7～9 条）。

## 3. 原则（做决定时按这个顺序）

1. **v3 的功能和操作习惯不能少**：入口、操作方式、手势、快捷键、设置项都保留。
2. **v3 的布局和图标是默认答案**：控件的位置、顺序、图标照 v3；要改，在对比页里列出理由并经用户确认。
3. **修 v3 的问题**：截断、溢出、对比度不够、点击区域太小、同屏重复、状态不清、宽窄屏错乱，以及结构问题（整页重建、硬编码颜色、按整屏宽度判断布局）。
4. **补全缺的状态**：加载、空、出错、受限、离线、权限被拒、进行中、完成，统一用 `live_ui` 的状态组件。
5. **增强只做有明确收益的**：信息更清楚、操作更少、更流畅；不为好看改风格。
6. **同一件事全应用只有一种做法**：一个动作一个图标、一个组件、一套文字。
7. **各客户端一致**（用户 2026-10-01 要求）：同一个功能在手机竖屏、手机横屏、平板、Windows、Linux、电视、iOS、macOS 上用同一个组件、同样的样子、同样的操作和关闭方式。屏幕大小只决定放在哪（例如面板竖屏在画面下方、横屏在右侧；小菜单在按钮上方还是下方），不换成另一种东西。弹窗配色跟应用主题，全屏时不另换一套。平台惯例只在必须时遵守（系统返回手势、窗口按钮、Ctrl 和 Cmd），并在对比页写明。
8. **弹法照 v3，不先定规则再套**：v3 用小菜单、对话框还是面板，逐个看好不好用；只修具体的问题并写明（U.2f 第一版把所有弹窗统一成底部面板，被否决）。
9. **还原 v3 从代码取**：还原图里的文字、选项、分组、数值都从 v3 代码和 `assets/translations/zh.json` 取（`tools/ui/strings.py` 列出一个文件用到的全部文字）；长面板画完整内容；功能有多种状态的先把状态理全（U.2f 弹幕设置凭印象画错被指出“缺少功能”；录制任务有 9 种状态，v3 对话框只分 3 种）。

## 5. 形态和多尺寸动态适配

### 5.1 判定

1. **电视模式**：检测到电视（电视界面模式或 leanback 特性）时自动进入，也可以在设置里手动开关；电视模式下不按宽度分级。
2. **宽度分档**（和 Android 窗口尺寸分档一致）：紧凑 <600、中等 600–839、展开 840–1199、大 1200–1599、超大 ≥1600。
3. **高度分档**：紧凑 <480、中等 480–899、展开 ≥900。**高度紧凑优先**：横屏手机宽约 850–930，按宽度是“展开”，但高度紧凑，按“横屏手机”排。
4. **折叠屏姿态**：半开的桌面姿态和书本姿态单独处理，控件和文字避开铰链。
5. **只读父组件给的约束**（`LayoutBuilder`），不读整屏尺寸；窗口尺寸变化时切换布局，保留滚动位置和播放状态，不重建播放器。v3 用 680 一个分界、读整屏（`Get.width`），窗口缩放时有的页面不跟随，这是要修的问题。

### 5.2 形态清单（出图时按这个对照）

| 形态 | 出图尺寸 | 哪些界面有 |
|---|---|---|
| 竖屏 | 393×852 | 全部手机界面 |
| 横屏全屏 | 852×393；窄手机 740×360 | 直播间、多画面、网络电视播放 |
| 竖屏全屏 | 393×852 | 直播间（竖屏流） |
| 宽屏 | 1280×800 | 全部页面（平板横屏、Windows 和 Linux 窗口、iPad、macOS） |
| 超大 | 1920×1080 | 直播间、网格页、设置（看内容区是否太宽） |
| 应用内小窗 | 窗口内 360×203 左右 | 直播间离开后的悬浮小窗 |
| 系统画中画 | Android 画中画、iOS 画中画、桌面小窗 | 直播间 |
| 电视 | 1920×1080（逻辑 960×540） | 电视全部界面 |

### 5.3 动态适配规则

- **网格列数**：列数 = clamp(⌊(内容区宽度 + 间隙) ÷ (最小卡宽 + 间隙)⌋, 2, 8)，最小卡宽紧凑 160、中等和展开 180、大和超大 200；393 宽的手机是 2 列（和 v3 一致）。修 v3 固定断点 2/3/4/5 列、拖窗口时卡片忽大忽小。
- **导航**：紧凑用底部导航栏（v3），中等以上用侧边导航栏（v3 宽屏）。
- **直播间**：只有一个展示状态枚举（内嵌、全屏、竖屏全屏、画中画、应用内小窗）；视频画面只挂载一个，切换状态时移动它，不重建。宽屏时画面加右侧聊天栏（v3 的左右分栏，聊天栏约 34%，300–400）。
- **面板和弹窗**：同一个组件；竖屏放画面下方或底部，横屏和宽屏放右侧（宽 360）；小菜单贴着按钮，放得下的一边弹出（第 7 节）。
- **内容最大宽度**：设置、详情等阅读型内容在大屏上不超过 720，居中或左对齐带侧栏。
- **大屏的方向锁定**：Android 17 起在最短边 ≥600 的设备上方向锁定会被系统忽略；平板和折叠屏只按当前方向排，锁方向只在手机上生效。
- **桌面窗口**：最小 360×400（落到紧凑布局）；记住大小、位置、最大化状态；按显示器缩放比例渲染。
- **系统环境**：刘海、灵动岛、安全区、手势条、键盘弹出、分屏、自由窗口、横竖屏切换、折叠开合都要正常；系统字体放大到 1.3 倍和 1.5 倍不截断；深浅两套主题都单独看过。
- **刷新率**：见第 8.1 节。

### 5.4 输入方式

| 输入 | 要求 |
|---|---|
| 触摸 | 点击区域至少 48×48，间距至少 8；画面手势（亮度、音量、单击、双击）照 v3 |
| 鼠标、触控板 | 悬停状态；右键等于长按；直播间滚轮调音量（照 v3）；控制层随鼠标移动显示、静止后隐藏；悬停显示按钮名称 |
| 键盘 | v3 的快捷键全保留：空格和媒体键暂停、R 刷新、↑↓ 音量、Esc 依次关弹层、退全屏、返回；macOS 和 iPad 键盘用 Cmd 代替 Ctrl；焦点框只在用键盘时显示；Tab 顺序和视觉顺序一致 |
| 遥控器（电视） | 每页有默认焦点；方向键能到所有元素；返回键逐级退出；长按确认等于菜单键 |
| 系统返回 | Android 返回键和预测返回、iOS 滑动返回都走同一条退出链：弹层 → 全屏 → 普通 → 离开 |

### 5.5 电视

以 pure_live_TV 为参考，细则：画布 960×540，左右 48、上下 28 安全边距；左侧收起的导航轨，获得焦点时展开；网格 4 列，按行列记忆焦点；焦点卡片放大 1.05 倍加 3 像素近白描边（低端盒子可选只描边）；字号比手机大一级，正文不低于 14；只有深色；直播间始终全屏，上下键换台、左键直播间列表、右键播放设置、确认键信息栏、返回键逐级退出。同一功能的面板、菜单和手机版是同一个组件的电视样式（焦点放大、字号大一级），内容和顺序一致。

### 5.6 苹果平台

- **iOS、iPadOS**：没有返回键，靠左边缘滑动返回和顶栏返回按钮（顶栏已有返回按钮，保持）；内容避开灵动岛、刘海和主屏指示条；画中画用系统画中画；iPad 的分屏和台前调度按第 5.1 节的宽度分档自然适配；外接键盘用 Cmd 快捷键，指针有悬停态。
- **macOS**：窗口按钮在左上（标题栏左侧留出位置，标题和按钮右移）；顶部菜单栏放应用菜单（关于、设置、退出）和常用快捷键；全屏进入系统全屏空间；托盘对应菜单栏图标（可选）。
- **约束**：本机没有 Mac，暂时只设计、不构建；设计时每个任务写一行“苹果平台差异”（大多数是“无”）。

## 7. 弹窗和面板

照 v3 的弹法，只修具体问题（第 3 节第 7、8 条）。四种，组件在 `live_ui`，各客户端同一个：

| 类型 | 用在哪（v3 就是这样弹的） | 位置 | 关闭 |
|---|---|---|---|
| 小菜单 | 选一项：清晰度、线路、画面比例、右上角菜单 | 贴着按钮，放得下的一边 | 选完就关；点外面、返回键、Esc |
| 对话框 | 确认、输入、短内容：取消关注、删除、改名、定时；卡片长按（v3 是居中对话框，U.4a 的 A1 待定） | 屏幕中间 | 按钮；返回键、Esc |
| 面板 | 边看边调、内容多：录制、弹幕设置、长按弹幕、切换直播间 | 有画面时：竖屏在画面下方，横屏和宽屏在右侧（宽 360）；没有画面的页面：底部（竖屏）或右侧（宽屏） | ✕、返回键、Esc、竖屏时下拉 |
| 提示条 | 操作结果：已复制、已开始录制、已切换 | 底部（全屏时画面中下部） | 3 秒后自动消失（同 v3 `common/global/initialized.dart:172`），带“撤销”等操作的 4 秒 |

- 当前项一律“主色 + 勾”；弹窗里的字不小于 14 号；同一时间只开一个；打开时播放器控制层不自动隐藏。
- 电视上同一组件换电视样式（焦点放大、字号大一级），内容和顺序不变。

## 8. 设计系统（`live_ui`）

### 8.1 颜色

- Material 3，用户主题色作种子（默认蓝，3.x 设置照旧），支持动态取色；深浅两套分别检查对比度。
- 用角色不用色值：表面、表面容器（低/中/高/最高）、主色、主色容器、次色容器、轮廓、错误。
- 语义色固定、不随主题变：直播红 `#D92D20` 配白字（必须带“直播”二字）、录制红、成功绿、警告黄。
- 画面区域（播放器、全屏、多画面、画中画、小窗）在所有主题下黑底白字；画面上的控件单独一组角色：前景白、阴影、60% 黑渐变。
- 修 v3：卡片和弹幕行硬编码白和 `grey[900]` 改用表面容器角色；默认蓝白字对比只有 3.1:1（候选 C-3）。

### 8.2 文字

- 五个字号角色对应 v3 的五个字号设置（12、13、14、15、20），用户调整照旧生效；系统字体放大照常生效。
- 主次分明：同一处主信息和次信息至少差一档字号或字重。字重只用 400 和 600（微软雅黑没有 500）。最小 12；中文行高不低于字号的 1.4 倍。
- 人数、码率、时长、时钟、倒计时用等宽数字；人数写成“1.2万”，不做滚动动画。
- 画面上控制层的文字随系统放大最多 1.3 倍。

### 8.3 间距、圆角、阴影

- 间距按 4 的倍数；同组紧、组间松。
- 圆角沿用 v3：房间卡片跟随“卡片设置”（默认 20）、其他卡片 16、按钮 12、列表行 12、输入框 12、对话框 24、小菜单 8、面板顶角 16。
- 阴影只用于浮层（菜单、面板、悬浮小窗），卡片用表面层次。

### 8.4 图标（`AppIcons`）

- 按用途命名，每个用途对应 v3 在该位置用的图标：Remix（`remixicon`）、Material、v3 自带 `CustomIcons.ttf`、弹幕 SVG（`DanmakuIcon`）。U.1 已做直播间用到的部分。
- 修 v3：同一个图标在两处表示不同含义的，在对比页提出替换方案。
- 候选 C-2：全部换成 Material Symbols Rounded；`AppIcons` 按用途命名，换库只改一处。

### 8.5 通用组件

房间卡片、头像、状态页（骨架、空、出错、受限、离线）、标签栏、分页、设置行（开关、选择、滑块、计数、跳转）、小菜单、对话框、面板（画面下方 / 右侧 / 底部三种位置同一组件）、提示条、二维码。每个都有默认、悬停、焦点、按下、禁用、加载状态；电视下有焦点放大和描边。

### 8.6 动效

即时反馈 100–150 毫秒，常规状态变化 150–250 毫秒，页面和面板切换 250–350 毫秒，退出比进入快；减速曲线，不回弹；页面切换沿用 v3（`FadeForwards`）；跟随系统“减少动态效果”。

## 9. 性能、流畅度和刷新率

### 9.1 刷新率

- v3 的“界面刷新率”三档保留：省电（交给系统）、均衡（按下和滚动时最高，停下 1.5 秒回落）、性能（一直最高）；进后台释放，画中画保持。
- 增强（在对应任务的对比页确认）：
  - 直播间播放中按视频帧率选显示模式（30/60 帧选 60 或 120 赫兹，25/50 帧选 50 或 100 赫兹）；Android 11 起对视频画面声明内容帧率（准确值、`FIXED_SOURCE`），默认只在无缝时切换；暂停和退出时清除（U.2i）。
  - 直播间里拖面板、滚列表时临时高刷，停下回到按帧率的档位。
  - 飞行弹幕速度按时间算，60/90/120/144 赫兹下一样快（U.2h）。
  - 电视可选“匹配内容帧率”，切台时切换。
  - Windows、Linux、macOS 只读显示器刷新率，不改系统设置。
  - iOS 的 ProMotion：Flutter 默认支持，播放时按视频帧率声明首选帧率。

### 9.2 流畅度要求（每个任务都做到）

1. 局部刷新：状态变化只重建用到它的小部件，不整页重建。
2. 列表懒加载；卡片高度可预估；图片按显示尺寸解码；滚动中不做重活。
3. 分层：视频、飞行弹幕、控制层、页面各自独立重绘。
4. 重活不在界面线程（弹幕解码、大 JSON、图片处理）。
5. 内存：图片缓存有上限；进出直播间 20 次内存不持续增长。

### 9.3 性能对设计的约束（摘要）

不用模糊（视频上方和全应用）；控制层下用黑色线性渐变；视频不圆角不裁剪；画面尺寸动画只做合成层变换；骨架屏静态无扫光；不做人数滚动动画；弹幕只描边、不加模糊阴影，透明度直接用文字颜色；圆角用装饰不用裁剪；播放器只有一份（小窗、画中画、直播间共用）；多画面最大格数按设备能力；阴影只用于浮层；Windows 不用 Mica 和亚克力。

### 9.4 指标和验证

| 指标 | 目标 |
|---|---|
| 冷启动到首帧 | 中端机不超过 v3 的 60% |
| 点击直播间到画面出现 | 不超过 v3 的 70% |
| 滚动帧耗时 | 120 赫兹设备 P90 ≤8 毫秒，掉帧 <1% |
| 弹幕高密度（每秒 200 条） | 不掉帧，界面线程 ≤3 毫秒/帧 |
| 内存 | 连续进出 50 个直播间不增长 |

v3 基线（归档 v4 实测）：Windows 首页 481 MB、一个直播间 801 MB、3 格多画面 1054 MB；Android 直播间 PSS 462 MB。每个任务完成后 profile 模式看一次帧时间；基准场景（热门快速滚动、每秒 50 条弹幕、4 路多画面、设置页滚动、进出直播间 20 次）写成集成测试，在 K90 和 Windows 上跑。

## 10. 代码结构和门禁（已确认，U.0 完成）

| 位置 | 放什么 | 对应 v3 |
|---|---|---|
| `packages/live_ui/lib/src/theme/` | 颜色和字号角色、间距、圆角、动效 | `lib/common/style/` |

## 11. 工作方式（详见 [PROCESS.md](PROCESS.md)）

每个任务十步：读代码 → 还原 v3 → 设计新方案（各客户端、各形态、各状态）→ 生成效果图和按钮编号示意图 → 发布对比评审页 → 用户逐条点“满意 / 不满意 / 再想想”并写意见 → 不满意的改了重新生成、同一个页面出下一版 → 定稿后导出图片、写说明、推送 GitHub → 开发代理按任务书实现 → 合并验收。

- **效果图有源文件**：每张图是 `compare/<编号>/src/` 里的 HTML（用 `tools/ui/mock/kit` 的组件样式），`render.py` 一条命令生成原图、编号示意图、深色图；改一处重新生成即可。
- **评审页能直接表态**：对比页的每条改动、每个选择下面有按钮和备注框，自动保存，我直接读取，不用在聊天里逐条描述。
- **同步到 GitHub**：每次定稿和每个新版本都导出图片（对比页按章节、单张效果图、编号示意图）、更新 README 和 TASKS，门禁通过后推送。
- **节奏**：每批 2～4 个界面一个对比页；一批确认后，开发和下一批设计并行。

## 附录 A：必须保留的旧操作习惯（回归测试清单）

每条在对应任务重构时写成测试：

1. 手机单击画面：控制层可见且在播放 → 隐藏；暂停中 → 显示并继续播放。桌面单击只显示控制层。
2. 控制条范围内的点击不触发弹幕命中。
3. 双击：竖屏源进入竖屏全屏，其余进入全屏；在全屏中先退出。
4. 左侧上下滑调亮度、右侧调音量；锁定按钮锁住所有手势。
5. 竖屏直播间的三档面板；拖过最低档或点把手进入竖屏全屏；竖屏全屏时在底部上滑退出。
6. 点击或长按命中的弹幕，打开复制和屏蔽菜单。
7. 返回链：弹层 → 全屏 → 普通 → 离开；Esc 和 iOS 滑动返回走同一条链。
8. 应用内小窗：有弹层时隐藏；手机上第一次点击显示控件，再点回到直播间；只有有画面且没有加载错误时才转为小窗。
9. 切换画质和线路不重建播放器，以最后一次选择为准。
10. 进入直播间不改设备音量（全局静音除外）。
11. 强制横屏全屏退出后恢复竖屏（手机）。
12. 可选的“默认全屏”：进入直播间后自动全屏。
13. 多画面：点格子切换声音焦点；一大多小中点小格晋升；长按或右键打开格子菜单；点空格选直播间。
14. 卡片长按或右键 = 操作菜单。
15. Windows：在新窗口打开直播间；小窗可选置顶。
16. 键盘：空格和媒体键暂停，R 刷新，↑↓ 音量，Esc 链（macOS 用 Cmd 组合键）。
17. 回到前台时识别剪贴板中的分享口令（兼容旧格式）。
18. 定时关闭。
