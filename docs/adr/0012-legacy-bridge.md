# 0012 旧应用接入 v4 平台层（3.3.x）

- 状态：已接受
- 日期：2026-09-27

## 背景

PLAN 第 4 阶段的完成标准是“旧应用接入后发布 3.3.x”，目的是让用户先用上 v4 平台层的修复，同时让 v4 代码在真实用户中得到验证。

旧应用的平台接口（`lib/core/interface/live_site.dart`）分两部分：

- **列表、搜索、链接**：只返回卡片 `LiveRoom` 和分区 `LiveCategory`/`LiveArea`。进入直播间时，页面会重新请求详情（`live_play_controller.dart:294,699`），不使用卡片里的数据。
- **详情和取流**：详情里带着平台专属的数据，旧播放器、录制器和多画面直接读它们。例如：
  - 抖音、快手的原始流数据（`douyin_site.dart:665`、`kuaishou_site.dart:174`）；
  - B 站、虎牙的弹幕参数；
  - 斗鱼的画质游标；
  - 租期接口。

要把详情和取流也接到 v4，就得把 v4 模型反向转换成这些旧格式。第 5、6 阶段会用新的播放、弹幕、录制层整体替换它们，这部分转换写完就作废。

## 决定

1. **3.3.x 只把列表、搜索和链接解析接到 v4**：分类、分区房间、推荐、搜索，以及斗鱼别名这类要联网才能解析的链接。详情和取流继续走旧代码，诊断里查出的详情类缺陷直接在旧代码里定点修复。
2. **桥接层放在旧应用里**（`lib/core/site/v4_bridge/`），属于接线代码，符合 ADR 0007。它负责：
   - 把旧接口的页码调用转换成 v4 的不透明游标：按“平台 + 列表 + 参数”缓存下一页游标。没有缓存游标时，从第 1 页顺序补齐，不猜。
   - 把 `RoomCard`、`Category`、`Area` 转换成旧模型。
   - 把 `SiteError` 转换成旧页面能处理的异常，保留类型名，便于日志定位。
3. **标识必须和旧版一致**：旧版会持久化收藏的分区（`favorite_areas_controller.dart`）和关注的房间。只有当桥接后的输出与 `fixtures/` 里该平台的旧版期望值逐字段一致，只剩规格明确要求的差异时，该平台才切到 v4。验证写成旧应用测试 `test/v4_bridge/`。
4. **按平台开关**：`lib/core/site/v4_bridge/v4_platforms.dart` 列出已切换的平台，只在代码里改，不做成用户设置。出问题时，发布一个把该平台移出列表的补丁版本即可回退。
5. **请求节流**：旧应用用 `ThrottledHttp` 包住 `IoLiveHttp`，间隔取各适配器声明的值（快手）。代理和 Cookie 从旧设置转换成 `ProxyPolicy` 和 `CookieVault`。

## 备选方案与放弃理由

- **详情和取流也桥接**：要为 5 个平台重建旧版的流数据、弹幕参数和租期格式，这些都会在第 5、6 阶段被替换。
- **不接入，只在旧代码里逐个修缺陷**：v4 平台层得不到真实用户的验证；列表类缺陷（快手翻页、推荐重复、虎牙搜索重复、HTML 实体、B 站搜索封面、抖音人数口径）在 v4 里已经修好并有样本测试。
- **做成用户可见的开关**：违背“界面只做必要的选择”，也增加测试矩阵。

## 影响

- 3.3.x 的发布说明要写明哪些平台的列表和搜索换成了新平台层。
- 桥接层在第 8 阶段随旧应用一起删除。
