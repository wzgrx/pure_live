# D04.1 弹幕性能和可读性：批量通知、昵称颜色对比度

- 规模：中；分组：弹幕；依赖：—；能否和别的任务同时做：可以和 A02.3、A10.3 同时；和直播间组改到同一批文件时错开（`room_controller.dart`、`chat_list.dart`）
- 出设计：不用（照已确认的设计和本任务单）
- 先读：审查报告 B-5、B-6、B-20；调研报告 `docs/V-需求和反馈/V03-审查和调研/V03.2-流畅度、刷新率、分辨率调研/README.md` 2.5 节 S5、1.7 节 R5
- 可以改：`features/live_play/logic/room_controller.dart`、`features/live_play/danmaku/`、`features/live_play/record/record_panel.dart`、`shared/danmaku/danmaku_overlay.dart`；其他目录不改。

## 要做的

- c1 B-6、调研 S5：房间控制器收到弹幕后批量通知（每帧最多一次，或约 15 Hz），聊天列表单独监听弹幕流；聊天列表改成 `reverse: true`（索引反转，最新的在底部），去掉 `chat_list.dart:150-166` 每条消息后的 `jumpTo(maxScrollExtent)`；跟随最新时不跳，往上翻看旧消息时列表不动；表情只解析一次（缓存在消息上）。不影响飞行弹幕的时序。
- c2 B-5：聊天昵称颜色按相对亮度计算，逐步加深（浅色主题）或提亮（深色主题），直到对背景对比度 ≥ 4.5:1。
- c3 B-20：录制面板不再在界面线程同步 `File.existsSync()`，改成异步检查并缓存。
- c4 调研 R5：画面弹幕层（`shared/danmaku/danmaku_overlay.dart:388`，按每帧时间差累加）遇到时间差为 0 的帧（可变刷新率下引擎会给出相同时间戳，Flutter #190372）时跳过、不在下一帧补双步。

## 验收

- 每秒 200 条弹幕时界面线程每帧 ≤ 3ms（计划书第 9.4 节），聊天列表顺滑；所有昵称颜色在两种主题下对比度 ≥ 4.5:1。
- 测试：批量合并的条数和时序；跟随最新和往上翻两种状态；相同时间戳的帧位移平滑；颜色对比度（多种颜色 × 两种主题）；录制面板不调同步文件接口。可以写一个基准测试（每秒 200 条，统计重建次数）。
