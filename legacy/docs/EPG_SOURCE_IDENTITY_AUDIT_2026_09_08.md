## 结论与根因

基线 `cbfeae8cc9584683f650a3a1977b05b8d5f69953`，业务提交 `25b117594719bf5233d712078d728b11638cac28`。接续 [EPG 导入事务审计](EPG_IMPORT_TRANSACTION_AUDIT_2026_09_08.md)，本批修复跨来源原始频道 ID 相同时的频道覆盖、节目混合与房间映射歧义。

已核对冻结上游 `c6c9bd70aedc503c003110dae10a83ad0bb891d8` 的完整 importer、database、IptvSite 文件，仅读取本地 Git 对象，没有 fetch/merge。首个错误状态为导入器把 feed 的原始频道 ID 直接写入全局主键；programme 同样存原始 ID，而节目查询没有来源条件。上游保留相同写入与查询契约，归类 **upstream-existing**。房间按 raw TVG ID 跨频道查询映射且要求单条，多个映射触发 `Too many elements`，同属既有问题。

| 路径 | 本批修订 |
| --- | --- |
| 导入及查询身份 | `epgChannelKey(sourceId, rawId)` 使用带前缀的 JSON 二元组，处理分隔符、Unicode 与看似新键的原始 ID；channelId 字段保留 feed 原文，channel 主键与 programme 引用使用来源限定键。 |
| 房间、分类卡片 | 共用来源限定的解析入口；映射按 IPTV channelId + providerId 查询，再核对所选 EPG 来源。移除跨频道 raw TVG 映射查询；保留原始 TVG 匹配和原有名称匹配算法。 |
| 锁定与历史引用 | 同来源旧 raw mapping 解析为当前存储键；锁定而失效的映射保持空结果，不自动模糊替换。其他 provider 的旧映射不复用；未选择来源时不展示其他来源节目。 |
| 播放器节目表 | 老房间 raw EPG 引用先在所选来源解析；其他来源的存储键不直接查询。节目查询成功不作为媒体解码成功证据。 |

选择局部身份修订和有界兼容，而非合并上游或改写匹配器。横竖屏/全屏/小窗/音频模式共用的数据入口受影响，但布局、播放器所有权、暂停/退出意图、弹幕、原生录制和 Windows 窗口代码没有重写；这些模式的实际呈现继续待验。

## schema 6 → 7 与旧数据

- 表和列保持原定义、生成文件未变，数据语义升至 **schema 7**。旧 1–6 步骤和身份迁移放入同一事务，`PRAGMA user_version` 也在事务内提交。已读取本机 Drift 2.34.4 执行器：它在 migration callback 完成后另写版本，因此本批提前提交相同版本，避免数据已提交而版本未写时再次转换缺少频道行的引用。
- 临时别名表按来源快照转换 programmes/mappings，避免原始 ID 恰等于另一个新键时产生链式重复改写；频道行先快照后重建，保留其全部其他字段。
- 提醒和预约录制没有来源列：优先使用已关联 IPTV 频道的唯一映射，其次唯一全局别名。歧义旧引用保留原值，不猜选来源；时间、状态、输出路径、用户关联频道和来源开关等保持。
- 历史碰撞已经丢失的频道元数据不凭空补造；保留其 programme/mapping 并转换来源限定引用，重新导入后再恢复频道目录。
- 迁移故障触发器验证回滚后仍为版本 6、旧快照不变，撤掉故障后重开重试成功；模拟已提交迁移之后的打开异常，重开仍为 7 且孤立引用只转换一次。未来版本 8 打开被显式阻止，版本及数据保持。
- 1–5 版本测试按现有迁移步骤重建历史 schema 合同，并非历史 APK 导出的数据库。正常重开验证持久性；另对具有存活频道行的已转换数据人工回写版本 6，验证该夹具重放一致。不要把人工修改版本号当成通用降级方式。
