# 虎牙醒目留言 HTTP 所有权审计

## 冻结、来源与第一个错误状态

- 本地基线 `124ec716`，只读上游 `c6c9bd70`，本轮不合并上游。
- `upstream-existing`：留言板使用 `BaseTarsHttp` 默认值 60000，但包装类把它解释为
  **秒**，且缺少发送/接收总等待边界。每次请求创建 Dio，成功/失败均未关闭。
- 本分支 `398d182d` 已把 WebSocket 处理与留言板等待分开，但外层 3 秒
  `Future.timeout` 只结束等待，不取消底层连接。弱网重试可叠加仍在等待的客户端。
- `huya_site.dart` 与 `huya_utils.dart` 还有两份请求/解析实现：一份 HTTPS、一份 HTTP，
  空列表处理和“最近一条”的排序也不一致。重复实现扩大修复遗漏的风险。

这属于辅助请求的资源缺陷，不作为已证明的媒体 EOF 或所有 CPU/卡顿问题的根因。

## 修复设计

共用一个 HTTPS 实现，连接/发送/接收各有界，整次留言板请求最多等待 3 秒；
每次请求独占客户端，并在成功、HTTP 失败、解码失败、总超时路径统一强制关闭。
保留 WebSocket 消息非阻塞处理、按会话隔离、现有有限重试和事件 ID 去重。
不更改通用 TARS 默认值、不新增长期后台任务，不更改直播取流、录制或界面。

测试通过真实 Dio 适配器与 TARS 编解码验证，不只匹配源代码字符串。

## 验证

- 修复前抽出等价的客户端工厂作为测试接缝，不改变超时/资源所有权；七项回归实际失败，
  `20260905T044754648Z-quality-focused.json`。前两轮夹具构造缺少合法的 TARS 响应字段，
  相关夹具错误不计为产品缺陷；补全后本记录七项均失败于 HTTPS/连接释放断言。
- 修复后包括 7 项留言板和现有弹幕传输、播放器、签名、缓存的 **130/130** 定向测试通过，
  `20260905T045039282Z-quality-focused.json`，并覆盖请求方法、主播 ID、页大小、UA、
  空结果、排序/事件 ID、正常返回、HTTP 失败、WUP 解码失败及超时关闭。
- 客户端由工厂每次新建，`finally` 不关闭其他平台/房间共享的 Dio；弱网下不留下等待至
  默认 60000 秒的旧请求。WebSocket 外层 3 秒等待仍作为注入 fetcher 的独立保障。
- 生产 HuyaSite 委托入口公开 HTTPS/WUP 请求通过，232 ms 返回合法空留言板；
  `20260905T045242145Z-quality-focused.json`。该房间在此时没有醒目留言，不据此声称
  正在发送的付费留言已由真实 UI 接收；有内容/排序/ID 由前述确定性夹具分别验证。
- 最终全仓门禁在实际运行后补记；回滚只涉及此共享助手、HuyaSite
  的委托和相关测试，不回退播放器已验证的原生凭据/预取策略。
