# 0001 v4 重写的 12 项基础决定

- 状态：已接受（“播放内核”一项被 [0006](0006-license-compliance.md) 取代：只用 mpv；“仓库方式”中的目录安排先被 [0007](0007-repo-layout-workspace.md) 取代，现由 [0013](0013-legacy-folder.md) 决定：旧应用收进 `legacy/`）
- 日期：2026-09-27

## 背景

v3.2.11 的 `lib/` 有 18.3 万行，播放管理类 5028 行，内置 1.6 万行 GetX，约 150 个依赖（含 3 套播放器、4 份 FFmpeg），arm64 安装包 144 MB，正式发布使用调试签名。用户要求全部重写并重新设计界面、交互、适配和性能，工具链和依赖一律用官方最新稳定版。方案见 [docs/rewrite/PLAN.md](../rewrite/PLAN.md)。

## 决定

| 事项 | 决定 | 主要理由 |
|---|---|---|
| 仓库方式 | 原仓库 `master` 原地替换，旧应用留在根目录作为 workspace 根（ADR 0007） | 保留 stars、issues、发布记录和应用内更新地址；底层包可以先接回旧应用发布 |
| 首批平台 | B 站、斗鱼、虎牙、抖音、快手 | 覆盖大部分使用量；其余 28 个按维护成本逐个评估 |
| 播放内核 | Android mpv 为主、fvp 备用；Windows mpv；去掉 IJK、Exo | IJK 占 12.7 MB，Exo 与 mpv 能力重叠；两个内核足够兜底 |
| 录制 | 本地中继直写 + 共用 FFmpeg，去掉 FFmpegKit | FFmpegKit 占 29.1 MB；中继续流让录制没有缺口 |
| 状态管理 | Riverpod 3 + go_router | 可测试、可替换依赖；Mangayomi、LocalSend 等大型项目验证过 |
| 签名 | 正式密钥 + APK 签名 v3 密钥轮换 | 调试证书存在被冒签风险；轮换在 Android 13+ 无缝，9–12 需实测，8 需重装 |
| Firebase | 移除 | 国内经常无法访问；WebDAV 和局域网同步已覆盖同步需求 |
| TV | 同一安装包内的 TV 模式 | 一套代码；启动时检测 Android TV，也可手动切换 |
| minSdk | 保持 26 | 不放弃 Android 8 用户；代价是这部分用户换签名时需要重装 |
| JDK | 27 | 最新特性版，Gradle 9.8 已支持 |
| 崩溃上报 | 可选、默认关闭 | 隐私默认安全 |
| 视觉风格 | Claude 在第 2 阶段调研后决定 | 用户授权 Claude 决定后续选择 |

## 备选方案与放弃理由

- 另开新仓库：工作区更干净，但会丢失 stars、issues 和更新地址，而且和“只保留 master”冲突。
- 一次性重写全部 33 个平台：工作量集中在后期验证，风险高；先做 5 个把架构跑通。
- 保留 FFmpegKit：实现简单，但体积大，且录制无法无缝续流。

## 影响

- 第 3 阶段需要把旧应用移动到 根目录的旧应用，并调整 CI 和构建脚本的路径。
- 签名切换前必须在 Android 9、12、13 以上真机验证覆盖安装。
- 之后的技术选择由 Claude 决定，逐一写入本目录。
