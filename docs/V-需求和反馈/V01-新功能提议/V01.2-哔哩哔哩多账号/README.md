## 目标

有两个以上哔哩哔哩账号的用户（大号、小号，或家里几个人共用一台电视或平板），现在换账号要退出再扫码，或者去 Cookie 页粘贴另一份 Cookie。提议：记住登录过的哔哩哔哩账号（名字、头像、uid），在账号页一键切换，不用重新扫码。

## 评估结论和设计（定稿，2026-10-09）

### 读过的上游代码（`~/ref/pure_live_TV`，`6ba16c55` 加的文件，现在的版本）

- `lib/services/cookie_manager/bilibili/bilibili_account_roster.dart`（183 行）：`BilibiliRosterAccount`（uid、名字、头像、Cookie、锁码），整张名册用 `HivePrefUtil.setObjectList` 存在偏好里（**明文**，`_persist` `:98-101`）。`recordActive`（`:105-116`）：uid 大于 0 才记，同 uid 更新 Cookie、名字和头像，锁码保留。`switchTo`（`:152-157`）：先写 uid 再写 Cookie，靠 Cookie 变化重新取账号信息。`remove`（`:144-148`）：只删名册，注释写“删当前的要调用方先退出”。没有上限。
- `bilibili_account_service.dart`（118 行）：`_loadAndCommit`（`:48-73`）取到账号信息、名字不空时调 `recordActive`；平台说 Cookie 失效时 `logout`（`:55`）；`logout`（`:103-107`）**只清当前 Cookie 和 uid，不动名册**，所以退出以后那个账号的 Cookie 还明文留在名册里。
- `features/settings/pages/account_bilibili_page.dart`（389 行）：名册一组（每行头像、名字、“当前账号”或 UID、锁的图标），点一行弹“切换 / 密码锁 / 删除”的选择框；删当前的会先退出；最后一行“添加账号”弹扫码框；当前账号还没进名册时补一行“虚拟”的（`_displayAccounts` `:124-140`）。头像字段从来没被填过（调 `recordActive` 时都不传 `avatar`），行里实际显示的都是名字的第一个字。

**借鉴**：登录（核验）成功就记进名册、同 uid 更新；切换 = 把那个账号的 Cookie 和 uid 写成当前的，靠现有的 Cookie 变化通知让各处跟上；先写 uid 再写 Cookie；删当前的等于退出；名册的“添加账号”进扫码。

**不借鉴**：明文存 Cookie（4.x 每个账号单独加密，名字也在密文里）；退出后名册里还留着 Cookie（4.x 退出就忘掉，S5）；没有上限（S3）；方向键锁码和启动解锁（S15）；点一行先弹选择框（手机上直接放“切换”按钮，S6）。

### 和现有代码的关系（核对过的文件:行）

- 当前账号：`packages/live_store/lib/src/secrets.dart` 的 `SecretRefs.cookie`（`cookie/bilibili`）和设置 `bilibiliUid`（`settings.dart:1481`，`internal`，只在带账号的备份里）。平台适配器和直播间只认这两个（`apps/pure_live/lib/app/platforms.dart:164` 的 `storedUid`、`room_controller.dart` 订阅 `cookieChanges`），所以切换只要改这两个，弹幕重连、取流自然跟上，不用改平台层。
- 核验拿到 uid 的地方有五处：扫码、网页登录（共用 `account_services.dart` 的 `storeBilibiliLogin`）、粘贴保存和页面核验（`platform_cookie_view.dart` 的 `_save`、`_verify`）、账号总览打开时（`account_list_view.dart` 的 `_check`）、启动 1 秒后（`app/startup.dart` 的 `verifyBilibiliLogin`）。原来它们都调 `AccountActions.rememberBilibiliUid`，现在改成 `rememberBilibili(uid, name:)`，记 uid 的同时记进名册，一处改动五处生效。
- 备份：`BackupService.exportAll`（`backup_service.dart:34`）只在 `includeSensitiveData` 时写 `cookie` 分区；本地和 WebDAV 备份（`shared/backup/backup_data.dart` 的 `exportBackup`）从来不带；设备同步发送、对方拉取都用 `includeSensitiveData: includeAccounts`（`remote_sync_service.dart:385`、`:412`，“同步账号 Cookie”默认关）；J05.1 把整个 `cookie` 分区算作“账号 Cookie”一类（`sync_parts.dart` 的 `_wholeSections`）。3.x 读 `cookie` 分区只取认识的键（v3.2.11 `lib/common/services/settings/cookie_settings_controller.dart` 的 `parseConfig`），多一个键没有影响。
- 录制：录制取流时读当前 Cookie；已经在录的流不受切换影响，断线重连再取流时用新账号（和现在换 Cookie 一样）。

### 设计选择（D-003：维护者按建议定，用户随时可以推翻）

| 编号 | 问题 | 选了什么 | 为什么 |
|---|---|---|---|
| S1 | 名册存在哪 | 每个账号一条加密的秘密 `account/bilibili/<uid>`，值是名字、Cookie、最后使用时间（都在密文里）；不建新表、不加设置 | 和当前 Cookie 同一个加密存储（K02、J02 的 `SecretStore`、Keystore）；名字和 uid 也是个人信息，放进设置会跟着普通备份走，秘密只在带账号时导出；Keystore 出错时一次写入要么全成、要么全不变 |
| S2 | 当前账号怎么存 | 不变：`cookie/bilibili` 和 `bilibiliUid`；名册是附加的 | D-018；3.x 导入、平台适配器、弹幕都只认这两个 |
| S3 | 最多几个 | 5 个；第 6 个登录时忘掉最久没用的那个（永远不忘当前的）；“添加账号”一行在满了时写明 | 提议的建议；少存几份登录凭据；一屏放得下；忘掉的只是“记住”，要用时重新登录 |
| S4 | 什么时候记进名册 | Cookie 核验通过、拿到 uid 时（扫码、网页、粘贴、页面核验、账号总览、启动核验）；同 uid 更新 Cookie 和名字；没变时不写 | 照上游“登录即记入”；核验不了（没网）的没有 uid，分不清是谁，不记；一个入口改动覆盖五处 |
| S5 | 退出当前账号 | 退出（总览、页面、清空保存、核验失效自动退出）时同时从名册删掉它；其他记住的账号不动 | 默认行为不变：只有一个账号时，退出后本机不留这个 Cookie，和现在完全一样；上游退出后名册里还留着明文 Cookie，不照搬 |
| S6 | 界面放哪 | 哔哩哔哩账号页（Cookie 页）状态卡下面加一组“已记住的账号”：每行名字的第一个字、名字、“UID n · 当前账号”或“UID n”；不是当前的行尾“切换”和删除；最后一行“添加账号”。账号总览（A12.1）的行不变，只有“没登录但记着账号”时点它进这一页（原来直接进扫码） | A12.1 确认过的总览不动，一个账号的用户在总览里看不到变化；哔哩哔哩的登录本来就在这一页管；切换只要两步（进页面、点切换） |
| S7 | 切换 | 先确认（“切换账号”：“切换到“X”？正在看的直播间会用这个账号重新连接弹幕。”）；确认后先写 uid 再写 Cookie（一次加密写入，失败时什么都不变并提示）；页面的 Cookie 框换成新的、重新核验；离开的账号留在名册里。当前登录没核验过、不在名册里时，确认框写“现在的登录还没核验过，切换后不会记住它。” | 切换会让打开着的直播间重连，先问一下；顺序照上游；不悄悄丢掉没记住的登录 |
| S8 | 切到一个已经失效的 | 切换后马上核验；平台说没登录 → 提示“哔哩哔哩登录已失效，请重新登录”，退出并忘掉它；之前的账号还在名册里，可以切回去。不在后台核验其他账号 | 和总览、启动核验对失效登录的做法一样（K02）；后台逐个核验会多请求平台、容易触发风控（-352） |
| S9 | 删除 | 不是当前的账号行尾有删除按钮，先确认（红色“删除”）；当前账号没有删除按钮，用页面原有的“退出登录” | 删当前的就是退出（上游同样）；一个动作一个按钮（UI.md 第 3 节第 6 条） |
| S10 | 添加 | 组里最后一行“添加账号”进扫码页；登录后回到这一页，新账号是当前的，原来的可以切回 | 不另做页面；网页登录、粘贴 Cookie 从扫码页的“扫不了？”照旧能进 |
| S11 | 头像 | 不显示真头像，用名字的第一个字（`CommonAvatar` 没有图时的样子） | 4.x 的核验接口 `BilibiliSite.account` 只回名字和 uid；上游的头像字段实际一直是空的；加头像要改平台层、多一次请求 |
| S12 | 备份和设备同步带不带 | 和当前 Cookie 走同一条路：放在 `cookie` 分区的 `bilibiliAccounts` 里，只在“带账号”时导出。本地和 WebDAV 备份不带（和现在一样）；设备同步只在打开“同步账号 Cookie”、并且勾着“账号 Cookie”（J05.1）时带；对方来拉取时同样看本机的开关 | 提议的建议；名册里每一条都是登录凭据，不能比当前 Cookie 更容易离开设备 |
| S13 | 收到名册怎么用 | 加进本机名册（同 uid 替换），本机记住的其他账号不删；当前 Cookie 照旧被替换。预览的“写入 N 项账号信息（其他账号不变）”把名册里非当前的账号也算进 N。不带名册的文件（3.x、旧 4.x）只写当前账号，不动名册；超过 5 个时忘掉最久没用的，不忘正在用的 | 预览已经承诺“其他账号不变”；同步不应该悄悄删掉接收方记住的登录；提议的 c6 |
| S14 | 录制中途换账号要不要提示 | 不提示 | 在录的流不受影响，只有断线重连取流时用新账号，和现在换 Cookie 一样 |
| S15 | 锁码、电视的启动解锁 | 不做 | 手机不需要（提议）；电视端开工时随 A17.2 评估，只需在名册上加锁码 |
| S16 | 效果图和评审页 | 没做 | D-036 授权维护者定；改动是在已有页面加一组和账号总览一样的行；布局由 widget 测试固定（竖屏、横屏 852×393 加 1.3 倍字号、宽屏 1280），真机截图在 K01.2 的验证里补 |
| S17 | 其他平台 | 只做哔哩哔哩；存储按平台写好（`account/<平台>/<uid>`，备份键 `<平台>Accounts`） | 其他平台的核验大多拿不到 uid（只有哔哩哔哩、抖音能在线核验，抖音不回 uid）；以后要做时只接界面 |

### 默认行为

- 只有一个账号的用户：登录、核验、退出、备份、同步都和以前一样；唯一看得到的变化是哔哩哔哩账号页多了“已记住的账号”一组（一行“当前账号”和一行“添加账号”）。
- 没有新设置，3.x 的键不变（D-018）。

### 需要用户决定的

- 没有超出授权的问题：Cookie 和名字都加密存、退出就忘、只随带账号的导出走，都按提议的建议和现有规则定。用户想要别的（例如退出时仍留在名册里、在账号总览里直接切换）可以推翻上面的 S5、S6。
