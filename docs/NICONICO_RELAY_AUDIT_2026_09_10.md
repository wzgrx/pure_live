# niconico 运行时 Cookie 与 HLS 中继验收（2026-09-10）

## 目标与实现

前置为 [会话与按路径 Cookie](NICONICO_SESSION_AUDIT_2026_09_10.md)。此前生产中继只接收命令中的静态 Cookie 与响应 Cookie；这不足以表达 niconico 独立 seat 的路径作用域、过期和 grant 替换。

- `HlsUpstreamClient` 增加运行时 `requestCookies(Uri)`，在连接取得后、发送前按实际 URI 读取，每个重定向重新取值；普通与预取请求共用该入口。
- 显式提供运行时来源时，它是唯一 Cookie 来源。返回 null 就不发送 Cookie，不回退到旧命令或响应缓存；运行时模式不留存响应 Cookie。未提供时保留原平台行为。
- 回调异常在既有请求所有权内中止请求；关闭在途连接后仍有 stop 检查，迟到连接不发送凭据。`clear()` 释放回调引用。
- `FFmpegHlsInputRelay` 传递该能力，并在桌面也启用必需的中继；无有效 HLS 输入则报错，而不是把依赖运行时 Cookie 的源静默交给原生直连。
- 会话生命周期仍由调用者持有。本接口不把 Cookie 回调冒充 seat 所有者，也不自动处理服务端更换根播放地址。

## 真实中继与媒体验证

新增 `tool/probes/niconico_relay_probe_test.dart`，显式开关运行：匿名元数据 → 独立 seat → 生产 HLS 中继 → 本机 FFmpeg 六秒双轨拷贝录制 → ffprobe 检查 → 双轨完整严格解码。通过 Clash 7897 访问上游；原生进程参数仅有本地中继 URL，平台 Cookie 与签名 URL 不进入参数或摘要。

探针观察 seat 结束并关闭中继；更换根 URI 时要求消费者重新解析，不将旧清单配合新根凭据继续使用。原生进程有时间上限、退出/管道所有权，诊断输出限 1 MiB 且只保存到忽略目录；最后关闭中继和 seat，核对 Cookie 和中继资源。

本机工具为 FFmpeg/ffprobe `2026-03-12-git-9dc44b43b2-full_build-www.gyan.dev`，与应用内 FFmpegKit 是不同证据层。
