# J06.1 3.x 数据迁移的真机验证：记录

## 2026-10-08 第一次（模拟器，路 A）

- 设备：本机模拟器（Android 16 / API 36，x86_64，1200×2608、480 dpi，带窗口、`-gpu host`；API 37 镜像和无窗口模式在本机不能用，见 V03.4 记录）。不碰用户 K90 上的正式包（D-019）。
- 3.x：GitHub 发布页的 `PureLive-3.2.11-4134-debug-signed-android-x86_64-release.apk`。
- 4.x：master `87e001ecf` 的 `flutter build apk --release --split-per-abi --target-platform android-x64`，包名 `com.mystyle.purelive`、versionCode 9001；两个包的签名证书 SHA-256 都是 `1e832295…7ff7b9`（D-006），`adb install -r` 覆盖成功。
- 造数据：**没有逐项用 3.x 界面造**，改成写一份 3.x 格式的完整备份（`backupVersion: 3`、带敏感数据），在 3.2.11 里用“备份与恢复 → 恢复备份”导入，让 3.x 自己写进它的 Hive（`HIVE_DB/app_settings.hive`，58979 字节）。备份里有：关注 15 个（哔哩哔哩 3、斗鱼 3、虎牙 2、抖音、快手、YY、网易 CC、京东、酷狗、百度各 1）、观看记录 11 条、分组 3 个（常看、游戏、音乐，5 条房间和分组的关系）、关注分区 2 个、屏蔽词 `Test`、`test`、`广告`、屏蔽用户 2 个、设置若干（深色主题、弹幕速度 130、字号 20、透明度 0.8、上边距 40、首选清晰度超清、刷新率“性能”、首选平台斗鱼、平台顺序斗鱼/哔哩哔哩/虎牙、记录保留 50）、假 Cookie（哔哩哔哩、虎牙、斗鱼）、WebDAV 2 个。假数据和备份文件只在本机临时目录，不进仓库。
- 第一次启动 4.x 时断网（`svc wifi disable`、`svc data disable`）。

## 核对（查库 `files/pure_live.db` + 界面）

| 项 | 结果 |
|---|---|
| 关注 | ✓ 15 个；界面“未开播 15”，平台标签 11 个（全部、斗鱼 3、哔哩哔哩 3、虎牙 2、抖音、快手……） |
| 观看记录 | ✓ 11 条 |
| 分组 | ✓ 3 个、5 条关系（一个房间在两组）；关注页按当前标签显示有成员的分组芯片 |
| 关注分区 | ✓ 2 个（哔哩哔哩、斗鱼 英雄联盟） |
| 屏蔽 | ✓ `Test` 和 `test` 合并成一个（`test`），`广告`；屏蔽用户 2 个 |
| 设置 | ✓ 深色主题、弹幕速度 130 / 字号 20 / 透明度 0.8 / 上边距 40、首选清晰度超清、刷新率“性能”、首选平台斗鱼、平台顺序、记录保留 50 都在 `settings` 表里 |
| WebDAV | ✓ 2 个配置；密码在 `secrets`（加密）。选中的配置没迁过来：造的备份里 `currentWebDavConfig` 写的是名字，3.x 实际存的是整个配置的 JSON（`legacy_snapshot.dart:256-259` 只认 JSON）——是造数据的问题，不是迁移的问题 |
| Cookie | 虎牙、斗鱼 ✓（加密存在 `secrets`）；哔哩哔哩没有：3.x 恢复备份时自己核验了登录（提示“哔哩哔哩登录已失效”）并删掉了假 Cookie，迁移前就不在了 |
| 底部导航 | 只剩“热门”：造的备份里 `savedMenuIds` 用了 3.x 不认的 id（`favorite`、`area`，3.x 是 `favorites`、`areas`），3.x 自己把它规整成 `["popular"]`，4.x 照样迁过来——和 3.x 一致 |
| 账本 | ✓ `meta` 里 `legacy.importedSources` 记了 Hive 文件（路径、大小、修改时间） |
| 联网后第二次启动 | ✓ 关注刷新出“已开播 7 · 录播 1 · 未开播 7”，没有重复导入 |
