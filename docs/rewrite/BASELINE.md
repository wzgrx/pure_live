# v3.2.11 基线

第 0 阶段测量的旧版数据，用来校准 [PLAN.md](PLAN.md) 第 10 节的性能预算。帧耗时、弹幕高密度、连续进出直播间的内存增长等指标，要在第 3 阶段建立性能测试工具后，用同一套工具分别测旧应用（`apps/legacy`）和新应用，这里暂不填。

测量对象：v3.2.11 正式发布包（源码 `f0d64772`）。日期：2026-09-27。

## 初步结论

- **内存是最大短板**：Windows 首页空闲私有内存 481 MB，一个直播间 801 MB，3 格多画面 1054 MB；Android 直播间 PSS 462 MB，其中原生堆和图形各约 150 MB。第 10 节的内存预算按“比旧版降低一半”设定。
- **包体**：arm64 138 MB，FFmpegKit、IJK、fvp 三份独立 FFmpeg 加上 libmpv 内的一份；Windows 包里 FFmpegKit 和 FFmpeg DLL 占 52 MB。
- **启动**：Windows 到首帧约 2 秒，目标 1 秒以内。

## Windows

环境：Windows 11，24 个逻辑处理器；便携版独立目录，用户数据与测试目录相同（3 条历史记录）。

| 场景 | 指标 | 数值 |
|---|---|---|
| 启动 | 进程启动到窗口显示（Flutter 首帧后才显示窗口），5 次 | 2057 / 1777 / 2990 / 1980 / 1938 ms，中位数 **1980 ms** |
| 首页空闲 20 秒 | 私有内存 / 工作集 | **481 MB** / 197 MB |
| 斗鱼原画 2K60 直播间，播放 60 秒 | 私有内存 / 工作集 / CPU | **801 MB** / 386 MB / 一个核的 58% |
| 多画面 3 格（虎牙、斗鱼 ×2），60 秒 | 私有内存 / 工作集 / CPU | **1054 MB** / 592 MB / 一个核的 93% |

测量方法：`C:\Users\123\claude-work\measure-start.ps1`（轮询主窗口可见，结束后等待 20 秒读取内存）；直播间和多画面用 PowerShell `Get-Process` 读取 `PrivateMemorySize64`、`WorkingSet64`，CPU 取 10 秒内 `TotalProcessorTime` 的增量。启动是热缓存启动（同一次开机内连续运行）。

## Android

环境：REDMI K90（Android 17，8 核），覆盖安装 v3.2.11 arm64 正式包，保留原有数据；在设备租约内操作，只用 intent 启动，没有点击输入。

| 场景 | 指标 | 数值 |
|---|---|---|
| 冷启动 | `am start -W` 的 TotalTime，5 次（先 force-stop） | 224 / 166 / 155 / 174 / 174 ms，中位数 **174 ms** |
| 首页空闲约 20 秒 | PSS / RSS | **195 MB** / 364 MB（Java 堆 5.9 MB、原生堆 27 MB、图形 41 MB） |
| 斗鱼直播间（分享 intent 打开），播放 60 秒 | PSS / RSS / CPU | **462 MB** / 649 MB（原生堆 157 MB、图形 145 MB）/ 74%（满量程 800%） |

注意：`am start -W` 只统计到系统画出启动窗口，不是 Flutter 首帧，也不是首页内容可见。v4 在首页内容显示时调用 `reportFullyDrawn()`，让系统工具直接测到“完全可用”的时间；在此之前，用第 3 阶段的性能测试工具补测旧版的 Flutter 首帧时间。
