## 修改前复现与代码审查

旧页无条件用 `Row + 3:2 Expanded` 放置地址和端口。在 320 像素窗口中，扣除页面、卡片和字段间距后只有
约 256 像素，两框分别只得到约 146/98 像素；3.0 倍英文标签虽然由输入框内部裁切而未抛出 RenderFlex，
但已失去完整标签和正常编辑宽度。新增几何回归要求窄屏/大字号纵排时，旧实现两框仍处于同一纵坐标，稳定失败。

端口输入另有一个确定性状态问题：页面采用即时持久化，但 `int.tryParse(val) ?? 1080` 会在用户清空字段准备重输时，
立刻把最后有效的应用层端口 `7897` 覆盖成 `1080`；`65536` 等超出 TCP 范围的整数也会直接进入设置。修改前
回归得到期望 `7897`、实际 `1080`，与源码分支一致。

## 修订

- 抽取两组共用的代理端点布局；在正文宽度不足 420 像素或文字缩放较大时纵向堆叠地址/端口，并给予两框完整宽度；
  宽桌面继续保留紧凑的 3:2 横排。
- 为四个输入框增加稳定键，分别验证应用层和播放器两组端点可滚动到达，而不是只证明首屏存在。
- 新增统一 `parseProxyPortInput`，仅接受 `1..65535` 的完整十进制端口；空值、编辑中间态、0 和越界值保留在
  文本框并显示双语提示，同时继续使用最后一个有效端口，避免输入过程让正在使用的代理连接跳到无关端口。
- 地址继续复用中文输入法标点归一化和代理指令注入防护；本批未改变应用层与播放器代理的职责边界。
