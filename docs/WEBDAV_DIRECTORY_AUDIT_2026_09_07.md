## 第一个错误状态

`WebDAVService.readDirectory` 在依赖已经成功解析后，对 `response.isEmpty` 抛 `Empty response from server`。新建目录没有子文件是正常状态，页面却进入目录加载失败分支，用户首次上传备份前即看到错误。非空目录、HTTP 错误和 XML 语法错误需要分别验证，不能把所有失败变为空列表。

同时，服务构造固定开启依赖调试日志。依赖 `WdDio` 在 debug 模式添加 `LogInterceptor(responseBody: true)`，并在请求选项中设置 authorization。默认记录请求头和响应体可能带出凭据与恢复内容；日常备份不需要这样的协议明文日志。

## 独立待处理的相邻风险

以下是代码审查发现，尚未写成“已稳定复现/修复”的结论：

1. `loadFiles` 没有请求代次或服务/路径快照约束，先发请求后返回时可能覆盖新目录或新配置的列表，旧失败也可能覆盖新成功。
2. 删除当前配置后 `initializeWebDAV` 的 null 分支不清理旧服务、列表、加载/错误状态；`_webdavService` 在首次无配置时又是未初始化的 late 字段。
3. 下载恢复没有跨网络等待的选择身份约束；切换配置/离页后，先前下载仍可能提交本地恢复。上传、删除的完成反馈和刷新也没有对应所有权约束。
4. 空目录目前没有明确空状态文字。修正服务返回后还需检查目录页面的空状态、上传入口、窄窗口和大字号呈现。

这些项目保留为 WebDAV 工作组的未验收项，不用一个目录解析回归代表整个云端备份通过。真实用户云端配置、上传和删除本轮均未操作；本地 HTTP 夹具只监听 loopback，使用合成认证值。
