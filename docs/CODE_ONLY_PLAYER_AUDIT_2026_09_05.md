## 1. 竖屏全屏底栏溢出：fork-regression

首个错误状态：双行内容已经替换，外层 `AnimatedPositioned.height` 却还处于 56→104 的动画中。子级另一个 Obx 读取新模式而高度来自父级旧快照，也存在不同步窗口。

来源：底栏动画继承 `a340cc774`，双行竖屏布局引入于 `6e1deea12`。两者组合导致问题，不归因于上游视频接口。

抽出原有容器作为生产代码共用的 `BottomControlSurface`，保持旧动画后运行回归：常规→竖屏、隐藏动画中→竖屏均出现 **底部溢出 40 px**。记录 `20260904T221101909Z-quality-focused.json`。

修复：布局高度和模式使用同一父级快照；高度立即满足当前内容，仅平移动画控制显示/隐藏；隐藏时退出点击及辅助功能树。不裁掉溢出、不缩小内容、不增加恢复延时。

## 2. 录制按钮缩窄溢出：upstream-existing

`be8fbab85` 引入的两个同类型 AnimatedSwitcher 在文字/图标切换时复用状态，旧文字仍会在新 40 dp 约束下布局；Row 中 Text 未分配剩余宽度。本地冻结上游同样保留此实现。

抽取原内容到 `RecordActionContent`，保持旧行为后复现：缩窄时长文字溢出、1.8 倍字体和英文长标签溢出。记录 `20260904T221255678Z-quality-focused.json`（底栏 2 项通过、按钮 2 项失败）。

修复：文字占 Row 剩余宽度，单行省略；Tooltip 保留完整动作名称。对录制任务、启停、文件大小统计没有修改。

## 3. 比例检测的事件饥饿：fork-regression，独立于历史黑屏定责

代码位置 `_scheduleVideoGeometryObservation`，来自 `45dbd7ac8`。每次尺寸事件取消并重新建立 120 ms 定时器。如果事件持续比 120 ms 更频繁，识别一直没有执行机会，源保持 unknown，三个展示模式都可能使用默认比例。

已采用固定窗口合并：窗口内收集最新尺寸但不推迟窗口期限；源切换仍取消旧计时器并递增 generation，拒绝过期事件。保留有效宽高成对检查和检测器稳定条件，不恢复房间比例缓存。

这条源代码路径与此前个别房间 PiP 返回后的现象相容，但历史日志缺少连续尺寸事件证据，因此不将其写成该次黑屏已确认的唯一根因。
