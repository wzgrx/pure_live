# 0009 平台样本的格式、录制与期望值

- 状态：已接受
- 日期：2026-09-27

## 背景

第 1 阶段要为 5 个主力平台录制接口和弹幕样本，并用旧版解析器生成期望值，冻结后作为 v4 的验收标准（PLAN 第 14 节，诊断 [06-tests.md](../rewrite/diagnosis/06-tests.md) ⑥）。

现有 `test/fixtures/` 有 8 个平台的样本，但格式各不相同：有精简 JSON、JSON 投影、规整化 HTML，来源信息写在 README 里，原始抓包放在被忽略的 `local-artifacts/`，现在已经找不到了。5 个主力平台一个录制样本都没有。

## 决定

1. **位置**：仓库根目录的 `fixtures/<平台>/<样本编号>-<情况>/`。编号沿用 `spec/sites/<平台>.md` 第 11 节“样本清单”的 S 编号。根目录的样本旧应用的测试和 v4 各包都能读到；`test/fixtures/` 维持现状，不再新增。
2. **一个样本一个目录**，里面放三类文件：
   - `body.<扩展名>`：脱敏后的响应体。除了被替换的值，其余保持原样，不做精简或投影，这样接口字段一变就能在比对中发现。
   - `meta.json`：录制信息，包括：
     - 请求方法、URL（签名参数已替换）、请求头（凭据已替换）；
     - 状态码和响应头；
     - 录制时间，走直连还是代理；
     - 原始响应体的 SHA-256 和长度；
     - 脱敏记录：替换了哪些字段、分别用什么规则；
     - 录制工具的版本。
   - `expected.json`：用旧版解析器生成的标准化期望值，并记录生成入口和旧版提交。
3. **弹幕**：二进制帧存为 `frames.jsonl`，每行一帧，记录方向（收/发）、相对时间和 base64 内容，脱敏在帧解码后进行、再重新编码。**媒体**：只保存前若干字节和 FLV tag 索引（类型、时间戳、关键帧、配置哈希、大小），不保存媒体数据。
4. **脱敏**规则由平台声明，统一由 `live_cli fixture` 执行：
   - Cookie、令牌、签名材料替换为合成值；如果签名需要离线复算，用合成材料重新计算签名。
   - 观众身份按“同一个人对应同一个假名”替换，同一个样本内保持一致（对照表只在录制时存在于内存里，不落盘）。
   - 媒体 URL 的签名参数替换为合成值，`expire` 等时间字段保留；CDN 主机名可以换成 `example.test`，但保留 CDN 码。
   - 主播和房间的公开信息（标题、名字、封面）保留。它们是公开数据，也是解析器需要验证的对象。
   - 替换时保留原值的形状（长度、数字、大小写、分隔符），解析器的格式校验照样能跑；含中文的昵称换成“观众 N”。
   - 写入前检查脱敏后的正文和 meta.json：只要还含有任何被替换的原值（6 个字符以上），就拒绝写入。
5. **期望值生成**：根目录的 `test/fixtures_expected/<平台>_test.dart` 读取样本，调用旧版的解析入口，与 `expected.json` 比对。
   - 设置 `PURELIVE_UPDATE_EXPECTED=1` 时改为写入期望值。
   - 首次生成后人工审核再提交，从此冻结。
   - 这些测试同时保护旧应用：3.3.x 的改动如果改变了解析结果，CI 会失败。
6. **重录**：平台接口变化时，用同一条命令重录。期望值的差异必须在提交里说明，是平台变了还是解析器改了。

## 备选方案与放弃理由

- **沿用 `test/fixtures/` 的精简 JSON**：精简时可能删掉 v4 需要的字段，接口变化也看不出来。
- **原始响应不脱敏、存私有位置**：之前放在 `local-artifacts/` 的原始抓包已经丢失，而且 CI 用不上。
- **期望值手写**：旧测试就是这样，平台接口变了测试也发现不了（诊断 06 ⑤-5）。

## 影响

- `tools/live_cli` 增加 `fixture` 子命令（录制 HTTP、脱敏、自检），成为第 4 阶段 `probe` 的基础。
- 期望值测试随旧应用测试一起在 CI 中运行。
- 需要人工确认的样本情况（例如回放、别名房间）在各平台规格的“样本清单”里逐项勾选。
