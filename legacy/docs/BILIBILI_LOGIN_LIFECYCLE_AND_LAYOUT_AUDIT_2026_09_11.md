## 修改前问题

1. 二维码使用固定周期 `Timer.periodic`，上一轮网络请求未结束时下一轮仍会启动；慢网络下可叠加多个轮询与账号核验。
2. 刷新二维码只替换 key，没有取消或隔离旧生成/旧轮询结果；旧二维码的过期、扫码或成功响应仍可能覆盖新二维码。
3. 控制器退出只取消周期计时器。迟到的生成、轮询和身份核验仍可更新状态或返回上一层页面。
4. 轮询异常每三秒重复弹出原始错误，缺少有界退避与稳定重试状态；扫码成功但响应缺少 Cookie 时也会继续轮询。
5. 身份核验期间没有独立可见状态；核验失败后的页面状态与重试路径不明确。
6. 二维码等待/已扫码提示使用不可换行的紧凑横排，Web 登录顶栏固定显示图标和文字；320×480 / 3.0 倍英文下存在挤压风险。
7. WebView 声明关闭 `shouldOverrideUrlLoading`，但又在该回调中取消 `m.bilibili.com` / `www.bilibili.com` 导航；完成处理只放在 `m.bilibili.com` 的 `onLoadStop`，`www` 路径没有 Cookie 核验入口。
8. 多次 Web 重定向会重叠读取 Cookie、请求身份并返回页面；切换二维码登录的重复点击也会发起多次路由，并用固定空白等待隐藏真实状态。

## 修订

- 二维码生成、轮询、Cookie 核验、完成导航和提示均提供可注入边界；生产 HTTP 解析集中为明确模型，二维码只接受完整 HTTPS 地址。
- 固定周期轮询改为“本轮完成后再调度下一轮”；同一 key 的并发轮询共享任务，失败采用有界退避，连续三次后进入可见重试状态，避免请求和提示堆叠。
- 每次刷新建立新代次并撤销旧计时器；生成、轮询、扫码 Cookie 核验及控制器关闭都校验代次和 key，旧结果不再改变新页面或触发导航。
- 覆盖未扫码、已扫码、核验中、核验成功、过期和失败状态；缺少 Cookie、轮询中断与身份核验未完成分别提供双语反馈。Cookie 分项清理控制字符和首尾空白后再合并。
- WebView 直接使用初始 URL，请求拦截显式启用；HTTPS 的 `m.bilibili.com` 与 `www.bilibili.com` 在导航拦截和加载完成两条路径共用同一合并式核验事务。
- Web Cookie 读取、身份核验、页面完成和二维码切换均受生命周期代次保护；重复重定向与重复切换共享任务，二维码切换优先终止旧核验意图，路由异常恢复浏览器及可见提示。
- 二维码页使用完整滚动面、响应式二维码尺寸和可换行状态行；Web 顶栏在窄屏/大字号切换为带 Tooltip 的图标动作，核验与切换阶段显示明确进度，不再留下空白页。
