# 播放器有归属输入事务审计（2026-09-10）

## 范围与原因

承接 [niconico 输入所有权](NICONICO_INPUT_OWNERSHIP_AUDIT_2026_09_10.md)。生产 seat/master/relay 已有共同生命周期，但既有播放器传输层只接受 URL 与查询策略；若先在事务外创建会话，再将本地 URL 交给播放器，创建中取消、迟到返回和切源失败的归属会丢失。本轮扩展实际共享的 `PlaybackSourceTransport`，并加入 niconico 的可重建输入配方；不是完整平台注册或应用验收。

未改依赖、版本、APK、Root/LSP、MT 配置及手机状态。未合并上游，正式 3.2.0 仍以完整目标为门禁。

## 实现与边界

- 新 `openOwned` 接受带 `CancelToken` 的输入工厂，没有伪媒体 URL 或短期 bootstrap URL。创建、原生打开、提交和清理处于同一代际事务。
- 创建被取消时等待其部分资源清理；迟到的输入关闭后才完成退出。原生打开悬挂时仍可关闭它持有的输入，不等待该原生 Future 返回。
- 新意图取消未提交的替换，原活动输入保留至新输入成功提交；中间被取代的意图不再启动工厂。创建失败、原生失败或会话失效均不提交候选。
- `PlaybackInputLease` 关闭幂等，关闭请求立即使其失效；原生打开前后检查远端 owner 的存活状态。退出也等待已开始的清理。
- 只有工厂收到的同一 token 的取消错误视为预期取消；异源 Dio 取消、创建和清理错误仍由打开及等待中的退出观察。旧注入式工厂无取消合同，保留迟到结果归属，不强制等待任意旧 Future；默认生产中继采用创建等待。
- `NiconicoPlaybackInput` 仅保留节目和画质身份及依赖，每次打开重新读取 watch、创建独立 seat/relay。代理每次打开确定，播放模式固定 `recording:false`，不缓存授权、Cookie 或共享会话。

目前 `PlayerManager` 的既有 URL 调用会经过修改后的共享传输层，但新配方尚未穿过 `LivePlayUrlResolution`、质量/线路选择、恢复、悬浮窗及路由快照；录制器状态也未接线。不得将底层接口完成描述成这些调用链已经接通。
