## 首个差异与根因

本地证据 `local-artifacts/recorder-audio-pes-20260911/retained-pes-anchors.json` 按 FLV tag 与 TS/PES/ADTS 边界读取原字节，逐帧 SHA-256 确认全部 278 个 AAC 编码载荷及顺序一致：

- 旧单段包含 41 个音频 PES，常见每包七帧；第 259…265 帧共用一个 PES 时间锚点。
- clock-v1 多段的第一段有 262 帧、39 个 PES：第 259…260 帧一包，第 261 帧另起一包。第二段的 16 帧重新分为四包。
- 首个解码音频时钟差异实际出现在第 **261** 帧，早于第二段的第 262 帧；旧单段到多段的偏移最大为 123 个 44.1 kHz 采样点。

因此，CSV 的视频参考起点修正了原来的跨段整体阶跃，但没有保留被合并进 PES 内部的逐帧音频时间锚点。分段改变 PES 分组，后续解析按音频帧长度推导内部时间时得到不同结果；这是当前录制路径的已复现缺陷，不是网络丢帧结论。上游项目是否具有相同组合仍未核定。

源码交叉检查：[MPEG-TS 写包逻辑](https://ffmpeg.org/doxygen/trunk/mpegtsenc_8c_source.html) 保存缓冲中首包 PTS/DTS，按负载大小或音频延迟刷新；[AVIO flush 定义](https://ffmpeg.org/ffmpeg-formats.html) 针对底层 I/O，和拆开每个音频 PES 并非同一层。[CLI 默认 mux delay](https://ffmpeg.org/doxygen/trunk/ffmpeg__opt_8c_source.html) 为 0.7 秒，MPEG-TS 的时间偏移使用其两倍。这些是原理佐证，当前实际二进制行为以留存对照为准。

## 业务改动与测试基线

- 只修改录制 builder 的 child MPEG-TS 参数：保留 `flush_packets=1`、禁止子段二次负时间戳归一化；将音频缓冲延迟设为零，并显式保留既有 1.4 秒前导偏移。没有更改输入网络超时/缓冲、音频中继、编解码器、清理事务或 CSV 格式。
- 旧 clock-v1 文件仍按其原有 journal 合并；该参数修订不恢复旧 TS 已丢失的内部时间锚点。旧格式文件也保持原恢复路径。
- 新矩阵保留 **旧单段、旧多段、修订前 clock-v1 多段** 三个可执行对照，额外增加实际生产单段；严格比较“同一生产参数的单段 vs 多段”，继续使用视频 2/90000 秒、音频 2/实际采样率秒门槛。
- 原先“旧单段 vs 新多段”结果仍完整报告，但不要求新代码重造旧 PES 分组造成的有损时间线。微博必须复现旧视频阶跃和修订前音频超限；微博及新抖动夹具还要求输出相对源的偏差范围严格优于旧单段。没有删除内容门槛、放大容差或隐藏旧失败。
- 新增 26 秒合成 FLV：AAC 48 kHz 单声道，9…14 秒静音，并按固定七项序列为音频时间戳加入 −4…+5 ms 扰动。仅改时间字段，保持编码载荷/顺序/结构，拒绝非单调时间戳。实际共有 1220 个 AAC 原包，最小载荷 4 B，234 帧加上 ADTS 头仍不超过 170 B；相邻时间戳间隔 12…29 ms。静音小包用于覆盖只缩小 PES 容量仍会聚合小帧的漏洞，避免仅对微博的大 AAC 帧奏效。

新增输入：904837 B，SHA-256 `32bd18402e86fa77dbed028da2f0f3ac9ba8d41980d3af17aceb7733a248be71`；完整六输入 manifest 位于 `local-artifacts/recorder-audio-pes-20260911/fixtures/manifest.json`。
