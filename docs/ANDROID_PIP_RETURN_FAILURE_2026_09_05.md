## 已观察的事实

- 设备 K90 Pro，Android 17；安装源码 `cf114605a9a4a9ad83838b9d9c884f70fb10fe66` 的 arm64 Debug 包。
- 证据目录：`local-artifacts/diagnostics/android-portrait-presentation-20260905T055016643/`。

- 无原生 FATAL，但日志另有两处 Flutter 布局溢出：`video_controller_panel.dart` 的竖屏底栏 Column 在 48 dp 高约束内布局；`record_action_button.dart` 的文字 Row 超出 0.2 px。它们不是黑屏根因的现成证据，应分别处理。

## 尚未证明的原因

此前几个不同抖音房间的同一路径均通过，所以本次是已观察但尚未稳定重复的失败，不能直接归为虎牙/上游/用户设备或宣称整体模式都正常。

可能涉及恢复时的播放器源/Surface、当前源返回的尺寸、直播内容变化或短暂恢复过程。画质源开启会重置几何代次；PiP 状态监听本身只更新模式和弹幕恢复。需要补齐同一房间恢复前后的 source/session generation、尺寸与首帧时间，再判断是否发生了不必要的重开或陈旧回调。原生日志在恢复附近出现 720×1280 解码器配置，但这单独不足以证明实际播放器输出已稳定。

禁止用任意延时、强行锁定竖屏、忽略失败断言或无条件重建播放器来盖过症状。暂不更改核心几何/恢复状态机，先做固定房间重复及故障夹具。

## 关闭条件

1. 固定房间重复，保存恢复前后首帧、几何、音频、弹幕和 Surface 状态；必要时用另一个暗画面竖屏源区分内容与生命周期。
