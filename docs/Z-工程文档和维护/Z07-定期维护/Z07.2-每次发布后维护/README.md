## 目标

每次发布（新版本号上线、`assets/version.json` 改完）之后，按一张固定的清单把文档和进度收拾好：哪些任务随这个版本发出去了、哪些还待真机、版本路线往前走了一格、README 的“路线图”和“已知问题”是现在的样子、相关 issue 已回复。第一次做时把清单写进本 README，以后每次发布照做。

## 方案

- c1 发布后清单（写进本 README，每次照做）：
  1. 读 `git log <上一个版本标签>..<这个版本标签> --oneline`，列出这个版本包含的任务（提交信息里的 `[任务编号]` 和合并提交）。
  2. 登记表：这些任务里还是“待真机”的列成一张表，交给 S02 开一次批量验证（像 S02.5）；已经“完成”的不动。
  3. `docs/PLAN.md` 第 5 节：这个版本标成“已发布（日期）”，下一版的内容按 STATUS 的第一档调整（PLAN 由维护者改，执行者写建议）。
  4. Y03：`releases/v<版本>.md` 和发布页一致（发布页多“下载哪个”和 SHA-256 两节）；根目录 README 的“路线图”“已知问题”“支持的平台”和发布说明一致。
  5. V02：这个版本修了的 issue，回复（写版本号和修了什么）并关闭。
  6. `python3 tools/docs/docs.py`；门禁 `--all`；提交。
- c2 第一次做：对 4.0.0（构建号 5001）补做一遍——18 个待真机交给 S02.5；PLAN 第 5 节标出 4.0.0 已发布；README 路线图和 `releases/v4.0.0.md` 的“以后要做的”对照现在的 STATUS 更新（例如“平台层已经准备好、界面还没接上的”现在在 E06.2，暂停中）。
