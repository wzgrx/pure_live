# LL-HLS 完整父分片录制路径审计（2026-09-09）

## 目标与实现选择

承接 [DATERANGE 保留合同](HLS_DATERANGE_AUDIT_2026_09_09.md)，起点 c136ea72，完成源码 718cad567cdecf68952a6d0bbcd322822ec40318。此前 TTing 当前清单还有 PART、PART-INF、PRELOAD-HINT、RENDITION-REPORT、SERVER-CONTROL 五类标签未准入。本批是维护分支录制预取的协议能力扩展，不是上游同步。

[HLS 第二版工作草案 -22 §3.2 / §6.3.3](https://datatracker.ietf.org/doc/html/draft-pantos-hls-rfc8216bis-22#section-3.2)说明完整分片与 PART 是可选择的媒体路径。本批录制选择完整父分片取得媒体，不重复录制 PART 和其父分片；这不是新增低延迟播放器、PART 拼接器或阻塞刷新客户端。

## 代码合同

- 五类标签进入有类型的只读元数据，不以全局忽略未知标签代替解析。校验字段类型、持续时间、服务端数值关系、显式/隐式范围、重复记录及上下文；SKIP 仍不准入。
- PART 的媒体序号属于父分片。MAP、KEY、DISCONTINUITY、PDT 必须先于该父分片的第一个 PART；范围省略 offset 时只引用同父分片、同 URI 的前一个范围。
- 仅验证已可见 PART 子集不长于父分片，不要求已完成旧父分片保留全部历史 PART 标签。对小于 part target 85% 的非末尾片保留独立片、GAP 及下一片 GAP 的例外。
- 保存尚未完成父分片的 PART 前缀，临时未给 PART 标签不视为父分片已完成；更新只可增长，标识/PDT 改变或前缀消失回滚。父分片出现时核对旧 PART 的 MAP/密钥/时钟/时长，再原子转换为完整媒体输入。
- 只有 PART 的初次输入、结束时仍有未完成父分片、越过未完成父分片等场景不算完整录制准入。记录这个边界，不把未发布的 PART 媒体计入已录制覆盖。
- 单快照最多 1024 个 PART、单父分片最多 256 个、两类 hint 各一条、最多 16 个 rendition report；LL 元数据有 256 KiB 上限，未完成 PART 继续计入原有窗口总字节预算。关闭与清理沿既有单 owner 路径。
- PRELOAD-HINT 是未来提示，不赋予下载权限；其 URI、范围与类型被读取但不请求。RENDITION-REPORT 只保存边界信息，不据此选择或下载别的质量/音轨；兼容上游相对 URI 及本地 relay 已规范化的 HTTP 绝对 URI。
- 本地输出仅含实际提供的完整媒体分片和保留事件，不继承源站 PART/PRELOAD/REPORT 或 SERVER-CONTROL 声明。冻结仍绑定最后真正发布的本地清单，未发布的后续 PART 不变成终态媒体。
- 应用默认 hlsPrefetch 仍为 false；本批真实探针显式开启，后续按真实录制结果决定应用层启用和设备验收。

## 验证与失败分层

证据目录：`local-artifacts/hls-ll-recording-20260909`。

1. `red`：旧窗口在完整父分片加 LL 元数据输入上抛出 `Snapshot identity or tag contract differs`，有效失败 1 项。排队等待其他 Java 工作后才开始，无重启或杀进程。
2. `first`：155 项通过，1 项夹具失败。旧 plan 测试把 PART 放在 ENDLIST 之后来模拟不支持标签，新解析器正确检测非法位置；将其改为显式未知测试标签，保留原有整批零准入/零下载断言，未放宽生产校验。
3. `fixed`：八文件 157/157 通过，含真实 TCP 完整父分片轮换、只下载父分片、重复读取、冻结、第二音轨失败回滚及 DATERANGE 相邻回归。分析随后发现一处探针使用 testing getter 的标注和一处大括号提示，修订后再执行严格分析。
4. `validation`：九个变更 Dart 文件严格分析通过；固定 CMAF 的 1/1 原生对照通过。`controls/range-1788965547446647/evidence.json` 中 `dateRangesPreserved` 和 `lowLatencyCompleteParents` 均为 true：关闭源站后两次缓存读取的 462 包（180 视频、282 音频）等于独立直连参考，八项缓存、22 次源请求，完整解码退出 0，关闭后池零占用。这里是 CLI ffprobe/ffmpeg，不外推为真实 Manager 或设备验收。
5. 初次在线准入于 14:52:59 UTC 开始，三份媒体已准入后在关联清单阶段出现 TLS 握手异常；未启动录制。一次有界复查于 14:55:38 UTC 开始，4 root + 20 media 全部取得，20 份媒体均准入；三个明确质量主清单选两路，自动档仍不猜测多变体。720 当前为竖屏 720×1280。
6. 首次 opt-in 真实 Windows Manager 录制仍为 0/1：`real-recording/TTing 录制 1788965882001048` 保存失败、采样及时间线；约 20.423 秒 native 退出 -1482175992，媒体 0 字节，覆盖不完整=true，非手动停止。前两份本地媒体清单曾返回 200，但视频清单在诊断时钟 31672 ms 返回本地 502；此请求未读取上游，故该 502 不等于源站 502。生产后台 `_refresh` 将失败 feed 标为不可发布，却未留原始阶段，此轮首个根因尚待新增诊断取证。
7. 补充可选刷新失败观察器，按 snapshot/retention 分类，每个 relay 最多保留两个终态事件；持久化只含本地 ID、时间、固定错误类别/合同码与 HTTP 状态，没有 URL、异常全文或凭据。观察器异常不改变调度，停止/关闭后不报告取消错误。三文件 35/35 回归及全部 13 个变更 Dart 文件严格分析通过，覆盖真实 TCP 503、解析失败、本地合并失败、快照脱离与观察器隔离。未加重试或放宽窗口校验。

8. 新增诊断后的单次有界真实取证仍 0/1：`diagnostic-recording/TTing 录制 1788966504045339`。诊断时钟 **32633 ms**、视频本地 ID `1`、`stage=retention / kind=format / contract=sequence-gap`，确认失败条件为 `HlsRetainedWindow.merge` 的连续序号检查，不是这次的 LL 标签解析/TLS/源站 HTTP 状态。首次采集没有此诊断，保留其根因未知，不倒推为同一条件。
   - native 在约 102.462 秒手动结束，停止 1507 ms、退出 0、已排空=true、尾部丢弃=false，但覆盖不完整=true，故在 `native-stop` 门禁失败；尚未进入生产 MP4 提交和独立全量解码。
   - 仅一个 TS，2,772,060 字节，SHA-256 `84761AE59096C58282DBCD61B9389D14711E887320215E5C17D5121D593A78D4`。原生日志只有 60 视频帧，统计时间 83 秒不等于连续 83 秒视频；禁止把退出 0 或存在文件记为完整 A/V PASS。
   - 诊断固定保留 512 次本地请求，另省略 3427 次；已捕获其中 493 次本地 502，显示 native 仍反复请求失败清单。仅一个刷新失败事件，没有重试上游，诊断内存保持上限。这一终态反馈与播放器侧重试行为仍需独立审查。
