本批审查抖音、虎牙、快手、Twitch、SOOP 与 YY 六个平台的 Cookie 编辑入口、保存边界、返回行为和大字号布局。没有读取或写入真实账号 Cookie，没有操作手机、访问平台网络、构建应用或发布候选。

## 修改前问题

1. 六个平台分别复制约 108 行相同页面；样式或交互修订需要多处同步，实际文件已出现换行风格与类命名差异。
2. 表单把粘贴文本原样写入持久配置。首尾空白、CR/LF、Tab、NUL 与 DEL 等 HTTP 头控制字符会进入后续 Cookie 请求头，空白字符串还会被账号页识别为已配置。
3. 保存按钮固定为 44 像素高，长帮助、320×480 窗口与 3.0 倍文字组合会把输入和动作推到初始视口之外，按钮内容也缺少随字体扩展的高度。
4. 保存后页面没有明确结果；按钮仍使用含义较弱的“设置”，多行输入同时接入 `onSubmitted`，软键盘行为与显式保存动作没有清晰分层。
5. 编辑已有值后执行系统返回或顶栏返回会直接离开，草稿静默丢失。

## 修订

- 新增 `AccountCookieEditorPage`，六个平台只提供各自提示、输入控制器与保存回调；滚动、字段、按钮、反馈和返回状态由单一实现维护。
- 新增 `normalizeAccountCookie`，保存前统一移除 HTTP 头控制字符并裁掉首尾空白；六个生产控制器分别持久化规范化结果，空白输入归一为空值。设置控制器在首次使用及备份解析时也执行同一迁移，既有配置和导入配置不再绕过边界。
- 编辑页使用完整 `ListView` 和响应式页边距；保存按钮以最小高度和垂直内边距随文字扩展，多行输入关闭联想、自动修正、智能引号和智能破折号。
- 保存统一显示“Cookie 已保存在本机”，并把规范化结果回写输入框；换行只继续编辑，保存保持独立显式动作。
- 页面跟踪已保存快照。存在修改时，系统返回与顶栏返回先显示可滚动确认框；“继续编辑”保留草稿，“舍弃”在状态更新完成后退出，重复返回只产生一个确认流程。
- 新增稳定控件键，覆盖滚动区、输入、保存及确认框动作，便于后续 Android/Windows 原生验收复用同一语义目标。
