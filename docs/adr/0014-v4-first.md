# 0014 停止构建 3.x，直接推进 v4；构建和门禁改在本机运行

- 状态：已接受（取消 0012 中“接入后发布 3.3.x”的安排）。**部分被 ADR 0039 取代：v4 改为在 v3 代码上重构**
- 日期：2026-09-27

## 背景

用户 2026-09-27 的要求：

- “不构建 v3 老版本，直接写 v4 的代码，推进 v4，写完直接构建 v4”；
- “可以构建的优先本地电脑构建，Action 太慢了，而且没有费用了”。

原计划第 4 阶段先把 v4 平台层接回旧应用、发布 3.3.x 验证，第 5 阶段也要回接旧应用。这些工作会被第 6 阶段的新应用整体替换，现在全部取消，时间都用在 v4 上。GitHub Actions 的额度已经用完，托管机器也比本机慢得多。

## 决定

1. **3.x 不再构建和发布。** v3.2.11 是最后一个 3.x 版本。
   - ADR 0012 的“接入后发布 3.3.x”取消。已写好的桥接代码留在 `legacy/` 里，不再扩展。
   - STATUS 里“旧应用（3.3.x）待办”不再修到旧应用里。它们都已写进规格或回归清单，由 v4 的实现覆盖。
   - Windows 上验证旧构建脚本的安排也取消。
2. **`legacy/` 冻结，只作对照。** 规格里引用的旧代码位置、样本期望值都来自这里。
   - 门禁不再跑旧应用的 analyze 和测试。`tools/gate/gate.sh --legacy` 保留，需要时手动运行。
   - v4 包的接口可以自由修改，不为旧应用保持兼容。
   - 旧应用最后一次完整验证通过的提交是 `a3f9824d`：全量测试通过，arm64 正式包构建通过，FFmpeg 为 n9.0.2。
3. **旧应用暂时仍是 workspace 成员。** 它的依赖约束还参与解析。一旦它挡住了 v4 需要的最新版本，就把它移出 workspace：它不再构建，不需要能解析。不让 v4 迁就旧应用。
4. **第 5、6 阶段合并推进，先做能构建的纵切片。** 第一个 v4 预览版包括：
   - 页面：发现、搜索、关注、我的；
   - 直播间：播放（mpv，斗鱼租期拼接）和弹幕。
   然后再逐步补齐录制、多画面、设置全集、TV 和其余平台。
   - 预览版包名为 `com.mystyle.purelive.next`，可以和 3.x 并存安装。
   - 版本号为 `4.0.0-preview.N`。
5. **构建和门禁都在本机运行。**
   - 推送前必须在本机通过 `tools/gate/gate.sh --all`。
   - `ci.yml` 和 `weekly.yml` 改为只能手动触发；`check_latest` 也在本机运行。
   - 发布用的安装包在本机（WSL，Windows 包在 Windows）构建和校验，不用 Actions。
6. **已安装 3.x 的在线更新不变。** 根目录的 `assets/version.json`、`assets/releases.json` 维持 3.2.11，直到 v4.0.0 正式版再决定怎么引导 3.x 用户升级。这要和签名、数据迁移一起定，另写 ADR。

## 备选方案与放弃理由

- **继续发 3.3.x**：桥接和旧代码里的定点修复，会在 v4 切换时整体作废。用户明确不要。
- **把 `legacy/` 立刻移出 workspace**：需要给它恢复单独的锁文件和依赖覆盖，现在没有收益。等出现冲突时再移。
- **CI 只保留 v4 成员的检查**：额度已经用完，自动触发的任何 job 都会失败或排队。

## 影响

- 3.2.11 的已知问题在 v4 发布前不会修。
- 推送不再有远程检查兜底，本机门禁是唯一的质量关口，每次推送前都必须跑。
- 第 4 阶段的完成标准改为“样本测试和探针全过”，已经达到。
